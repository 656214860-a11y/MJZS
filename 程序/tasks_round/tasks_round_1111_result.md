## 实现与边界

1. 既有显式字段提取仍优先；缺项且本轮引用有可读转换稿时，调用当前 writing 路由单独提取。梗概、角色、题材允许据正文归纳；集数、时长、画幅、视频模型、交付形态仅接受有原文依据的明确值。
2. 本地 Agent 任务只给本轮归档路径与唯一相对 JSON 结果路径，不注入附件全文、不加入剧本 SKILL/阶段生成要求。CLI 复用原进程，不额外占用唯一剧本槽位；桌面提取会话与正式生成配置分开。显式 API 走已配置模型的独立 JSON 提取，不生成或发布剧本。
3. 主线程沿用现有附件轮询入口读取结果；请求 ID、结构、结果大小、原文依据及附件指纹通过后，回填下方输入框缺失字段，再进入原八项 UI 门禁和四项简报契约。用户手填优先，默认示例不参与，不恢复可编辑示例或旧表单。
4. 迟到结果、输入/项目/附件选择变化、附件字节变化、取消和超时均不自动套用。具体字段无依据则仍提示缺项；归纳值压成单行，不能借换行注入另一项制作要求。PDF 等无转换稿仍保留原可操作提示，不伪称已读。
5. TSV 第二列已有字段、故事主线/故事人物别名的原最小修复一并保留；真实用户附件只读探针仅作为根因证据，不复制正文到仓库。
