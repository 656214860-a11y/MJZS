## 根因与实现

1. S1 / P1：发送闭包在执行时读取可变的窗口项目。现在捕获提交时项目，切换项目先中断旧请求；排队、执行及回调按请求 token 和项目核验，旧请求不得进入新项目。
2. S2 / P1：中断只停轮询，没有撤销排队票据。新增精确撤销单张票据的注册表入口，经 L3 注入；控制器在完成或取消时清理本请求票据及定时器。移除进程轮询中误撤本项目全部排队请求的行为，保留其他请求。
3. S3 / P2：刷新恢复使用不可取消请求且绕开排队。发送与恢复复用同一派发入口；恢复传入真实取消回调，工作结束或异常释放并发槽位，取消后的结果不回填界面。
4. F1 / P2：下载从全部模型分区混读，却用当前模型命名。下载资格与正文均限定当前模型，保存使用同一次捕获的模型身份；其他模型有稿不能启用下载。相同正文重复下载复用既有文件。
5. F2 / P2：引用阶段无条件裁为三份，并给少量选择补入历史。明确 @ 引用优先，其次完整保留选择；只在无明确选择时沿用最近三份。上传/发送最多五份及总文本上限继续由 prepare 校验，超限不静默截断。
