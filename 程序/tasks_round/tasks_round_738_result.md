# R738 结果｜同日自动续开只读根因诊断

**轮次类型：** 只读诊断。未修改任何产品 `.py`、测试 `.py`、用户项目数据或启动配置。

## 已确认的根因

不是“今日项目选择”失败。实机配置中 `project_choice_day=2026-10-01`、`project_choice_path`、`projects.json.active` 和项目登记路径完全一致；正在运行的正式启动器也是 `D:\漫剧制作助手\启动漫剧制作助手.pyw`（16:49:23 启动）。对该实际项目直接调用 `local_video.open_studio()` 实测为 **0.005 秒**。

卡顿发生在 `Desktop.load(..., defer_page=True)` 已完成项目选择之后：

| 实测事件 | 相对时刻 |
| --- | ---: |
| `load()` 返回（已安排 80ms 回调） | 336.1ms |
| `show_loaded_project()` 进入 `show(0)` | 444.7ms |
| `show(0)` 返回 | 935.3ms |

因此 `show(0)` 连续占用 Tk 主线程 **490.6ms**。Tk 在这段同步建页期间不能派发重绘，窗口就持续呈现上一次已绘制的“我的项目／正在载入今日项目…”——与用户截图一致。回调确实已进入，并非项目选择页逻辑重新弹出。

## 精确位置与证据

- `desktop.py:3280` `Desktop.load()`：自动续开路径在 `defer_page=True` 时只安排回调。
- `desktop.py:3315` 内部 `show_loaded_project()`：80ms 后同步调用 `self.show(0)`。
- `desktop.py:3631` `Desktop.show()`：销毁旧项目页并立即构建目标页。
- `desktop.py:3808` `Desktop.writing()`：`show(0)` 的剧本准备页构建入口；它在主线程内一次性创建对话框、输入区、按钮、聊天/文件区域以及绑定。

探针使用实际项目路径与正式内置 Python，隔离了项目注册写入、后台对账、资产恢复等非首屏副作用；首屏建页仍稳定占用约 491ms，故这些被隔离分支不是本次截图所示阻塞源。该过程未抛异常，所以没有可提供的异常堆栈；这是 Tk 单线程同步回调阻塞，而非异常中断。

## 复现与验证方式

1. 用内置 Python 初始化 `Desktop` 的临时应用配置，项目路径取实际“咔咔的世界”。
2. 调用同一生产方法 `app.load(project, defer_page=True)`，记录 `load()` 返回、回调进入和 `show()` 返回的单调时钟。
3. 结果如上：80ms 延时后进入建页，但直到约 491ms 后事件循环才重新可运行；最终 `page_index=0`、`root` 仍为目标项目、状态已变为项目路径。
