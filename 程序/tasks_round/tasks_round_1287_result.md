## 实现及验收

导入先复制到同目录独占临时文件，以 1 MiB 分块复制并核对源/临时文件摘要。FFprobe 验证实际流、有限正时长及视频尺寸，FFmpeg 完整解码所有相关流；视频默认要求音轨，无声项目可显式 require_audio=false。封面图流不能充当视频。验证成功才独占原子发布，重名不覆盖。失败清理本次临时文件，原输入及已有正式文件保留。音频页面转入既有异步执行器，避免完整解码阻塞 UI。阶段完成复用同一媒体事实口径。

首轮 43/43 通过；扩充封面流负例后媒体/完成/架构台账 33/33、3.5 秒通过。关联架构、分镜预演、阶段执行、文案共 45 项首轮仅静态行号一项失败，其余通过；五处 JSON 解析语句与 HEAD 逐行一致，仅台账位置更新，原三项检查复验通过，未新增豁免。默认冒烟 8/8。

实际 3 GiB PCM 音频导入（3221225516 字节）24.149 秒，Python 分配峰值 3145407 字节；输出 SHA256 与输入相同，源文件保留。测试在临时项目调用真实 FFprobe/FFmpeg、复制/全量解码/正式发布链路，完成后临时项目清除。峰值是 tracemalloc 的 Python 分配，不代表外部解码进程总内存。另有常规 64 MiB 内存上限回归。证据：临时目录 o03-large-result.json。

负例覆盖伪扩展名、截断 WAV/MP4、零时长、只有音频的视频容器、封面图流、必要音轨、源/临时内容变化、重名与原子发布失败；有效音频/分镜预演音频/视频走真实工具成功。
