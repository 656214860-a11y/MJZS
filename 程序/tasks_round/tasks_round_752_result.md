# R752 结果｜修复轮：对话动作失败反馈

## 结论

已修复云朵对话中“已理解”之后的实际动作失败被静默压成空结果的问题。无论内置 `Pet.run_plan()` 还是可替换宿主的执行器发生异常，用户都会看到“操作未完成，请稍后重试。”；异常详情仅保留在既有错误记录，避免向对话回显内部信息。

## 证据与验证

- 根因：`pet_ui.py:1577-1647` 的 `run_plan()` 在宽泛异常路径中只写 `errors` 后返回空串；`pet_cloud.py:1958-1975` 的兜底也返回空串。`drain()` 会照常恢复空闲，因此用户看不到动作失败。
- 处置：原生执行器和云朵兜底均改为同一脱敏、可行动失败文本；错误原因仍进入既有 `errors`，不改变成功或拒绝执行的语义。
- 回归：`tests/test_pet_ui.py` 注入 `show_panel()` 故障，断言失败文案和 `run_plan` 记录；另注入替换宿主的 `run_plan()` 故障，断言云朵记录出现失败文案且 `run` 记录保留。
- 默认 `smoke_test.py`：8/8 通过。
- `smoke_test.py --affected pet_ui pet_cloud`：9/9 通过；定向安全自检 111 秒、0 红。
- `smoke_test.py --architecture`：138 条、0 红、33.756 秒，通过。
- 例外全量判断：本轮触及 `pet_ui.py` 的 UI 执行链，按 AGENTS.md 的 UI 生命周期升级规则运行完整安全全量；`run_selftests.py --all --safe` 为 3,484 条、807.9 秒、0 个文件有红，`ALL TESTS PASSED`。全量基线已推进至 R752。

## J. 整改路线

继续将缺陷普查中“内部记录后返回空值”的用户动作链逐项收口：先注入失败确认空白确实可达，再区分业务拒绝、可选空操作与真实失败。真实失败必须有脱敏、可行动反馈和保留的诊断记录。

## K. 测试迁移计划

两条执行失败回归保留在现有 `tests/test_pet_ui.py` 的聊天落地测试组，沿用无真实项目数据的假宿主。未来新增宠物执行器时，必须复用该失败文本契约或显式在入口层转换，不得仅靠内部 `errors` 列表。
