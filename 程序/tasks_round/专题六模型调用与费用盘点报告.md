# 专题六盘点报告：模型调用与费用

## 1. 范围

本报告盘点「模型调用与费用」的现状：模型在哪里选、预算怎么设怎么拦、用量和费用在界面哪里显示、程序记哪几本账怎么对账、会员线路与自带密钥两条路的差别、失败和重试算不算钱、价格表从哪来怎么更新。只管桌面程序一侧已实现的代码与文档；服务端管理后台、供应商真实账单、支付与退款不在本次核实范围，涉及处标注未核实。

## 5. 给主控的问题建议

**Q6-1 「推荐模型线路」这张卡要不要补回界面？**
背景：07 册 §7.9.7 记了 R1925 已做的账号页线路卡片，但当前代码里客户端方法与控制器方法都在、却没有界面调用方（差异 D6-01）。要么 UI 在某次改版中被移走，要么从未接线。
方案 A：补回账号页卡片（按 §7.9.7 首期设计原样：复制地址＋邀请链接＋固定提示）。代价小，是把已写设计落地。
方案 B：确认不再要这个入口，把 §7.9.7 的「客户端（R1925）」段落改写为「接口保留、界面未接线」并记未实现。代价为零但功能缺口留档。
方案 C：等平台计费方案（REQ-APP-02）定了再一起做，本次只在 11 册标「未实现」。避免做一个很快要被替换的入口。
建议选 C：线路卡片的价值是把用户导到付费中转站，而邀请链接返佣规则文档里写明仍「留空待确认」，现在补回来也是半成品；先在 11 册如实标「未实现＋待裁决」。

**Q6-2 金额预算和价格表只做手工编辑，还是要界面？**
背景：`budget_amount` 与 `price_table.model_rates` 目前只能靠手工编辑项目根 `cost_profile.json`（F6-08、F6-37），`docs/process/每分钟成本核算.md` 是唯一的录入说明。
方案 A：维持手工＋文档。代价零，但填错格式（费率缺键、币种大小写）会被 `ConfigError` 拦下且提示不够引导。
方案 B：在「设置 → 预算」页加只读展示（当前上限、费率版本、已配模型数）＋「打开配置文件」按钮。代价小，堵住「不知道该改哪个文件」的最常见疑问。
方案 C：做完整编辑表单（上限、币种、版本、逐模型费率）。代价中等，要做费率校验与多币种口径，收益是消灭手工 JSON。
建议选 B：先把「在哪看、改哪个文件」说清楚；完整表单等用户对费率结构有真实诉求再做。

**Q6-3 金额上限的覆盖边界按现状写死，还是要扩到全入口？**
背景：金额上限只覆盖文本、Seedream 资产/首帧、逐句 TTS、内置 Comfy 云图片、云端视频提交；本地 ComfyUI、自定义云节点、其他图片代理不在内（F6-13）。文档已声明这不是全部制作费用的硬上限。
方案 A：维持现状，11 册把覆盖边界列成显式表并在「设置 → 预算」页提示一句。代价小，口径诚实。
方案 B：把未计价工作流在启用 `budget_amount` 时一律转人工（现状已是半阻断：只拦提交）。代价中，用户体验上等于禁用本地 Comfy。
方案 C：做全入口费用采集（本地 GPU 用量、自定义节点、其他代理）。代价大，需要计量口径设计，本期做不了。
建议选 A，并把「启用金额上限后未计价工作流不能提交」这个现状写成显式规则，避免用户以为开了上限就全覆盖。

**Q6-4 「会员线路费用」在 11 册里怎么定性？**
背景：会员（租约）只决定能不能用付费阶段，调用计量与估算对自带密钥和任何线路一视同仁（F6-28、F6-29）；平台按量计费与余额扣减在文档里是「后续需求」（§7.9.7.2），代码里 `_balance` 无写入方、没有计量上报接口（F6-14、F6-28）。
方案 A：11 册把「平台线路计费与余额显示」整段标「未实现」「待裁决」，会员与 BYOK 只写「放行权不同、本地计量相同」。
方案 B：把平台计费按 §7.9.7.2 的业务设计写成「部分实现」，风险是把未验收设计写成现状。
建议选 A：与 DOC-D3「不把目标写成现状」一致。

**Q6-5 「未知／保守占用」的费用要不要给直达处理入口？**
背景：超时、断连、远端失败的钱按「未知」留在预算占用里，唯一释放路径是「设置 → 预算 → 费用核对」人工填账单（0 表示确认无费用）。用量总览只列出未知笔数，没有跳转到核对的动作。
方案 A：维持现状，11 册把「unknown → 费用核对」的处理链写成操作说明。
方案 B：在用量总览与任务中心的 `cost` 列对 unknown 项加「去核对」直达（跳到费用核对窗口并预选该请求）。代价小，减少用户找不到入口的停顿。
建议选 B：这是纯界面接线，不动计费口径。
