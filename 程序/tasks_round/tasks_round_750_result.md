# R750 结果｜修复轮：幽灵登记清理失败反馈

## 结论

已修复项目选择弹窗清除失效登记时的静默写入失败。主界面与弹窗统一经 `clear_missing_project()` 清理；注册表写失败会显示具体原因和“稍后重试”，且不会刷新项目列表或误报成功。

## 证据与验证

- 根因：`desktop.py:3528-3535` 在弹窗回调中直接调用 `Projects.clear_missing_registration()`；该调用抛出异常时没有用户可见分支。
- 处置：将弹窗改为复用主界面清理方法；该方法只对注册表写入／登记竞态的 `OSError`、`ValueError` 做可观察降级。目录仍存在的用户可修正错误保持语义化上抛。
- 回归：`tests/test_core.py` 注入登记写入的 `OSError`，断言不刷新页面、返回失败，并显示具体原因；成功清理回归仍通过。
- 默认 `smoke_test.py`：8/8 通过。
- `smoke_test.py --affected desktop`：9/9 通过；5 个测试文件、13 条、0 红。
- `smoke_test.py --architecture`：138 条、0 红、35.193 秒，通过。
- 完整安全全量判断：`750 - last_full_safe_all_round(748) = 2 < 3`，且本轮未改 Tk 绑定／生命周期；不运行全量。

## J. 整改路线

继续以缺陷台账为顺序，优先修复用户可见却没有可行动反馈的 UI 链路；每条先复现其异常通路，再把确属外部失败的路径落为明确提示，编程错误仍维持上抛。
