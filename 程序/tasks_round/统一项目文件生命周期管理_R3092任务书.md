## 3. 设计要点

### 3.1 索引元数据字段表（Q26）

| 字段 | 含义 | 来源 |
| --- | --- | --- |
| `path` | 项目相对 posix 路径 | 扫描/索引 |
| `stage` | 阶段 id（`pet_bus.STAGES`） | 由路径推导（`stage_layout`） |
| `kind` | 类型（剧本/设定/分镜/资产/音频/视频/清单/报告/日志/其他） | 规则映射 |
| `status` | 草稿/已发布/已归档 | 由「是否在成果确认清单／是否在回收站」推导 |
| `size` / `mtime` | 字节数 / 修改时间 | `stat` |
| `order` | 顺序键（文件名前缀序号／分镜号／集号） | 命名规则解析 |
| `title` | 人类可读标题 | 文件名去前缀去扩展名 |
| `origin` | 系统生成／用户上传／模型产出 | 写入入口标记 |
| `missing` | 清单有、磁盘无（异常标记） | 一致性校验 |

### 3.2 索引文件形态

- 位置：`<项目>/工作流任务/文件索引/index.json`
- 顶层：`{"schema_version": 1, "project": "<名称>", "generated_at": "...", "files": [...]}`
- 写入走 `agent.core.save()`；读取走 `file_cache.read_json()`
- 索引是**可再生的缓存**：损坏或缺失时全量重建，不承载唯一事实
- 因 `asset_thumbs` 缓存根在 `%TEMP%`，索引**不放** `%TEMP%`（避免跨项目串味与丢失）

### 3.3 命名中心（`contract/file_naming.py`）

- `TEMPLATES`：`kind → 命名模板`（如 `script → '{project}_{file_type}_{content}_{yyyymmdd}.md'`，与 `script_contract.stage_file_name()` 等价）
- `generate_name(kind, **kwargs) -> str`：模板渲染＋片段清洗（沿用 `_file_name_part` 的清洗规则，`script_contract.py:411-415`）
- `parse(name) -> dict`：解析既有文件名取出 `order`/`title`/`kind`，供索引 `order`/`title` 字段
- `validate(name) -> None|str`：非法字符、控制字符、Windows 保留名（CON/PRN/AUX/NUL/COM1-9/LPT1-9）、末尾点/空格、长度上限（260）
- 旧名识别（只读兼容）：剧本四段式、`EP00X_分镜定稿_日期`、`EP001_SH001_哈希`、资产 `CHAR/LOC/PROP`、`原名_uuid6`、`NNN_shot_id`、`shots/shot_id`
