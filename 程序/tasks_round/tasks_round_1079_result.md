## 根因与修复

1. `idea_chat._brief_value` 的冒号后 `\s*` 会跨行，空字段误读下一字段。表单读取又只接受非空覆盖，无法表达清空。现限定横向空白，表单解析区分“未提供”和“明确为空”，保留多行正文与人物对白。
2. 创作表单原先仅读简报文件，不读已归档附件。L3 新增只读字段提取，复用项目上下文、附件枚举和解析副本；UI 打开表单时回填，上传完成时只刷新尚未编辑的空文本框。
3. 保存内容及当前输入优先于附件，包括明确清空；用户删除后刷新、保存并重开均不复活旧值。不修改生产锁下拉选项、聊天记录、Agent/API 投递和用户文件。

## 支持边界

- 读取最近三份项目内归档的 Markdown 解析副本，复用已有文本、DOCX、XLSX 转换；识别“字段：内容”和制表符分隔的字段行，以及集数、主要角色、题材类型等别名。
- 不调用模型猜测字段，不把无标签小说自动摘要。无解析副本（如 PDF、图片）、超限解析副本或未识别字段时显示手工填写／交由 Agent 解析提示；不读取外部原始上传路径。
- 本地 Agent 仍只收到相对路径；API 全文边界与原限制保持。未做真实项目视觉验收、未重启用户应用。
