# R1561：云视频实际发送内容与来源证据一致

类型：P0-5 追溯缺陷修复；无匹配队列任务。

根因：engine 先构建请求并记录摘要，随后适配器 submit 又读取素材重建请求。素材在两次读取间变化时，首帧来源摘要与实际发送内容不同；参考资产摘要也可能仍来自更早的准备步骤。

修复：engine 传入同一份冻结 payload 和捕获的首帧路径；Wan、Seedance 适配器接受可选 payload，原三参数调用保持可用。来源清单从冻结请求逐项提取参考图摘要，数量不一致则发送前报错。无重试或计价策略变更。

先验复现：新增实际请求一致性用例在两种适配器均失败，错误为记录与发送的首帧 SHA256 不同（.git/r1561-before.log）。修复后相关 96 项通过，包含素材冻结后变化、参考图实际字节、只构建一次请求，以及既有 API/生产流程/视频返工与费用恢复（.git/r1561-tests.log，17.216 秒）。无真实模型请求。

采用 minimal-diff-fix 技能执行最小修复；未改本地上传实现或新增测试基础设施。P0-3 继续待真实验收；本轮定向验证不代替供应商真实故障与商用审核。提交随本报告，最终提交以 git log --grep="^R1561:" 为准。

补充验证：架构与服务契约 18 项、smoke 8 项、轮次基线 5 项均通过（.git/r1561-architecture.log、.git/r1561-smoke.log、.git/r1561-gates.log）。最近全量通过仍为 R1559；本轮未重复全量测试。
