- 测试：两项新增回归先红后绿；API 单模块 38/38，执行器定向及受影响 43/43，默认冒烟 8/8、受影响冒烟 9/9。架构首次 310/311，唯一轮次元数据问题已在正式全量 4304/4304（含架构 311/311）中闭环。中央已有 R1213 正式全量凭据，本轮差值 6，需在 master 正式全量；历史凭据不是本轮同树验证。
- 欠账：解决本次旧路径与同文下载副本脱节导致发送阻断；无对应中央队列任务，不扩展历史待办。

## 根因与复现

只读检查发现：阶段台账仅含一份未确认项目设定，旧名称文件不存在；同目录的模型名称文件仍在，与台账原正文只差最后一个换行。旧版自动保存和下载的命名、末尾换行口径不同，后续整理文件后台账仍绑定旧路径。preparation_continuation 在请求 API 前调用校验，因只检查旧路径而报“文件已删除或修改”。这不是 API 返回失败，也不是已证实的正文变更。

隔离复现：生成设定 → 保存同文副本（分别覆盖有/无末尾换行）→ 移除旧名称文件 → 点击确认。修复前两项新增测试在该校验处失败，修复后进入大纲，未启动四角色。

## 修改与安全边界

- 仅原路径缺失时查找同目录 Markdown，候选解析后必须仍在当前阶段根目录内。
- 仅内容 SHA256 完全一致，或补一个旧版下载缺失的末尾换行后完全一致，才允许关联。不同版本不采用；原文件仍在但正文修改时，即使另有旧版副本也保持阻断。
- 预检只返回已校验的内存状态，不写项目。正式发送经现有 L3 可取消发布器保存新路径和实际正文哈希，保留确认状态；保存失败不调用模型或四角色。共享缓存仍先深拷贝。
- 不重建已删除原稿、不改写副本、不递归搜索、不自动确认、不跳过设定/大纲/角色卡流程。
