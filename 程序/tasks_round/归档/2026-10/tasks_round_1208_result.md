## 根因与修复

`writing_api.reply` 原来只检查 brief_complete.json 即转入 HOLLMWOOD，跳过后续阶段提示词；提示词规定的设定→大纲→角色卡→自然剧本没有程序门禁。桌面每次发送还重新校验/覆盖简报，单独“确认”无法继续。

1. 同一所选 SKILL 和阶段契约生成前三步；每次只保存一份待确认 Markdown。设定、人物设定进入项目设定类别，大纲进入项目大纲类别，文件名互不覆盖。
2. 阶段记录绑定简报哈希及正文哈希；明确确认才推进，普通修改留在当前阶段。三份文件逐项确认后才调用四角色，全部已确认正文进入共享简报；直接 API 模式同样执行前置阶段。
3. 文件发布及阶段记录使用注入的 L3 发布器；发布失败回滚。网络错误、空文、截断、取消不会采用失败输出。确认在下一阶段调用前持久化，失败可重试。简报变化重新从设定开始；已确认正文丢失/变更阻断，不能拿旧确认启动四角色。
4. 桌面阶段追问沿用已有简报；新简报字段仍走原校验。收到阶段文件刷新目录，提示审阅和确认。

角色顺序、审核往返、SKILL 文件、brief 字段契约未改；未调用真实外部 API、未重启应用、未改真实创作数据。
