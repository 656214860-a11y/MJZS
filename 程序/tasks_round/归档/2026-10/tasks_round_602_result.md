# R602｜性能轮：剧本对话历史读取缓存

## 本轮结论

- 模型分区对话 JSON 现在按“文件路径 + mtime 纳秒 + 大小”缓存；文件未变化时不再重复解析 JSON，外部修改或替换文件时自动失效。
- 缓存最多保留 16 份对话，读取一律返回行字典副本，编辑/删除流程不会污染缓存。
- 既有“仅提交最近 6 条、字符上限”的请求策略未改；本轮减少本地重复 I/O 与解析，不改变发送内容、历史保留或用户数据格式。

## 改动文件

- `idea_chat.py`：增加有界、外部修改可失效的历史读取缓存，并在原子保存后刷新缓存。
- `tests/test_idea_chat.py`：覆盖缓存副本隔离与外部文件更新失效。

## 验证

- `tests.test_writing_api`：20/20 通过。
- 架构门禁：101/101 通过；默认冒烟：8/8 通过。

## 后续

- 对话文件仍是兼容性优先的单 JSON 原子写入格式；若要继续降低超长历史追加成本，需要单独设计可迁移的分段日志/摘要格式，不能在性能轮中静默改写用户历史。
- 附件首次入库仍需后台任务专用队列，避免与直接模型请求共用 `async_()` 的结果票据；该项保留为下一独立改造。
