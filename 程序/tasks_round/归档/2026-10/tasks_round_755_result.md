# R755 结果｜修复轮：确认弹窗故障不得自动执行

## 结论

已修复 `stage_models.plan()` 的危险默认回退：确认窗口抛异常时，过去会返回 `'run'`，等同于未经用户确认直接启动制作动作。现在停止本次操作，并在既有状态栏显示“未能打开操作确认窗口，请稍后重试。”。

## 根因与修复证据

- 根因位于 `stage_models.py:136-147`：`PLANNER(...)` 的宽泛异常分支返回 `'run'`，把 UI 故障误解释为用户选择“直接执行”。
- 先将回归测试改为故障注入：`tests/test_manual_plan.py` 的伪 `PLANNER` 抛错，断言 `plan()` 返回 `None` 且状态栏含可行动提示；旧实现会返回 `'run'`，测试因此失败。
- 修复后该分支只调用既有 `_status()` 并返回 `None`；未触及项目数据、阶段完成语义或发布器。

## 验证

- `python smoke_test.py`：8/8。

- 全量结束后的 Tk `after` 清理输出为既有关闭时回调残留诊断，测试编排最终结果为 0 红；本轮未将其误记为测试失败。

## J. 整改路线

继续按故障注入优先核验 `stage_models.py` 其余 UI 入口（尤其配置窗口打开失败）是否存在“无反馈”或默认执行；仅在测试证明后做最小可观察降级。禁止把用户确认失败降级为自动执行。

## K. 测试迁移计划

`tests/test_manual_plan.py` 持续承载手动制作确认的失败安全契约：确认窗口异常、非法选择和用户取消都必须返回 `None`，且异常情形必须有状态反馈。新增确认入口时须复用该故障注入模式。
