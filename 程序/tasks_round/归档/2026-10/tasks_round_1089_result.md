## D. 架构与数据一致性发现

### F3 — P2：整项目回收与恢复契约不匹配

证据：`projects.py:342` 将整个项目目录交给 `recycle_paths`；`storage_maintenance.py:78–89` 支持移动目录并生成清单。反向入口 `recycle_recovery_service.py:43–47` 却仅保留 `is_file()` 条目，`storage_maintenance.py:142–147` 的实际恢复也拒绝非文件。

影响：通过应用删除整个项目后，项目内容仍保存在回收目录，但无法经现有恢复入口找回。不是物理永久丢失；仍可人工恢复。现有 `tests/test_recycle_recovery_service.py:84–89` 的库根案例覆盖文件，不能证明目录恢复有效。

建议：统一清单中的文件/目录类型契约；目录恢复仍须校验真实路径边界、符号链接/连接点、目标冲突，并明确项目注册信息如何恢复。不能简单删除安全检查。

### F4 — P2：普通 API 分支取消后仍可能发布结果

证据：`desktop.py:1820–1822` 取消 UI 任务并设置请求取消事件；`idea_chat_controller.py:71–77` 实际置位事件。`desktop.py:1667–1670` 经 `stage_execution_service.py:133–137` 把回调传到 `writing_api.reply`。然而 `writing_api.py:377–386` 的普通/工具 API 分支不检查该回调：模型返回后仍调用 `_auto_save_script_raw`；工具循环 `writing_api.py:269–332` 也未接收取消回调。`writing_api.py:204–227` 满足正文条件时会执行发布。

触发条件：简报完整、非 HOLLMWOOD 分支、请求尚在执行时用户点击中断，随后旧请求成功返回有效剧本。影响：UI 已丢弃旧结果，但后台仍可能更新工作稿；工具分支仍可能继续文件操作。HOLLMWOOD 的取消检查不能保护另两条分支。

建议：将取消/请求代次检查传到工具循环及最终发布边界；网络无法即时中止时，至少禁止取消后的业务副作用。保留 UI 迟到回调防线，但不要把它当作文件写入防线。

## E. 安全发现

### F1 — P1：认证 HTTP 请求允许跨源重定向携带密钥

证据：`model_pool.py:535–538` 和 `model_pool.py:562–566` 使用默认 `urllib.request.urlopen`，请求包含供应商 `Authorization` 或 `x-api-key`。未发现全局安装的拒绝重定向处理器。仓库其他模块如 `seedream_api.py:134–147` 已有拒绝重定向策略，但不覆盖这里。

实跑无网络探针：对标准库 `HTTPRedirectHandler.redirect_request` 传入合成的 HTTPS POST、合成认证头及另一主机的 HTTP 302 目标。输出：`cross_origin=True scheme=http authorization_forwarded=True x_api_key_forwarded=True`。未发送网络请求、未使用真实密钥。

影响：当供应商或中转返回跨主机重定向时，认证头可能发给新的接收者；HTTPS 降级到 HTTP 也可携带认证头。这不是“所有正常请求都会泄露”，而是缺少重定向信任边界。

建议：在共用传输边界默认拒绝认证请求重定向；确需支持时限定 HTTPS 同源，并在跨源前移除敏感头。流式与非流式使用同一策略，不能收到响应后才检查最终 URL。

### F2 — P2：Office 附档只限制压缩大小，解压解析没有预算

证据：`idea_attachments.py:48–60` 在压缩包大小检查后完整读取 DOCX XML，再构建 ElementTree；`idea_attachments.py:65–89` 对 XLSX 工作簿、共享字符串及工作表执行同类完整读取。没有单成员/累计展开大小限制。`store` 的本地模式也会尝试转换受支持的小压缩文件；后续 24000 字限制不约束此前的解压解析资源。

实跑内存探针：构造合成 DOCX ZIP，抽取现有读取函数执行，结果 `compressed_bytes=2192 expanded_xml_bytes=2000129 returned_chars=2000000`。未写入项目数据，未构造大规模资源耗尽负载。

影响：用户上传来自第三方的高压缩率 Office 文件时，极小文件可产生远超准入限制的内存与解析开销，造成卡顿或进程资源耗尽。不是已证实的远程无交互攻击。

建议：对 XML 成员和累计展开量设置硬预算，读取时也执行上限；限制工作表/单元格数量，必要时采用受限流式解析。仅检查 ZIP 声明大小或最终提示词长度不足。
