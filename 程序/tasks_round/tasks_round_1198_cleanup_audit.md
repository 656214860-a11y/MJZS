# R1198 生成文件清理机制审计

日期：2026-10-09。范围：日报周报清理修复，同时扫描其他生成文件的生产与清理链路；其他发现仅诊断，没有执行真实项目清理。

## 扫描范围与证据强度

- 静态基点：445445f。对 Git 跟踪的全部 611 个 Python/PYW 源文件进行 AST 扫描，解析失败 0；含主程序与工具 248、SKILL 8、测试 342、维护脚本 11、附加工具 2。发现 341 个文件中的 4092 处写入、发布、目录创建、复制、移动、删除或临时文件候选调用。候选包含同名方法和测试夹具，不代表 4092 类真实产物。
- 随后沿生产者、调用方、回收与退出维护入口逐类核验。完整静态位置索引见 [调用索引](tasks_round_1198_cleanup_sources.tsv)，可按文件、行号复查。不是只搜索“cleanup”名称。
- 对注册表登记的 3 个现存项目和程序目录做文件名/大小元数据扫描，无读取剧本、图片、音视频正文，无真实删除。跳过 private、运行环境、.git、依赖目录及链接目录；程序目录含源文件，不能将全部体积当成垃圾。
- 动态脚本、模型任意输出、未登记项目、外部 ComfyUI/Blender/Codex 数据不在实盘穷举保证内；本报告覆盖项目代码可定位的生成类别，不声称任意外部文件都已核验。

## 已修复：日报、周报

相对项目根路径：`工作流任务/宠物/日报/`；日报 `YYYY-MM-DD.md`，周报 `周报-周一日期.md`，汇总文件在同目录。`pet_report.py` 是生产及保留规则来源。

原问题是汇总按最后 90 条保留而非 90 个自然日，Markdown 只去重、不按年龄清理；宽松日期前缀还会将人工备注误认成副本。现在生成日报或周报时，保留含基准日在内的最近 90 个自然日；周报保留与窗口相交的整周。仅处理有效日期的标准文件名及数字副本；无效日期和备注不动。保持正名优先、无正名时取最新副本。回收失败不虚报成功；单独生成周报也会修剪汇总。

Markdown 经 `storage_maintenance.recycle_paths` 移至 `工作流任务/回收站/自动维护_时间戳/`，附恢复清单；汇总窗口直接收敛。`keep=0` 保持不限年龄的兼容语义。没有新增定时器：不再生成报告的项目不会主动触发。回收是可恢复移动，不等于释放磁盘，也不自动清空回收站。
