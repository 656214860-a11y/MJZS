## 2. 设计决策（用户拍板）

1. 范围：全应用统一模块，分阶段落地
2. 布局：底部一条全局状态栏；左区常驻「页标题 · 项目路径 · Token/¥/余额 · 模型用量摘要」（截断+悬停+点击详情）；右区滚动消息
3. 顶部标题行整体删除，内容区/聊天框上移；侧栏图标轨上移；页头状态/模型名功能**等价迁移**到底栏（视频页模型/状态、剧本页流程说明、分镜页 JSON 提示不丢）；会话说明删除
4. 错误：与普通提示共用容器，四级分级 info/success/warning/error；错误/警告常驻直到处理或替换，普通消息约 8 秒自动消失；点击展开最近 N 条历史；致命错误仍弹窗
5. 架构：零第三方依赖；标准库自实现 StatusBus（`queue.Queue` + `after()` 泵，API 形态抄 PyPubSub）；消息模型 `dataclass(level, text, ttl, source)`
6. 视觉：沿用 `design_tokens` 与现有 `status_kind` 语义色，补 success 级（token 已有 `color.success`）；蓝本＝IDLE MultiStatusBar、Material 3 snackbar、Ant Design 四级语义
7. 附带：文案规范（`Token: 0` 加空格、空态措辞统一）；硬编码路径收敛到唯一路径权威（`agent/prompt_optimizer.py:22`、`storage_maintenance.py:15/18` 兜底）

## 3. GitHub 调研结论（可复用部分）

- API 形态抄 PyPubSub publish/subscribe（BSD-2）；解耦思路抄 watchdog「业务只发事件、订阅者只管渲染」
- 视觉规范抄 Material 3 snackbar（底部、一次一条、4–10 秒、单行动作）、Ant Design message 四级语义
- Tkinter 蓝本：CPython `idlelib/statusbar.py` MultiStatusBar（约 60 行纯标准库）、ttkbootstrap toast.py（单文件）
- 不引入 ttkbootstrap / CustomTkinter / Sun Valley（须整体替换控件体系）；Redux/状态机库过重不引入
