## 0. 总目标

把 L2 从「底座正确但流程各写一遍」收敛为「公共能力只有一份实现」，消除四类稳定性缺陷：

1. **不重复花钱**——付费调用缺幂等键，14 个模块手搓 sha256 口径互不相同，`recon_service` 完全无防护。
2. **不丢数据**——7 处「暂存→校验→替换→失败恢复」各写一遍，其中 4 处回滚不完整，全部只在 `except Exception` 内生效，取消与进程中断不回滚。
3. **不崩**——3 个模块级缓存无锁且满即 `clear()`，并发读会得到空结果或 `KeyError`。
4. **可见**——38 条日志全部只有中文单参数，0 个业务字段；业务状态变化对上层完全不可见，只能靠轮询文件。

**明确不做**：不引工作流引擎替换 `stage_parallel`；不引 ORM；不动 `stage_parallel.CONFIG` 这个并行与重试的唯一权威；不改 L0 契约签名。

## 3. 新增模块设计

企业级对标（GitHub API 实抓，非记忆）：

- **InvokeAI** `invokeai/app/services/` **55 个子目录**，一能力一目录，目录内按 base/common/impl 三段：`item_storage/`（base 1687B / common 198B / memory 1942B）、`invocation_cache/`（base 2103B / common 449B / memory 4784B）、`gallery_maintenance/`（common 2087B / default 48887B）。另有 `events/`（base + common + 框架适配三段分离）。
- **Dify** `api/core/` **31 个能力目录**：`errors`、`logging`、`repositories`、`entities`、`telemetry`、`moderation`、`file_scan`、`rbac` 各自独立；`api/services/` 下 `retention/`、`data_migration/`、`workspace/` 同样独立。

**结论**：这些能力在企业项目里全部单独建模块，本项目同样应当。

| 新模块 | 层 | 职责 | 对标 | 替代掉的重复实现 |
| --- | --- | --- | --- | --- |
| `infra/unit_of_work.py` | L1 | 事务组合：`begin()` / `commit()` / `rollback()`。把「备份→写→失败恢复」收成一个原语，含取消与中断路径 | InvokeAI `item_storage` | 7 处事务、3 套备份底座 |
| `infra/business_log.py` | L1 | 结构化业务日志：`log_event(kind, **fields)`，字段含 stage / shot_id / asset_id / cost_ms | Dify `core/logging` + `telemetry` | 38 条零字段中文日志 |
| `infra/idempotency.py` | L1 | 幂等键：`key_of(*parts)`，内部调用 `hash_backend`（不重复实现哈希） | Dify `credit_pool_service` | 14 模块手搓 sha256（39 处 hashlib） |
