# L3 编排调度可靠性与容量验收任务书

2026-11-19，R3716。交付对象为 Windows 桌面助手。产品负责人根据开发机实测决定放行、延期或回滚。本文登记后续执行范围；工作包均待执行。

## 目标与已确认决定

1. 用户从助手界面发起制作。L3 负责任务拆分、依赖、受理、并发、取消、恢复和终态汇总；L2 判定业务合法性。单机可同时管理许多远端模型任务，模型推理由用户选定的供应商完成。
2. 首期采用用户自带 Key，桌面直连供应商或用户选择的第三方中转站；助手记录创作成本，保留实际费用、估算、未知三种口径。付费请求疑似已被上游受理时，只暂停该项，先查单；取得可安全重试的证据后才重试。无法查单时转人工核实，其他无依赖任务继续。凭据与数据归属以 [REQ-APP-02 及云端设计](../说明/账户会员云端设计.md) 为准。
3. **后续功能触发条件**：开发平台充值线路时，再接入中转站、发放或撤销用户专属 Key、同步额度、对接支付、按自定价扣款及退款对账。当前供应商未选定；OpenRouter 仅是历史讨论示例。服务端已有的计费分流与可选 Lago 适配可供后续复用。本任务书交付本地调度能力，验收无需平台中转、真实付费或新增云端 worker。
4. 用户要求参考面向红果短剧的制作规模。公开成片时长要求不能推导出平台规定的并发数。下列批量、时长和指标是工程验证口径；达标与否须有候选版本实测。高峰工期、硬件和真实供应商配额待取得数据后校准。

- [ ] **W3 · 资源与公平调度。** 画出从待执行镜头到线程、网络提交、轮询、下载、子进程及发布的资源归属；测到瓶颈后再选有界分页、批次窗口或既有执行池调整。验证满载时仍可取消，短音频可获执行机会，输出盘满时保留已完成成果，并明确剩余任务如何恢复。
- [ ] **W4 · 生命周期与费用未知。** 用假供应商注入超时、429、回执丢失、明确拒绝、重复／乱序回调、下载失败，以及程序在各阶段退出。下单身份在重启前后可核对；未知项不盲重发、已采用产物不重复生成，独立镜头继续，依赖缺失的下游保持等待。对每个适用阶段记录通过／失败／未测。
- [ ] **W5 · 接口与诊断。** 按 W1 的消费者证据缩小桌面对象传递范围，保留现有服务兼容路径；在 L3 能跟踪受理、等待、运行、待核实、取消和最终结果。验收同一命令经 UI 或恢复入口执行时业务判定一致；导出诊断可定位镜头和请求，长跑错误记录增长有测量，隐私字段不入日志。

## 框架复用、风险与回滚

各工作包须先查现有模块，尽量复用 GitHub 成熟框架、模块、功能或代码，减少重复开发和交付周期。可用 [Blender Flamenco](https://flamenco.blender.org/usage/jobs-tasks-commands/) 比对影视作业／任务状态，用 [Temporal Python SDK](https://github.com/temporalio/sdk-python) 比对幂等活动、重试与超时语义。拟替换现有实现时，给出同一故障／负载用例的前后结果、许可证、Windows 分发成本、是否需额外常驻服务以及对旧任务的兼容性，由证据决定采用或保留。计费引擎与模型中转商分别选型。

按 W1→W2 优先推进，W3–W5 按接口依赖分批，W6 汇总。每轮只提交可独立回滚的改动，使用临时项目和脱敏样本。改变持久状态前验证旧版本读取与回退；回滚保留未决请求身份和已采用产物，禁止靠清空队列消除未知状态。交付基线、复现／回归用例、运行参数、指标与剩余风险；全册执行后再出任务完成文件。
