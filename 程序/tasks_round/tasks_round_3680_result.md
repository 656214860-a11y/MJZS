## 实现与边界

- 进程级独立 LRU。JSON 64 项/8 MiB，文本 32 项/8 MiB，字节 32 项/8 MiB，摘要 64 项/64 KiB。每个预算计入保留键、签名、摘要和解析后的值，节点开销有预留。合计记账预算 24 MiB + 64 KiB。单项超限仍可读取，读完不进入缓存。摘要仅留摘要及元数据，源文件仍以 1 MiB 块流式读取。
- Windows 签名使用卷和文件 ID、大小、LastWriteTime、ChangeTime 及逐文件 USN。当前本机仅靠文件身份和时间戳时，快速改写、还原 mtime 1,000 次碰撞 682 次。加 USN 后同方法观测 0 次碰撞、0 次签名不可用。系统盘临时目录和主树盘均验证可读 USN。无可靠 USN 的文件系统按调用实读并旁路缓存，长摘要在此情况下仍需流式读完整文件。该策略验证已完成外部覆盖，写句柄持续打开期间的内容与元数据一致性由写入方负责。应用内通知继续经 `externally_overwritten` 等现有入口。
- 只在缓存状态及 LRU 更新时持进程锁。文件读取、解析、计算摘要和估算值权重在缓存锁外。缺失文件及坏 JSON 缓存失效。读盘前后签名不一致时最多尝试三次。clear/invalidate 推进版本，阻止进行中的读回填。JSON 复制与共享入口各自保留原调用语义。
- 回归覆盖 32 次同大小同 mtime 原位覆盖及替换、并发摘要、读盘期间替换、并发 clear/外部失效、坏 JSON 和删除、未知签名回退、100/1000 项驱逐、聚合和单项字节上限。定向分支覆盖 25/44（56.8%），原下限 54.0%。

Windows，本机随附 CPython 3.14.7。用同一进程、同一临时目录和同一对文件，交替执行从 `f2247a1d` 读出的原模块和新模块。5 轮，每轮清缓存后读 1 次，再连续热读 1,000 次。冷读为应用缓存冷，OS 文件缓存未清空。时间为墙钟，无 UI/Tk 并发调度指标。

| 样本 | 冷读中位，原 → 新 | 热读 1000 次中位 / 最大，原 → 新 |

| 31,430 B、60 镜 JSON 共享读取 | 1.166 → 1.486 ms | 14.549 / 17.185 → 55.212 / 84.219 ms |
