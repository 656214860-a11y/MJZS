## 根因与修改

`workflow_context.snapshot()` 经 `stage_execution_service.storyboard_catalog()` 读取目录，导致 L2 反向依赖 L3。目录服务实际要求由 L3 注入 `ProjectContext`。

用户在本轮明确允许为同一根因跨越三个生产模块限制。`workflow_context.py` 接收上下文并直接调用同层目录服务；`desktop.py` 与 `writing_api.py` 在调用前构造上下文。提示词入口已有预计算 data 时仍接受根路径；需自行读取快照时接受注入上下文。

将既有工厂原样迁至唯一 L3 装配模块 `project_context_factory.py`，`stage_execution_service` 静态重导出同一函数，保留兼容。`stage_parallel`、`storyboard_selection`、`writing_api`、`white_model`、`workflow_tasks` 不再为装配上下文反向依赖总编排器；目录查询直接复用已有 L2 服务。未复制目录算法、未新增动态导入或层级豁免。同步 architecture.md 与 L3 登记。

扩展 UI 回归发现同类漏接：`local_previs.show` 的四处白模目录调用把裸路径传给 L2；`storyboard_final.finalize` 未向资产计划服务传入上下文。分别改为既有 L3 目录入口和共享 L3 工厂注入。`asset_batch.auto_plan` 复用现有 `plan_unattended_assets`；`asset_auto_batch_service.auto_batch` 向计划服务注入上下文。未改变回收、发布或用户数据语义。
