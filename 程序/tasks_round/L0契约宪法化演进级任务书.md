## 0.0 执行入口（交接给执行模型）

1. 读 `程序/AGENTS.md` 全文、本任务书 §0.0、§1.4、§2、§3、§3.4，再读当前要做的那一轮。
2. 按 §6.1 依赖图找出前置已满足的轮次；从 **KR** 开始，然后 **K0**。门未满足的轮次在结果文件写「阻塞于门 G-x」，转做其他前置已满足的轮次，不空等、不代做他人车道。
3. 每轮：`round_claim.py next` 领号 → 在 `codex/` 功能工作树开发（KR 例外：只入库规则文档，在主工作区 master 提交）→ 按轮内命令测试 → 写 `tasks_round/tasks_round_<N>_result.md`（三问开头）→ `scripts\dev.py commit`。
4. 任务书勾选行的文字一律不改（`taskbook_closure` 按原文逐条比对完成文件）；每轮完成情况写在结果文件里，收口时由 K23 的任务完成文件逐条引用原文并给证据。
5. 全部轮次结束后做 K22、K23。完成标准按 `AGENTS.md` §8：未满足验收不得输出 `[TASK_COMPLETE]`。
6. 遇到 §3.4「必须停下」的情形，输出 `[TASK_BLOCKED]` 并写明所需的最小用户动作。

## 1. 总目标与成熟度口径

### 1.1 总目标

让 L0 成为系统**唯一的、可验证的、可演进的「宪法」**，且边界清晰：

1. **边界清晰**：L0 只放纯声明，零 IO、零平台调用，不依赖任何上层；平台与 IO 下沉到新的 L0P 平台基座。
2. **可验证**：六类契约（领域对象、交互结果、错误码、事件消息、上下文与配置、阶段与工作流）全部有类型化 schema、黄金样本和坏样本自审。
3. **可演进**：公共 API 有边界、有版本、有破坏性变更检测、有弃用周期；契约变更能自动算出影响面；文档从代码生成并强同步。
4. **在通用 Windows 平台上可安装可运行**：中文、空格、超长路径，缺失环境变量，非 UTF-8 区域设置，程序目录只读，都有契约口径和验证用例。

K-Q2 L0 三分：

K-Q7 弃用周期：

### 8.1 每轮必跑（K0、K7 的测量段、K22、K23 除外）

### 8.3 新测试要求

- 断言检验行为，不检验源码字符串。门禁类测试允许 AST 扫描，但必须配坏样本自审。
- 修复类先红后绿，结果文件贴改动前的失败输出。
- skip 只引用 `tests/skip_reasons.py` 常量，并登记 `维护记录/skip台账.json`。
- 新增架构门禁同轮登记到 `architecture.md`「当前架构门禁清单」并同步基线。
- 含 Tk 的测试经隐藏桌面运行器执行。

### 8.4 三个基线（每轮结束必报）

默认冒烟 8/8；架构门禁当轮实际总数、失败集合及改前后比较；全量凭据以 `full-safe-receipts.json` 为准（`AGENTS.md` 规则 29）。
