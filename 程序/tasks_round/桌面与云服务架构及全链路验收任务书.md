## 五层职责与网关覆盖

| 附件维度 | 实际位置、调用方向 | 覆盖判断 |
|---|---|---|
| 用户交互 | 桌面 L5 启动装配，L4 Tk 界面受理操作、呈现状态；后台完成后通过生命周期管理回到界面。 | 有正式界面入口。需贯通验证关窗、切项目和迟到结果。 |
| 接入网关 | 服务端 `deploy/nginx-mj.conf` 配 TLS、按 IP 限流，公共和管理请求分别转到回环上游；`app/main.py` 处理中间件、路由与健康检查，身份、权益由应用处理。桌面 L3 `stage_handler_registry.start()` 分派内部命令；L1 `http_client` 负责出站 HTTP，覆盖超时、重试、响应上限和脱敏，存量例外有登记。 | 三处职责和信任边界明确。配置仅证明具备接入能力。实际证书、限流、管理面隔离要用部署证据验收。配置指向单上游；多实例负载均衡、WAF 的必要性取决于暴露面、负载和风险。桌面外部控制 API 已撤回。 |
| 业务服务 | 桌面 L3 串联 13 阶段、L2 处理剧本、分镜、资产、音视频等领域；独立服务承担账号、试用及会员闸门。 | 服务端登录能力已有实现。平台代付、账单对账、未知供应商回执须按具体供应商和既有设计分别核对。 |
| 数据访问 | 桌面 L1 文件缓存、索引和发布事务，L0 定义版本、路径、事件契约；会员服务用 SQLite。 | 有版本兼容、原子写和恢复原语。单项恢复、跨文件一致性、整机丢失是不同的验收场景。 |
| 基础设施 | Windows、随附 Python、媒体工具及子进程支撑桌面；服务器进程、反向代理、systemd、备份存储支撑会员服务。 | 可部署构件已存在。桌面 L0 是契约层。架构表中 L0P 平台基座的实体和接线以目标分支核验。 |

典型链路：用户点击制作 → 阶段分派 → 业务校验 → 本地运行或出站模型调用 → 产物发布与核验 → 界面呈现。会员请求经过会员服务网关；模型请求的目的地随既有路由配置变化。验收须记录使用的是哪条路径。

## 横切支撑与待验收工作

| 工作项 | 现有依据 | 后续动作、依赖与验收凭据 |
|---|---|---|
| A．可观测性 | 桌面业务日志、`diagnostic_capture`、模型请求标识与计量、`scripts/release_watch.py` 观察失败与成本；服务端有健康检查。 | 用测试账号或假供应商分别运行一次成功、一次超时和一次取消，从 UI 结果追到本次请求、供应商回执（如有）、产物与费用状态。导出脱敏证据，列出标识中断的位置、告警触发条件与接收结果。 |
| B．安全与数据边界 | 公共与管理入口分离、TLS／IP 限流、会员安全专项、日志白名单。详见[会员设计](../说明/账户会员云端设计.md)。 | 先核对目标版本与实际生效配置；在获准测试环境验证有效／失效会话、权益拒绝、管理面访问限制、限流与敏感字段遮盖。记录客户端表现、服务端状态和配置版本。线上动作与真实用户数据另行授权。 |
| C．发布与回滚 | 有 Git 门禁、定向和全量测试、本地发布检查、快照及副本导入演练；当前分支门禁结果需独立核验。 | 取同版安装制品，在干净 Windows 测试环境用旧项目副本执行安装、升级、打开项目、失败回滚；核对原产物摘要与版本兼容。保留制品标识、操作记录、失败点及回滚结果。 |
| D．恢复与连续使用 | 桌面有原子发布和事务日志，A12 已做多批故障注入；服务端 `scripts/backup.py` 支持一致性备份与恢复，`scripts/offsite.py` 及 timer 支持加密异地备份。 | 等对应 A12／L2 结果合入后复用凭据，在可丢弃项目验证强退、重启、已采用成果保全和待核实请求；在隔离服务环境取回异地备份，恢复到新实例并核验数据。记录最新可恢复时间点、实际耗时、需人工介入步骤，交由产品负责人定恢复目标。 |
| E．端到端产品验收 | REQ-APP-01、DES-APP-01，PRD 已有七条用户故事。 | 从助手界面走一条本地制作链和一条受控云端链，验证启动、暂停、取消、产物核验和失败反馈；抽检本轮变更与出站规则。云端暂不可用时记下哪些本地操作可继续。测试优先用临时项目与受控服务，真实付费样例须有预算。 |

执行顺序：先对齐待验版本、已有报告和用户故事；A、B 可独立取证；C、D 需要制品及恢复环境；E 汇合证据并将未通过项回写对应 REQ／DES 或既有任务书。每项登记负责人、受测版本、通过／失败／未测、证据位置和下一动作。实现缺口按所属功能逐步立项，未经实际验证的质量目标保留待验收状态。
