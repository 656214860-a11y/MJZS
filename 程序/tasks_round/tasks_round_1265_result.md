## 根因与修改

1. API 原先读取的是包含 profiles 的配置集合，技能装配却要求当前有效档，导致已勾选技能可能未注入；工作线程还会重读配置。现在发送边界统一捕获模型记录、调用方式、当前有效档、选中技能正文和直接引用、四角色规则。排队和运行期间改选模型或改技能文件不改变该请求；新请求重新加载。
2. 旧版单技能 20,000 字符裁剪会静默遗漏正文；缺失技能 ID 又会在配置刷新时被清掉。现在保留失效选择用于前置校验，加载失败、缺失直接 Markdown/文本引用、空技能、单包或合计超过 96,000 字符均明确拒绝。完整 API 请求继续经原上下文预算闸门，在网络调用前拒绝。桌面任务书亦注入冻结正文。
3. 请求历史记录保存实际调用方式、模型、选中/加载路径、名称、字符数和 SHA-256，不落凭据或额外保存技能正文。气泡显示已勾选数量、本次加载数量和名称；旧消息无清单时不伪造已加载。
4. 测试读取真实保存配置，覆盖 API 模型切换、API/Codex/Claude 方式切换、发送后文件修改、缺失技能保持草稿且零调用、规划及三次创作/审核七次调用共用冻结内容。桌面投递断言核对任务书和实际粘贴内容相同。

未修改四角色顺序、审核往返、SKILL 文件、brief 契约或共享阶段成果。引用沿用直接 Markdown/文本引用边界，不递归展开全部资料包。
