## 只读诊断

- 气泡创建：`pet_cloud.py:360-370` 的 `Cloud.build()` 建立 `tk.Toplevel(self.parent)`。
- 定位函数：`pet_cloud.py:1234-1260` 的 `Cloud._place_window()`；原始核心逻辑为：

```python
parent_rect = (self.parent.winfo_rootx(), self.parent.winfo_rooty(),
               self.parent.winfo_width(), self.parent.winfo_height())
if int(parent_rect[2]) <= 1 or int(parent_rect[3]) <= 1:
    self._position_job = self.parent.after_idle(self._place_window)
    return None
```

- 原算法确实读取 `winfo_rootx()` / `winfo_rooty()` 及宽高，但未布局时只有无上限 `after_idle()`，没有 50ms 间隔或最大次数。启动映射阶段持续读到 `(0,0,1,1)` 时，可能让首次气泡位置脱离主窗口、停在角落。
- 有效父窗口时，`centered_popup_origin()`（216-227）按父窗口中心计算；`_parent_work_area()`（1262-1283）取父窗口所在显示器工作区并参与钳制，并非单以主屏尺寸居中。

## 修复前后对比

| 情况 | 修复前 | 修复后 |
| --- | --- | --- |
| 父窗口宽/高 ≤ 1 | `after_idle()` 无上限重试 | `after(50ms)` 重试，最多 10 次 |
| 父窗口有效 | 父窗口中心 + 工作区钳制 | 保持不变 |
| 最大等待 | 无上限 | 500ms，之后不写入 `(0,0)` 兜底坐标 |

## 改动文件

- `pet_cloud.py`
  - 新增 `POSITION_RETRY_MS = 50`、`POSITION_RETRY_MAX = 10`。
  - `Cloud._place_window()` 在未布局时改为受限延迟重试；布局完成后清零重试计数，再执行父窗口中心定位和工作区边界钳制。
- `tests/test_pet_cloud_contract.py`
  - 更新未布局窗口断言为 50ms 重试。
  - 新增第 11 次不再安排重试的断言。

未改：气泡样式、尺寸、动画、主窗口位置、其他弹窗、用户数据。

## 新增/覆盖的回归断言

1. 父窗口 `(2000, 500, 800, 600)`，气泡 `(400, 300)` 居中为 `(2200, 650)`，保留副屏坐标。
2. 父窗口 `(0, 0, 1, 1)` 时不报错，安排一次 `after(50, ...)` 重试。
3. 未布局连续达到 10 次后不再安排第 11 次重试。
4. 主屏父窗口及过大气泡均被钳制在工作区可视范围内。
