## T1 私有服务器远端 CI 与备份校验（P0）

**问题**：门禁只在本机，hooks 可被 `--no-verify` 绕过；无远端 CI。

**步骤**
1. 只读核验：`git remote -v`、服务器上 bare 仓库是否可 push/fetch、最近一次同步时间。需要 SSH 凭据时停下来问用户，不把凭据写入任何文件。
2. 在服务器的 bare 仓库加 `post-receive` 或 `pre-receive` 钩子，或部署轻量 runner（Gitea Actions / 自托管 runner，二选一，先问用户）。
3. CI 任务：对每次 push 的 `master` 与 `codex/*` 跑 `scripts/local_ci.py exit`（静态 → 架构 → 冒烟，约 4 分钟）。夜间跑 `run_selftests.py --all --safe`。
4. 服务器是 Linux：只跑不依赖 Tk 的静态与架构门禁（先确认这些门禁在 Linux 上能跑：路径分隔符、编码、`\r\n`），在文档写明覆盖差异；服务器需要 Python 3.10+，解释器与本机内置的不同，须在结果文件注明版本。
5. 每周一次 `git bundle` 到服务器另一目录，保留最近 4 份；写校验脚本 `scripts/backup_verify.py`（`git bundle verify`）。

**验收**：故意推一个违反分层门禁的提交到临时分支，远端 CI 判红；删除该分支。结果文件贴红绿证据。

**不做**：不改 `AGENTS.md` 的本地提交流程；不 `git push` 到 master（用户明确授权前只推临时分支）。
