## C. 两条调用路线与凭据隔离
平台：桌面业务用例→既有路由适配→本方版本化网关→可替换中转→模型。桌面仅带本方短期会话凭据和逻辑模型 ID；上游 key、供应商配额和 key 轮换仅在服务端。供应商是否逐用户建账号/key 属 D10 待定，不阻塞本方账号注册，也不把 key 余额映射成用户钱包。

BYOK：同一桌面用例→现有模型适配→用户配置供应商，用户承担上游费用。BYOK key 经既有 DPAPI/key_env 在本机取用，不上传本方会员或钱包服务；会员是否有权使用某项付费桌面功能与 key 是否有效独立校验。无本方调用费、无平台预留/扣款；本地仍可记录估算费用及预算，不叫平台余额。

每次操作冻结 `route_mode(platform/byok/local)`、逻辑模型/实际模型映射版本、凭据引用（不是密钥）、计费主体和允许的降级集合。平台池与 BYOK 池不混合自动候选。BYOK 失败不能切平台收费，平台失败不能静默取本机 key；用户明确选择切换时，建立新操作、重新报价/展示付费方，同时保留旧操作未知状态及可能双重费用提示。自动化阶段也不能绕过这一点。

同一路线内降级仍须匹配能力、批准的模型/预算上限与受理状态；未知或已受理禁止另发。平台服务端切中转仅在原尝试确认未受理、报价合同允许且绑定新的 attempt 时进行；实际模型/单位变化须新报价。客户端、阶段与网关共享总重试/截止预算，只有一层拥有重新提交权。只读查单、结果重下载可有限退避，不重跑生成。

## D. 账号、权益、钱包的独立状态
| 对象 | 候选状态/真源 | 影响边界 |
|---|---|---|
| 本方账号 | active/restricted/closed；服务端真源 | 登录凭据失效不等于账号删除；禁新收费操作仍允许合法查账/申诉渠道；不删本地项目 |
| 登录会话 | valid/expired/revoked/unknown | 401 刷新/重登后查原任务，不创建新提交；网络不可用为 unknown，不伪装为余额不足 |
| 会员权益 | active/expired/suspended/unknown，带权益版本和生效区间 | 与钱包余额独立；会员费不自动充值，充值不自动续会员；过期后能否花余额待产品决策 |
| 钱包 | 币种分账的 available/reserved/settled；限制态另记 | 余额从不可变分录投影，不能用会员标志、上游 key 配额或本地估算替代；未知请求的 hold 单列 |
| 赠送额度 | 独立资金批次/来源/适用范围/有效区间 | 与充值分开记；扣用优先级、到期策略、退款规则均待定，不能自动兑换现金 |

## E. 版本化 API、操作身份与查单
以下是待评审的逻辑协议草案，`/v1` 为主版本，不是已上线地址。认证以服务端主体为准，不信任请求体 account_id；所有任务/报价/账单/素材按主体逐项授权，猜到 ID 不能查别人的任务。返回 `api_version/request_id/server_time/data/error`；error 含稳定 code、acceptance、retry_action，不暴露上游正文。兼容新增可选字段，破坏性变化升主版本；未知枚举保守显示未知，停止写操作，保留本地编辑。

| 逻辑端点 | 输入/输出与幂等要求 |
|---|---|
| GET /v1/me、/entitlements、/wallet | 独立状态、权益版本/有效期、账本游标与余额时点；客户端缓存只展示，不授权扣费 |
| GET /v1/models | 平台逻辑模型、能力/单位、catalog_version，不发 key/内部供应商配置 |
| POST /v1/quotes | operation_id、模型、route_mode、规范化输入摘要、用量上限；返回 quote_id、price_version、有效区间、精确金额上限及币种、计量/舍入规则版本 |
| POST /v1/operations | Idempotency-Key、operation_id、quote_id、输入/素材引用与摘要；服务端校验并原子预留+登记后持久排队；返回 task_id、acceptance、execution_state、billing_state，不承诺已完成 |
| GET /v1/operations/by-client-id/{operation_id} | 提交响应丢失、尚无 task_id 时按原账户+客户端操作号查单；包括 received/reserved/submitting/unknown 与可靠的未见状态，不要求先有供应商 task ID |
| GET /v1/tasks/{task_id}、/usage、/result | 返回任务/计费两种状态、账本引用、结果校验摘要；下载能力短期授权，不以 URL 持久存在证明结算 |
| POST /v1/tasks/{task_id}/cancel | 独立幂等命令号；返回 cancel_requested/confirmed/unsupported/unknown，继续查单与结算 |
| GET /v1/ledger?cursor=... | 主体隔离的稳定游标分页、分录 ID、operation_id、原始/冲正关联与报价版本；用于展示、对账 |
| POST /v1/payment-orders 与 GET /v1/payment-orders/{id} | 独立支付幂等号及订单类型；不得复用模型操作号充当支付身份；仅列边界，渠道字段待 C0 |

身份层次：L3 业务 operation_id（与 L2 在途合同对接）→客户端一次收费操作 client_operation_id→服务端 task_id→attempt_id→provider_request/task_id；HTTP request_id 仅诊断相关性。应用退出/断网/重登后保留前两个稳定身份及原报价，新的 HTTP 请求号不得生成新的收费身份。账号切换后旧单仍归原账号，不能拿新账号重建同一操作。

幂等唯一键 `(authenticated_subject, operation_kind, client_operation_id)`；同键同规范化请求指纹返回原单，同键异参 409 IDEMPOTENCY_CONFLICT，零新增预留/提交。指纹绑定路由、模型、quote_id、参数/素材内容摘要、输入规范化版本，不记录正文。账本、预留与操作记录同一原子提交；事务外通过持久 dispatch intent/outbox 发送，不把数据库锁跨网络持有。并发重复用唯一约束裁决，不仅靠缓存锁。

网关在上游受理后崩溃仍可能丢 provider_task_id，所以采购必须支持按客户请求号查单或供应商幂等令牌；仅支持按返回 task_id 查单不够。上游不具备时拒绝启用自动收费重试，保留 unknown 进入人工对账，不能声称端到端 exactly-once。查单 404/暂未可见不证明未受理；只在网关持久状态证明尚未发送且供应商可见窗口已核实后才能恢复同一操作提交。幂等记录/墓碑保留覆盖任务、对账、重试和争议窗口，具体期限待定；过期身份不能被当新单自动再发，须返回需核对状态。

## F. 报价、精确金额与费用授权
本方价格表与供应商成本表分开；price_version 不可变，冻结报价适用的单位（输入/输出/缓存 token、图片张数/规格、音视频时长等）、单价、币种、精度、舍入方法、最低计费/失败计费规则及模型映射版本。缺价格、缺单位或未获批准的收费政策时 quote unavailable，禁止凭旧状态页价格生成新收费决定。

金额传输采用明确 currency+scale 的整数金额字符串，费率/非整数用量用有限十进制字符串；服务端十进制/定点计算，禁止 binary float 结算、NaN/无穷/布尔值/隐式换汇。scale、舍入点和方向按版本合同明确；不假设所有币种都是“分”。估价不等于扣款凭证，未知用量不按零。费用展示标 estimated/reported/reconciled，并给时间点。

quote 绑定输入摘要、最大输出/媒体规格、可扣最高额 max_charge、有效期和权益/政策版本。提交前重新检查账号、权益、钱包、报价有效性；新价或过期报价须返回重新报价，不以静默更新继续扣款。预留要覆盖获准最高费用；服务端强制输出/时长上限，不能确认上限的模型不得按该模式上线。供应商实际成本超限不允许额外从用户钱包扣款，超出部分隔离为差异待核，成本承担规则 C0 决策。

钱包并发在服务端原子校验和预留，确保可用额非负，不接受本地余额算出的“已授权”。已预留操作固定各资金批次分摊；赠送额度在执行中到期不改变原 hold 的来源。结算后的未用预留归回同批次，若其已到期则记录失效，不转成充值现金。币种/权益/赠送消费次序未确定前不开放真实调用。

## G. 调用与资金双状态机
执行状态：received→reserved→submitting→accepted/running→succeeded/failed/cancelled；submitting 后可进入 acceptance_unknown；取消请求为独立标志，不覆盖原受理证据。资金状态：none→held→settled/released，证据不明为 reconciliation_pending（hold 仍保留）；已结算修正走 adjustment，不回写历史。执行终态不自动决定资金终态。

| 窗口/事件 | 执行动作 | 资金动作与允许重试 |
|---|---|---|
| 校验/额度不足/发送前取消 | 明确未发送，终止本次操作 | 不建 hold 或原子释放；零上游调用 |
| 预留成功、worker 未发送即崩溃 | 恢复同一 dispatch intent，先检查状态/取消标志 | 复用 hold，不第二次扣可用额；确证未发送才可释放/重派 |
| 上游发送中断、HTTP 5xx/超时/响应损坏 | acceptance_unknown，按原请求身份查单 | 保留 hold/待核，不新建收费任务，不降级另模型 |
| 已受理或运行中 | 记录远端身份、有限轮询；进程重启恢复查询 | 保留预留；供应商追加用量仅由单调版本凭据更新 |
| 成功且获得可信最终用量 | 独立取得结果并校验，发布走原 L3 链 | 唯一 settlement 分录扣实际获准费用，原子释放余量；重复回调/轮询不二次扣款 |
| 失败/取消且供应商证明未收费 | 记录终态和证据 | 唯一 release；失败本身不够作为释放证据 |
| 失败/部分完成/取消且供应商已计费 | 展示未完成及实际费用来源 | 按已批准失败计费合同结算；政策未确定则待核，不擅自决定全退/全扣 |
| 结果成功但下载失败/过期链接 | 查询同一结果、刷新下载授权、校验和/续传 | 不重新生成，不自动退款；恢复不可得进入争议流程，不能再扣生成费 |
| 结算数据库不可用 | 保留供应商回执与待处理意图，展示待结算 | 不把结果丢弃、不释放 hold；恢复后用同一分录键结算 |
| hold 长期未知/任务到期 | 定期查单、对账、告警/人工处理 | 时间经过不是零费用证据；不照搬本地 stale 清扫释放，期限/SLA 待 C0 |

取消语义：发送前可确保不发送；发送后只请求取消，直到权威确认都可能继续计费。UI 的 Cancelled 保留“已停止本地等待/远端待核”数据，后台对账不能被窗口关闭或切项目停止。超时分开标注用户等待超时、HTTP 超时、供应商截止，任何一项都不是退款承诺。

对账以本方 operation/attempt、供应商请求号、单位/模型、报价和时间区间匹配供应商账单；重复账单按稳定凭据 ID 去重，乱序事件不回退终态。账单与实时回执差异、缺单、重复上游扣费、超授权费用进入异常队列，有证据再生成关联调整分录；人工调整保留操作者/理由/证据引用。供应商支出与用户扣费两本账对照，不用上游余额差额摊到用户钱包。退款/优惠是新的商业分录，不伪造供应商未受理。

## H. 错误合同与桌面消费
以下 code 为云端命名空间候选，不能直接注册到现有 L0。适配器使用现有 ServiceResult 四字段，data 承载 operation_id/task_id、acceptance、billing_state、retry_action；L3 保留 Cancelled，L4 不展示原始供应商错误。recoverable 表示可采取恢复措施，不表示可以重复收费提交。

| 云端/传输情况 | 桌面语义 | 后续动作 |
|---|---|---|
| 401 SESSION_EXPIRED | 会员会话需恢复，区别 BYOK_AUTH_FAILED | 重登后查原单，不清本机 key |
| 403 ENTITLEMENT_REQUIRED/ACCOUNT_RESTRICTED | UserError，具体权益或账号原因 | 不清项目；不自动充值/续费 |
| 402 BALANCE_INSUFFICIENT | UserError，原子预留失败 | 明示不足，不换 BYOK；充值为用户独立动作 |
| 409 IDEMPOTENCY_CONFLICT / QUOTE_STALE | UserError，保留原单 | 冲突核对输入；新价需重新确认，不能自动改原指纹 |
| 422 MODEL_UNSUPPORTED/INPUT_INVALID | UserError | 修正请求；已受理标识优先，不能仅凭状态断言零费 |
| 429 CAPACITY_LIMIT | SystemError/recoverable | 仅确定未受理才可在总预算内重试；否则查单 |
| 网络超时/5xx/不可解析响应 | SystemError + acceptance unknown | 查单、待核，禁止盲目重发或释放 |
| CANCEL_REQUESTED/CANCELLED | Cancelled + 远端/费用各自状态 | 不当成功或零费；继续后台查单 |
| RESULT_DOWNLOAD_FAILED | SystemError，生成结果可能成功 | 同结果恢复下载，不新生成 |
| RECONCILIATION_PENDING / 未知版本/枚举 | 保留任务与费用未知提示 | 停止收费写操作，仍允许本地读编辑及兼容只读查询 |

原始 http_client 错误只能证明传输情况，业务适配须合并已持久的受理证据；不能把一个迟到 401/429 覆盖已存 task_id。报错不包含密钥、供应商内部 URL 或完整文本。
