# R603｜性能轮：创意附件后台预处理

## 本轮结论

- 剧本准备页选择 `.md`、`.txt`、`.docx` 等创意附件后，入库、DOCX 解析、文本校验和字符统计已移至专用后台线程；Tk 主线程只轮询并提交完成结果。
- 预处理期间“发送”保持禁用，控制器拒绝提交；成功后才启用引用/发送，失败时明确保留失败状态，避免半成品附件进入模型请求。
- 该后台队列独立于模型请求的 `async_()` 票据和阶段并发槽，不会混入流式回复或取消语义；现有附件路径、格式和提交内容保持不变。

## 改动文件

- `idea_attachments.py`：预处理结果补充“文件名 + 已截断文本字符数”，供 UI 直接展示，避免完成回调再次同步读文件。
- `idea_chat_controller.py`：增加无 Tk 的附件预处理任务状态、结果队列和提交阻断。
- `desktop.py`：注册 100ms 主线程轮询；选择附件后展示后台状态，仅完成后更新控件。
- `tests/test_idea_chat_controller.py`：覆盖后台预处理尚未完成时不可发送、完成后附件状态可用。
- `tests/test_idea_chat.py`：把既有附件界面接线回归调整为等待后台结果。
