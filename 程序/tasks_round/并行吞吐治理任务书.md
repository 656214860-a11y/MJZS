## 4. 高并发规则草案（供 A3/B3 落地，❓ 处待拍板）

- 车道注册：活跃车道必须在 `lanes.json` 登记（lane 名＝工作树目录名）；未登记工作树不算活跃车道、不参与 scope 门禁也不受保护
- 车道上限 20：超上限时 `round_claim.py next` 拒绝并提示先回收（回收仍走 `worktree_ledger.py --plan`＋用户逐条确认）
- 合并排队：master 合并仍单通道（MERGE_HEAD 互斥不变）；多分支就绪时由一条「合并车道」按登记顺序批量合并，减少状态页抬头/结果文件开销
- 冲突预测：`dev.py scope` 在多车道下输出按车道分组的重叠清单；add/add 门禁对全部活跃分支保持 O(n) 可接受
- 脏树裁定：工作树脏超过 7 天或所属会话失联 → 列入清理清单，内容先抢救再删

## 6. 风险与回滚

| 风险 | 缓解 | 回滚 |
| --- | --- | --- |
| 合并豁免锁 → perf 测试假红（`test_perf_baseline` 300ms 先例） | exit-CI 降优先级；perf/soak 移出合并 CI | 恢复等锁逻辑（git revert） |
| 全量降频 → 回归潜伏期变长 | 保留「高风险改动触发当次全量」；分级而非取消 | 恢复 interval/合并分级 |
| 清理误删未合入工作 | 逐条用户确认；删前 `git branch --merged` 核验；脏树先裁定；清单留 tip sha | 按 sha 重建分支 |
| 20 车道 → scope 门禁噪音/漏报 | 门禁只看「登记活跃车道」；阈值评审 | 恢复上限与旧扫描口径 |
| 台账分文件 → 门禁读取方漏改 | 读取方清单先盘点；双读过渡期 | 恢复单文件＋归并脚本逆操作 |
| 规则文本预算超限 | `AGENTS.md` 16KB 硬门禁；先删旧补新 | git revert |
