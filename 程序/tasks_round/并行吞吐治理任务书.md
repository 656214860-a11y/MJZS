## 4. 高并发规则草案 v2（A3/B3 落地）

- 车道注册：活跃车道必须在 `lanes.json` 登记（lane＝工作树目录名，含 owner/role/last_seen）；超 20 上限 `round_claim.py next` 拒绝并提示回收
- 合并队列：各车道 `merge-request` 入队（branch/owner/summary），专职合并车道按序消费执行 `merge_round` 等效流程；可批量；队列项带租约，死合并可被接管（不自动 abort MERGE_HEAD）
- GUI 车道：`role: gui` 标记的车道承接 GUI 密集改动；其余车道 GUI 测试仍可跑但排队优先级降低
- 脏树：失联 >7 天或会话失联的工作树列入清理清单，内容先抢救再删（用户确认）
- 冲突预测：`dev.py scope` 输出按车道分组重叠清单；同文件改（非同名新增）只警告不阻断，观察一轮后再评估
- 领号：ahead>10 只数源码提交；合并轮领号在 CI 通过后（不烧号）

## 5. 外部方案评估（B0 复核，2026-11-17 调研）

| 方案 | 匹配 | 判定 |
| --- | --- | --- |
| `yongjip/mergetrain`（MIT，PyPI） | 专为本地多 LLM agent×worktree 设计：SQLite 队列、单 runner FIFO 合并列车、隔离集成树、合并结果门禁、批准后原子推送、MCP/技能插件 | **B0 首选 spike**：场景完全重合；风险＝协议适配成本（领号/状态页/证据）、项目年轻、bus factor 1；回退＝保留 merge_round 自建队列 |
| `max-sixty/worktrunk`（Rust，winget/cargo） | 并行 agent 工作树生命周期：`wt switch/remove/list/merge`、hooks、`wt sync` 叠分支 rebase | B0 次评：可替代 worktree_ledger 手工生命周期；Windows 装为 `git-wt`（与 Windows Terminal 冲突），有 Defender 误报个案；不引入则维持现有脚本 |
| SVRF / OpenMerge / CIHub / LumaPrism mergequeue | GitHub forge/PR 依赖 | 否决（自建裸仓无 forge；借概念：braided train、批量+bisect） |
| Zuul / GitLab Merge Trains / Bors | 投机执行+批量合并黄金标准 | 否决（需 forge+CI 基础设施；借概念：speculative CI） |
| Jujutsu / Sapling | 操作日志 VCS，理论根治 rebase 搅动 | 否决（迁移成本吞掉钩子体系；观察项） |
| 自建 CI（Woodpecker 等） | 服务器跑非 GUI 门禁 | ❓ 与已裁决「单机不引入托管 CI」（U1）冲突，须用户明确推翻才评估 |
| `git rerere` | Git 内置，重复冲突自动复用解法 | **零成本启用**（A2 登记） |

## 7. 风险与回滚

| 风险 | 缓解 | 回滚 |
| --- | --- | --- |
| 合并豁免锁 → perf 假红（`test_perf_baseline` 先例） | exit-CI 降优先级；perf/soak 移出合并 CI；B1-c 须用户确认 | 恢复等锁逻辑（git revert） |
| 全量降频 → 回归潜伏期变长 | 保留高风险改动触发当次全量；分级而非取消 | 恢复 interval/合并分级 |
| mergetrain 适配不符/项目太年轻 | B0 spike 先行；自建队列为保底方案；协议不符即弃 | 卸载依赖，merge_round 不变 |
| 合并队列死锁/合并车道本身成瓶颈 | 队列项租约＋看门狗；合并车道可人工接管 | 退回会话各自 merge_round |
| 清理误删未合入工作 | 逐条确认；`--merged` 核验；脏树先裁定；留 tip sha | 按 sha 重建分支 |
| 20 车道 → scope 噪音/漏报 | 只看登记活跃车道；同文件改仅警告 | 恢复上限与旧口径 |
| GUI 超时放宽 → 排队更久 | role:gui 专道分流；DEFERRED 强制标注 | 恢复 15min |
| 规则文本预算超限 | 16KB 硬门禁；删旧补新 | git revert |
