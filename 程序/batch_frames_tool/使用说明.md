# ComfyUI 批量首帧 · FLUX.2 Klein 4B

## 需要准备

1. 启动本地 ComfyUI。把浏览器里的本机地址填入批量工具；桌面版端口不一定是8189。
2. 使用已更新的ComfyUI，安装以下模型（不包含在本工具包）：
   - models/diffusion_models/flux-2-klein-4b-fp8.safetensors
   - models/text_encoders/qwen_3_4b.safetensors
   - models/vae/flux2-vae.safetensors
3. 在制作助手第4步刷新JSON。使用刷新目录内的episode.json及同级assets.json和图片文件。

模型与官方画布工作流：https://docs.comfy.org/tutorials/flux/flux-2-klein
附带的“官方双参考图工作流.json”来自Comfy-Org/workflow_templates，可拖进ComfyUI学习或单镜测试。

## 批量操作

双击“启动批量首帧.pyw”，无需额外安装Python库。本机已安装Python；换电脑需安装带Tkinter的Python。

1. 选择第4步刷新的镜头JSON。
2. 输入本机ComfyUI地址，先填写一个镜头编号测试；确认效果后再留空批量生成。
3. 选择横屏768×432或竖屏432×768。
4. 点击“检查模型与参考资产”，查看可生成与跳过项。
5. 点击“开始逐镜生成”。每次只提交一镜，完成后再处理下一镜。
6. 返回助手第5步，选择同一JSON，刷新首帧列表。

## 工作流结构

分镜提示词 + 每镜1～4张参考图 → 分别缩放和VAE编码 → ReferenceLatent串联正负条件 → Klein4B（CFG=1，Euler，4步）→ VAE解码 → SaveImage → 下载 → 关联JSON的frame字段。

这不是把batch_size调大：不同镜头使用不同提示词和参考资产，batch_size始终为1。
参考图不会先拼接成板。低显存默认每图缩至约0.5百万像素，输出分辨率较低。
8GB显存仍可能不足或速度慢；先关闭其他占显存程序，用ComfyUI低显存模式。此包不保证固定速度或人物完全一致。

## 保存与继续

- 图片保存到所选JSON同级frames目录，优先镜头编号.png；遇到同名文件保留旧文件，使用唯一后缀。
- 自动更新所选JSON的frame路径，修改前备份至同级“首帧任务”目录；不修改初稿或另一个项目的JSON。
- 已有首帧、已删除镜头、参考图不齐、超出4张参考图的镜头跳过，并显示原因。
- 只读取已登记资产；assets.json缺图时可读取当前镜头asset_bindings中的有效图片。
- 同一JSON只允许一个批量任务；已提交任务保存prompt_id，中断后用同一配置再次运行可继续查询。
- 点击暂停只停止等待和后续提交，不中断ComfyUI正在执行的镜头。
- unknown状态不会自动重新提交，需先在ComfyUI核实，避免重复生成。

## 两份JSON工作流的区别

- 官方双参考图工作流.json：可拖入ComfyUI画布，但只是官方单镜示例。
- 批量首帧_API示例.json：程序提交用示例，有占位图片名。批量工具会按每个镜头自动重建节点和上传引用图片，不需要你手动编辑它。

本工具仅调用本机ComfyUI，不需要云API Key。已做离线逻辑检查；尚未完成本机实际模型推理验证。
