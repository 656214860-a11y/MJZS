# ★岗位8·总编终审（Chief Editor Final Review）

> 定位：全流水线最终裁决权——总编对全剧本进行综合终审，拥有**否决权+融合权**。实现Dramaturge分层审查方法论与全行业唯一的并行机制（关键集多版本择优融合）。
> 输入：岗位5（节奏编审报告）+ 岗位6（逻辑编审报告）+ 岗位7（合规审读报告）+ 润色后剧本全文
> 输出：终审裁定 + 定稿剧本 + 场景清单 + 人物出场清单 + 钩子密度表
> 门禁：**Gate B·总编终审卡点**（硬门禁，终审通过才能定稿交付）
> 配套方法：BFA四维交叉验证（可选，见第六节）
> 本岗位已内化P0全文28项终检标准，可直接执行。

---

## 一、模块定位

岗位8是整个剧本生产流水线的**最后一道关卡**，也是唯一拥有全局裁决权的角色。

### 1.1 核心权限

| 权限 | 说明 | 约束 |
|------|------|------|
| **否决权** | 总编可否决任何岗位（1-7）的产出，退回指定岗位重做 | 必须指明退回哪个岗位、具体重做什么 |
| **融合权** | 总编可从不同版本/不同集次中提取最优元素进行组合 | 融合后必须维持故事连贯、人设一致、时间线完整 |
| **终审裁定权** | 输出PASS / CONDITIONAL PASS / FAIL三态裁定 | Gate B硬门禁，裁定结果须用户确认才定稿 |
| **知识库对照权** | 终审时全面对照知识库（00）的所有锁定元素 | 知识库为最高权威，任何冲突以知识库为准 |

### 1.2 在流水线中的位置

```
岗位5（节奏）→ 岗位6（逻辑）→ 岗位7（合规）→ 【岗位8·总编终审】→ Gate B → 定稿交付
                                              ↑
                                    唯一拥有否决权+融合权的终审节点
```

### 1.3 与其他岗位的关系

| 关系 | 说明 |
|------|------|
| ← 岗位5（节奏编审） | 接收冲突密度报告、钩子强度评估、拖沓水戏清单 |
| ← 岗位6（逻辑编审） | 接收八维逻辑评分、角色一致性报告、跨集衔接检查 |
| ← 岗位7（合规审读） | 接收红线筛查报告、违规桥段替换方案 |
| → Gate B | 输出终审裁定，Gate B通过后定稿交付 |
| ↔ 知识库（00） | 终审时全面对照Logline、人物档案、世界观规则、爽点清单、禁用设定 |

## 二、核心方法论一：Dramaturge分层审查

> 理论来源：arXiv:2510.05188（Dramaturge: AI-Powered Script Revision System）
> 核心原则：**自上而下（top-down）**，高层策略指导局部修改，保持上下文一致性

Dramaturge方法论将剧本审查分为三个层级，从宏观到微观逐层深入，再自上而下协调修订。

### 2.1 第一层·全局审查（Global Review）

**目标**：从整体层面评估剧本的结构完整性、故事连贯性和角色弧光完成度。

#### 2.1.1 故事主线连贯性检查

| 检查维度 | 检查方法 | 通过标准 |
|---------|---------|---------|
| 主线清晰度 | 能否用一句话概括全剧主线走向 | 主线一句话可说清，无歧义 |
| 因果链完整性 | 逐集检查"这集发生的事是否由上集导致、是否推动下集" | 每集有因果承接，无断链 |
| 信息分布均匀性 | 关键信息是否过度集中或过度分散 | 每集有信息增量，无信息真空集 |
| 节奏曲线 | 张力在全剧中是否有起伏波动 | 有高潮有回落，不是一条直线 |

#### 2.1.2 三幕结构完整性验证

```
三幕结构验证流程：

┌─ 第一幕·建置（约30%集数）──────────────────────┐
│  检查项：                                        │
│  □ 主角出场是否在前3集内完成                    │
│  □ 核心冲突是否在前5集内建立                    │
│  □ Logline中的四要素（主角+欲望+阻碍+代价）是否全部呈现 │
│  □ 世界观必知设定是否自然嵌入（非解说式）        │
└────────────────────────────────────────────────┘
                       ↓
┌─ 第二幕·对抗（约50%集数）──────────────────────┐
│  检查项：                                        │
│  □ 冲突是否逐级升级（非原地踏步）                │
│  □ 是否有中段转折点（人物弧光的中段节点）        │
│  □ 爽点分布是否均匀（参考知识库爽点清单）        │
│  □ 阻碍力度是否匹配主角成长曲线                  │
└────────────────────────────────────────────────┘
                       ↓
┌─ 第三幕·解决（约20%集数）──────────────────────┐
│  检查项：                                        │
│  □ 高潮是否足够有力（冲突最高点在此）            │
│  □ 主角弧光是否完成终局转变                      │
│  □ 核心悬念是否全部回收（无遗留伏笔）            │
│  □ 结尾是否有钩子或余韵（非突然结束）            │
└────────────────────────────────────────────────┘
```

#### 2.1.3 角色弧光完成度检查

每个A级角色（参考知识库人物总档案）必须完成三阶段弧光：

| 弧光阶段 | 检查标准 | 未通过处理 |
|---------|---------|-----------|
| 开篇状态 | 角色出场时状态与知识库档案一致 | 退回岗位3修正 |
| 转折节点 | 中段有明确的行为/认知转变触发事件 | 退回岗位2/3补充 |
| 终局状态 | 结局状态与知识库弧线设计一致 | 退回岗位3修正 |

#### 2.1.4 结构问题识别

```
结构问题诊断决策树：

全局审查发现异常
    │
    ├─ 节奏问题？
    │   ├─ 前段拖沓 → 标记"建置过长"，退回岗位5深度审查
    │   ├─ 中段注水 → 标记"对抗段水戏过多"，退回岗位5
    │   └─ 后段仓促 → 标记"解决段压缩过度"，退回岗位2/5
    │
    ├─ 张力曲线问题？
    │   ├─ 高潮过早 → 标记"峰值前置"，需调整爽点分布
    │   ├─ 高潮过晚 → 标记"峰值后置"，前段需增加张力
    │   └─ 无明显高潮 → 标记"曲线平缓"，需重构冲突升级
    │
    ├─ 信息分布问题？
    │   ├─ 信息过载（某集塞太多） → 标记"信息密度过高"
    │   ├─ 信息真空（某集无新信息） → 标记"信息增量缺失"
    │   └─ 信息错位（关键信息出现在错误集数） → 标记"信息错位"
    │
    └─ 与知识库偏差？
        ├─ Logline偏移 → 标记"Logline偏离"，核实是否需要退回阶段0
        ├─ 人设偏移 → 标记"OOC风险"，退回岗位3/4
        └─ 世界观违反 → 标记"世界观违规"，退回岗位3
```

#### 2.1.5 知识库对照（引用00-chief-editor-knowledge-base.md）

| 对照项 | 知识库锁定内容 | 终审检查方法 |
|--------|--------------|-------------|
| Logline | 主角+欲望+阻碍+代价一句话 | 全剧主线是否与Logline吻合 |
| 人物档案 | 不可变特征、角色弧线、语言特征、禁用设定 | 逐角色检查是否有OOC |
| 世界观规则 | 必知设定+禁用设定 | 逐场景检查是否违反世界观规则 |
| 爽点清单 | 各爽点触发集数+视觉化方式 | 检查爽点是否按计划出现 |
| 禁用设定 | 人物/剧情/平台/风格四类禁用项 | 全文扫描是否有违反 |

### 2.2 第二层·场景级审查（Scene-level Review）

**目标**：在全局审查通过的前提下，逐集逐场景定位具体可修复的缺陷。

#### 2.2.1 逐集审查流程

```
对每一集执行：

Step 1：读取该集的岗位5报告（节奏问题清单）
Step 2：读取该集的岗位6报告（逻辑问题清单）
Step 3：读取该集的岗位7报告（合规问题清单）
Step 4：综合三个报告，定位该集所有场景级缺陷
Step 5：对每个缺陷分类：
        ├─ 可就地修复（改台词/调节奏/换表述）→ 标记"就地修复"
        ├─ 需场景重构（重写整场戏）→ 标记"场景重构"
        └─ 需跨集调整（影响前后集）→ 标记"跨集联动修复"
Step 6：输出该集场景级问题清单
```

#### 2.2.2 场景级缺陷分类

| 缺陷类别 | 具体表现 | 来源岗位报告 | 修复策略 |
|---------|---------|-------------|---------|
| 对白级缺陷 | 台词OOC、潜台词缺失、语速不匹配、信息密度过低 | 岗位4/6 | 就地修改台词 |
| 冲突级缺陷 | 冲突密度不足、冲突升级不够、冲突解决过快 | 岗位5 | 增加冲突层次/延长对抗段 |
| 钩子级缺陷 | 开场钩子弱、结尾卡点无悬念、钩子类型与题材不匹配 | 岗位5 | 更换钩子类型/增强力度 |
| 逻辑级缺陷 | 因果断裂、动机不足、设定矛盾、跨集不衔接 | 岗位6 | 补充因果链/修正设定 |
| 合规级缺陷 | 暴力过度、伦理越线、敏感内容 | 岗位7 | 执行替换方案 |
| 空间级缺陷 | 场景描写不完整、缺五感、空间小气 | 岗位5/6 | 补充空间描写 |

#### 2.2.3 句子级对白诊断

对关键场景（承重戏）的对白逐句检查：

| 检查维度 | 通过标准 | 不通过处理 |
|---------|---------|-----------|
| 身份匹配 | 台词符合说话人的身份/教育/性格 | 改写台词使其符合角色语言指纹 |
| 情绪匹配 | 台词情绪与场景情绪一致 | 调整情绪基调 |
| 潜台词层级 | 重要对白至少有第1层潜台词 | 增加潜台词层次 |
| 节奏匹配 | 对白长度与场景节奏匹配 | 压缩或扩展对白 |
| 信息密度 | 每句对白有信息增量 | 删除空话/补充信息 |
| 画面联动 | 对白能引发视觉想象 | 增加画面感描述 |
| 金句密度 | 关键场景有记忆点金句 | 打造金句 |

### 2.3 第三层·协调修订（Hierarchical Coordinated Revision）

**目标**：将第一层（全局）和第二层（场景级）的发现整合，自上而下指导修订，确保局部修改不破坏全局一致性。

#### 2.3.1 协调修订流程

```
第三层·协调修订流程：

Step 1：汇总全局审查发现 + 场景级审查发现
        ↓
Step 2：优先级排序
        ├─ P0-致命问题（必须修复才能定稿）
        ├─ P0-严重问题（优先修复）
        └─ P0-一般问题（记录，可酌情处理）
        ↓
Step 3：自上而下修订
        ├─ 先解决全局结构问题（因为结构变了，场景级要跟着改）
        ├─ 再解决场景级具体缺陷
        └─ 最后处理句子级对白微调
        ↓
Step 4：一致性检查
        ├─ 修改后是否引入新的全局问题？
        ├─ 修改后是否与知识库产生新冲突？
        └─ 修改后是否影响其他集的衔接？
        ↓
Step 5：迭代判断
        ├─ 有实质性改进且无新问题 → 进入P0终检
        ├─ 仍有P0-致命问题 → 继续修订
        └─ 修订后引入更严重的问题 → 触发否决退回
        ↓
Step 6：输出修订后剧本 + 修订日志
```

#### 2.3.2 自上而下原则的具体应用

| 层级 | 修订内容 | 约束条件 |
|------|---------|---------|
| 全局层 | 调整三幕比例、移动爽点位置、重构冲突升级线 | 改完后场景级必须跟着调整 |
| 场景层 | 重写整场戏、增加/删除场景、调整场景顺序 | 改完后检查因果链不断裂 |
| 对白层 | 改写台词、调整语速、增加潜台词 | 改完后检查角色语言指纹不变 |

**关键原则**：**自上而下（top-down）**——高层策略指导局部修改，保持上下文一致性。任何局部修改必须服从全局策略，不允许"局部最优但全局撕裂"。

#### 2.3.3 迭代终止条件

```
迭代终止判断：

检查修订后剧本：
    │
    ├─ 是否还有P0-致命问题？
    │   ├─ 是 → 继续修订（回到Step 3）
    │   └─ 否 → 继续↓
    │
    ├─ 是否还有P0-严重问题？
    │   ├─ 是 → 优先修复，修复后回到Step 4
    │   └─ 否 → 继续↓
    │
    ├─ 修订是否引入新问题？
    │   ├─ 是 → 新问题比原问题更严重？→ 触发否决退回
    │   │      新问题不如原问题严重？→ 继续修订新问题
    │   └─ 否 → 继续↓
    │
    ├─ 是否还有实质性改进空间？
    │   ├─ 是 → 继续修订
    │   └─ 否 → 迭代终止，进入P0终检
    │
    └─ 迭次数是否超过上限（3次）？
        ├─ 是 → 标记"迭代上限到达"，输出当前最佳版本
        └─ 否 → 继续修订
```

## 三、核心方法论二：多版本择优融合（唯一并行机制）

> 来源：SKILL.md第七章"关键创意并行机制"
> 定位：全行业唯一的并行环节——仅在关键集的钩子/反转桥段产出2-3个备选版本，总编择优融合

### 3.1 触发条件

| 触发场景 | 具体集数范围 | 并行内容 | 版本数 |
|---------|------------|---------|--------|
| 黄金开篇钩子 | 前10集 | 每集开场钩子设计 | 2-3个 |
| 付费转折点反转 | 第10-15集 | 反转桥段设计 | 2-3个 |
| 大结局前高潮 | 最后2-3集 | 高潮桥段设计 | 2-3个 |

> **注意**：并行仅限上述关键集的特定桥段，不扩展到全集并行。非关键集走标准串行流程。

### 3.2 并行版本生成流程

```
多版本并行生成流程：

Step 1：识别关键集 → 提取该集的钩子/反转/高潮桥段
    │
    ↓
Step 2：启动2-3个并行版本
    │
    ├─ 版本A：钩子类型1 / 反转方向1 / 高潮路径1
    ├─ 版本B：钩子类型2 / 反转方向2 / 高潮路径2
    └─ 版本C（可选）：钩子类型3 / 反转方向3 / 高潮路径3
    │
    ↓
Step 3：每个版本独立完成全链路
    │
    ├─ 版本A：钩子设计 → 初稿 → 润色（岗位2→3→4）
    ├─ 版本B：钩子设计 → 初稿 → 润色（岗位2→3→4）
    └─ 版本C：钩子设计 → 初稿 → 润色（岗位2→3→4）
    │
    ↓
Step 4：总编终审时择优融合（见3.3节）
    │
    ↓
Step 5：融合后复检（见3.4节）
```

### 3.3 择优融合规则

#### 3.3.1 三大择优优先级

| 优先级 | 适用场景 | 择优标准 | 评分依据 |
|--------|---------|---------|---------|
| 钩子优先 | 开场钩子选择 | 取最强开场钩子 | 红果钩子三角评分最高 |
| 情感优先 | 结尾卡点选择 | 取情感冲击力最强版本 | 情绪暴击评分最高 |
| 冲突优先 | 中段冲突选择 | 取冲突升级幅度最大版本 | DramaBench冲突评分最高 |

#### 3.3.2 融合组合规则

```
融合组合决策规则：

规则1：钩子+卡点跨版本组合
    版本A的开场钩子 + 版本B的结尾卡点
    → 适用条件：A的开场更强但B的结尾更有悬念
    → 必检项：中间过渡是否自然

规则2：力度+深度跨版本组合
    版本A的反转力度 + 版本B的情感深度
    → 适用条件：A的反转更震撼但B的情感更打动人
    → 必检项：反转与情感的衔接是否生硬

规则3：整版本择优（不融合）
    直接选择综合评分最高的版本
    → 适用条件：某版本全面领先，无需跨版本取材
    → 必检项：无（整版本已自洽）

规则4：局部元素提取
    从版本C中提取一个配角反应细节，融入版本A
    → 适用条件：某版本整体一般但有个别亮点
    → 必检项：提取的元素是否与目标版本风格统一
```

#### 3.3.3 融合示例

**示例1：第1集开场钩子择优**

| 版本 | 钩子类型 | 钩子三角评分 | 情感评分 | 冲突评分 |
|------|---------|------------|---------|---------|
| 版本A | 悬念钩子（主角收到神秘信） | 8.5 | 6.0 | 7.0 |
| 版本B | 冲突钩子（主角当众被羞辱） | 7.0 | 7.5 | 9.0 |
| 版本C | 反差钩子（废柴突然展露实力） | 9.0 | 6.5 | 8.0 |

总编裁定：
- 钩子优先 → 选版本C的开场钩子（三角评分9.0最高）
- 但版本C的结尾卡点情感评分偏低（6.5）
- 融合方案：**版本C的开场钩子 + 版本B的结尾卡点**
- 理由：版本C开场抓人（反差钩子爆率高），版本B结尾情感冲击更强

**示例2：第12集付费转折点反转择优**

| 版本 | 反转方向 | 反转力度 | 情感深度 | DramaBench冲突 |
|------|---------|---------|---------|---------------|
| 版本A | 盟友背叛 | 9.0 | 8.5 | 8.0 |
| 版本B | 身份揭示 | 7.5 | 9.5 | 7.0 |
| 版本C | 计划失败 | 8.0 | 7.0 | 9.0 |

总编裁定：
- 冲突优先 → 版本C的DramaBench评分最高（9.0）
- 情感优先 → 版本B的情感深度最高（9.5）
- 融合方案：**版本A的反转框架 + 版本B的情感反应 + 版本C的冲突升级**
- 具体操作：以版本A的盟友背叛为主线，融入版本B中主角发现背叛后的深层情感反应描写，再叠加版本C中冲突进一步升级的桥段
- 必检项：背叛→情感反应→冲突升级 的衔接是否自然连贯

## 四、核心方法论三：否决权+融合权规则

### 4.1 否决权

总编对岗位1-7的任何产出拥有否决权，可将问题退回指定岗位重做。

#### 4.1.1 否决触发条件

| 否决触发条件 | 具体表现 | 退回岗位 |
|-------------|---------|---------|
| **OOC（角色违反知识库档案）** | 角色行为/台词与知识库人物档案矛盾 | 退回岗位3（初稿）或岗位4（台词） |
| **逻辑漏洞无法就地修复** | 剧情因果断裂、设定矛盾、跨集不衔接，且无法在终审阶段局部修补 | 退回岗位2（大纲）或岗位3（初稿） |
| **节奏严重失衡需结构性重设计** | 冲突密度完全不达标、张力曲线严重畸形、需重新安排集数分配 | 退回岗位2（大纲）或岗位5（节奏） |
| **合规违规且无法替换** | 触碰平台红线且替换方案无法保证剧情完整性 | 退回岗位3（初稿）重写违规桥段 |
| **与知识库Logline严重偏离** | 全剧主线与锁定的Logline不吻合 | 退回阶段0（总编定调）重新对齐 |

#### 4.1.2 否决执行流程

```
否决执行流程：

Step 1：识别否决触发条件
    │
    ↓
Step 2：定位问题源头
    ├─ 是哪个岗位产出的？
    ├─ 问题具体在哪里？（集数/场景/台词）
    └─ 退回哪个岗位能最有效修复？
    │
    ↓
Step 3：填写否决通知
    ┌─────────────────────────────────────────┐
    │ 否决通知                                  │
    │                                          │
    │ 退回岗位：岗位X（岗位名称）                │
    │ 问题定位：第X集·第X场·具体问题             │
    │ 否决原因：[OOC/逻辑漏洞/节奏失衡/合规违规]  │
    │ 重做要求：                                │
    │   1. ...                                  │
    │   2. ...                                  │
    │ 重做约束：不得引入新问题，不得修改知识库    │
    └─────────────────────────────────────────┘
    │
    ↓
Step 4：退回执行
    ├─ 目标岗位收到否决通知后重做
    ├─ 重做完后重新走岗位5/6/7检查
    └─ 再次进入岗位8终审
    │
    ↓
Step 5：否决次数记录
    ├─ 同一岗位被否决≥2次 → 标记"高危岗位"
    └─ 同一问题被否决≥3次 → 升级处理，通知用户
```

#### 4.1.3 否决限制

| 限制项 | 规则 |
|--------|------|
| 否决粒度 | 最小粒度为"场景级"，不因个别台词问题否决整集 |
| 否决范围 | 只退回产生问题的岗位，不连带退回无关岗位 |
| 否决次数上限 | 同一问题最多否决3次，超过则升级处理 |
| 知识库不可因否决修改 | 否决退回的岗位重做时不得修改知识库（00）的锁定内容 |

### 4.2 融合权

总编可从不同版本、不同集次中提取最优元素进行组合融合。

#### 4.2.1 融合约束条件

| 约束 | 说明 |
|------|------|
| 故事连贯性 | 融合后故事主线不得断裂或跳跃 |
| 角色一致性 | 融合后角色行为/台词不得产生OOC |
| 时间线完整性 | 融合后时间线不得出现前后矛盾 |
| 风格统一性 | 融合后整体语言风格不得撕裂 |
| 信息分布均匀 | 融合后不得出现信息过载或真空 |

#### 4.2.2 融合禁止项

```
以下融合操作禁止执行：

✗ 跨题材融合（如甜宠桥段融入悬疑剧本）
✗ 跨人设融合（如把A角色的台词特征移植到B角色）
✗ 时间线冲突融合（如把第15集桥段移到第5集但不调因果链）
✗ 知识库违规融合（融合后违反知识库禁用设定）
✗ 合规降级融合（融合后引入岗位7已清除的合规问题）
```

### 6.1 BFA四维评分体系

| 维度 | 满分 | 评估内容 | 阈值 |
|------|------|---------|------|

## 十一、终审执行纪律

1. **不确认不定稿**：Gate B为硬门禁，终审裁定通过 ≠ 用户确认，必须等用户回复"确认"才能定稿
2. **P0为最低门槛**：P0-致命项未全部通过，终审裁定不得为PASS
3. **知识库为最高权威**：任何终审发现与知识库冲突，以知识库为准
4. **多版本融合仅限关键集**：不扩展到全集并行，非关键集走标准串行
5. **否决必须指明退回岗位**：不得笼统否决，必须指明退回哪个岗位、重做什么
6. **融合后必复检**：任何融合版本必须重新走岗位5+6快速复检
7. **迭代不超过3次**：协调修订同一问题最多迭代3次，超过则升级处理
8. **质检≠确认**：P0 28项终检+BFA四维验证均为技术自检，通过后仍须输出Gate B确认清单等用户确认
