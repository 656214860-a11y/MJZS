# 总编知识库（Chief Editor Knowledge Base）

> 定位：全局锚点——人物档案、世界观规则、Logline、平台规则的唯一权威来源。阶段0定稿后全程锁死，所有岗位必须引用。
> 行业对标：行业标准中"总编定调"阶段产出的核心文档，全程锁死防止人设崩。

---

## 一、知识库六要素

### 1. Logline（一句话卖点）

**公式**：[主角] + [核心欲望] + [不可抗力阻碍] + [失败的致命代价]

**标准**：
- 一句话讲完整剧卖点
- 能让听众/读者立刻判断适不适合短剧
- 包含主角、欲望、阻碍、代价四要素

**示例**：
- ✅ "废柴少年想救被抓走的妹妹，但他只有三天时间，还被全江湖追杀"
- ❌ "一个剑客想要变强"（无阻碍、无代价）

### 2. 赛道定位

| 维度 | 内容 |
|------|------|
| 题材赛道 | 修仙/赘婿/重生/甜宠/复仇/悬疑/逆袭/系统流 |
| 目标受众 | 年龄段+性别+偏好标签 |
| 目标平台 | 抖音/红果/快手/微信视频号 |
| 平台规则 | 各平台内容规范要点（引用SD platform-safety-compliance-guide.md） |
| 时长规格 | 单集时长（60秒/90秒/120秒）+ 目标总集数 |

### 3. 人物总档案（全程锁死的核心）

每个A级角色（≤5个）必须包含：

```
角色名：
角色定位：主角/反派/关键助力/情感线/关键变量
表面身份：观众第一眼看到的身份
隐藏身份：（如有）后期揭示的真实身份
核心欲望：这个角色最想要什么
最大恐惧：这个角色最害怕什么
不可变特征：外貌/体型/年龄/性别/标志性特征（全程不可改）
色彩锚点：主色调+辅助色（视觉一致性用）
角色弧线：开篇状态→中段转折→终局状态（一句话概括）
语言特征：口头禅/说话风格/用词偏好/语速
运动个性：步态/手势习惯/标志性动作
禁用设定：这个角色绝不会做什么/绝不会说什么（防止OOC）
```

> 此档案的人物档案可直接作为扣子图像生成的角色参考输入；如需参考图，用扣子图像生成能力产出。

### 4. 世界观规则

**三问筛选法**（只保留"观众必须知道才能看懂剧情"的设定）：
1. 观众不知道这个设定，能不能看懂这场戏？→ 不能就保留
2. 这个设定能不能用画面展示，而不是台词说？→ 能就用画面
3. 能不能留到后面再解释？→ 能就往后放

**输出格式**：
```
规则1：[规则名] - [一句话说明] - [影响哪些场景]
规则2：...
禁用设定：[这个世界观里不存在/不能发生什么]
```

### 5. 核心爽点清单

短剧核心竞争力——观众就是为了这些瞬间留下来的。

| 爽点类型 | 触发集数 | 描述 | 视觉化方式 |
|---------|---------|------|-----------|
| 打脸爽 | 第X集 | 被轻视→展示实力→震惊全场 | ... |
| 逆袭爽 | 第X集 | 从底层→一步步爬到高位 | ... |
| 复仇爽 | 第X集 | 被伤害→精准报复→大快人心 | ... |
| 揭秘爽 | 第X集 | 悬念→反转→真相大白 | ... |
| 甜宠爽 | 第X集 | 误会→心动→撒糖 | ... |
| 系统/金手指爽 | 第X集 | 获得能力→碾压对手 | ... |

### 6. 禁用设定清单

全程锁死的"绝对不能出现"清单：
- 人物禁用设定（角色绝不会做什么）
- 剧情禁用桥段（不可出现的情节）
- 平台禁用内容（引用SD platform-safety-compliance-guide.md 的红线项）
- 风格禁用（不可出现的语言风格/视觉风格）

## 二、知识库创建流程

```
Step 1：通读小说/消化创意
  → 提炼Logline
  → 判断适不适合短剧（快评5问）

Step 2：赛道定位
  → 确定题材、受众、平台、时长

Step 3：人物总档案
  → 提取核心角色（≤5个A级）
  → 角色合并（功能相同的合并）
  → 填写每人档案

Step 4：世界观规则
  → 三问筛选法
  → 只保留必知设定

Step 5：爽点清单
  → 从原著/创意中提取
  → 按集数规划分布

Step 6：禁用设定清单
  → 人物OOC防线
  → 平台合规红线

Step 7：锁定
  → 输出知识库文档
  → 标记"已锁定·全程不可修改"
  → 后续所有岗位必须引用此文档
```

---

## 三、锁死规则

1. **时间锁**：阶段0完成并经用户确认后，知识库进入锁定状态
2. **引用锁**：所有后续岗位（1-8）在执行时，必须先读取知识库，确保产出与知识库一致
3. **修改锁**：锁定后如需修改，必须经总编（用户）批准，且修改后必须重新检查所有已完成岗位的产出是否受影响
4. **冲突锁**：当任何岗位产出与知识库冲突时，以知识库为准，岗位产出需修正

| → 岗位6（逻辑） | 知识库的世界观规则作为逻辑检查基准 |
| → 岗位7（合规） | 知识库的禁用设定清单+平台规则作为合规检查基准 |
