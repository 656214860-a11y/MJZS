# 短剧剧本工业化生产流水线（Screenplay Production Line）

> 定位：扣子独立运行的剧本创作工作流——对标短剧行业标准 SOP，以"总编统筹+7岗位串行"架构实现从 IP/创意到定稿剧本的工业化生产。
> 运行环境：扣子。全部方法论已内置于本技能的 `references/`，无需 Trae、无需外部技能即可跑完整条流水线。
> 核心铁律：串行为主、两道硬门禁、关键创意多版本择优、总编拥有否决权+融合权。

## 二、核心工业法则

1. **串行为主，不并行写全集**：7 个岗位按序串行执行。不存在"多个 AI 各自写完整剧本再拼稿"的模式——行业踩坑证明这会导致风格撕裂、人设反复横跳。

2. **两道硬门禁**：
   - **Gate A·大纲审核卡点**（岗位2完成后）：分集大纲必须经用户确认才能进入脚本初稿。大纲不改好，后面全部返工——这是短剧行业返工头号原因。
   - **Gate B·总编终审卡点**（岗位8完成后）：终审通过才能定稿交付。

3. **唯一并行环节**：仅在关键集（前10集黄金开篇、付费转折点）的钩子/反转桥段，产出 2-3 个备选版本，总编择优融合亮点。不并行写完整全集。

4. **总编知识库全程锁死**：`00-chief-editor-knowledge-base.md` 中的人物档案、世界观规则、Logline、平台规则，在阶段0定稿后全程锁死，后续所有环节必须引用，防止人设崩。

5. **质检≠确认**：各岗位技术自检（节奏/逻辑/合规）通过后，仍须输出确认清单，等用户回复"确认"才能推进。

6. **总编拥有否决权+融合权**：统筹不是简单拼接，总编必须像真人总编一样判断好坏、解决前后矛盾、拍板取舍。

## 三、标准生产流程（7岗位串行 + 2道门禁）

```
阶段0：总编定调
  通读小说/创意 → Logline提炼 → 赛道定位
  → 产出总编知识库（00·全程锁死）
        ↓
岗位1·拆书编剧
  通读原著 → 提炼故事核 → 砍支线/独白/铺垫
  → 输出情节节点表
        ↓
岗位2·分集大纲+钩子编剧
  按目标集数拆分 → 每集公式（承接悬念+冲突爆发+结尾钩子）
  → 输出分集大纲 + 钩子设计清单
        ↓
  🚦 Gate A·大纲审核卡点（硬门禁）
  暂停 → 输出大纲确认清单 → 等用户"确认"
        ↓
岗位3·脚本编剧（写初稿）
  按分集大纲逐集写拍摄脚本
  → 场景/内外日夜/动作/台词，禁心理描写
        ↓
岗位4·台词润色编剧
  书面文字→口语短句 → 统一人物说话风格 → 压缩长对白
        ↓
岗位5·节奏编审
  逐集审查：冲突密度/拖沓水戏/钩子强度/单集时长
  → 节奏审查报告 + 修改建议
        ↓
岗位6·逻辑编审
  检查剧情漏洞/前后设定冲突/人物动机 + 多角色视角交叉审查
  → 逻辑审查报告 + 修改建议
        ↓
岗位7·合规审读
  平台红线筛查（暴力/伦理/敏感）→ 替换违规桥段
  → 合规审查报告 + 替换方案
        ↓
岗位8·总编终审
  分层审查（全局→场景→协调修订）+ 关键集多版本择优融合
  → 终审裁定 + 定稿剧本
        ↓
  🚦 Gate B·总编终审卡点（硬门禁）
  暂停 → 输出终审确认清单 → 等用户"确认"
        ↓
定稿交付
  定稿剧本 + 场景清单 + 人物出场清单 + 钩子密度表
```

## 六、双入口设计

| 入口 | 触发条件 | 流程 |
|------|---------|------|
| **入口A：小说IP改编** | 用户提供小说/原著/网文文本 | 阶段0→岗位1（拆书）→岗位2（大纲）→Gate A→岗位3~8→Gate B→定稿 |
| **入口B：原创剧本** | 只有创意/题材/一句话梗概 | 阶段0→岗位2（大纲，跳过岗位1）→Gate A→岗位3~8→Gate B→定稿 |

两个入口在岗位2（大纲）汇合，后续完全相同。

## 七、关键创意并行机制（唯一并行环节）

### 7.1 触发条件
- 前10集黄金开篇的每集钩子设计
- 付费转折点（通常第10-15集）的反转桥段
- 大结局前的高潮桥段

### 7.2 执行方式
```
识别关键集 → 提取该集钩子/反转桥段
  ↓
产出 2-3 个备选版本（不同钩子类型/不同反转方向）
  ↓
每个版本独立完成：钩子设计 → 初稿 → 润色
  ↓
总编终审择优融合（如 A 的开场钩子 + B 的结尾卡点），并检查衔接
```

### 7.3 择优融合规则
1. **钩子优先**：开场钩子取最强版本（按钩子三角评分）
2. **情感优先**：结尾卡点取情感冲击最强版本
3. **冲突优先**：中段冲突取升级幅度最大版本（DramaBench 评分最高）
4. **融合后必检**：重新走岗位5（节奏）+岗位6（逻辑）快速复检

## 八、执行预算与"够用就行"

| 指标 | 标准 |
|------|------|
| 总对话轮数 | 15-25轮（完整流水线） |
| 模块加载 | 按岗位序加载，每岗 1 个模块，不提前加载后续模块 |
| 质检 | 岗位5节奏 + 岗位6逻辑 + 岗位7合规 + 岗位8 P0 28项（BFA可选） |
| 门禁 | 2道硬门禁（Gate A + Gate B）+ 各岗位技术自检 |

1. 每个岗位只加载本岗位模块，用到的方法均已在模块内写全。
2. 喜剧风格规则按需套用：阶段0检测到诙谐/搞笑/沙雕/无厘头/轻喜/吐槽/方言喜剧等关键词时，贯穿大纲→初稿→润色→节奏→终审；未命中不套用。
3. 岗位5/6/7的技术自检不阻断主流程，问题记录后交岗位8总编统一裁定。
4. 非关键集（第11集之后）可适当降低节奏、逻辑编审深度，快速过检。

## 九、扣子工作目录约定

每个剧本项目独立建文件夹，产物按语义命名（扣子云盘内，路径可由用户指定）。建议结构：

```
剧本项目_[项目名]/
├── 00_总编知识库.md
├── 01_情节节点表.md（或 .xlsx）
├── 02_分集大纲与钩子.md
├── 03_剧本初稿/第X集.md
├── 04_润色剧本/第X集.md
├── 05_审查报告/节奏_第X集.md
├── 05_审查报告/逻辑_第X集.md
├── 05_审查报告/合规_第X集.md
└── 08_定稿/第X集.md + 定稿交付清单.md
```

> 如需角色/场景参考图，可在扣子里用图像生成能力直接产出，人物档案作为输入。

### 本程序运行时的目录映射

- 总编知识库、情节节点表、分集大纲、审查报告、确认清单等过程文档，写入项目 `01剧本准备/docs/`。
- 剧本正文的唯一落点是程序发布的 `script_raw.md`；该文件由程序写入，SKILL 执行者不得直接改写。
- Gate A 与 Gate B 的用户确认，在本程序中均表示暂停并等待用户在界面确认；不使用扣子云盘目录承接确认。

## 十、执行纪律

1. **不确认不推进**：Gate A、Gate B 为硬阻断，质检通过≠用户确认
2. **串行不跳步**：7 个岗位按序执行，不跳过任何岗位
3. **大纲不通过不写脚本**：Gate A 未通过，绝对不得进入岗位3
4. **总编知识库锁死**：阶段0定稿后，人物档案/世界观/Logline 不可修改
5. **多版本择优仅限关键集**：不扩展到全集并行
6. **总编否决权**：岗位8有权否决任何岗位产出并指明退回重做
