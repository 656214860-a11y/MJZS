# 需求与设计（按阶段）

本目录按制作阶段拆分需求与设计：每个阶段一份文件，`## 需求` 描述系统现在想去的方向，`## 设计` 描述怎么实现。
两份内容都原地修改，不记历史（历史看 git）；每条 `DES-xx` 标注它实现的 `REQ-xx`。
全局分层（L0–L5）与唯一权威源表以 `architecture.md` 为准；阶段文件只描述该阶段内部，不另立第二套分层。

- `docs/stages/Sxx_<阶段名>.md`：`## 需求` 为该阶段需求，`## 设计` 为该阶段设计（模块分工、设计条目、测试锚定表）。
- 新增或修改阶段条款时直接改对应阶段文件，不新建第二份需求／设计文件。

编号规则：`REQ-<阶段号>-<序号>` → `DES-<阶段号>-<序号>`（标注所实现的 REQ）→ 测试 docstring 写 REQ。
删除的编号不复用。测试锚定门禁读本目录下全部 `REQ` 行。

状态：✅ 已实现　🟡 部分实现／与代码不一致　⬜ 未实现　❓ 待人拍板

已覆盖阶段：S01–S13（13 个）。

`docs/review/` 是给人审阅的高危路径评审说明（时序＋失败模式清单），不是需求／设计条款，见该目录 README。
