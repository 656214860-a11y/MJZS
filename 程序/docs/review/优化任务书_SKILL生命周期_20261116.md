## 1. 现状盘点（审计结论）

### 1.1 现有链路一句话

阶段配置面板勾选 → `skill_config.json`（按项目）→ 发送边界 `validate_selected_skills`＋`master_gate`＋`freeze_skills` 内联 → `skill_orchestrator`（三虎自动流）DAG 执行。

### 1.2 对照 DSH 五层架构的已有／缺失

| DSH 层 | 本应用现状 | 证据 |
| --- | --- | --- |
| ① 表示层／UI 触发 | 阶段配置面板：SKILL 勾选、全选／取消、新增、删除已勾选；说明目录面板 | `skill_panel.py` `choose_skill_action`/`add_skill_from_file`/`delete_checked_skills` |
| ② 导入与解析层 | `skill_import_service`：预检→暂存→换入→试冻结→台账；体积／链接护栏；`master_import_service` 同构管总控包 | `skill_import_service.py`、`master_import_service.py` |
| ③ 发现与索引层 | `skill_registry.Registry`：两层目录、指纹热加载、17 字段 frontmatter 校验、problems/warnings 分级 | `skill_registry.py` |
| ④ 生命周期与宿主支撑 | 单进程桌面应用，无 host/client 分离（不适用）；导入台账、回收站、暂存回滚已有；**缺统一操作日志、更新检测、体检上屏** | `skill_import_service.ledger_path`、`storage_maintenance.recycle_paths` |
| ⑤ 安装核心复用层 | 文件放置 `user_stage_directory_for`、内容摘要 `sha256` 入台账、同名冲突处理（同层硬拦／跨层软提示）；**缺版本与升级检测消费方** | `skill_registry.py`、`skill_import_service.record` |

### 1.3 关键事实（任务书引用的锚点）

- 两层目录：内置 `程序/skills/`（升级覆盖）＋用户 `程序/data/skills/`（升级保留，`distribution_manifest.md` 显式排除）。同名用户优先，内置版软提示遮蔽。
- 扫描范围：仅 `01—13` 阶段目录下一层的 `*.skill.md` 与包目录（`SKILL.md`/README 兜底）；阶段目录外的文件不进注册表。根目录遗留 `.skill.md` 仅**内置层**有懒迁移（`_migrate_root_manifests` 只扫 `self.root`），**用户层根目录文件静默不可见**——不对称点。
- 校验：`validate_skill` 查 17 个必填字段、列表／布尔类型、capabilities 枚举、阶段目录与 frontmatter 一致、文件名＝name、依赖冲突自洽。问题进 `problems()`、软提示进 `warnings()`——**两者没有任何 UI 消费方**，只有测试与 `codex_skill_sync` 读它们。
- 试冻结：`workflow_settings._inline_skill_report(strict=True)` 在换入后按真实发送流程验证（空正文、引用缺失／越界、超上限即撤回）。
- 发送冻结：`freeze_skills`→`_skill_blocks` 递归内联 Markdown 引用（锚点节选、`仅 \`锁\` 为…时追加` 条件、环／重复／越界检测、内联预算），闭包写入 `skill_injection` 回执。非 writing 阶段走 `skill_prompt` 路径引用（agent 自行读文件）。
- 分发：`codex_skill_sync` 把已登记 `*.skill.md` 物化为 `~/.codex/skills/<name>/SKILL.md`（只留 name＋description frontmatter，正文按需引用），带 owner marker 与孤儿回收；首帧后后台跑，`desktop_idea_chat` 发送时再跑。
- 在线更新先例：`master_skill_update` 从 GitHub 拉 codeload zip，`_safe_members` 做路径穿越／体量防护，diff 摘要＋用户确认＋原子换入＋回收站——**这套件可复用到普通 SKILL 的远程导入**。
- 开发侧件：`scripts/create-skill.js`（生成器，`程序/scripts/**` 不进发布包，**用户拿不到**）、`scripts/skill_package_pins.py`＋`维护记录/外部技能包哈希.json`、`skills/skills-lock.json`。
- 已知 deferred：设置页「SKILL 管理」格用户此前明确「这一轮不做」（`pet_ui_view.py`、`pet_ui_settings.py` 注释）。

### 1.4 与 DSH 标准的本质差异（不是缺口，是范式）

- **调用方式**：DSH/Claude/Codex 是「模型按 description 自动匹配或 `/name` 显式调用」；本应用是「用户按阶段勾选 → 固定注入」。自动调用、`@skill` 触发不适用，不列为缺口。
- **目录暴露**：DSH session catalog 只给模型 name＋description；本应用等价物是勾选面板＋说明面板，发送时全量内联（有上限）。不算缺口。
- **Skill vs Plugin**：本应用 SKILL 只是提示词包，无 `apply(ctx)` 代码插件概念；外部包内 `scripts/` 目前惰性不执行。不需要照搬 plugin 体系，但**导入含可执行内容的包应有提示**（见 G7）。

## 2. 网络标准调研结论（补全依据）

| 来源 | 安装／管理／使用／验证要点 |
| --- | --- |
| DSH（deepseek-harness `dsh-skill`） | Skill＝Markdown 指令集，**不是** `dsh plugin add` 的对象（那是代码插件）。本地 provider 按 rank 扫 6 个根：项目 `.dsh/skills`(100) → 项目 `.agents/skills`(200) → `Config.customSkillDirs`(300) → 用户 `~/.dsh/skills`(400) → 用户 `~/.agents/skills`(500) →（插件内嵌）。低 rank 值覆盖高 rank 同名。session catalog 只暴露排序后的 name＋description；`/name` 手动调用，description 匹配自动加载；条目校验、重名可预期仲裁、单源不可用不拖垮整体。第三方 `dsh-skills-anywhere` 演示了聚合 60+ agent 目录、`list`/`doctor` 诊断、零拷贝的 provider 模式。 |
| Agent Skills 规范（agentskills.io） | 目录必含 `SKILL.md`；可选 `scripts/`、`references/`、`assets/`。frontmatter 必填仅 `name`（≤64 字符、小写数字连字符、须等于目录名）与 `description`（≤1024 字符、写清何时用）；可选 `license`、`compatibility`、`metadata`、`allowed-tools`。正文无格式限制，长内容拆到引用文件按需读。 |
| Claude Code | 位置优先级：企业 managed（最高，同名覆盖）→ 个人 `~/.claude/skills/` → 项目 `.claude/skills/`（cwd 向上到仓库根逐级）→ 嵌套目录 → `--add-dir` → 插件 `/plugins/<name>/skills/` → claude.ai 同步。`/name` 调用＋description 自动触发；`.claude/commands/*.md` 为旧式单文件命令。 |
| OpenAI Codex | `~/.codex/skills/**/SKILL.md` 递归（隐藏项与符号链接跳过）；仓库级 `.agents/skills` 从 cwd 向上扫到仓库根。name ≤100 字符、description ≤500 字符；只注入 name/desc/路径目录，正文留盘。启动时加载一次，`npx skills` 生态 CLI 提供 `add/find/list/use/check/update/remove/init` 生命周期动词。 |
| Vercel `skills` CLI／skills.sh | 开放生态：`npx skills add owner/repo`（项目级默认、`-g` 全局）、`check` 查更新、`update`/`remove` 管理；skills.sh 目录＋安装量榜单，安全审计声明＋「自行判断」免责。 |

**对本应用的可迁移结论**：①生命周期动词集（add/find/list/check/update/remove/doctor）是业界事实标准；②「项目级 vs 用户级」分层是标配；③远程安装主流是 GitHub 仓库／目录 URL；④多端分发主流是把 SKILL.md 物化到各 agent 的 skills 目录；⑤验证主流是「doctor/体检」命令＋加载前校验。

## 5. 各任务详述

### T1 SKILL 体检上屏＋发送前预览（P0）

**问题**：`registry.problems()`/`warnings()` 算出来没人看；用户勾选后要到发送失败才知道引用断了。

**步骤**
1. 新增 L3 无 Tk 服务（建议 `skill_health_service.py` 或并入现有服务，先搜入口）：输入 registry，输出每个 SKILL 的 `{name, stage, layer, problems, warnings, closure_dry_run}`；closure 复用 `workflow_settings._skill_blocks(strict=True)` 的只读路径，捕获引用闭包与内联字符数，**不发送、不落盘**。
2. 阶段配置面板加「体检」入口（`skill_action` 下拉或独立按钮，走 `ui_widgets` 既有组件）：列出本阶段 problems/warnings，点击条目显示该 SKILL 的引用闭包表（沿用 `reference_row` 字段：kind/status/target/depth）与「预计内联 N 字符／上限 M」。
3. 修用户层不对称：`data/skills/` 根目录的 `.skill.md` 目前静默不可见。二选一并在结果文件写明理由：(a) `_migrate_root_manifests` 扩到 user_root；(b) `plan_import`/`validate` 显式拒绝根目录目标。倾向 (a)，与内置层行为一致。
4. 文档：`architecture.md` 权威源表 SKILL 行补「体检服务」指针（若新模块）。

**验收**：造一个缺字段、一条断链、一条越界引用的 SKILL，面板体检逐条列出且不发送；`test_skill_*` 新增用例先红后绿；`smoke_test.py --affected skill_health_service`（或实际模块名）绿。

**不做**：不改 frontmatter 契约；不做全局总览页（那是 T7）。

### T2 导入来源扩展：文件夹直选＋ZIP 导入（P0）

**问题**：只能挑单个文件；用户拿到的常是整个技能文件夹或 zip 包。

**步骤**
1. `add_skill_from_file` 增加「本地文件夹」入口：`FileDialog.directory()` 已存在；选中文件夹时先找 `SKILL.md`（再 README 兜底，同 `_package_source` 口径），找不到按单文件逻辑报「不是 SKILL 包」。
2. 新增 ZIP 导入：`plan_import`/`perform_import` 前加 `skill_archive.py`（L2/L3，无 Tk）：zipfile 解到暂存目录，复用 `master_skill_update._safe_members` 的路径穿越／`..`／盘符／体量防护（抽公共件或复制改名，先搜是否已有共享实现——`test_http_boundary` 类似的边界门禁思路），然后走与文件夹相同的包导入路径。
3. ZIP 内结构判定：含 `SKILL.md` 的子目录视为包；根级 `*.skill.md` 视为清单；都没有→硬拦并说明。
4. 体积护栏沿用 `PACKAGE_MAX_*`；ZIP 条目数上限同 `MAX_FILES` 口径另设常量。

**验收**：zip 含 `../evil.md`、绝对路径、超体量各一例被拒；正常包导入后试冻结通过、旧版进回收站；`tests/` 新文件覆盖三种拒绝与成功路径。

**不做**：不接网络（T3）；不解 `.skill.md` 之外的压缩格式。

### T3 远程导入：GitHub／URL SKILL 包（P1）

**问题**：业界主流安装源是 GitHub 仓库／URL，本应用完全离线文件流。

**步骤**
1. `skill_import_service` 或新 `skill_remote_service`（L3）加来源解析：`https://github.com/<owner>/<repo>`（可带 `#<ref>`／子目录）、`https://…/*.zip` 直链；其余 URL 形态先只收 zip。
2. 下载走 `platform_tools.open_https`（与 `master_skill_update._fetch` 同一出站口径；注意 `DRAMA_SUPPRESS_NETWORK` 自检开关要继承）。二进制 zip 不走 `http_client.request_json`（那是 JSON 口径），在结果文件注明该边界决策。
3. 下载→落 `data/skills/下载缓存/`（或复用 `data/总控包更新/` 同级新目录）→ 走 T2 的 ZIP 解包→`plan_import`/`perform_import` 同一条链。
4. 台账扩展：`record()` 增 `source_url`、`source_ref`（commit/ tag）、`version`（若 frontmatter 有）字段；读取侧容忍旧行缺字段。
5. UI：`add_skill_from_file` 对话框加「从链接导入」入口（URL 输入框复用 `ui_widgets` 既有输入组件）。

**验收**：本地起 HTTP 服务喂 zip 走通全链路（自检环境用 fetch 注入，不真联网）；台账行含新字段且旧台账可读；超时／404／坏 zip 各有错误文案用例。

**不做**：不做技能市场／registry 浏览（T10 远期）；不支持 npm/git clone 等重源。

### T4 导入台账消费：更新检测＋本地修改识别＋删除闭环（P1）

**问题**：台账写了没人读；「检测来源是否更新」是注释里的空头支票。

**步骤**
1. `skill_import_service` 增 `check_updates(program)`：遍历台账，对本地目录源重算 `_tree_digest` 比对 `sha256`；对 T3 的远程源按 `source_url`/`source_ref` 重新拉摘要（HEAD 或小包）；产出 `{key: 'unchanged'|'source-newer'|'local-modified'|'source-missing'}`。
2. 「本地修改」判定：对已安装目标重算摘要与台账 `sha256` 不一致→`local-modified`（用户手改过，不提示覆盖）。
3. UI 挂点：阶段配置面板「新增」旁加「检查更新」（或并入 T1 体检页，先搜入口再定）；有更新的条目给「重新导入」按钮，走既有 `perform_import`（旧版自动进回收站）。
4. 删除闭环：`delete_checked_skills` 成功后从台账移除对应行；`migrate_legacy_imports` 已示范台账写法，保持同一 `save()` 入口。

**验收**：改台账源目录一个字节→`source-newer`；手改 `data/skills` 内文件→`local-modified`；删除后台账无残留行；全部有测试。

**不做**：不做静默自动更新（必须用户确认，与 `master_skill_update.apply` 同规矩）。

### T5 项目级 SKILL 层＋共享层评估（P1）

**问题**：SKILL 全局生效；单个漫剧项目想带自己的专属 SKILL 只能污染全局列表。DSH/Claude 的「项目级 vs 用户级」是标配。

**步骤**
1. 先出设计稿写进结果文件再动代码：候选位置 `<项目>/skills/`（随项目走、项目目录归用户所有）vs `<项目>/skill_config.json` 同级约定目录；优先级建议 **项目级 > 用户级 > 内置级**（对齐 DSH project(100/200) > user(400/500)）。
2. `skill_registry.Registry` 增第三层：`layers()` 变 `(project?, user, builtin)`；`skill_roots()` 引用边界同步；`stage_from_path`/`_stage_directories` 复用不动。
3. 面板：`Panel.__init__` 已有 `self.project()`，把项目根传给 registry（`default_registry` 按 program 缓存，项目级需按 `(program, project)` 二级缓存或查询时注入——先想清楚缓存键，别复现第 44 期那个 bug）。
4. 「新增」目标目录选择：当前阶段面板加「导入到：项目／全局」二选一（默认项目级，符合最小惊讶）。
5. `.agents/skills` 共享层**只评估不实现**：本机 `~/.agents/skills` 已有大量第三方 SKILL（sw-* 等，标准 frontmatter），评估「只读引入为包」的可行性与风险（格式不兼容本应用 17 字段契约，只能走 `imported_package_meta` 总入口路径），结论写结果文件供下轮拍板。
6. AGENTS.md 权威源表 SKILL 行、`architecture.md` 同步更新（层数、优先级、路径权威归属）。

**验收**：项目 A 导入的 SKILL 在项目 B 的面板不可见；同名三层仲裁顺序有测试；`stage_layout.validate_stage_contract()` 不受影响（阶段目录契约不变）；启动路径零新增扫描（项目根只在打开面板时读）。

**不做**：不做项目级 SKILL 的云同步；不动 `data/skills` 现有用户层语义。

### T6 多端技能导出：agent 导出服务泛化（P1）

**不做**：不同步外部包（只 `.skill.md` 清单，与 codex 现状一致）；不做双向回导。

### T7 统一「SKILL 管理」页（P2）

**问题**：管理入口散在 13 个阶段面板里；设置页「SKILL 管理」格此前明确 deferred，现在生命周期任务铺开后该落地了。

**步骤**

### T8 生命周期补全：重命名／编辑／启用禁用／version（P2）

**问题**：改一个错别字要删了重导；禁用一个坏 SKILL 只能逐项目取消勾选。

**步骤**
1. **重命名**：管理页行操作；改名＝frontmatter `name` 与文件名同步改（清单）或目录名（包），同步迁移 `skill_config.json` 里所有项目的引用（`stage_config` 读改写经既有 `put` 入口）、台账 key、codex/claude 同步 marker 重算。改名前 dry-run 列出受影响项目数。
2. **编辑**：行操作「在编辑器打开」——用系统关联程序打开源文件（`os.startfile`，Windows 桌面应用合适），不内嵌编辑器；保存后注册表指纹自动热加载，无需额外刷新。
3. **启用禁用**：禁用＝不进 `getAll()` 但保留文件。实现候选：(a) 台账级 `disabled` 标记，`scan()` 时过滤；(b) `.disabled` 后缀约定。倾向 (a)，理由：不改目录结构、删除即恢复、台账已有读写入口。禁用条目在管理页灰显可恢复。
4. **version**：frontmatter 允许可选 `version` 字段（解析器已容忍未知键）；`record()` 台账行同步记录；T4 的更新检测优先比 version 再比摘要。

**验收**：重命名后旧项目配置引用不断、面板新名出现；禁用后发送边界 `validate_selected_skills` 对「曾勾选现禁用」给明确报错而非静默丢；每项先红后绿。

**不做**：不做 SKILL 内容在线编辑器；不做跨项目批量勾选迁移 UI（重命名迁移是静默且列清单的）。

### T9 安全加固：不可信来源提示＋完整性校验＋外部字段映射（P2）

**问题**：导入的 SKILL 会成为发给模型的指令内容（提示注入面），目前只有字段问题确认。

**步骤**
1. 导入确认框增加来源行：本地路径／URL／ZIP，标注「外部内容将作为指令注入模型请求」；包内检测到 `scripts/`、`.exe`、`.dll`、`*.ps1`、`*.bat` 时追加「含可执行文件，本应用不会运行但请知悉」。
2. 完整性校验：`scan()` 或 T1 体检时对用户层条目重算 `_tree_digest` 与台账 `sha256` 比对，不一致→`local-modified` 进 warnings（与 T4 同一判定函数，别写两份）。
3. 外部字段映射：`imported_package_meta` 增识别 Agent Skills spec 可选字段——`license`/`compatibility` 进 meta 原样保留并在面板说明区显示；`allowed-tools` 尝试映射 `tools`（映射不了的进 constraints 提示，不硬猜）。本应用 17 字段契约不放宽。
4. `scripts/skill_package_pins.py` 思路下沉：用户导入包在台账里已有 sha256；若后续要「钉住不被改」，复用台账字段即可，本任务不引入新锁文件。

**验收**：含 `evil.ps1` 的包导入时确认框出现警告行；手改用户层文件后体检出现 `local-modified`；外部包 `license` 字段在说明区可见；均有测试。

**不做**：不做内容安全扫描／恶意代码检测（超出本应用能力，文档里写明「请自行判断」同 skills.sh 口径）；不动内置层信任假设。

## 6. 有意差异与「不做」清单
