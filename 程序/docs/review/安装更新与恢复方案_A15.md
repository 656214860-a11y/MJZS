# 安装更新与恢复方案（A15）

本页是发布失败模式。开发顺序在 `runbook.md` §12：车道提交、变基、车道工作树出口 CI、快进推送。推送更新的是 Git 仓库；用户启动的目录按本页切换。执行步骤以 `说明/发布检查单.md` 为准。

## 当前能力边界

应用当前没有在线自动更新器，也没有可验证的安装器切换协议。正式发布只支持“从受控源码构建全新目录 → 完整校验 → 人工切换快捷方式/目录”的并列部署；禁止把开发工作树、用户项目或旧发布目录作为增量覆盖目标。未来若引入更新框架，必须复用相同摘要、SBOM、签名和回退门，不能增加第二套发布事实源。

## 程序版本恢复

1. 用 `distribution_build.py --build --destination <新空目录>` 生成候选；非空目录会被拒绝，旧版本保持只读可启动。
2. 在候选目录执行 `distribution_selfcheck.py --release`，再完成默认冒烟、架构门禁和适用全量；签名或许可证门未通过不得切换。
3. 切换只改变用户启动的目录/快捷方式，不把候选文件覆盖进旧版本。
4. 新版启动失败时切回旧发布目录。开发仓库的源码撤销用独立 `git revert`；它不等于用户数据恢复。
5. 旧发布目录至少保留到一轮完整使用周期结束。恢复后重跑分发自检和默认冒烟，确认旧目录摘要未改变。

## 用户数据恢复

- 用户项目不进入发布包，也不随程序目录更新、删除或回滚。迁移前由 `contract.artifact_schema.migrate_file` 在项目文件同目录生成 `.bak`，原子发布后读回版本；发布或断言失败时自动恢复备份。
- 旧版程序遇到未来 `schema_version` 必须可读或明确拒写，不能覆盖新版数据。需要回退数据时，按项目文件逐项使用迁移留下的 `.bak`，不能用 Git、旧程序目录或重装代替。
- `程序/data/` 下的模型缓存、用户 Skill 等目标机状态不进发布副本，升级时保留不覆盖；私有配置、密钥、项目索引和日志同样不得从发布包写回。

## 验证与失败门

| 风险 | 自动证据 | 发布判定 |
| --- | --- | --- |
| 覆盖旧版本 | `test_distribution_build` 的非空目标拒绝与并列目录用例 | 旧发布目录摘要不变 |
| 发布包夹带用户状态 | 分发清单排除项与 `distribution_selfcheck` | 命中即失败 |
| 数据迁移半写 | `test_artifact_schema` 的备份、原子发布、读回断言、失败恢复 | 原文件字节恢复或保留 `.bak` 并报错 |
| 旧版覆盖未来数据 | `test_artifact_schema` / wiring 的 future-schema 拒写 | 文件保持不变 |
| 自动更新/签名 | 当前未实现 | 外部发布门，不得声称具备 |

发布负责人必须分别记录“程序目录回退验证”和“项目数据恢复验证”；只验证其中一个不构成更新恢复通过。
