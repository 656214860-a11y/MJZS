# 02 阶段完成判定（`stage_completion_service`）

规则：阶段算不算完成，只看磁盘上的成果，不看模型或页面说了什么（AGENTS §2.3 第 20 条）。

## 时序：从“引擎完成”到“下一阶段解锁”
1. 收尾方调用三虎。入口有这几个：
   - `desktop.py:541`：剧本 Agent 退出；
   - `desktop.py:1440`：媒体人工确认之后；
   - `keyframe_comfy.py:882`；
   - `desktop_media_pages.py:156`；
   - `desktop_pet_bridge.py:128-129`：ok 时走 `report_done`，否则走 `drain(False)`；
   - 自动任务队列：`pet_ui_stages.py:44-54`。
2. 这些入口都汇到 `pet_ui_stages.py:31-41／81-106`，统一调用 `stage_completion_service.emit_verified_completion`（`:645`）。
3. `completion_evidence`（`:592-642`）按阶段核验证据。不通过就发 `stage.paused`，阶段不推进。
4. keyframe／previs 核验通过后，先写阶段清单 `publish_stage_manifest`（`:650-654`）。清单写失败，按未完成处理。
5. 只有 script 阶段会先发 `script.completed`，用来武装自动链（`pet_ui_stages.py:100-102`）。
6. `emit('stage.completed', stage, text)`（`:657`）→ `pet_bus`：先校验契约，再按幂等键在入队和 pump 时各去重一次（`pet_bus.py:86-90,226-244`）。
7. 订阅方收到事件后：
   - `pet_state.Machine.complete` 把状态存为 success（`pet_state.py:92`）；
   - `stage_flow.Auto.done` 推进自动链（`stage_flow.py:424`）；
   - 归还并发号，刷新按钮。
8. 下一阶段要过门禁：
   - 自动：`Auto.next_stage` → `pet_ui_stages.gate_reason`（`:353`）→ `pet_agent.gate`（`:959`）→ `stage_parallel.evaluate`（`:919`）。自动链已武装时按生产口径，否则按浏览口径。
   - 手动：`stage_flow.blockers`（`:268`）→ `blocked_stages`（`stage_parallel.py:930`）。
9. 旁路：`skill_orchestrator.py:607-631` 在 SKILL 返回 DONE 后，只对 script／script_structure 用自己的 `verified_stage_output`（`:48-67`）判断并发完成事件，其余阶段一律发 paused。这条旁路不经过 `stage_completion_service`。

## 各阶段查什么（`completion_evidence`）

| 阶段 | 证据 |
| --- | --- |
| root 为空 | 直接通过（`:598`，为兼容轻量宿主） |
| audio／edit／delivery | `成果确认/<指纹>.json` 必须满足：schema=1；scope 等于当前采用分镜的 sha；status=complete 且已人工确认；每个输出都在 `read_dirs` 范围内、非空，size 与 sha256 一致，ffprobe 通过且时长大于 0。edit 另查交接包母版 sha 与 qc；delivery 另查 qc.passed 与绑定的输出 |
| script | `script_contract.resolve_script_source`：有选中文件就核 sha 与目录；没有选中时，只有恰好一份候选才算通过 |
| script_structure | 只看 `is_structured_script`，即前 4 KB 含规定标题，且来源不是大纲 |
| animatic | `animatic_service.evidence`：清单、来源 sha、每个文件的 sha、三项人工确认 |
| storyboard | 有含镜头的已采用分镜，且 `draft_problems` 为空 |
| assets／continuity／final／keyframe／previs | 对应 SG-01～05 的检查要求 `ok and started`（`:622-627`）；空项目不会被判完成 |
| video | `studio.auto_edit_ready()`：每镜都已下载、质检通过、验收 sha 一致 |

## 失败模式

| 场景 | 现在会怎样 | 证据 | 测试 |
| --- | --- | --- | --- |
| 模型说“做完了”，但没有产物 | 不算完成 | `stage_completion_service.py:645` | `test_pet_ui.py` `test_report_done_without_an_artifact_cannot_complete_a_stage` |
| 改了分镜，旧媒体成果还在 | 失效：scope 绑定采用分镜的 sha | `:137` | `test_source_change_and_episode_switch_invalidate` |
| **改了分镜，旧资产清单还在** | 资产检查不核对当前分镜版本，旧清单只要齐全就算完成 | `stage_parallel.py:685-749` | 无测试 |
| **结构剧本两套口径** | 编排器要求 `structure_manifest_problems` 为空，三虎路径不查。清单缺失时，经三虎路径仍可能判为完成。S02 设计第 22 条写的是走 `verified_stage_output`，与代码不符 | `skill_orchestrator.py:63-64` 对 `stage_completion_service.py:610` | 无测试 |
| 带标题的空壳结构稿 | 能通过：只看标题字符串 | `script_contract.is_structured_script` | 无测试 |
| 剧本没选中文件，只有一份旧稿 | 算通过 | `script_contract.py:423` | — |
| 空文件、占位文件 | 媒体、首帧、资产图都查 `st_size` | `:53`；`stage_parallel.py:719,822` | 有 |
| 旧编号目录里的成果 | `read_dirs` 依次返回新目录、旧编号目录、旧英文目录（旧英文目录 2027-03-31 截止）。`existing_dir` 只看一层，新目录里有任何内容就会遮住旧目录；animatic 只读新目录 | `stage_path_service.py:63-87` | `test_stage_path_service.py`、`test_legacy_folder_can_be_explicitly_adopted` |
| 外部工具写到一半的媒体 | 有 size，但会被 ffprobe 和前后两次 hash 对比拦下 | `:107-114,168` | `test_file_change_during_probe_rejected` 等 |
| **核验之后、发事件之前文件又变了** | 核验和 emit 之间没有锁；keyframe／previs 的清单是核验之后再读一次 `_adopted` 写出的，两次读到的内容可能不一致 | `:645-703` | 无测试 |
| **同一阶段第二次完成被总线吞掉**（推断） | 幂等键只由 kind＋payload 算出，不含时间。同一阶段、同一文案的第二次 `stage.completed`（例如 `desktop.py:1440` 的固定文案“本集成果已校验并确认”，第二集确认时会再发一次），只要还在最近 512 条记录内，就在 pump 时被丢掉，自动链收不到 | `pet_bus.py:86-90,236`；`SEEN_LIMIT=512` | 无测试 |
| 门禁检查自己抛异常 | 一律放行（fail-open）：`assets_locked`、`ledger_ready`、`pet_agent.gate`、`Auto._gate_reason`、`gate_reason` 的 except 分支都返回“无阻塞” | `stage_parallel.py:697,761`；`pet_agent.py:969`；`pet_ui_stages.py:370` | 无测试 |
| 有结构剧本时 storyboard 门禁 | 直接跳过门禁 | `pet_ui_stages.py:363` | — |
| video 阶段 | 依据 studio 当前打开的那一集，不是采用分镜的 scope；没有 studio 时恒为未完成 | `:628-631` | `test_video_uses_injected_desktop_adapter_callback` |

## 建议跟进
1. 三虎路径的 script_structure 也要求 `structure_manifest_problems` 为空，与编排器一致；或者把 S02 设计第 22 条改成与代码一致。两边选哪个由你拍板。
2. 总线幂等键对 `stage.completed` 加上本次的成果指纹或剧集，避免第二集的完成事件被当成重复丢掉。先写复现测试确认。
3. 门禁异常改为阻塞并提示（fail-closed），或者至少记一条日志。这是行为变更，需要拍板。
4. 资产完成判定加上分镜版本比对，做法参照 continuity 的 `stale_reason`。
