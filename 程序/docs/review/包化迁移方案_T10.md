# T10 顶层模块包化迁移方案（先出方案，经用户批准后按搬家轮执行）

## 现状

- `程序/` 顶层 359 个 `.py`（不含测试），全部平铺；`tests/architecture/_layers.py` 登记分层，`PROJECT_MAP.md` 手工导航。
- 前缀族已天然聚类（见下表），但族内仍有跨层混合（如 `asset_*` 横跨 L1–L4）。

## 目标包结构（按层为主、前缀族为辅）

```
程序/
  contract/      # 现 L0：pet_bus, *_contract, service_contract, error_codes, artifact_schema, stage_layout, storyboard_paths, project_context …
  infra/         # 现 L1：file_cache, model_pool, model_secrets, app_logging, storage_maintenance, platform_tools, api_endpoints …
  domain/        # 现 L2：writing_*, asset_*, keyframe_*, storyboard_*, delivery_* …（后续按族再分子包）
  orchestrator/  # 现 L3：stage_*, skill_orchestrator, agent_dispatch, writing_api …
  ui/            # 现 L4：desktop_*, pet_ui_*, ui_*, app.py, skill_panel_* …
```

## 迁移规则（每轮一个前缀族，测试搬家轮 §3.6 口径）

1. 只 `git mv` + 改 import；测试逻辑、断言、fixture 原样。
2. 旧路径留薄转发（`from pkg.mod import *` 并登记 `test_legacy_facade_manifest`），下一阶段清除。
3. 同轮更新：`_layers.py`、`PROJECT_MAP.md`、`distribution_manifest.md`、动态导入字符串（`ui_plugin_registry`、`stage_handler_registry`）、`sys.path` 假设、`.gitignore`/打包清单。
4. 每轮验收：`test_layers`、`test_no_circular_import`、`test_static_hygiene`、`test_startup_budget` 绿 + `distribution_build.py --verify`。

## 建议顺序（风险从低到高）

| 批次 | 前缀族 | 规模 | 风险 |
| --- | --- | --- | --- |
| 1 | `account_*`、`project_*` | ~15 文件 | 低，偏 L1/L2 |
| 2 | `error_codes` 等已建小模块并入 `contract/` | 5–10 | 低 |
| 3 | `writing_*` | ~15 | 中，L2/L3 混合 |
| 4 | `asset_*`/`asset_batch_*`/`asset_reference_*` | ~25 | 中，族内跨层需先标层 |
| 5 | `keyframe_*`、`storyboard_*` | ~20 | 中高 |
| 6 | `desktop_*`/`pet_ui_*`/`ui_*` | ~50 | 高，UI 动态装配多 |
| 7 | `app.py`/`pet_*.py` 拆分 | 10+ | 最后，单独立项 |

## 前置工作（下一轮先做）

2. 用户确认包名（`contract/infra/domain/orchestrator/ui` 还是中文无关的短名）与是否允许 `__init__.py` 再导出。
