# 09 资产数据生命周期

本册覆盖资产数据从文字到图片、首帧、视频四种形态的存放、字段、命名、版本记录、状态流转、过期判定与展示。现状以 `tasks_round/专题二资产数据盘点报告.md`（R3987，下称「盘点报告」）为准，行内 `F` 编号即该报告的事实编号；目标以《工程文档细化任务书》DOC-D9 为准。目录结构、原子发布与缓存一致性见 [04 册 §2、§3](04_数据与本地存储.md)，存储盘点与保留策略见 [04 册 §6](04_数据与本地存储.md) 和 [存储盘点与保留](../process/存储盘点与保留.md)，本册不重复。

记号：✅ 已实现；🟡 部分实现；⬜ 未实现（目标）；❓ 待裁决或未核实。每行最后一列为状态。

## 4. 字段表

字段出自 `asset_contract.schema()`/`defaults()`（F02–F05）。「改了影响谁」一列：首帧来源证据为每个引用资产记 {id, 元数据 digest, 图片 sha256}，元数据 digest 覆盖除 `_registry_base`、`image` 外的全部清单字段（`domain/keyframe_evidence.py:109-112`），因此任何字段改动——包括改名——现在都会使引用它的首帧被判「待重新导入复核」（F19）；哪些字段该算、哪些该豁免，见 §8 与 §13。

| 字段 | 适用 | 谁写、什么时候写 | 界面能不能改 | 改了影响谁 | 状态 |
|---|---|---|---|---|---|
| `name` | 三类 | `rename_asset`（改名对话框），旧名进 `aliases` | 能 | 当前进 digest → 首帧复核 | ✅ `asset_batch_service.rename_asset` |
| `description` | 三类 | `update_fields`（详情页编辑） | 能 | 当前进 digest → 首帧复核 | ✅ `asset_plan.update_fields` |
| `physical_features` | 角色 | 只经 SKILL/Agent 写；界面只读展示 | 不能 | 当前进 digest → 首帧复核 | ✅ `asset_detail` 原始数据块 |
| `image_prompt`/`negative_prompt`/`prompt_source*` | 三类 | `update_fields` 与 `sync_reference_prompts`（AUTO_FIELDS 自动写） | 能 | 当前进 digest → 首帧复核 | ✅ `asset_reference_prompts.sync_reference_prompts` |
| `reference_images`/`reference_role`/`reference_exclude` | 三类 | `attach`/`unbind` 按 (digest, role) 挂接；职责由 `_role_block` 编辑 | 能 | 当前进 digest → 首帧复核 | ✅ `asset_reference_images.attach` |
| `character_anchor`/`base_anchor` | 角色 | `apply_gate_choice`（门禁选择）与 `_anchor_block` 编辑 | 能 | 当前进 digest → 首帧复核 | ✅ `asset_plan.apply_gate_choice` |
| `canonical_board`/`canon_board_views` | 角色 | `_board_block` 正典板绑定/清除/重新生成 | 能 | 当前进 digest → 首帧复核 | ✅ `ui/asset_detail.py` |
| `state_variants` | 角色 | `_variants_block` 增删改＋缩略图；编号形如 `CST-01` | 能 | 当前进 digest → 首帧复核 | ✅ `ui/asset_detail.py` |

| `scale`/`material`/`holder`/`reference_image` | 道具 | `update_fields`；`holder` 为 `CHAR_###` 或空 | 能 | 当前进 digest → 首帧复核 | ✅ `asset_plan.update_fields` |

## 8. 过期判定

目标（DOC-D9-3）：角色改了之后，已做出的首帧和视频只标过期、列出受影响的镜头、由用户逐个或批量决定重做；不自动重做。

| 条目 | 现在怎样 | 目标怎样 | 状态 |
|---|---|---|---|
| 首帧过期判据 | `frame_problem` 重算 `source_evidence`＝分镜 sha＋提示词 sha＋每个引用资产 {id, 元数据 digest, 图片 sha256}，不一致返回「首帧来源分镜、提示词或参考资产已变化，待重新导入复核」；门禁 SG-04 汇总、详情页顶部提示；不自动重做（F19–F21） | 首帧按此口径标过期、列镜头、由用户决定重做 | ✅ `keyframe_evidence.frame_problem` |
| 视频过期判据 | 无持久标记：只在「采用分镜」时由 `adoption_impact` 一次性预告「N 段视频将失效」（写状态栏，不落盘）；版本记录里的 `signature` 是提交时指纹，之后无人重算；`asset_impact` 能列出受影响视频但不写任何标记（F24） | 视频标过期、列出受影响镜头、由用户决定重做；不自动重做 | ⬜ 来源：用户决定 2026-11-21 |
| 视频重做入口 | 用户人工「需修改」：`review('revise')` 写回版本记录后放行重提（F25） | 沿用现状，并入过期后的重做流程 | ✅ `engine.review` |
| 哪些改动算「过期」 | 现在元数据 digest 覆盖除 `_registry_base`、`image` 外的全部清单字段，任何字段改动都触发首帧复核（见 §4） | 只改了描述文字、名字、别名算不算 | ❓ 见 §13（建议：只有会影响画面的改动才算过期——外观要求、提示词、参考图、状态变体、图片本身；改名字和别名不算——建议，待确认） |
