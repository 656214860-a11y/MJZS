# 04 数据与本地存储

本册覆盖存储架构、目录结构、台账清单、规模上限、计量台账与保留策略。

## 1. 存储架构：JSON 真源 + SQLite 派生层

**决策：不把主数据搬进 SQLite。** 维持现有双层结构，并把判据写成契约。

### 1.1 分层判据（唯一一条）

> **丢了能不能重建？能 → SQLite；不能 → JSON。**

| 层 | 存什么 | 介质 | 位置 | 可重建 |
|---|---|---|---|---|
| **真源** | 剧本、分镜、资产清单、采用记录、配置、台账 | **JSON／Markdown** | 用户项目目录、`程序/配置` | **否** |
| **派生** | 产物索引、作业状态、指标汇总 | **SQLite（WAL）** | `程序/data/` | **是** |

### 1.2 为什么不做主存储迁移

| 用户提出的理由 | 实测结论 |
|---|---|
| 「查找更快」 | **不成立**。3000 镜 JSON 2.52 MB、解析 9.6 ms、单镜查找 0.066 ms。真瓶颈是**目录扫描 583 ms**，与存储格式无关 |
| 「管理更方便」 | 引入 SQLite 主存储需重写整套写入路径：原子发布器、`file_cache` 失效事件、回收站语义、`artifact_schema` 迁移、13 阶段读写口。`AGENTS.md` 的 C1／C2／C5 三条硬约束**全部绑在文件模型上** |
| 「数据更稳定」 | **方向相反**。SQLite 单文件在高并发写、断电、跨进程下有 WAL 不一致、database is locked、journal 残留风险；而 JSON + 原子 rename 在崩溃下是强语义（要么旧版完整，要么新版完整） |

### 1.3 现有 SQLite 使用（三处，均为派生）

| 模块 | 路径 | 用途 | 重建 |
|---|---|---|---|
| `infra/artifact_index.py` | `data/artifact_index/<sha256(项目根)>.sqlite` | 产物索引：路径、版本、四态（候选/采用/归档/回收）、重复检测 | `rebuild()` |
| `infra/job_store.py` | `data/job_store/<sha256(根)>.sqlite` | 作业持久化：幂等键、六态机、退避、checkpoint | 崩溃后 reconcile |
| `infra/metrics.py` | `data/metrics/summary.sqlite` | 结构化指标日汇总（raw JSONL 14 天 + sqlite 180 天） | 可从 JSONL 重算 |

**共同约束**：全部 WAL 模式；**永不写入用户项目目录**；损坏可重建。

### 1.4 何时才该引入客户端主存储

满足**任一**条件时重新评估（写死判据，避免反复讨论）：

1. 单项目分镜数 > 5000 且实测写入路径 p95 > 500 ms（当前瓶颈在扫描，不在 JSON）。
2. 跨项目查询成为刚需（如「所有项目里找某个角色」）且 `artifact_index` 无法覆盖。
3. 需要多方并发写同一项目（当前是单机单用户，此项不成立）。

## 2. 目录结构

### 2.1 程序级（`程序/`）

| 路径 | 内容 | 进 Git |
|---|---|---|
| `配置/` | 全局配置：`客户端档案.json`、`SKILL/预设.json`、`宠物/配置.json` | 否 |
| `data/` | 运行数据：索引、作业库、指标、skills 用户层、voice_models | 否 |
| `private/` | 密钥：`密钥/*.dpapi`、`env_imported.json`、`.mac_key.dpapi` | **否，禁入 Git** |
| `logs/` | 运行日志（保留/轮转由 `log_maintenance` 管） | 否 |
| `assets/`、`skills/`、`workflows/` | 内置资源、SKILL、流程 | 是 |
| `episode/` | 演示目录 | 是 |

程序级状态文件：`config.json`、`projects.json`、`desktop_settings.json`、`external_tools.lock.json`。
**升级安装只覆盖程序文件，这些一律保留。**

### 2.2 项目级（用户选定目录）

```
<项目>/
├─ skill_config.json              # 阶段模型、SKILL 勾选、制作锁、reasoning
├─ cost_profile.json              # 成本配置（缺失则只显示已落盘用量）
├─ storage_policy.json            # retention_days
├─ 产物来源关系.json              # artifact_lineage
├─ 01剧本准备/ … 13质检交付/      # 13 个阶段目录（stage_layout）
│   └─ 创意对话/                  # 对话.json、已删除消息.json
├─ 回收站/                        # 用户可见删除的落点
├─ 确认快照/                      # 阶段确认快照（<阶段>_<时间戳>_<sha8>.md）
└─ outputs/                       # desktop-task-queue.json、desktop-task-history.json
```

**项目 = 一部剧**；一集 = 一个 episode 子目录；资产**项目级共享**（角色正典跨集复用）。

### 2.3 项目级关键 JSON

| 文件 | 写入方 | 内容 |

| `assets.json` | `asset_plan` | 资产清单（`CHAR_###`／`LOC_###`／`PROP_###`） |
| `episode.json` | 分镜定稿 | 镜头数组 |
| `continuity_ledger.json` | 连贯性清单 | 冻结锚点 |
| `frames.json` | 首帧管理 | 每镜候选与采用 |
| `videos.json`／`video_manifest.json` | 视频生成 | 镜头版本台账 |
| `voice.json`／`subtitles.json`／`audio_manifest.json` | 配音字幕 | 音轨与字幕台账 |
| `edit_manifest.json`／`edit_bundle.json` | 后期剪辑 | 成片与分轨清单 |
| `成果确认/<hash>.json` | `stage_completion_service` | 完成核验凭据 |

字段级权威：`contract/artifact_schema.REGISTRY`；投影见 [`data_model.md`](../../data_model.md)。

### 2.4 项目登记与失效找回

`projects.json` 登记项目根目录。**能打开的登记**＝目录存在且含 `config.json`；
以下两种都按「失效登记」处理，走同一条找回路径：

| 形态 | 判据 | 打开时 |
|---|---|---|
| 目录不在 | `path` 不是目录 | 报「目录不存在或已被移动」＋可照做的话 |
| 空壳 | 目录存在但缺 `config.json`（常见于项目文件夹被改名／移走后，后台写入在原位置留下的壳） | 报「没有项目配置文件…留下的空壳」＋可照做的话 |

- **找回**（`domain/projects.reconcile_missing`）：只扫项目库一级目录（`iterdir`，不递归）；候选＝有 `config.json` 或至少一个阶段目录的目录。命中一条自动认领并同步登记路径、激活项与 `config.json` 里的活路径引用；多条交给界面选；指纹对不上时把未登记的项目库目录摆出来手动指定。手动指定逐项拒绝：库外、回收站（`工作流任务`）、已登记、不可识别、登记自身。
- **候选排除**：登记自身路径、被其他能打开的登记占着的目录、回收站目录一律不进候选，也不会被直接认领（`claim_reconciled` 拒认已登记目录）。
- **清除登记**：失效登记可「只清除登记，不动磁盘」——只删 `projects.json` 条目，壳目录与其文件原样保留；能打开的项目拒绝清除（须走「删除选中项目」进回收站）。
- **重建索引**（`rebuild_registry`）：库内登记只留可识别为项目的目录（纯空壳进 `dropped`，带阶段目录的残缺项目保留）；库外登记只留还能打开的；未登记的可识别目录补登。
- 失效登记的目录**绝不写入、不移动、不删除**；认领成功只改登记与新目录配置引用，原壳原样留在磁盘上。

### 2.5 用户级备份与导入

- **入口**：项目首页项目列表右键菜单「导出项目…」「导入备份包…」（`ui/desktop_project_pages`），业务实现 `domain/project_archive`（L2 纯业务，不 import tkinter）。导出沿用删除项目的在制任务判定，成功状态栏在脱敏命中非空时附「其中 N 个配置文件的密钥已移除」（N＝`manifest.redacted` 去重文件数）；导入不依赖选中项，选包后先 `inspect_archive` 校验并弹出确认「将把备份包还原为新项目 <名>，不会改动任何现有项目」，确认后才后台导入。
- **包格式**：zip 根 `manifest.json`（`format='manju-project-archive/1'`、`app_version`、`name`、`original_root`、`exported_at`、`file_count`、`total_bytes`、`files[]={path,size,sha256,mtime}`、`dirs`、`redacted`、`notes`），项目文件统一在 `project/` 前缀下。命名 `<slug>_<YYYYMMDD-HHMMSS>.zip`，重名补 `_2` 等序号。
- **导出**（`export_project`）：只导已登记且能打开的项目；先写 `.part` 读回复核 sha256 再原子改名 `.zip`；单文件 >4GB 或项目总量超过目标盘可用空间一半时拒绝；`operation.lock`／`*.lock`／`__pycache__`／`*.pyc`／`*.tmp`／`*.part`／缩略图缓存目录（`.thumbs`／`thumbs`／`缩略图`）与符号链接、junction 不打入包，全部记入 `manifest.notes`。
- **密钥防线**：`config.json`、`projects.json`、`cloud_video/*/config.json` 中命中 `(?i)(api[_-]?key|secret|token|password)` 的非空字符串打包为脱敏副本 `<已移除>`，命中字段记入 `manifest.redacted`；解析不了的文件按原样打包并记 notes。
- **导入**（`Projects.import_archive`）：`inspect_archive` 校验 manifest 格式族与主版本号（≤ 当前格式版本，过新即拒）→目标盘余量 ≥ 项目总量 1.2 倍→`base/._import_<uuid8>` 临时解包并逐文件验 sha256（失败删现场；解包目标目录已存在即拒绝，杜绝误清既有目录）→可识别项目校验→`<slug>_<YYYYMMDD>` 防撞名→`os.replace` 落位→`_live_path_writes` 同款改写 `config.json`/`projects.json` 活路径→`organize` 补骨架→写登记。穿越路径（绝对路径、`..`、盘符、反斜杠）与链接条目一律拒绝；登记写失败时项目移回临时目录保留并提示可恢复。

## 3. 写入与一致性

### 3.1 原子发布（C2）

```
写：临时文件 → fsync → rename（原子）
读：file_cache.read_json()（带缓存）
缓存失效：只认 published / recycled / externally_overwritten 三种事件
```

**禁止**：直接 `open(path,'w')` 写正式 JSON；绕过 `agent.core.save()`。

### 3.2 事件驱动的缓存一致性

| 事件 | 触发 |
|---|---|
| `published` | 原子发布成功 |
| `recycled` | 进入回收站 |
| `externally_overwritten` | 检测到外部改写 |

页面**不靠刷新补一致性**；陈旧缓存是 C2 违规。

### 3.3 目录扫描禁令（性能约束）

**写入路径不得盲扫目录，一律先查 `artifact_index`。**

实测依据：21000 文件时 `rglob` 583 ms、`os.walk` 149 ms；而 `publication.transaction` 每次写都扫描，实测约 100 ms／次（支配了持久队列 132 ms／入队的成本）。

**要求**：
1. 写入路径先查 `artifact_index`；命中即用。
2. 索引缺失时按**项目级锁**做一次 `rebuild`，不逐个文件扫描。
3. `rebuild` 在后台执行器跑，不阻塞 UI。
4. **已知瓶颈**：`publication.transaction` 的扫描范围未优化，属待办性能项，不在本轮修复。

### 3.4 连贯性台账结构

`continuity_ledger.json` 冻结三类锚点：

| 锚点 | 内容 | 冻结粒度 |
|---|---|---|
| 角色锚点 | 外观、发型、服装、持物 | 按批次 |
| 场景锚点 | 光源方向、空间布局 | 按批次 |
| 道具锚点 | 形状、尺度、位置 | 按批次 |

**批内一致性**：同批 `scene_id` + `character_ids` + `costume_id` 必须一致，不一致则重切批次。

## 4. 数据边界

| 数据 | 位置 | 上传 |
|---|---|---|
| 项目、剧本、分镜、素材 | 用户目录 | **否**（除作为模型输入） |
| API Key | `private/密钥/*.dpapi`（DPAPI 加密） | **否** |
| 计量用量（未来官方中转站） | 服务端（仅设计） | **未接入**；如实现仅允许计量字段。客户端和服务端当前均无 `/v1/metering`，不得显示为已上报 |
| 会员与授权状态 | 服务端 | **是**，不含项目内容 |

## 5. 计量台账与预算

### 5.1 两本账

| 账 | 实现 | 内容 |
|---|---|---|
| Token 账 | `pet_llm.Ledger` | `{at, model, tier, prompt_tokens, completion_tokens, cached_tokens}` |
| 金额账 | `pet_llm.RequestLedger` | 逐笔：`id`（`money_request_id` 关联键）、金额、币种 |

**不变量**（R1615）：
1. `price()` 总额 = 分项和，分项四舍五入后**不得**再对总和二次舍入。
2. `_model_price()` 缺模型／版本／币种返回 `None`，**绝不补零**。

### 5.2 预算机制

| 层 | 模块 | 职责 |
|---|---|---|
| L1 机制 | `infra/budget.py` | `check_amount()` 超限判定、`headroom()` 剩余量、`reserve/settle/cancel`、`summary()` 聚合 |
| L3 策略 | `orchestrator/pet_budget.py` | 五类硬上限（image/firstframe/video/voice/tokens）、默认额度、90% 预警、别名、会话计数 |
| L3 策略 | `skill_budget.py` | SKILL 三本账 |

**规则**：未知用量不显示为 0（标「未知」）；超额继续需明确操作；失败重试费用计入。

### 5.3 成本可视化

批量启动前**必须**展示：最大任务数、单任务计费单位、重试上限、预估区间、未知项清单。
结束后展示：实报用量、失败重试次数、实际时长。

## 6. 存储盘点与保留

| 机制 | 模块 | 行为 |
|---|---|---|
| 存储盘点 | 项目首页只读视图 | 显示各类占用与可回收候选 |
| 保留期 | `storage_policy.json` 的 `retention_days` | 按策略清理未采用版本 |
| 回收站恢复 | `recycle_recovery_service` | 取最新回收副本恢复 |
| 日志保留 | `infra/log_maintenance.py` | 保留/轮转/容量帽 |
| 工作区卫生 | `infra/workspace_maintenance.py` | `__pycache__`、超期 `.selftmp` |

**硬约束**：不自动删除用户原件；保留采用素材及追溯凭据（C5）。

## 7. 规模上限与实测

| 形态 | 集数 | 时长 | 总镜数 | 媒体文件数 |
|---|---|---|---|---|
| 红果短剧 | 约 80 | 1–2 分钟／集 | 约 3000 | 约 21000 |
| 电影 | 1 | 90–120 分钟 | 约 1200–1800 | 约 12000 |

### 7.1 实测基线

| 项 | 实测 | 结论 |
|---|---|---|
| 3000 镜 `episode.json` | 2.52 MB | 可接受 |
| JSON 序列化／解析 | 8.6 ms／9.6 ms | 不是瓶颈 |
| 单镜查找（线性） | 0.066 ms | 不是瓶颈 |
| 21000 文件 `rglob` | 583 ms | **瓶颈** |
| 21000 文件 `os.walk` | 149 ms | 优化路径 |
| `publication.transaction` | 约 100 ms／次 | **瓶颈**，待性能轮 |

### 7.2 处置

1. 写入路径查索引（§3.3）。
2. 索引 `rebuild` 后台化。
3. 超出规模时给明确提示，**不允许静默降级或崩溃**。

## 8. 数据迁移与版本兼容

| 场景 | 规则 |
|---|---|
| 产物格式变更 | 写 `schema_version`；`migrate()` 只加键不删数据 |
| 读取旧版 | 容忍缺版本 |
| 目录改名 | 旧编号目录**只读兼容**；显式修改经 L3 复制到新编号 |
| 配置升级 | 保留用户值，新增键取默认 |
| 项目配置版本 | `config.json`／`skill_config.json` 登记在 `artifact_schema`（`project_config`／`skill_config`，第 1 版，无必备字段）；属主写回经 `stamp()` 补 `schema_version`，缺版本容忍，高于登记版本拒读拒写 |
| 项目配置读坏 | `config.json` 读坏回退同目录 `config.json.bak`（每次读通刷新的「最近一次可读快照」，命名同 `migrate_file`）；回退成功记日志＋诊断台账提示；无可用快照时报可操作错误，坏文件原样保留、不静默新建空配置 |

## 9. 未决事项

1. `publication.transaction` 扫描范围优化——待性能轮。
2. 客户端主存储迁移——按 §1.4 判据，当前不迁移。
3. 单项目上限的硬拦截点（超过多少镜提示）——待首批实测后定。
