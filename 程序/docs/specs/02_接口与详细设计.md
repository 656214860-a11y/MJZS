# 02 接口与详细设计

本册覆盖内部模块契约、外部 HTTP API、错误码、SKILL 契约与阶段产物契约。**接口的唯一权威是代码**（`contract/` 包）；本册写「谁调谁、形状是什么、违反会怎样」，代码变更时同步回改本册。

## 1. 内部接口

### 1.1 L2 服务返回契约（`contract/service_contract.py`）

所有 L2 业务服务返回**四字段结果**，不得返回裸值或抛裸异常：

| 字段 | 类型 | 含义 |
|---|---|---|
| `ok` | `bool` | 成功／失败 |
| `reason` | `str` | 失败原因码（成功为空串） |
| `recoverable` | `bool` | 是否可重试 |
| `data` | `Any` | 成功时的载荷 |

**约束**：谓词检验行为而非字符串；`test_service_return_contract` 与棘轮守卫强制。

### 1.2 L2 写服务的发布器注入（C1）

```
L3 编排 → 构造 publisher → 注入 L2 服务 → L2 调用 publisher → L1 原子发布器写盘
```

**硬约束**：L2 **只接收**注入的发布器；**缺发布器时显式拒绝**，绝不降级直写（`说明/已知坑与不可破坏契约.md` C1）。

L3 注入点：
- `stage_execution_service.publish_stage_text()`
- `stage_execution_service.publish_stage_bytes()`
- `stage_execution_service.publish_stage_bundle()`

### 1.3 项目上下文（`project_context.ProjectContext`）

- **唯一构造**：`project_context_factory.project_context()`（L3）
- `stage_execution_service.project_context` 是**静态重导出**，不是第二实现
- 装配**不扫描、不写入**项目
- 请求前有上下文预算预检：完全重复的大段上下文去重（保留首份全文 + 去重摘要）；唯一内容仍超限则**安全拒绝**，不启动模型、不创建任务工件

### 1.4 事件契约（`contract/pet_bus.py`）

| 项 | 规则 |
|---|---|
| 发送 | 只经 `pet_bus.emit_safe()`；仅 `pet_agent._emit()`／`pet_ui._emit()` 可作受控转发 |
| 幂等键 | `identify(kind, payload)` = sha256(kind + 排序后的 payload)[:32]，重复上报只算一次 |
| 背压 | `PENDING_LIMIT=1024`；到水位后只丢 `SHEDDABLE_EVENTS`（`stage.executing`、`notify.aggregate`） |
| 永不让路 | 终态（`stage.completed`／`stage.failed`／`script.completed`／`delivery.ready`）与 `stage.paused` 永不丢弃 |
| 线程模型 | 工作线程只 `publish`；主线程 150ms 心跳 `pump` |
| 审计 | 订阅者异常内存留最近 64 条，落盘上限 128 条 |

### 1.5 阶段启动唯一入口

```
stage_handler_registry.start(desktop, stage, ...)
  ├─ 会员闸门（宿主已挂 account 时生效；未挂不设闸）
  ├─ 上下文预算预检
  └─ 分派到阶段处理函数
```

手动、自动、三虎三条路径**全部**经此入口（规则 17）。会员闸门前置在此，防止未登录／非会员绕过付费阶段（C6）。

### 1.6 路径与删除的唯一入口

| 操作 | 唯一入口 |
|---|---|
| 阶段路径（新写） | `stage_path_service.write_dir()`／`read_dirs()` |
| 路径生成 | `stage_layout`／`storyboard_paths`／`script_contract`／`asset_contract` |
| 用户可见删除 | `storage_maintenance.recycle_paths()` |
| 缓存仅受控清理 | `storage_maintenance` |

**约束**：其他模块**不得字符串拼接路径**（规则 12）；删除不走回收站即 C5 违规。

### 1.7 出站请求唯一入口（规则 42）

```
业务代码 → http_client.request_json(url, timeout=必填, ...)
  └─ 超时必填／错误码归一／有界重试／响应大小上限／日志脱敏
```

`urlopen`／`build_opener` only 许 `http_client` 与登记白名单，由 `test_http_boundary` 守卫（棘轮，白名单只减不增）。

## 2. 外部 HTTP API（客户端 → 服务端）

服务端为独立仓库 `D:\漫剧服务端`（FastAPI + SQLite WAL，独立发版）。**接口权威在服务端代码与 `D:\漫剧服务端\README.md`**，本节只写客户端消费的形状。

### 2.1 传输安全

| 项 | 值 |
|---|---|
| Base URL | `https://8.138.223.126`（当前测试服） |
| 证书 | **内置钉扎证书**（`account_client.PINNED_CERT`），`ssl.create_default_context(cadata=...)` |
| 校验 | **不关闭校验**；钉扎而非放宽 |
| 变更条件 | 生产域名上线时必须换证书并重新钉扎，不得用 `CERT_NONE` 过渡 |

### 2.2 端点清单（客户端消费）

| 方法 | 路径 | 用途 | 鉴权 |
|---|---|---|---|
| `POST` | `/v1/auth/code` | 邮箱验证码发送 | 无 |
| `POST` | `/v1/auth/login` | 验证码登录，返回会话令牌 | 无 |
| `POST` | `/v1/lease/renew` | 续签授权租约（须带 `device_id`） | 会话令牌 |
| `GET` | `/v1/me` | 账号信息 | 租约作 Bearer |
| `POST` | `/v1/redeem` | 兑换码 | 会话令牌 |
| `GET` | `/v1/meta` | 元信息（只给 kid） | 无 |
| `POST` | `/v1/metering` | 计量上报（默认中转站用量） | 会话令牌 |

**详细字段、错误码、状态机见 [`说明/账户会员云端设计.md`](../说明/账户会员云端设计.md)**（该文件保留，不并入本册——它是账户域的设计权威）。

### 2.3 计量上报的隐私边界

上报**只含计量字段**：项目标识（哈希）、阶段、模型、供应商请求 ID、计费单位、状态、时间戳。

**不得上报**：提示词正文、剧本正文、素材内容、文件路径原文、用户 API Key。

自建 API 的调用**不上报**（只入本地台账）。

## 3. 阶段产物契约

### 3.1 十三阶段输入输出

阶段顺序唯一权威 `pet_bus.STAGES`；字段级契约在 `docs/stages/`。本节给**跨阶段的形状约束**：

| 阶段 | 主产物 | 版本化 | 采用机制 |
|---|---|---|---|
| S01 剧本准备 | 自然剧本 `.md` | `artifact_schema` | `natural_script_selection.json`（路径 + sha256） |
| S02 剧本结构 | 结构化剧本 `.md` | 同上 | 阶段确认台账 |
| S03 初步分镜 | 镜头初稿 JSON | 同上 | `storyboard_adoption_contract.adopted` |
| S04 分镜预演 | 预演视频 + manifest | 同上 | 人工确认（SG-B） |
| S05 资产管理 | `assets.json` + 正典板 + 锚点 | 同上 | 资产采用 |
| S06 连贯性清单 | `continuity_ledger.json` / `.md` | 同上 | 台账冻结 |
| S07 分镜定稿 | `episode.json` + 提示词批次 | 同上 | 定稿采用 |
| S08 首帧 | `frames.json` + 图像 | 同上 | 逐镜筛选采用 |
| S09 白模预演 | 白模视频 + `previs.json` | 同上 | 条件门禁 SG-05 |
| S10 视频生成 | `videos.json` / `video_manifest.json` | 同上 | 验收采用 |
| S11 配音与字幕 | `voice.json`／`subtitles.json`／SRT | 同上 | 听审采用 |
| S12 后期剪辑 | `edit_manifest.json`／成片 | 同上 | 完整播放确认 |
| S13 质检与交付 | 交付包 + 报告 | 同上 | 内容审核 + 商用确认 |

### 3.2 采用关系的通用规则

**任何采用都必须绑定「相对路径 + 内容摘要」**。改稿使下游确认失效，不允许静默把旧确认沿用到新版本。

| 规则 | 说明 |
|---|---|
| 新版本生效 | 必须更新来源关系 |
| 旧版保留 | 可回退，不删 |
| 摘要不符 | 视为不同版本，需重新确认 |
| 部分采用 | 记录 `partial_adoption` 标记，确认基线收窄 |

### 3.3 版本化产物（`contract/artifact_schema.py`）

- 写入侧：`stamp(kind, payload)` 落 `schema_version`
- 读取侧：`validate(kind, payload)` 返回问题清单（不抛异常）
- 历史产物：`migrate(kind, payload)` 抬版本，**只加键、不删数据**
- 读取侧**容忍缺版本**（向后兼容）

### 3.4 分镜预演契约（S04，SG-B）

放行 S05 的条件：Animatic **可播放且非空**；总时长 59–61 秒；每镜与对白时间对照可查；用户已确认节奏、时长、对白同步。

### 3.5 视频生成契约（S10）

每镜提交前须有：非空 `video_prompt`、`duration`（2–15 秒）、首帧文件。缺首帧则提示回 S08，不提交。

### 3.6 交付契约（S13）

| 项 | 要求 |
|---|---|
| 成片 | MP4（H.264/AAC），竖屏 1080×1920，25fps |
| 字幕 | SRT，覆盖 100% 非空对白 |
| 素材清单 | 分轨清单，每个文件可校验 |
| 可编辑格式 | EDL／FCPXML，须在声明支持的软件版本实际导入通过 |
| 技术探测 | FFprobe 必需；缺失直接报错，不退化为按扩展名放行 |

## 4. 恢复与故障处置接口

### 4.1 未知远端状态

**规则：先查后提交，不盲目重发。**

| 场景 | 处置 |
|---|---|
| 提交超时但可能有结果 | 查请求台账，按幂等键核对 |
| 429 限流 | 读 `Retry-After`，**须钳制总等待**（`backoff_max` 不作为总等待封顶证据） |
| 5xx | 有界重试，超限转人工 |
| 断网 | 保留本地产物，联网后按台账对账 |

### 4.2 已采用素材不重发

批量任务重跑时，**已采用的成功素材不重复提交**。判据是产物存在 + 采用记录有效，不是任务状态。

### 4.3 取消语义

取消**不保证**远端退款或撤销。本地取消只表示不再接受结果；未知远端结果必须查单／对账后决定是否重试（不能以本地取消推断退款）。

## 5. 错误码与分类

分层错误类型（`contract/error_codes.py`、`contract/infra_errors.py`）：

| 类 | 含义 | UI 表现 |
|---|---|---|
| `UserError` | 用户可修正（缺必填、路径非法） | 明确提示 + 修正入口 |
| `SystemError` | 系统问题（磁盘满、依赖缺失） | 可读状态 + 日志位置 |
| `Cancelled` | 用户取消 | 静默（不报错） |

**severity 分级**：A 级（发布/写入异常、假完成）须对账 `stage_completion_service`；C 级仅限 `TclError` 且控件已销毁的受控竞争。

**AI 适配器失败分类**：判定表见 [`说明/生成服务失败处理契约.md`](../说明/生成服务失败处理契约.md)，由 `test_adapter_failure_conformance` 钉在真实适配器上。

## 6. SKILL 契约

SKILL 只提供**说明**，不执行代码。契约（17 字段 frontmatter）在 `skill_registry.py` 与 `skills/*/*.skill.md`，**权威是代码与文件本身**。

| 项 | 规则 |
|---|---|
| 注册层级 | 项目 > 用户（`data/skills/`）> 内置（`skills/`） |
| 制作锁 | `skill_config.json` 顶层 `production_locks` |
| 体检 | `workflow_settings.skill_health_report` |
| 不做什么 | 不引入 code plugin 二分、不做在线市场、不做云同步（见 PRD §1.5） |

## 7. 接口变更检查单

改接口时逐项核对：

1. 是否新建了平行入口？（规则 28：先搜已有入口）
2. L2 是否绕过注入的发布器直接写？（C1）
3. 是否新增了直连 `urlopen`？（规则 42）
4. 是否新增了字符串拼路径？（规则 12）
5. 是否新增了直调 `Bus.emit()`？（规则 22）
6. 分层是否反向 import？（规则 11）
7. 测试锚点（`REQ-`／`DES-`）是否仍成立？
8. 本册与 `docs/stages/` 是否同步？
