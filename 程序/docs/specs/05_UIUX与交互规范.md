# 05 UI/UX 与交互规范

本册覆盖窗口尺寸、高 DPI、多显示器、13 页布局、3000 镜表格方案、可访问性与微交互。

**视觉取值的唯一权威是 [`design_tokens.md`](../../design_tokens.md)，组件契约的唯一权威是 [`ui_components.md`](../../ui_components.md)。** 本册写**布局与适配的硬约束**，不复述颜色与字号。

### 1.1 高 DPI 的具体后果

无 `SetProcessDpiAwareness` 时，Windows 在缩放 125%／150%／200% 下会对整个窗口做**位图拉伸**：

- 文字与图标发虚（不是真缩放）
- `GetSystemMetrics` 取到的边框度量（`SM_CXSIZEFRAME`／`SM_CXPADDEDBORDER`）与视觉不符，`ui/desktop_layout_resize.py:55–104` 的自定义边框会算错
- 笔记本出厂常见 125%／150%，是「一打开就觉得糊」的第一印象问题

## 2. 窗口尺寸规范

| 项 | 值 | 依据 |
|---|---|---|
| 主窗口默认 | **1280×900** | 保持现状；侧栏 96px 图标轨在 800 高下放不下（R2946 实测） |
| 主窗口最小 | **1280×720** | 13 阶段导航（96px）+ 内容区最小可用宽度；低于此值禁用而非硬挤 |
| 屏幕可用区更小时 | 按 `ui_theme.main_window_size` 边距收缩，**不改变最小值** | 保持既有行为 |
| 阶段配置窗 | 默认自适应，最小 560×430 | 现有 |
| 弹窗／浮层 | 锚定触发控件，钳位到目标显示器 | 现有 `monitor_bounds` |

**待实现**：把 `DESKTOP_LAYOUT['min_width']` 从 800 改为 1280、`min_height` 从 600 改为 720。**注意**：这会让 800×600 屏无法使用，需确认目标用户屏幕分布（PRD §5.4 已声明最小 1366×768）。

**建议**：`min_width=1280` 与 PRD「最小 1366×768」一致（1366 > 1280 可满足），`min_height=720` 同理（768 > 720）。此为**修正项**，非现状。

## 3. 高 DPI 适配方案

### 3.1 实现方式

| 步骤 | 做法 |
|---|---|
| 1. 声明感知 | 进程启动最早期调 `SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)`（Win10 1703+）；回退 `SetProcessDpiAwareness(PROCESS_PER_MONITOR_DPI_AWARE)` |
| 2. 或改 manifest | 在可执行文件的 manifest 加 `<dpiAware>`／`<dpiAwareness>PerMonitorV2</dpiAwareness>` |
| 3. 布局缩放 | 全部尺寸取自 `ui_tokens`，按 `winfo_fpixels('1i')/96` 换算；**禁止魔法数字**（规则 34） |
| 4. 图标 | 用矢量或按 DPI 提供多倍图；PNG 图标按 `nav_icon` 的尺寸 token 加载 |
| 5. 跨屏拖动 | 响应 `WM_DPICHANGED`，重新计算布局与字体 |

**约束**：DPI 变化时**不重建整个窗口**，只重算尺寸与字体；重建会丢失用户输入。

### 3.2 验收标准

| 缩放 | 要求 |
|---|---|
| 100% | 布局与现有一致，无回归 |
| 125% | 文字清晰不糊；控件不重叠；边框宽度视觉一致 |
| 150% | 同上 |
| 200% | 同上；1280×720 逻辑像素在 200% 下需 2560×1440 物理像素，屏幕不足时按可用区收缩 |

**未实测前标注为目标值**，不宣称达成。

## 4. 3000 镜表格方案

### 4.1 实测约束（R3415）

| 项 | 实测 | 含义 |
|---|---|---|
| 合成 1000 控件 | 明显变慢 | **控件数量是瓶颈** |
| 滚动中位数 | 150 ms | 灾难线 |
| 内存增量 | 30 MiB | 100 次切页后不应持续爬升 |
| Treeview 插 3000 行 | 17.8 ms | **行本身不是瓶颈** |
| 建议 | 可见控件 ≤200 | 硬预算 |

**关键结论**：`ttk.Treeview` 的行**不是控件**，插入很快；真正的成本在**行内放缩略图或自定义渲染器**（`asset_thumbs:532/620/634` 是实测同步热点）。

### 4.2 方案：分页 + 筛选，表格不放缩略图

| 机制 | 规格 |
|---|---|
| 分页 | **每页 ≤100 行**；底部翻页控件（首页/上页/页码/下页/末页） |
| 筛选 | 按场次、角色、状态、时长区间筛选，缩小结果集 |
| 排序 | 单列排序，排序在数据层做，不在 UI 层 |
| 缩略图 | **表格内不放**；改为「缩略图」列显示文字标识 + 点击打开查看器 |
| 选中 | 跨页保持选中状态（用 shot_id 集合，不依赖行索引） |
| 空态 | 明确提示「本页无镜头」与「筛选无结果」区分 |

**为什么不做虚拟滚动**：`ttk.Treeview` 原生不支持只渲染可见行；自建需接管滚动事件与几何计算，实现成本约 5–10 天且易碎。分页 + 筛选覆盖 90% 痛点。

### 4.3 交互规范

| 操作 | 行为 |
|---|---|
| 双击行 | 打开该镜详情（不切页） |
| 单行编辑 | 就地编辑单元格；失焦提交；Esc 取消 |
| 批量选择 | Ctrl/Shift 多选；跨页保留 |
| 全选 | Ctrl+A 只选当前页，提示「已选本页 N 镜」 |
| 跳转 | 输入镜号直接跳到对应页并高亮 |

## 5. 13 页布局

统一骨架（每页必须包含）：

```
┌─ 侧栏 96px ─┬───────── 内容区 ─────────┐
│ 01 剧本准备 │ [页头：阶段名 + 状态 + 费用]  │
│ 02 剧本结构 │ [输入与产物清单]              │
│ …           │ [主操作区：生成/暂停/重试/采用] │
│ 13 质检交付 │ [表格或预览区]                │
│             │ [失败原因 + 下一步]           │
└─────────────┴──────────────────────────────┘
[统一状态栏]
```

| 区域 | 必备元素 |
|---|---|
| 页头 | 阶段序号与名称、当前状态、适用时的费用与用量 |
| 输入区 | 本阶段依赖的输入清单 + 就绪状态 |
| 产物区 | 本阶段产物清单 + 采用状态 |
| 操作区 | 生成／暂停／重试／采用／导出（按阶段可用性） |
| 反馈区 | 失败原因、下一步、日志入口 |

新增页面须登记到 `desktop_page_registry`。

## 6. 微交互与状态反馈

| 场景 | 规范 |
|---|---|
| 长任务 | `ui_task_progress` 进度卡；可取消；可转后台 |
| 忙碌态 | 加载转圈（`ui_motion`），不用纯文字「请稍候」 |
| 空态 | 明确说明「为什么空」+「怎么填」 |
| 错误 | 明确原因 + 下一步 + 日志位置；不吞异常 |
| 悬停 | `ui_hover_fade` 渐变，时长取 token |
| 滚动 | `ui_scroll` 缓动 |
| 销毁保护 | 迟到回调前检查控件 `winfo_exists()`，否则 `TclError` |

**取消与关窗反馈 p95 ≤100 ms**（目标值）。

## 9. 设计系统约束（不可破坏）

1. **所有视觉取值取自 `design_tokens`**：`padx`/`pady`、颜色、字号、圆角一律不写魔法数字与内联 hex（规则 34）。
2. **图标规则**：主导航图标固定 24×24 画布居中；阶段文件复合图标自动裁边；输入框图标行保持 MDL2 字形 `ICON_FONT`。
3. **组件唯一入口**：主/次按钮、卡片等只用 `ui_widgets`／`ui_theme` 的既有组件，不自建平行实现。
4. **表单控件**只用已登记样式名，不做局部样式改写。
5. **原生控件**：自配颜色的 `tk.Label`/`tk.Frame` 被门禁冻结，只减不增。
