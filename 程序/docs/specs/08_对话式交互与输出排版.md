# 08 对话式交互与输出排版

本册覆盖模型与用户对话的交互方式和回话的输出排版：消息种类、正文排版、流式输出、回话组织方式、可点选项、干活过程呈现、第 2 到 13 页的「过程与回话区」、长消息与对话记录、已建未接线组件的去向。现状以 `tasks_round/专题一对话式交互盘点报告.md`（R3988，下称「盘点报告」）为准，行内 `F` 编号即该报告的事实编号；目标以《工程文档细化任务书》DOC-D8 为准。窗口尺寸、13 页布局等界面规范见 [05 册](05_UIUX与交互规范.md)，对话记录的目录位置见 [04 册 §2](04_数据与本地存储.md)，本册不重复。

记号：✅ 已实现；🟡 部分实现；⬜ 未实现（目标）；❓ 待裁决或未核实。每行最后一列为状态。

## 2. 消息的种类

消息分六种：用户指令、模型回话、进度、审批、产物、出错。段（part）模型在 `domain/message_parts.py`：8 种 `PartType`（TEXT、REASONING、TOOL_CALL、TOOL_RESULT、SOURCE、FILE、ARTIFACT、DATA），段状态 `PartState`（PENDING／STREAMING／DONE／ERROR／ABORTED），产物再分 `ArtifactKind`（F10）。8 种段的渲染器都已建在 `ui/ui_part_renderers.py`（F11），但生产数据里目前只有 TEXT 和 REASONING 两种段，没有任何生产代码写其余 6 种（F12）。

| 种类 | 由哪些段组成（现在） | 目标怎样 | 状态 |
|---|---|---|---|
| 用户指令 | TEXT 段：发送时 `append` 写 `role='user'` 行，`derive_parts` 读回时转 TEXT 段（F12、F38） | 沿用现状 | ✅ `idea_transcript.append` |
| 模型回话 | TEXT 段（正文）＋旧行 `thinking`/`reasoning` 转成的 REASONING 段（F12） | 沿用现状；工具与产物段接入后回话可含 TOOL_CALL、ARTIFACT 等段 | ✅ `message_parts.derive_parts` |
| 进度 | 无专门段：进度写状态栏、流式文字贴在思考行下；TOOL_CALL、TOOL_RESULT 渲染器已建但无生产数据（F11、F12、F29） | 工具步骤与进度作为段进入回话区 | 🟡（渲染器已建未接线。目标来源：用户决定 2026-11-21） |
| 审批 | 无对应段；审批卡 `build_approval_gate` 与 `domain/hitl` 信封已建未接线（F25） | 审批作为可交互卡片进入过程与回话区 | 🟡（组件已建未接线。目标来源：用户决定 2026-11-21） |
| 产物 | ARTIFACT 段渲染器已建（一行「📄 标题 · kind [打开]」），无生产写入方（F11、F12） | 产物显示为可点开的一行 | 🟡（渲染器已建未接线） |
| 出错 | 无专门消息种类；`PartState` 已定义 ERROR、ABORTED（F10）；出错现在走状态栏与弹窗 | 失败说明作为回话按统一格式进入回话区 | 🟡（段状态已定义，无生产写入方。目标来源：用户决定 2026-11-21） |

其余 SOURCE（「[n] 标题」）、FILE（「📎 文件名」）、DATA（「（扩展数据）」）三种段的渲染器同样已建未接线（F11），去向见 §10。

## 5. 回话的组织方式

目标（DOC-D8-3）：对话回复、进度汇报、失败说明统一按「先结论，再分点，最后给下一步」组织；剧本、分镜等产物有各自的格式契约，不适用。

| 对象 | 现在怎样 | 目标怎样 | 状态 |

| 对话回复 | 发给模型的提示词里没有对回话组织的要求（F42–F45：注入的是产物格式与阶段流程约束，全库搜索确认无「回话怎么组织」的要求） | 先结论、再分点、最后给下一步 | ⬜ 来源：用户决定 2026-11-21 |
| 进度汇报 | 进度写状态栏，无回话组织约定（F29） | 同上 | ⬜ 来源：用户决定 2026-11-21 |
| 失败说明 | 失败走状态栏与弹窗，无回话组织约定 | 同上 | ⬜ 来源：用户决定 2026-11-21 |
| 产物（剧本、分镜等） | 已有各自的输出契约：`_preparation_task` 规定产物为完整 Markdown，`stage_output_contract('writing')` 定阶段产物格式（F42、F43） | 不适用（保持各自契约） | ✅ `writing_api.py` |
