# 01 架构与技术选型

本册覆盖技术栈、分层落地、模块划分、进程模型、数据流与选型结论。**分层表、目录树、门禁清单的唯一权威是 [`architecture.md`](../../architecture.md)**，本册只写选型理由与落地方式，不复述分层表。

## 1. 技术栈

| 项 | 选型 | 版本 | 理由 |
|---|---|---|---|
| 语言 | Python | 3.13（随附 `运行环境/Python`） | 用户无需安装；纯标准库可覆盖 Tk、JSON、线程、SQLite |
| 界面 | Tkinter / ttk | 标准库 | 见 [ADR-0013](../adr/0013-ui-framework-locked-tkinter.md)；锁定不换 |
| 生产依赖 | `requests`、`urllib3`、`certifi`、`charset-normalizer`、`idna`、`Pillow`、`psutil`、`nvidia-ml-py` | 见 [`requirements.txt`](../../requirements.txt) | 白名单锁版，见 [ADR-0002](../adr/0002-whitelist-dependencies.md) |
| 本地索引 | SQLite（标准库 `sqlite3`，WAL） | — | 已用于 artifact_index／job_store／metrics |
| 媒体处理 | FFmpeg / FFprobe（随附 LGPL 构建） | 见 `external_tools.lock.json` | 不引入 ffmpeg-python 等包装库 |
| 服务端 | Python + FastAPI + SQLite（WAL） | 独立仓库 `D:\漫剧服务端` | 独立发版，不纳入本册 |

**依赖准入**：新增依赖必须证明标准库与现有包不足，并在当轮结果文件写明理由与替代方案（[`维护记录/依赖白名单.md`](../../维护记录/依赖白名单.md)）。

## 2. 模块划分与分层落地

分层规则（唯一权威 [`architecture.md` §3](../../architecture.md)）：只允许 `L5 → L4 → L3 → L2 → L1 → L0` 单向 import。

各层职责与**本设计的约束**：

| 层 | 职责 | 设计约束 |
|---|---|---|
| L0 契约 | 纯数据契约、无 I/O 副作用 | 不 import Tk、不碰网络、不写文件 |
| L1 基础设施 | 缓存、密钥、预算、索引、执行器 | 写 JSON 只经 `agent.core.save()`；读只经 `file_cache.read_json()` |
| L2 业务 | 领域服务，**只接收注入的发布器** | 缺发布器显式拒绝，绝不降级直写（C1） |
| L3 编排 | 阶段总编排、并行、门禁、恢复 | 阶段启动唯一入口 `stage_handler_registry.start()` |
| L4 UI | 页面、控件、交互 | 只显示不判定；预算与状态判定在下层 |
| L5 入口 | 启动文件与启动适配器，只做启动、装配、退出收尾（成员见 `architecture.md` §3 的 L5 行） | 无业务逻辑 |

**模块规模约束**：单模块行数受 `test_module_size_ratchet` 棘轮约束，只减不增。`ui_widgets.py`（1125 行）已达上限，新组件不得加入，应放 `ui_theme.py` 或新建模块并登记。

## 3. 进程模型

### 3.1 主进程结构

```
启动漫剧制作助手.pyw（启动文件，按 L5 审计）
  └─ desktop.Desktop（L4，Tk 主线程）
       ├─ Tk 主线程：事件循环、界面绘制、150ms 心跳 pump
       ├─ BackgroundTaskLifecycle：所有主动后台任务（Desktop.async_()）
       └─ 有界执行器五池（infra/executors.py）：io / cpu / network / gpu / stream
```

**规则**：
1. **Tk 对象只在主线程创建与销毁。** 工作线程只 `pet_bus.emit_safe()` 发事件，主线程在心跳里 `pump()`。
2. **所有主动后台任务经 `Desktop.async_()`**，全生命周期由 `BackgroundTaskLifecycle` 管理；迟到／被替换／已取消的结果**不得**触发 UI 回调（C4）。
3. **L2/L3 不得直接 `threading.Thread`**，须经 `infra/executors.py`（`test_thread_boundary` 棘轮守卫）。
4. **取消语义＝拒绝迟到结果进 UI**，不强行杀线程（线程不可强杀）。

### 3.2 子进程

| 子进程 | 用途 | 生命周期 |
|---|---|---|
| `voice_engine/offline_asr_server.py` | 离线 ASR，stdio JSON-Lines 常驻 | 按需启动，空闲退出；**不 import 主运行时模块** |
| FFmpeg / FFprobe | 媒体探测与合成 | 每次调用短生命周期 |
| 本地 ComfyUI | 本地图像／白模生成 | 用户自管，程序只发 HTTP |

**约束**：登记子进程树 ≤3 秒回收，失败显式报告，不强杀未知进程（R3415 §H）。

### 3.3 并发预算

唯一权威 `stage_parallel.CONFIG`。当前口径：应用进程共享最大在途 **8**；视频阶段串行、批 2–3 镜、同时最多 3 个、失败重试 2 次转人工。

**边界**：该限制不提供跨进程机器总额度；多开应用时合计并发会超过 8，供应商账户限额需独立配置。

## 4. 数据流

### 4.1 阶段执行主链路

```
用户操作（L4 页面）
  → stage_handler_registry.start()（L3 唯一入口：会员闸门 → 上下文预检 → 执行）
      → project_context_factory.project_context()（L3，唯一上下文装配）
      → skill_orchestrator（L3）→ SKILL（模型侧）／直连 API（L2）
          → L2 业务服务（构造结果，不写盘）
          → L3 注入的发布器：publish_stage_text／bytes／bundle
              → agent.publication（L1：临时文件 + rename 原子发布）
              → file_cache 失效事件：published / recycled / externally_overwritten
      → stage_completion_service（L3：以产物核验完成，不采信模型文字）
          → pet_bus.emit_safe('stage.completed')（L0 事件）
              → broadcaster（用户可见播报，带前缀）
              → L4 订阅者刷新页面
```

**关键约束**：
- **完成判定以产物核验为准**（规则 20）。模型说「我做完了」不算完成。
- **事件只经 `pet_bus.emit_safe()`**，不直调 `Bus.emit()`（规则 22）。
- **播报前缀只由 `broadcaster` 定义**（`【阶段 X/13】` 等），无前缀消息被拒绝。

### 4.2 三虎自动全流程

```
desktop_automation_service（L3）
  → 逐个阶段调 stage_handler_registry.start()
  → 每阶段按确认策略：人工确认阶段暂停等采用；自动阶段直接推进
  → 失败超重试上限 → 停止并转人工，不跳过
  → 运行状态落 data/state.json 与持久队列，重启可续跑
```

**约束**：付费阶段启动前必须有一次费用确认；`delivery` 的商用通过不能自动放行（详见 [02 §4](02_接口与详细设计.md)）。

## 5. 自动化等级与降级路径

| 等级 | 行为 | 适用 |
|---|---|---|
| 全自动 | 从指定阶段跑到目标阶段，无人工介入（付费前仍需费用确认） | 免费阶段（S02–S04、S06、S09、S12） |
| 半自动 | 每阶段产出后暂停等采用 | 默认 |
| 全手动 | 用户逐项操作，不使用模型 | 模型不可用时 |

**降级路径**（每个自动步骤必须至少有一条可到达的人工路径）：

| 任务 | 降级方式 |
|---|---|
| 剧本生成 | 直接编辑文本文件／导入自己的剧本 |
| 分镜生成 | 手动编辑 `episode.json`／导入镜头 JSON |
| 资产图 | 导入自有图片（需填来源与许可） |
| 首帧 | 导入自有首帧 |
| 配音 | 导入自有音轨 |
| 视频 | 静帧运镜（FFmpeg 合成）／外部精剪 |
| 字幕 | 手改 SRT |

降级改变效果时**用户可见且需采用确认**，不静默替换。

## 7. 性能基线与约束

实测数据（R3415，i9-12900K／31.70 GiB／Win11 26100）与本设计的应对：

| 瓶颈 | 实测 | 设计应对 |
|---|---|---|
| 目录扫描 21000 文件 | `rglob` 583 ms／`os.walk` 149 ms | 写入路径先查 `artifact_index`，禁盲扫（[04 §3.3](04_数据与本地存储.md)） |
| `publication.transaction` 扫描 | 约 100 ms／次 | 同上；**已知瓶颈，待性能轮优化**，不靠换存储解决 |
| 控件数量 | 1000 控件明显变慢、滚动中位 150 ms、内存 +30 MiB | 分页 ≤100 行；表格不放缩略图（[05 §4](05_UIUX与交互规范.md)） |
| 3000 镜 JSON | 2.52 MB／解析 9.6 ms | 不是瓶颈，无需优化 |
| Treeview 插 3000 行 | 17.8 ms | 不是瓶颈 |

**目标**（未实测，标注为目标不宣称达成）：UI 单次回调 p95 ≤50 ms；取消／关窗反馈 p95 ≤100 ms；100 次切页后 RSS 增量 ≤30 MiB 且不持续爬升。

## 8. 技术选型结论与排除项

| 议题 | 结论 | 依据 |
|---|---|---|
| UI 框架 | **锁定 Tkinter** | [ADR-0013](../adr/0013-ui-framework-locked-tkinter.md) |
| UI 组件库 | 不引入 sv-ttk／ttkbootstrap／CustomTkinter | 会多出第二样式权威 |
| 客户端主存储 | **JSON 真源 + SQLite 派生层** | [04 §1](04_数据与本地存储.md) |
| 配置校验 | 复用 `artifact_schema` 模式，不引入 pydantic | 功能重叠且白名单约束 |
| HTTP | 唯一经 `http_client.request_json()` | 规则 42 |
| 日志 | 现有 `infra/app_logging.py`，不引入 loguru | 已够用 |
| 安装器 | Inno Setup（EXE）+ WiX v4（MSI） | [03 §2](03_安装签名与分发.md) |
| 签名 | GPG／minisign 首期，Authenticode 后评估 | [03 §3](03_安装签名与分发.md) |
| SBOM | CycloneDX 1.5 | [03 §4](03_安装签名与分发.md) |
| Electron／Tauri | 排除 | 迁移等于重写，破坏零装环境 |
| SKILL 内建总控 | 专用机制已移除；创作说明由用户选装 SKILL 提供，通用阶段编排保留 | [ADR-0014](../adr/0014-remove-builtin-skill-orchestrator.md) |
| SKILL 在线市场／云同步 | 排除 | 单机无账户体系与支付通道 |
| 应用专用内建总控 | 退役 | REQ-RET-01/02：不分发 00 总控资源或专用机检桥；通用注册器、阶段编排与制作锁继续保留 |
