## 7.5 素材授权与溯源

### 7.5.1 溯源要求

参考图、生成图、视频、音乐、字体、声音、外部导入**均记录**：来源、许可、必要授权、内容审核状态。

### 7.5.2 许可判定（P0-1）

| 规则 | 要求 |
|---|---|
| 许可 ID | 用**规范 ID**，禁止子串放行 |
| CC BY-NC | 商用请求**必须拦截** |
| ND | 改编用途**必须拦截** |
| BY-SA | 明示义务 |
| 缺来源信息 | 不可静默放行 |
| 两处过滤路径 | 必须一致 |

### 7.5.3 缺失授权的处置

**警告不阻断**（用户自担商用风险），但：
- 该素材**不得标记为「商用审核通过」**
- 交付报告中**单列风险项**
- 不自动填「原创」或「可商用」
- 检测失败显示「未知」并转人工

### 7.5.4 商用门控（P0-5）

交付素材 **100% 可追溯**才可标「商用通过」。必要授权缺失或高风险内容未处置时**不得标记通过**。检测失败转人工，不能视为通过。

## 7.6 模型管理

### 7.6.1 模型池

| 项 | 方案 |
|---|---|
| 权威 | 模型管理保存的模型池 |
| 取钥链 | DPAPI → `.env`（首次） → 环境变量 |
| 按阶段选模型 | `<项目>/skill_config.json` 阶段项 + `reasoning` 字段 |
| 推理等级 | auto / low / medium / high，按模型协议映射（`reasoning_effort`／`reasoning.effort`／`thinking.budget_tokens`） |

### 7.6.2 可用性探针（ADR-0011）

以**五维探针**表达模型可用性，不是单一布尔值。探针结果只做提示，不自动禁用模型。

### 7.6.3 失败切换

`ModelRouter` 按 SKILL 的 `fallbackModels` **有限次**切换（[生成服务失败处理契约](../contracts/生成服务失败处理契约.md)）。切换失败分类由 `test_adapter_failure_conformance` 钉在真实适配器上。

### 7.6.4 三处模型设置的区别

| 设置 | 位置 | 作用 |
|---|---|---|
| 模型池 | 模型管理 | 可用模型全集 |
| 阶段模型 | `skill_config.json` 阶段项 | 本阶段用哪个 |
| 推理等级 | `skill_config.json` 的 `reasoning` | 本阶段档位 |

**约束**：CLI／桌面引擎与生产模型不受 `reasoning` 影响。

### 7.6.1 SKILL 管理边界

应用不再内建专用总控包；安装的 SKILL 可自带创作说明，应用仍通过统一注册表管理项目、用户和内置三层 SKILL，优先级为项目＞用户＞内置。通用阶段编排与 `production_locks` 制作锁保持独立。

退役五个专用工具：`feed.validate`、`feed.gateCheck`、`feed.auditContract`、`style.lockRecommend`、`style.lockLadder`，不提供替代实现。保留 `engine` 命令类别，其候选复用已注册的用户／项目包入口；扁平技能仍使用 `/skill名`，不扫描任意 README 或执行包内脚本。空候选和未知命令返回空结果。

任务与验收边界见[内建总控退役任务书](../../tasks_round/总控机制删除任务书.md)。

## 7.9 账户与会员完整设计

### 7.9.0 权威、状态与核对范围

本章承接原《账户登录与会员订阅 — 设计文档（首期）》全部十节实质条款，并吸收立项清单 D1–D16、D11b、Q1–Q8。需求、设计与实现分别判定：**需求事实**指用户确认的产品约束；**已接受设计**指已接受 ADR 或明确设计裁决；**现有实现**仅指本轮读取源码可定位的能力；**未实现设计**指契约候选或缺少实现／验收凭据；**历史结论**保留追溯且不得作当前承诺。状态可并存，代码不自动覆盖需求。本章合并本身不授权实现功能。

R3832 在基点 `b860721f` 静态核对客户端 `domain/account_client.py`，及独立服务端仓库 `D:\漫剧服务端` 的 `app/main.py`，仅为公开 API 入出参与必要处理读取 `app/service.py`、`app/providers.py`、`app/lease.py`；未读取私密配置，未联网、未复验测试服、GUI、备份恢复或支付。以下“现有实现”均为该范围的静态证据，不等于端到端验收通过。部署状态、法律与资质结论不得由历史记录或工程源码自证。

### 7.9.1 范围

#### 7.9.1.1 首期做
- 邮箱验证码注册／登录；账号与登录身份分表，为短信、微信预留数据结构（**不实现**）。
- 服务器时间权威的 3 天试用；会员状态（`trial`／`active`／`expired`）由服务端判定。
- 客户端授权闸门：持有服务端签发的**授权租约**，离线可用一段时间。
- 设备绑定（每账号 3 台）、自助解绑；年龄声明；注销（7 天冷静期）与数据导出。

#### 7.9.1.2 首期不做（登记在 §7.9.10）
支付与充值、短信登录、微信扫码、中转站接入与分成、项目数据同步、代理模型调用、多因素认证。

#### 7.9.1.3 不变的前提
- 用户素材与项目留在本地，永不上传；用户仍自带 API Key，模型调用链不改。
- 本账户模块的桌面实现不新增第三方依赖／运行环境包（原设计称“零第三方依赖”，不否认产品已有白名单包）；服务端依赖单独管理，不进 `运行环境\`。
- 本机不新增入站监听。

### 7.9.2 总体架构

```
桌面端（Tkinter，零依赖）                 云端（阿里云小机型，独立仓库）
 L4 account_panel（登录/账号页）           HTTPS 反向代理（Caddy/Nginx）
 L3 account_controller（状态机、后台任务）   └─ 认证与订阅 API 服务
 L2 entitlement_service（闸门判定）            ├─ 邮件发送（阿里云邮件推送）
 L2 account_client（HTTP 客户端）              ├─ 数据库（见 §7.9.3.3）
 L1 lease_verifier（RSA 验签，纯 Python）      ├─ 租约签名（私钥只在服务端）
 L1 account_store（会话与租约落盘）            └─ 定时任务（注销清理、过期扫描）
```

分层依据 `architecture.md` 第 3 节：只允许向下依赖。以上为分层设计命名，实现须先搜已有入口。现有账户 HTTP 消费者经 `platform_tools.open_https`；新增 JSON API 遵守当前 `AGENTS.md` 出站权威，不把历史出口命名推广为通用例外。

### 7.9.3 服务端

以下十张表是原设计核心数据模型，保留全部字段，**不是当前完整数据库清单**。API 已增加的字段／表在本节补充；未核对全部迁移与数据库实例。

#### 7.9.3.1 数据模型（账号与身份分表）

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `user` | `id`、`status`（`active`／`pending_deletion`）、`created_at`、`deletion_at`、`age_confirmed_at`、`tos_version`、`privacy_version` | 口令另表存放（`user_password`） |
| `identity` | `user_id`、`kind`（`email`／`phone`／`wechat`）、`value_norm`、`verified_at`；唯一键 `(kind, value_norm)` | 首期只有 `email`；邮箱统一小写并去掉 `+标签` |
| `device` | `id`、`user_id`、`fingerprint_hash`、`name`、`first_seen`、`last_seen`、`unbound_at` | 同一账号最多 3 台有效设备 |
| `session` | `id`、`user_id`、`device_id`、`refresh_hash`、`expires_at`、`revoked_at` | 刷新令牌轮换，只存哈希 |
| `subscription` | `user_id`、`plan`、`status`、`trial_started_at`、`trial_ends_at`、`period_end` | 试用与兑换码会员已存在；另预留 `auto_renew`（默认关闭）、`channel`（默认 `redeem`，另预留 `wechat`／`alipay`），支付接入验收后才启用 |
| `trial_ledger` | `email_hash`、`device_hash`、`used_at` | **注销后保留**，仅存单向哈希，防止注销重注册重领试用；隐私政策须披露 |
| `user_password` | `user_id`（主键）、`pw_hash`、`updated_at` | R2022 新增（迁移 0007）：scrypt 哈希，与管理员口令共用 `security.hash_password`；只用验证码登录过的老账号没有这一行 |
| `email_code` | `email_hash`、`purpose`（`login`／`delete`／`register`／`reset`）、`code_hash`、`expires_at`、`attempts` | 验证码短期保存，按用途分开 |
| `audit_log` | `at`、`user_id`、`event`、`ip_hash` | 不记令牌与验证码，保留 90 天 |
| `redeem_code` | `code_hash`（唯一）、`plan`、`days`、`batch`、`created_at`、`expires_at`、`revoked_at`、`redeemed_by`、`redeemed_at` | R1897 新增（迁移 0003）：只存带盐哈希；账号物理删除时 `redeemed_by` 置空，兑换记录留作对账 |

#### 7.9.3.2 API 契约（均为 HTTPS + JSON，版本前缀 `/v1`）

| 接口 | 作用 | 要点 |
| --- | --- | --- |
| `POST /v1/auth/email/code` | 发送验证码 | 入参 `email`（R1890 实现：不收 `device_id`，设备在 verify 时才登记）；同邮箱 60 秒 1 次、1 小时 5 次；同 IP 1 小时 20 次。R2022 加可选 `purpose`：`login`（默认）与 `reset` 统一返回成功，不泄露邮箱是否已注册（`reset` 遇未注册邮箱不发信）；`register` 遇已注册邮箱返回 409 `email_registered`（产品要求的重复账号提示，按 IP 限额兜底）。发信失败返回 503 `mail_unavailable`，并撤回本次验证码与限流记录，不占冷却 |
| `POST /v1/auth/email/verify` | 校验验证码并登录 | 入参 `email`、`code`、`device{id,name,os}`、`age_confirmed`、`tos_version`；验证码 6 位、10 分钟有效、最多 5 次尝试；首次注册 `age_confirmed` 必须为 `true`；返回 `refresh_token` 与 `lease` |
| `POST /v1/auth/register` | 注册（R2022） | `{email, code(register 用途), password, device, age_confirmed, tos_version, privacy_version}`；口令 8–64 位且同时含字母和数字，否则 400 `weak_password`；已注册 409 `email_registered`；成功返回与 verify 相同 |
| `POST /v1/auth/password/login` | 口令登录（R2022） | `{email, password, device}`；邮箱不存在与口令错误同为 401 `password_invalid`；账号没设过口令 401 `password_not_set`；同邮箱 15 分钟错 10 次、同 IP 30 次后 429 |
| `POST /v1/auth/password/reset` | 找回口令（R2022） | `{email, code(reset 用途), password}`；设新口令并吊销该账号全部会话 |
| `POST /v1/account/password` | 设置／修改口令（R2022） | Bearer＋`{old_password?, password}`；已有口令须带原口令；保留当前会话、吊销其余会话；登录结果的 `user`、`/v1/me` 顶层带 `has_password` |
| `POST /v1/lease/renew` | 续签租约 | 凭 `refresh_token` 与 `device_id`（须与登记设备一致）；刷新令牌轮换；同设备在宽限内重试返回同一有效后继，宽限外复用吊销该账号全部会话（§7.9.4.4）；返回新 `refresh_token`、`lease` 与 `server_time` |
| `GET /v1/me` | 账号与订阅摘要 | 供账号页展示；以 `Authorization: Bearer <lease>` 鉴权（租约兼作访问凭证，须未过期、所属会话未被吊销） |
| `GET /v1/devices`、`DELETE /v1/devices/{id}` | 设备列表与解绑 | 每 30 天最多解绑 2 次，超限返回 429 `unbind_quota_exceeded`＋`Retry-After`，列表带 `unbind_left`、`next_unbind_at`、`current`（R1894 实现）；他人或不存在的设备一律 404 `device_not_found`；解绑即吊销该设备会话，其租约立即失效 |
| `POST /v1/account/delete-code` | 发注销验证码 | R1894 新增：Bearer 鉴权，向账号邮箱发**注销用途**验证码；验证码按用途分开存，登录码不能确认注销；发码频率与登录码共用限额 |
| `POST /v1/account/delete-request` | 申请注销 | Bearer＋`{code}`（注销用途码）；进入 7 天冷静期并吊销全部会话；冷静期内登录返回 403 `account_pending_deletion`，被拦的登录码不消耗 |
| `POST /v1/account/delete-cancel` | 撤销注销 | `{email, code}`，用**登录用途**验证码（会话已全部吊销，无 Bearer 可用）；仅冷静期内有效，否则 409 `not_pending_deletion`；撤销后重新登录 |
| `GET /v1/account/export` | 导出账号数据 | 返回 JSON：`account`、`consents`、`identities`、`devices`、`subscription`、`redemptions`（R1897 加，元素 `{plan, days, redeemed_at}`）；不含他人数据，不含令牌与验证码哈希 |
| `POST /v1/redeem` | 兑换码开通／续期 | R1897 新增：Bearer＋`{code}`。码 16 位 Crockford base32，显示 `XXXX-XXXX-XXXX-XXXX`，不分大小写、空格横杠可有可无，O→0、I/L→1 自动纠正。从 max(现在, `period_end`, `trial_ends_at`) 起顺延 `days`，`status` 转 `active`、`plan` 取码的套餐。返回 `lease`、`state`、`server_time`、`subscription{state,plan,trial_ends_at,period_end}`、`added_days`，客户端应直接替换本机租约。错误：400 `redeem_invalid`（格式错、不存在、已作废、已过兑换期）、409 `redeem_used`、429 `too_many_requests`（每用户每小时 10 次、每 IP 30 次失败）、401 `session_invalid` |
| `POST /v1/auth/logout` | 退出登录 | 以已签名租约作为 Bearer，吊销当前轮换链，重复调用成功。其他独立会话保留。 |
| `POST /v1/refund-request`、`GET /v1/refund-request` | 退款登记与查询 | 鉴权后登记本账号已兑换的码及原因，同码返回同一申请。查询只列本账号的申请。 |
| `GET /v1/meta` | 版本协商 | 返回服务端 API 版本、最低客户端版本、`server_time`、公钥 `kid` 列表（只给 kid，公钥本体内置在客户端，不经网络下发）；R2022 起 `features` 含 `password` 表示支持口令接口 |

约定：
- 错误体统一 `{code, message, retry_after?}`，`code` 为稳定字符串，客户端按 `code` 分支而不是按文字。
- 客户端请求头带 `X-Client-Version`；低于最低版本返回 `client_too_old`，客户端提示升级。
- 所有时间字段采用 UTC 秒级时间戳。原设计要求响应带 `server_time`，现有实现并非每个端点都返回，必须按下方实返字段表消费，不补造字段。
- 租约作为 Bearer 时，所属会话被吊销（非轮换）、设备已解绑或账号进入注销冷静期即失效（R1894）。
- 邮箱归一化会去掉 `+tag`，`a+x@example.com` 与 `a@example.com` 是同一账号。

### 7.9.4 授权租约（lease）

#### 7.9.4.1 格式
`base64url(payload_json) + "." + base64url(signature)`，签名为 **RSA-2048 + SHA-256（PKCS#1 v1.5）**。

`payload` 字段：

| 字段 | 含义 |
| --- | --- |
| `v` | 租约格式版本，当前为 1 |
| `kid` | 签名密钥编号，支持轮换 |
| `uid` | 账号 id |
| `sid` | 会话 id；服务端凭它判断租约所属会话是否已被吊销 |
| `did` | 设备指纹哈希，租约只对这台设备有效 |
| `state` | `trial`／`active`／`expired` |
| `plan` | 套餐标识 |
| `trial_ends_at` | 试用到期时间（`trial` 时有效） |
| `period_end` | 订阅到期时间（`active` 时有效） |
| `issued_at` | 签发时间（服务器时间） |
| `iat_server` | 签名覆盖的服务端签发时钟，UTC 秒。旧版租约可缺省。 |
| `expires_at` | 租约有效期，默认签发后 **7 天** |
| `grace_until` | 宽限截止，默认 `expires_at` 后 **3 天**；`trial` 时 `expires_at` 与 `grace_until` 都封顶在 `trial_ends_at`，试用不能靠宽限延长 |
| `nonce` | 随机数，防重放日志对账 |

#### 7.9.4.2 客户端验签
- 公钥内置在客户端；标准库没有非对称验签，所以用**纯 Python 做 RSA 验签**：`pow(sig, e, n)` 后与 `SHA-256` 的 DigestInfo 编码做完整比对（只比对哈希值，不用宽松解析，避免已知的填充伪造问题）。
- 不用 HMAC 共享密钥：密钥嵌在客户端会被提取，等于没有签名。
- 公钥可多把并存（`kid`），用于密钥轮换。

#### 7.9.4.3 离线状态机

| 条件 | 客户端状态 | 行为 |
| --- | --- | --- |
| `now < expires_at` 且 `state` 为 `trial`／`active` | `valid` | 全部功能可用 |
| `expires_at ≤ now < grace_until` | `grace` | 可用，但横幅提示"请联网续签" |
| `now ≥ grace_until`，或 `state = expired` | `locked` | 禁止付费阶段的新生成与导出；免费阶段（§7.9.5.2）、打开项目、查看和读取本地文件仍可用 |
| 无租约 / 验签失败 / `did` 不匹配 | `signed_out` | 提示登录；免费阶段仍可用 |
| 本地时间早于最近一次已知服务器时间（容差 5 分钟） | `clock_suspect` | 视为租约过期，须联网续签 |

最长离线可用 10 天（7 + 3）。客户端把"最近一次已知服务器时间"随租约一起持久化，每次续签更新。续签在启动时和每 12 小时进行，失败静默重试，不弹窗。

#### 7.9.4.4 并发续签与重放处置

- 首次续签原子记录后继会话及替换时刻。在同一设备且替换后不足 10 秒时，重复请求返回同一未吊销的后继凭据。服务端仅持久化令牌哈希。
- 设备解绑、会话过期或后继失效时，宽限内的重试也会被拒绝。超过窗口或迁移前未记录替换时间的旧令牌再次使用时，吊销该账号全部会话并记录审计。
- 服务端可通过 `MJ_REPLAY_GRACE_SECONDS` 配置窗口，默认为 10。迁移 `0009` 新增可空的替换时刻，保留旧会话的刷新哈希。
- 桌面端按会话使用私有目录的跨进程续签锁，取得锁后重读会话。若其他进程已更新，直接读取新租约。网络请求期间可继续读写项目，提交续签结果时再次核对会话以防覆盖登出或重新登录。网络失败保留现有租约，确认会话失效才清除并提示重新登录。
- 退出登录先请求服务端吊销轮换链，再清本机会话。无法确认服务端吊销时仍清本机，并明确提示远端会话将在到期后失效。

#### 7.9.4.5 异常登录提醒

首次成功登录建立设备与 IP 哈希基线。后续验证码或口令登录的设备或 IP 变化时，服务端按账号在每个 UTC 自然日最多发送一封提醒。邮件在登录事务提交和响应发送后处理，发送失败只记录异常类型。用户可以通过会员账户的已登录设备列表核对登录。

#### 7.9.5.2 闸门位置
- 所有阶段启动已统一经 `stage_handler_registry.start()`，闸门在此**入口前置判定**，禁止在各页面或各阶段内联散写。
- **免费范围（R1886 已定）**：不登录、试用过期或处于 `locked` 时，**前 2 个阶段（剧本准备、剧本结构）照常可用**；阶段集合由闸门按 `pet_bus.STAGES` 的阶段键判定，不按序号或中文名硬编码。
- 被拦截的动作：从"初步分镜"起的阶段启动（含手动、自动、三虎）和"质检与交付"的导出。放行：免费阶段、打开项目、浏览、读取本地文件、账号页自身。
- 两处闸门统一按阶段键判断：阶段启动与侧栏换页只在收费阶段且授权不可用时拦截。免费阶段、缺省阶段和非阶段工具页均按此规则放行。
- 判定被拒时只返回结构化结果，由 UI 层展示提示；是否需要新的 `pet_bus` 事件，实现时按 AGENTS §2.2 事件权威 在 `pet_bus` 登记，不另立事件名。

#### 7.9.5.3 凭据与存储
- 时钟来源：新租约以签名内的 `iat_server` 为准。响应体的 `server_time` 保留给展示与兼容用途。旧租约仍验签，可用已签名的 `issued_at` 作为兼容时钟基线。
- 最新签名时钟分别单调写入完整性保护的会话文件和当前用户注册表，授权取两者较高值。注册表不可用时继续使用会话数据与签名租约，会员账户的状态栏提示降级。
- 允许 300 秒回拨容差。应用运行期间，单调钟推进过期判断，单纯冻结系统时钟不会延长宽限。应用重启后从持久化基线重新判定；前调系统时间可能提前结束宽限。
- 订阅凭据**不走 DPAPI 机器绑定**（沿用既有决策 D10）：刷新令牌可被服务端吊销，换机重新登录成本低，机器绑定反而让用户换电脑后无法继承。落盘文件放 `程序\private\`，不入日志、不入任务 JSON（覆盖率审计 27）。
- 会话文件用 HMAC-SHA256 检测内容改动。DPAPI 只保护本机的 MAC 密钥，订阅凭据仍按 D10 通过服务端登录与吊销管理。文件级 MAC 的用途是完整性校验，设备绑定仍由租约和服务端核验。旧版未签名的会话或无法校验的会话会回到登录入口。
- 与 `model_secrets` 的模型 API Key 完全分开存放，不复用同一路径。
- 设备指纹：取机器稳定标识做加盐哈希，只上传哈希。ADR-0007 与现有 `account_store` 将设备回退种子独立保存，不把可随会话一起改掉的种子当可靠设备绑定。

#### 7.9.5.4 启动与 UI 约束
- 启动路径不做网络等待：先读本地租约判定，窗口可交互后再后台续签（AGENTS §2.5 规则 33）。
- 验权、续签、登录都在后台任务，取消与迟到结果按规则 30 处理。

### 7.9.6 合规与隐私要点（首期最低线）
- 注册页必须勾选"我已年满 18 周岁"并同意用户协议与隐私政策；服务端记录勾选时间与协议版本。不收集身份证。该声明**不是法律保护**，用户协议与隐私政策先用成熟模板，有收入后再请律师审阅。
- 隐私政策须披露：收集邮箱、设备指纹哈希、登录 IP 哈希；`trial_ledger` 在注销后仍保留单向哈希用于防滥用。
- 注销：冷静期 7 天，期间登录只能撤销；到期后物理删除 `user`、`identity`、`device`、`session`、`subscription`、`email_code`，保留 `trial_ledger` 哈希和 90 天审计日志（日志不含可还原的个人信息）。
- 支付接入后订单记录须按适用财税要求另定留存。旧设计“通常 5 年”仅保留为历史估计，**未经法务确认，不作为现行期限**；本期无在线支付。注销对 `user_password`、退款申请、兑换对账的清理／去标识与法定留存需按实际迁移和清理器另验；旧设计列出的物理删除表不等于当前完整清理清单。

### 7.9.7 第三方线路与后续平台计费

**范围演进**：2026-10-23 的首期方案仅做推荐线路预设，不提供 Key 池；2026-11-19 的 REQ-APP-02/DES-APP-02 提出并确认后续平台预置模型按量收费与 BYOK 并行。后者是后续需求和实施方向，不代表首期线路已自动升级为平台计费服务，也不代表上游许可、支付、回执归属与退款已验收。

- **已接受首期设计**：当时决定不建子 Key 池或自动分发，基于公众生成式 AI 服务及上游禁转售风险作此取舍；具体法律适用和上游条款仍须核实。后续若采用用户专属受限 Key 模式，应经新的供应商授权、计量、账务和安全验收，不能以旧设计直接宣称合规或上线。
- **已做（服务端迁移 0006、`app/providers.py`）**：`provider_preset` 表登记名称、接口地址（须 https）、模型说明、邀请链接（可空）、备注、受众（all／member）、排序、启用；`app_setting` 存总开关 `providers_enabled`，**默认关闭**，后台「线路」页可一键下架。`GET /v1/providers` 需有效登录，总开关关闭返回空列表，`member` 线路要求付费有效。只存地址与说明，不存任何 Key。
- **客户端（R1925）**：账号页「推荐模型线路」卡片，按需联网读取；提供「复制地址」「注册／邀请链接」；Key 仍由用户填入模型设置的自定义提供方，走 `model_secrets`。固定提示：第三方服务、费用另计不属于会员、合规自负、软件不保管 Key。
- **邀请链接留空**，直到与中转站确认返佣规则（比例、是否终身绑定、结算方式）；确认前不对外推广。
- **不写进软件、官网与官方群**：任何 VPN／翻墙指引。
- 原首期候选：中转站如提供代理／佣金接口，可评估 `issue_key`／`revoke_key`／`set_quota`／`get_usage` 适配；该旧接口表不是已实现能力，管理员 Token 只放服务端受控环境。

- 闸门唯一性与自检：收费阶段以经过签名校验、设备匹配和有效期判定的租约为放行依据。没有可用租约时前两阶段按免费规则放行。单测可注入真实签名的测试租约、授权判定结果或显式构造参数。
- 客户端加固提高绕过成本。租约签名和服务端资源仍由服务端控制。

#### 7.9.7.1 管理后台历史实现记录（`https://<服务器>:8433`，用户名＋口令＋TOTP）

此为旧文档记载的后续方案，取代 §7.9.3.4 的“SSH即管理员、无单独登录”方案；本轮未核对后台代码与部署，不将其记为已验证上线。
- 用户与会员：设置到期日、顺延、停用会员、踢下线、封禁／解封（封禁后登录、续签、租约一律拒绝，错误码 `account_banned`）。

#### 7.9.7.2 后续平台计费与 BYOK（REQ-APP-02／DES-APP-02）

- **需求事实**：自带 Key 调用只统计成本，用户直接向供应商结算；平台线路按量计费，与会员费分离。项目仍本地保存。用户提出“充值后代配凭据且用户不可见”，是否由上游分配受限 Key 或由平台后台创建，应按供应商可验证能力再定，不能把此候选当作已部署。
- **业务设计**：用户专属受限 Key 供桌面直连；付款到账、调额、余额、不可变售价版本、费用扣减与退款分别对账。平台客户售价与上游成本独立取证；同一请求的同一计费维度重复上报使用相同事件身份和原始时间；未知回执先查单再结算。供应商账户汇总账单不足以扣某个用户的单次费用。
- **密钥边界**：平台凭据由服务端持有；桌面只按获授权方式使用受限凭据，不把管理员密钥或代配方案原样下发。若凭据可被复制到第三方应用，必须先明确所有调用由谁承担；若要求“仅本助手可用”，必须得到上游可验证限制，不能靠客户端隐藏。
- **实施证据边界**：服务端分支 `codex/usage-billing-policy` 曾试点业务分流与计量端口，使用开源 Lago 官方 Python SDK 作可选适配；中转目录复用服务端已有 sub2api 接入。该分支成果不等于当前 master 已部署、付款验签或用户余额扣减已可用；实时状态以实际合并提交、部署与验收凭据为准。
- **上线前置**：核实供应商商业授权、额度/并发控制、计量粒度、可信供应商回执归属、支付验签、重放与未知回执对账、充值→调额、退款路径、并发余额控制及隐私政策。首期桌面无 `/v1/metering`；未通过前不得向桌面开放写账接口或宣称自动扣费。

### 7.9.8 安全清单（实现时逐项对抗测试）

立项历史的桌面前提（单机单用户、裁剪解释器、零桌面数据库与无本机入站面）不能推广成云端现状。云端可有独立数据库／依赖／鉴权入站，桌面仍不新增监听；本机用户可见删除遵守回收权威，云端不获本机文件权威；令牌与密钥禁止进入日志／任务JSON／错误上报。后台网络不得阻塞Tk，生命周期取消与迟到结果须丢弃。

前提重估与验收候选仍需逐项留证：阶段4 T12 原“单机无账号／支付”N/A 不再充分，须补越权／支付／注入／外泄；T13 回环无鉴权“接受”须在账号面重估；阶段5 U13 的多租户SLO／迁移回滚／灰度由N/A转适用，U1/U6/U11/U12优先；阶段4 T6/T7 本地性能口径不覆盖服务端。计费不变量为分项求和等于总额、不负额、币种隔离、退款扣费对称（未来支付期验收）；迁移前向／回滚／失败恢复／旧数据兼容、灰度授权失败率／错误率／成本与回滚演练、隐私／导出／注销与资质法务确认均不可由本次文本合并宣称通过。

- 改本地钟（回拨、前调）、改本地状态文件、重放旧租约、断网伪造租约、换设备复用租约，均不能通过闸门。
- 验证码暴力枚举、同邮箱／同 IP 刷接口须限流；login/reset 不泄露存在性。register 已注册返回 `email_registered` 是明确产品例外，须按 IP 限流并验收，不得宣称所有接口均不泄露。
- 刷新令牌轮换后旧令牌失效；已注销或被吊销的会话续签必败。
- 跨账号越权读写设备与导出；注入；日志与错误上报中不含验证码、令牌、完整邮箱。
- 阶段4 T12／T13 的 N/A 与"接受"裁决须随实现同批重估（见 §7.9.8 的前提重估）。
