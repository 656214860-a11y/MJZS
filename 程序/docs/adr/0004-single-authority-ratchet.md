# ADR-0004 唯一权威源与棘轮门禁

- 状态：已接受
- 日期：2026-11-19（补记；决策早于记录日）
- 层级 / 阶段：全局 / 全局
- 取代／被取代：—

## 背景与问题

358+ 顶层模块、多 agent 并行轮次下，「同一事实多处登记」是文档腐烂与缺陷的主要来源（本任务书诊断的四类腐烂：ADR 缺号、导航死链、阶段索引计数漂移、P0–P2 表只存于归档，均属此类）。需要既有「唯一真源」纪律，又要有强制力与历史欠账的收敛路径。

## 考虑过的选项

- **A. 每类事实只允许一个权威模块/文档，其余一律投影**（现行方案）：权威源清单见 `AGENTS.md` §2.2，分层依赖见 `architecture.md` §3，门禁见 `tests/architecture/`。
- **B. 多处登记、靠文档约定与人工同步**：已被上述腐烂实例证伪。
- **C. 一次性全量整改历史欠账**：未采纳——风险大、阻塞面广；改用棘轮基线（`维护记录/架构统一基数.json`）让欠账只减不增、逐步归零。
- 棘轮机制的完整备选评审记录历史未记录；以上按 `AGENTS.md` §2.2/§2.3、`架构统一基数.json`、`架构统一路线图_v2.md` 现存证据重建。

## 决定

每类事实设唯一权威（阶段顺序→`pet_bus.STAGES`；路径→`stage_layout`/`storyboard_paths`/`script_contract`/`asset_contract`/`model_pool.env_file`；删除→`storage_maintenance.recycle_paths()`；正式 JSON 读写→`file_cache.read_json`＋受控发布器；UI→`design_tokens.md`/`ui_components.md` 等，完整表见 §2.2）。`tests/architecture/` 门禁把权威边界变成可执行检查；历史欠账登记进 `架构统一基数.json` 棘轮，只许收缩。

## 后果（含不可破坏的约束）

- 新增「第二权威」即违规；文档冲突时以 §2.2 权威源与代码为准，文档是投影。
- 棘轮基线条目不得新增豁免、不得回涨；消项须有对应门禁或轮次证据。
- 改了就出 Bug 的边界集中在 §2.2 表内各行所指模块，修改前先确认消费者。
