# ADR-0002 依赖白名单而非零依赖

- 状态：已接受
- 日期：2026-11-17
- 层级 / 阶段：全局 / 全局
- 取代／被取代：—

## 背景与问题

产品需要 HTTP 客户端等第三方能力。早期约束是「零第三方依赖」，但自研全部轮子（HTTP、重试、TLS、媒体探测）成本高且质量不可控；同时交付形态要求用户下载解压或点击安装后即可启动，不能要求 pip、编译器或环境配置。决策出处：`tasks_round/引入成熟框架与工作树规范任务书.md` 已确认决策节（R3215/R3199 车道，提交 `504f53bf`）。

## 考虑过的选项

- **A. 维持绝对零依赖、自研全部能力**：实现成本高、质量风险自担，HTTP/TLS 等基础件不在产品核心竞争力内。
- **B. 白名单依赖＋随包预装环境＋准入规则**（现行方案）：依赖收敛到 `维护记录/依赖白名单.md` 登记的少量包，预装于绿色版本随包 Python 环境，用户无需 pip。
- **C. 运行时按需 pip 安装**：被拒——违反「解压即用、无需环境配置」的交付约束，且引入供应链与网络不确定性。

## 决定

采用白名单依赖：准入规则唯一权威为 `维护记录/依赖白名单.md`，随包环境按 `requirements.txt` 精确锁定；生产逻辑只迁移经批准的默认传输层（`infra/http_client` 委托 `platform_tools`/requests），不重写业务契约；交付脚本不引入 shell 依赖（`AGENTS.md` §2.1 规则 3）。

## 后果（含不可破坏的约束）

- 新增依赖必须先过白名单准入与门禁测试，不得绕过。
- 随包环境体积是硬预算（用户已接受约 240MB 完整环境估计并要求质量优先；最终生产 Python 62.77MiB＋随包 FFmpeg 约 251.7MiB，候选压缩 145.56MiB）。
- 依赖缺失时按 `tests/skip_reasons.py` 登记位显式跳过并在汇总报告，不静默降级。
