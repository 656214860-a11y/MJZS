# ADR-0001 分层架构与唯一权威源

- 状态：已接受
- 日期：2026-11-15
- 层级 / 阶段：全局 / 全局
- 取代／被取代：—

## 背景与问题

358+ 顶层模块、多人/多 agent 并行轮次，需要防止依赖混乱与事实多源。分层前代码出现过 L2 反向依赖 L3（R2443 修 `writing_api` 读阶段模型绕道编排层）、模块巨石与「僵尸名」（R1649、R1504–R1506 把 `desktop.py` 7241→2226 行、`pet_ui.py` 4832→915 行拆成 Mixin），依赖关系只能靠人工排查。

## 考虑过的选项

- **A. 采纳 L0–L5 单向分层＋每类事实唯一权威模块＋`tests/architecture/` 门禁强制**（现行方案）。
- **B. 维持平铺结构、靠约定自觉**：反证为上述反向依赖与僵尸名的实际发生，依赖混乱无法自动发现。
- **C. 以白名单/豁免压过违规**：被拒。R2443 明确「不用白名单压过测试」；历史欠账改走棘轮基线（`维护记录/架构统一基数.json`）逐步归零。
- 原始分层决策的备选评审记录历史未记录；以上按现存证据（`AGENTS.md` §2.2/§2.3、`架构变更记录.md`、R2443/R1649 结果）重建。

## 决定

L0 契约 → L1 基础设施 → L2 业务 → L3 编排 → L4 UI → L5 启动，只允许自上而下 import；路径、事件、前缀、删除、阶段启动、动态导入、JSON 读写各设唯一权威模块（`AGENTS.md` §2.2）；由 `tests/architecture/` 门禁强制。

## 后果（含不可破坏的约束）

**DES-APP-01 · 桌面与云端调用方向**（2026-11-19，REQ-APP-01）。桌面内的一次制作命令从 L4 界面进入 L3 阶段分派，按业务需要调用 L2 服务和 L1 模型、存储或 HTTP 能力，产物契约由 L0 定义。独立会员服务以 Nginx 接收入站请求，应用后端执行身份与权益校验。自带的本机进程通信依各自协议服务内部组件。外部软件控制桌面制作不属于产品接口。变更网络或账号设计时，验收分别覆盖桌面发起方、服务端接入和相应业务结果。

- 新模块必须先登记 `tests/architecture/_layers.py`；跨层需求走契约层演进（契约轮）。
- 反向 import 一律禁止（§2.3 规则 11）；越层或事实多源即门禁红。
- 历史欠账用棘轮逐步归零，不得新增豁免项；改了就出 Bug 的边界见 `AGENTS.md` §2.2/§2.3。
