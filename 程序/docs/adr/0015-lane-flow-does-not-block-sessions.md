# ADR-0015 车道开发不因全量、合并和发布停住

- 状态：已接受
- 日期：2026-11-20
- 层级 / 阶段：全局 / 全局
- 取代／被取代：—

## 背景与问题

并行车道已经按工作树分开，但三条旧路径仍会把别的会话停住。全量 `--all --safe` 创建 `full-safe-selftest.lock`，提交和合并要等这把锁，一轮全量实测可占十余分钟到三十分钟。合并在主干上先 `merge --no-commit` 再跑出口 CI，`MERGE_HEAD` 期间主干不能再合。提交范围门只拦两个车道同时新增的同名文件，两条车道改同一个已有文件仍能各自提交。`master`／`main` 可以被非快进推送改写。`git push` 只更新备份仓库，用户启动的是另一份目录，仓库绿不等于正在用的程序已更新。

## 考虑过的选项

- **A. 每个工作树各持一把全量锁**：多套全量会同时抢同一台 GUI 桌面，未采用。
- **B. 每次 `dev.py commit` 改跑分层全量，或用增量回执代替内容树回执**：分层不能代替内容树回执，每轮都跑全量会把阻塞加回来，未采用。
- **C. 把非 GUI 并行度提高到 12、引入路径租约、提交签名、Conventional Commits，或用远端 Linux CI 替换本机全量**：不解决锁和主干占用，未纳入本决定。
- **D. 在 AGENTS.md 新增一条编号规则**：无守卫的编号规则会顶到规则守卫上限，未采用。现行口径写在 `runbook.md`，由架构测试盯住。
- **E. 锁、合并顺序和发布副本分开守（现行方案）**：全量不再挡提交；出口 CI 在占主干之前；重叠改动在提交时拒绝；主干只接受快进；推送之后还要把安装副本放到新目录并冒烟。

## 决定

后续功能轮和修复轮按 `runbook.md` §12「现行开发闭环」执行，口径如下。

1. 全量只持 `<git common-dir>/full-safe-runner.lock`。它不创建 `full-safe-selftest.lock`。提交、合并和 `pre-commit` 只看后一把锁，因此不再为整段全量让路。
2. 全量的 Tk 部分按波次归还 `gui-selftest.lock`。别的会话发现全量占用 GUI 时最多再等 60 秒，到点记 `GUI_DEFERRED` 并返回。车道之间等 GUI 仍最多 30 分钟。
3. `dev.py commit` 拒绝任何与其他活跃车道未合入改动重叠的暂存路径，包括修改已有文件。合并提交和 `master`／`main` 上的提交跳过这道门。
4. 合并队列先把分支变基到当前 `master`。冲突退回该车道，不占主干，不领号。出口 CI 在车道工作树（分支未检出时用临时工作树）跑完，主干检出仍干净，才独占 `merge-lane.lock` 并 `merge --no-commit`。这把锁被占用时立刻返回，不等待。
5. 失联留下的 `MERGE_HEAD` 只在 `merge-lane.lock` 已静默、且锁里的提交等于 `MERGE_HEAD` 时自动还原。锁还活着、没有锁或提交对不上，保持现场。
6. 本地 `pre-push` 与远端 `pre-receive` 拒绝 `master`／`main` 的非快进更新和删除。其他分支不受这条限制。
7. 要交给正在使用的程序时，`git push` 之后还须按 `docs/specs/03_安装签名与分发.md` §1.1 把构建落到新的空目录，冒烟启动并确认用户数据仍在。旧目录保留一个使用周期，失败就切回旧目录。

`architecture.md` 的协作基础设施段是同一口径的架构入口。操作细则在 `runbook.md` §4、§5、§12、§13。

## 后果（含不可破坏的约束）

- 删掉上述顺序、重新让全量创建提交锁，或把「已推送」写成「用户侧已更新」，`tests/architecture/test_lane_flow_gates.py` 变红。
- 全量仍是 master 上每 8 个源码轮一次的内容树回执，不能改成每轮提交都跑，也不能用分层结果顶替。
- 合并道一次只进一个分支。变基冲突和出口 CI 失败都发生在占主干之前。
- 安装器与代码签名仍未实现。发布手段保持目录副本，直到 `03_安装签名与分发.md` 的安装器章节落地。
