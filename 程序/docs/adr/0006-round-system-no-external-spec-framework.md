# ADR-0006 保留轮次制、不引入外部 spec 框架

- 状态：已接受
- 日期：2026-11-19
- 层级 / 阶段：全局 / 全局
- 取代／被取代：—

## 背景与问题

工程文档体系腐烂（ADR 缺号、导航死链、索引计数漂移、P0–P2 表失位）与流程臃肿并存。需要决定治理路线：是否引入外部规格驱动框架（如 GitHub Spec Kit、arc42、Diátaxis 式文档体系）或推翻现有轮次制，还是在现有机制上补齐。决策出处：本任务书（`tasks_round/工程文档体系补齐与防腐烂任务书.md`）D1／D13／D15，用户拍板。

## 考虑过的选项

- **A. 引入外部 spec 框架（GitHub Spec Kit 等）**：未采纳——与现有 R 轮次＋任务书＋结果文件机制重复造轮子，迁移成本高且与门禁/凭据体系不兼容。
- **B. 推翻轮次制、改 issue/PR 驱动**：未采纳——`round_claim.py` 中央分配、结果文件、证据凭据、合并轮已形成闭环，推翻收益不抵成本。
- **C. 保留轮次制与任务书机制，文档侧只补 MADR＋Keep a Changelog 框架**（现行方案）：需求三层金字塔（产品 PRD→阶段 REQ/DES→任务书），ADR 用 MADR 精简五段，不引 arc42（不动 `architecture.md` 章节号）、不引 Diátaxis 强制改名。

## 决定

保留 R 轮次制、任务书闭环（规则 35）与结果文件/证据凭据机制；不新增轮次类型（沿用 §3.1 功能轮为主）；文档治理框架只保留 MADR（`docs/adr/`）与 Keep a Changelog（`CHANGELOG.md`）；需求文档采用三层金字塔，第四层「需求单」并入任务书「已确认决策清单」节；文档树按用途组织不按 L0–L5 分层，5 层仅作登记表元数据。

## 后果（含不可破坏的约束）

- 轮次号由 `round_claim.py` 中央分配、不复用；每轮一个可独立回滚的变更集。
- 新治理/框架类提案须先过任务书「已确认决策」节，执行者不得自行引入外部框架。
- `docs/adr/` 只承载 MADR 决策记录；阶段需求/设计仍在 `docs/stages/`，产品需求唯一权威在 `说明/产品需求规格.md`。
