# S02 剧本结构

## 需求

目标：把 S01 被采用的自然剧本整理成可追溯的结构剧本（角色／场景／道具档案 + 分场），作为初步分镜的唯一剧本源。不改写原稿。

### 输入与依赖

- **REQ-S02-01** ✅ 唯一输入是 S01 被采用的自然剧本（`resolve_script_source`）。找不到时报错并停止，不创建任何产出。S01 的设定、大纲、角色卡不进入本阶段输入。
- **REQ-S02-02** ✅ 本阶段不采集、不要求任何制作锁值；锁值由 S01 填写，本阶段只读用。
- **REQ-S02-03** ✅ 依赖 S01 完成；自动链上 S02 失败时不跳过；串行执行，失败重试 2 次后阻塞。

### 整理流程

- **REQ-S02-10** ✅ 默认路径是本地规则整理，不调用模型；结构剧本中标明“本地规则提取”。
- **REQ-S02-11** ✅ 流程固定六步：读原稿 → 提取 → 校验 → 按反馈重提取 → 复审 → 写入。用户点“手动制作结构剧本”即视为对这六步的确认。
- **REQ-S02-12** ✅ 结构剧本含「角色档案」「场景档案」「道具档案」「分场剧本」四区。角色档案每人含别名、跨集 ID、物理特征、默认服装、换装需求；场景含空间锚点、光照方向、尺度参考；分场含出场角色、情绪基调、起止状态、正文。
- **REQ-S02-13** ✅ 只认原稿写出的事实；原稿没写的一律标“待确认”，不编造。
- **REQ-S02-14** ✅ 校验不通过时按反馈重提取；复审仍不通过则不写入。原稿自相矛盾（同一道具多种尺寸）不静默修补，停止并提示用户先改原稿。
- **REQ-S02-15** ✅ 本阶段不做镜头三元组、镜头拆分、分镜 JSON、首帧或媒体提示词（属 S03）。

### 产出与完成

- **REQ-S02-20** ✅ 结构剧本只能经 `write_structured_script` 原子发布；空正文拒绝；原稿保持不变；发布同时记录来源血缘。
- **REQ-S02-21** ✅ 一份稿件算“结构剧本”，需标题为「# 结构化剧本」、有档案区，且来源不是大纲／梗概；记录的来源原稿被删除后，该结构稿不再显示，不删文件。
- **REQ-S02-22** ✅ 阶段完成 = 能解析到合格的结构剧本。模型文字、界面提示、manifest 是否存在都不算证据。
- **REQ-S02-23** ✅ `character_manifest.json`／`scene_manifest.json`／`prop_manifest.json` 归本阶段（`script-character-extraction` SKILL）。用户裁决（2026-10-17）：由本阶段产出并核验。实现：`write_structured_script` 发布结构剧本时同步由其「角色／场景／道具档案」派生并原子写入 `02剧本结构/output/`（`script_contract.write_structure_manifests`）；`skill_orchestrator.verified_stage_output` 在结构剧本合法之外，还要 `structure_manifest_problems` 为空（文件在、抬头对、编号唯一、条目合规、名单与当前结构剧本一致），否则本阶段不算完成。「待确认」字段在 manifest 中留空，不拦完成。局限：此前已完成的旧项目没有三份文件，需重新整理一次结构剧本。
- **REQ-S02-24** ✅ 新结构剧本写入 `02剧本结构/结构剧本/`；旧 `writing/` 目录只读兼容，不再写回。
- **REQ-S02-25** ✅ `PRODUCERS` 登记的落盘目录原为旧名 `00_script`。用户裁决：修复。现按产出阶段登记：三份清单 `02剧本结构`、`scene_breakdown.json` `03初步分镜`、`emotion_curve.json` `01剧本准备`；`stage_layout.STAGES` 各阶段 outputs 同源于 `script_manifest_contract.STAGE_MANIFESTS`；`00_script` 只作 `LEGACY_STAGE_ALIASES` 只读别名。

### SKILL

- **REQ-S02-30** ✅ 本阶段有 5 个 SKILL：`pipeline-script-structure`（总入口，默认勾选）、`script-structured-generation`、`script-character-extraction`、`script-dialogue-polish`、`script-worldbuilding`；后四个为可选勾选。
- **REQ-S02-31** ✅ 台词润色并回结构剧本的台词段，不单独出文件；世界观整理产物落 `docs/world_bible.md`。

### 非目标（明确不做）

- 不重写或替换自然剧本原稿。
- 不在本阶段产出 `emotion_curve.json`（S01）或 `scene_breakdown.json`（S03）。
- 不设本阶段独立门禁；S02 → S03 只靠依赖串行。

## 设计

### 模块分工

| 层 | 模块 | 职责 |
| --- | --- | --- |
| L4 | `desktop_script_pages`（`ScriptPagesMixin`） | 剧本结构页；只注入回调 |
| L3 | `stage_exec._run_script_structure` | 六步动作的执行回调 |
| L3 | `skill_orchestrator` | 模板编排；`verified_stage_output` 核验完成 |
| L3 | `stage_flow` / `stage_parallel` | 依赖 `DEPENDS`；串行、重试 2 次后阻塞 |
| L2 | `script_workspace_service` | 结构页文档与签名、自然稿采用 |
| L0/契约 | `script_contract` | 结构整理、校验、重提取、原子发布、路径与识别 |
| L0/契约 | `script_manifest_schema` | manifest 产出方 `PRODUCERS`、SKILL 并入表 `MERGED` |

### 设计条目

- **DES-S02-01**（REQ-S02-01）`stage_exec` 的 `read_script_raw` 调 `script_contract.resolve_script_source`；返回 None 即抛错，后续动作不执行。
- **DES-S02-02**（REQ-S02-02）`STAGE_LOCK_REQUIREMENTS` 不含 `script_structure`；`pipeline-script-structure` 直接读 S01 的项目锁。
- **DES-S02-03**（REQ-S02-03）`stage_flow.DEPENDS['script_structure']=('script',)`；并行配置在 `stage_parallel.CONFIG`。
- **DES-S02-10**（REQ-S02-10/11）`stage_exec.run` 用阶段模板 `script_structure` 驱动六个动作；提取由 `structure_script` 完成，写入 `_RULE_NOTE`（本地规则提取）。
- **DES-S02-12**（REQ-S02-12/13）`structure_script` 逐字段从原稿取首句，取不到写“待确认”。
- **DES-S02-14**（REQ-S02-14）`review_structured_script` 返回 `{approved, feedback}`；`revise_structured_script` 遇“互相矛盾的尺寸”反馈直接抛 ValueError，不改写。
- **DES-S02-15**（REQ-S02-15）`workflow_settings` 的 `script_structure` 阶段输出契约禁止镜头／分镜内容；本地规则路径不生成这些内容。
- **DES-S02-20**（REQ-S02-20）写入必经 `write_structured_script`，由 `tests/architecture/test_structured_script_write_boundary` 守边界；血缘记录在 `artifact_lineage`。
- **DES-S02-21**（REQ-S02-21）`is_structured_script` 读前 4096 字符判定；`_structured_source_is_available` 按血缘判断原稿是否仍在。
- **DES-S02-22**（REQ-S02-22）`stage_completion_service` → `skill_orchestrator.verified_stage_output` → `structured_script_path` 指向的文件满足 `is_structured_script`；步骤做完但无可读结构稿时标 FAILED。
- **DES-S02-24**（REQ-S02-24）新稿位置 `canonical_structured_script_path`（`write_dir(project,'structure')/结构剧本/`）；旧目录由 `read_dirs` 只读发现，同内容按 SHA256 去重。
- **DES-S02-30**（REQ-S02-30/31）SKILL 位于 `skills/02 剧本整理SKILL/`；`script_manifest_schema.MERGED` 记录台词润色并回正稿、世界观落 `docs/world_bible.md`。
- **DES-S02-23**（REQ-S02-23/25）`script_manifest_contract.STAGE_MANIFESTS` 定义每份 manifest 的归属阶段，`stage_layout.STAGES` 与 `script_manifest_schema.PRODUCERS` 同源引用。`write_structured_script` 的 `update_index` 回调里调 `write_structure_manifests`：`structure_manifests(正文)` 解析「角色档案／场景档案／道具档案」三个区，经 `manifest()` 补编号后原子写入 `02剧本结构/output/`。`structure_manifest_problems(project, 结构稿路径)` 是核验口径，被 `verified_stage_output` 调用；`stage_completion_service` 经它间接核验。
