# S02 剧本结构

## 需求

目标：把 S01 被采用的自然剧本整理成可追溯的结构剧本（角色／场景／道具档案 + 分场），作为初步分镜的唯一剧本源。不改写原稿。

### 输入与依赖

- **REQ-S02-01** ✅ 唯一输入是 S01 被采用的自然剧本（`resolve_script_source`）。找不到时报错并停止，不创建任何产出。S01 的设定、大纲、角色卡不进入本阶段输入。
- **REQ-S02-02** ✅ 本阶段不采集、不要求任何制作锁值；锁值由 S01 填写，本阶段只读用。
- **REQ-S02-03** ✅ 依赖 S01 完成；自动链上 S02 失败时不跳过；串行执行，失败重试 2 次后阻塞。

### 整理流程

- **REQ-S02-10** ✅ 默认路径是本地规则整理，不调用模型；结构剧本中标明“本地规则提取”。
- **REQ-S02-11** ✅ 流程固定六步：读原稿 → 提取 → 校验 → 按反馈重提取 → 复审 → 写入。用户点“手动制作结构剧本”即视为对这六步的确认。
- **REQ-S02-12** ✅ 结构剧本含「角色档案」「场景档案」「道具档案」「分场剧本」四区。角色档案每人含别名、跨集 ID、物理特征、默认服装、换装需求；场景含空间锚点、光照方向、尺度参考；分场含出场角色、情绪基调、起止状态、正文。
- **REQ-S02-13** ✅ 只认原稿写出的事实；原稿没写的一律标“待确认”，不编造。
- **REQ-S02-14** ✅ 校验不通过时按反馈重提取；复审仍不通过则不写入。原稿自相矛盾（同一道具多种尺寸）不静默修补，停止并提示用户先改原稿。
- **REQ-S02-15** ✅ 本阶段不做镜头三元组、镜头拆分、分镜 JSON、首帧或媒体提示词（属 S03）。

### 产出与完成

- **REQ-S02-20** ✅ 结构剧本只能经 `write_structured_script` 原子发布；空正文拒绝；原稿保持不变；发布同时记录来源血缘。（这条管程序自己的写入；模型或用户直接放进目录的稿怎么认，见 REQ-S02-21。）
- **REQ-S02-21** ✅ 一份稿件算“结构剧本”，要满足下面任一条，且来源不是大纲／梗概：① 标题为「# 结构化剧本」并有档案区（本地规则整理的版式）；② 放在「结构剧本」目录里、文件名按命名规则写明文件类型是「结构剧本」（如 `项目_结构剧本_第01集_20261122.md`）、正文非空——模型或用户按集写的稿版式不同也认，不看正文版式（用户 2026-11-22 报：模型写的结构剧本在结构页和初步分镜页都选不了）。记录的来源原稿被删除后，该结构稿不再显示，不删文件。局限：② 这类稿没有按档案区派生的三份清单，本阶段的完成核验（REQ-S02-23）对它不通过，不影响在初步分镜页选用；没有血缘记录，不参与同源去重和回收（REQ-S02-33）。
- **REQ-S02-22** ✅ 阶段完成 = 能解析到合格的结构剧本。模型文字、界面提示、manifest 是否存在都不算证据。
- **REQ-S02-23** ✅ `character_manifest.json`／`scene_manifest.json`／`prop_manifest.json` 归本阶段（`script-character-extraction` SKILL）。用户裁决（2026-10-17）：由本阶段产出并核验。实现：`write_structured_script` 发布结构剧本时同步由其「角色／场景／道具档案」派生并原子写入 `02剧本结构/output/`（`script_contract.write_structure_manifests`）；`skill_orchestrator.verified_stage_output` 在结构剧本合法之外，还要 `structure_manifest_problems` 为空（文件在、抬头对、编号唯一、条目合规、名单与当前结构剧本一致），否则本阶段不算完成。「待确认」字段在 manifest 中留空，不拦完成。局限：此前已完成的旧项目没有三份文件，需重新整理一次结构剧本。
- **REQ-S02-24** ✅ 新结构剧本写入 `02剧本结构/结构剧本/`；旧 `writing/` 目录只读兼容，不再写回。
- **REQ-S02-25** ✅ `PRODUCERS` 登记的落盘目录原为旧名 `00_script`。用户裁决：修复。现按产出阶段登记：三份清单 `02剧本结构`、`scene_breakdown.json` `03初步分镜`、`emotion_curve.json` `01剧本准备`；`stage_layout.STAGES` 各阶段 outputs 同源于 `script_manifest_contract.STAGE_MANIFESTS`；`00_script` 只作 `LEGACY_STAGE_ALIASES` 只读别名。
- **REQ-S02-33** ✅ 同源去重：同一来源原稿只显示一份结构剧本（最新那份）。重新生成同源结构剧本时，新文件写入成功后，旧的同源份走 `storage_maintenance.recycle_paths()` 进回收站（用户可恢复）；无来源记录的历史文件按内容 sha256 去重，不因没有来源记录而被误删。下拉框只列每个来源的最新份。
- **REQ-S02-34** ✅ 命名：新生成的结构剧本文件名内容段＝生成它的模型厂商（与自然剧本同格式，如 `摄影侠_结构剧本_Anthropic_20261022.md`）；本地规则生成（不调模型）用 `本地`。厂商名走现有文件名净化；旧 `_正稿_` 文件只读兼容识别，不批量改名。

### SKILL

- **REQ-S02-30** ✅ 本阶段有 5 个 SKILL：`pipeline-script-structure`（总入口，默认勾选）、`script-structured-generation`、`script-character-extraction`、`script-dialogue-polish`、`script-worldbuilding`；后四个为可选勾选。
- **REQ-S02-31** ✅ 台词润色并回结构剧本的台词段，不单独出文件；世界观整理产物落 `docs/world_bible.md`。

### 阅读区展示

- **REQ-S02-32** ✅ 阶段配置的 SKILL 说明与剧本结构的两个剧本内容框只折叠展示层的整行空白，以 `ui_tokens` 的小段距表示段落；磁盘剧本、SKILL 源文件和发给模型的 SKILL 注入内容均不改。未改动的编辑态保存必须保持原文件逐字节一致。自然／结构剧本的文件改由正文上方的横向下拉框选择（不再占左侧目录列），编辑按钮（结构框另有「删除」）缩窄靠右；三个流程按钮在两框下方，说明收为一行，正文拿满整行宽度。
- **REQ-S02-35** ✅ 两个剧本框的可见按钮只留「编辑」（编辑中变为「退出」），结构剧本框保留「删除」，撤销／复原／保存收进文本框右键菜单（R2724 反转 R1862 的手动保存契约）。「编辑」进入可编辑态；任何修改停止输入 `ui_tokens.SCRIPT_EDIT_SAVE_DEBOUNCE_MS`（600ms）后自动保存，内容未变化不写盘，退出编辑或切换文档前强制落盘，保存直接读文本框当前内容。右键菜单（经 `ContextMenu`）依次为「后退一步」（Tk `edit_undo`）、「前进一步」（`edit_redo`）、「复原全文」（先确认，恢复到进入编辑时的原文）、「立即保存」（幂等手动落盘）；`Ctrl+Z` 后退一步、`Ctrl+Y`／`Ctrl+Shift+Z` 前进一步，快捷键经 `ShortcutRegistry` 登记。编辑基线与落盘判定放无 Tk 的 `script_structure_edit_controller`，UI 只绑定回调。
- **REQ-S02-36** ✅ 两个剧本阅读框的正文左侧常驻行号槽，随滚动、内容增减与字号同步刷新，每个逻辑行一个号（软换行不重复编号）；`Ctrl+F` 在目标框上方呼出查找替换条，上一个/下一个循环命中、单个替换与替换全部带计数、`Esc` 关闭，只作用于当前焦点框；侧边大纲列出集数/场次（自然剧本）与标题层级（结构剧本），点击跳转到对应行并临时高亮，切换文档后刷新、无条目时显示空态；`Ctrl+滚轮`、`Ctrl+=`、`Ctrl+-` 以 ±1 步进调整正文字号（限 `ui_tokens` 区间，会话级不落盘），行号同步。替换操作走 `<<Modified>>` 既有链路，不改撤销/保存语义；全部零第三方依赖。

### 非目标（明确不做）

- 不重写或替换自然剧本原稿。
- 不在本阶段产出 `emotion_curve.json`（S01）或 `scene_breakdown.json`（S03）。
- 不设本阶段独立门禁；S02 → S03 只靠依赖串行。

### 设计条目

- **DES-S02-01**（REQ-S02-01）`stage_exec` 的 `read_script_raw` 调 `script_contract.resolve_script_source`；返回 None 即抛错，后续动作不执行。
- **DES-S02-02**（REQ-S02-02）`STAGE_LOCK_REQUIREMENTS` 不含 `script_structure`；`pipeline-script-structure` 直接读 S01 的项目锁。
- **DES-S02-03**（REQ-S02-03）`stage_flow.DEPENDS['script_structure']=('script',)`；并行配置在 `stage_parallel.CONFIG`。
- **DES-S02-10**（REQ-S02-10/11）`stage_exec.run` 用阶段模板 `script_structure` 驱动六个动作；提取由 `structure_script` 完成，写入 `_RULE_NOTE`（本地规则提取）。
- **DES-S02-12**（REQ-S02-12/13）`structure_script` 逐字段从原稿取首句，取不到写“待确认”。
- **DES-S02-14**（REQ-S02-14）`review_structured_script` 返回 `{approved, feedback}`；`revise_structured_script` 遇“互相矛盾的尺寸”反馈直接抛 ValueError，不改写。
- **DES-S02-15**（REQ-S02-15）`workflow_settings` 的 `script_structure` 阶段输出契约禁止镜头／分镜内容；本地规则路径不生成这些内容。
- **DES-S02-20**（REQ-S02-20）写入必经 `write_structured_script`，由 `tests/architecture/test_structured_script_write_boundary` 守边界；血缘记录在 `artifact_lineage`。
- **DES-S02-21**（REQ-S02-21）`is_structured_script` 读前 4096 字符判定：本地规则版式看标题和档案区；其余由 `_is_declared_structured_script` 看三样——路径里有 `结构剧本` 目录、文件名过 `is_structured_script_file_name`、正文非空。两种都要过「来源不是大纲／梗概」。`_structured_source_is_available` 按血缘判断原稿是否仍在；没有血缘记录的按正文首部「> 来源：」一行找原稿，没有这一行的照常显示。
- **DES-S02-22**（REQ-S02-22）`stage_completion_service` → `skill_orchestrator.verified_stage_output` → `structured_script_path` 指向的文件满足 `is_structured_script`；步骤做完但无可读结构稿时标 FAILED。
- **DES-S02-24**（REQ-S02-24）新稿位置 `canonical_structured_script_path`（`write_dir(project,'structure')/结构剧本/`）；旧目录由 `read_dirs` 只读发现，同内容按 SHA256 去重。
- **DES-S02-30**（REQ-S02-30/31）SKILL 位于 `skills/02 剧本整理SKILL/`；`script_manifest_schema.MERGED` 记录台词润色并回正稿、世界观落 `docs/world_bible.md`。
- **DES-S02-23**（REQ-S02-23/25）`script_manifest_contract.STAGE_MANIFESTS` 定义每份 manifest 的归属阶段，`stage_layout.STAGES` 与 `script_manifest_schema.PRODUCERS` 同源引用。`write_structured_script` 的 `update_index` 回调里调 `write_structure_manifests`：`structure_manifests(正文)` 解析「角色档案／场景档案／道具档案」三个区，经 `manifest()` 补编号后原子写入 `02剧本结构/output/`。`structure_manifest_problems(project, 结构稿路径)` 是核验口径，被 `verified_stage_output` 调用；`stage_completion_service` 经它间接核验。
- **DES-S02-32**（REQ-S02-32）`skill_note_render.parse()` 丢弃代码块外的空白 Markdown 行，正文标签使用 `NOTE_PARAGRAPH_SPACING`；`script_view_style.compact_display()` 生成只读紧凑展示文本，编辑态恢复已加载原文，未触发编辑标志时保存不写盘；`desktop_script_pages.content_box` 用 `_DocumentPicker`（Combobox，保留 `selection`／`get_children`／`item` 接口）替代目录表与可拖动分隔，选择框与编辑按钮同一行，正文独占整行宽度。
- **DES-S02-33**（REQ-S02-33）`script_contract._structured_script_candidates` 复用 `structured_script_paths` 的发现逻辑；`_structured_source_identity` 按血缘来源路径给结构稿分组，无来源记录退化为内容 sha256；`structured_script_paths` 每组只保留最新一份；`superseded_structured_scripts` 返回与新稿同来源的旧稿，`write_structured_script` 写入成功后经注入的 `supersede` 回调回收（回调在 L3/L4 里调 `storage_maintenance.recycle_paths`，契约层不直接依赖回收服务）。
- **DES-S02-34**（REQ-S02-34）`structured_script_file_name` 内容段默认 `本地`；`canonical_structured_script_path(project, content='本地')` 透传内容段；`write_structured_script(vendor=...)` 把厂商名经 `_file_name_part` 净化后作为内容段，缺省用 `本地`。旧 `_正稿_` 文件由 `stage_file_info` 照常解析（内容段任意字符串），不触发改名。
- **DES-S02-35**（REQ-S02-35）`script_structure_edit_controller.ScriptStructureEditController`（L2，无 Tk）只持「进入编辑时的原文」「上次落盘内容」与 `initial`／`dirty`／`save`：`save(text)` 与上次落盘相同则不写盘返回 False。`desktop_script_edit_session._ScriptEditSession`（L4）持有编辑态、防抖定时器（`preview.after`＋`SCRIPT_EDIT_SAVE_DEBOUNCE_MS`，预览销毁时 `after_cancel` 撤销）、右键菜单与快捷键登记；落盘回调 `save_text` 统一分流：natural 走 `script_contract.save_natural_script` 且落盘后 `_record_natural_edit`，structured 走 `agent.core.save_text`，均直接写文本框 `get('1.0','end-1c')` 当前内容、不做 strip 隐藏变换；撤销／重做用 Tk 原生 `edit_undo`／`edit_redo`，「复原全文」确认后把初始原文写回并立即落盘。`_ContentBox.select_document` 在编辑态先 `exit_edit`（内含 flush）再切换。
- **DES-S02-36**（REQ-S02-36）`_build_script_preview` 在文本框左列加 `script_line_numbers.LineNumberGutter`（Canvas 画行号，`yscrollcommand` 包一层刷新、`<Configure>` 与字号变化重绘）；`script_find_bar.FindBar` 默认 `grid_remove`，`Ctrl+F` 显示，命中位置由 `_search_positions`（字面量匹配，大小写可选）换算成 Tk 行列索引后 `tag_add('sel')`＋`see()`，替换要求 `state='normal'`（编辑态）否则提示；`script_outline.outline_entries` 复用 `script_view_style.spans` 与标签常量（natural 取 `script_episode`/`script_scene`，structured 取 `script_heading*`），`OutlinePanel` 用 Listbox 展示、点击 `see()` 并打 `script_outline_hit` 临时高亮；`_ContentBox` 把查找条放 `preview_area` 第 1 行、大纲放第 2 行右列（跨三行、默认折叠由「大纲」按钮开合），`Ctrl+F`/`Ctrl+=`/`Ctrl+-` 经 `ShortcutRegistry`（scope 含框 attribute 区分上下两框）、`Ctrl+滚轮` 由 `desktop_layout.scroll_page` 识别 `_ctrl_wheel_zoom` 转交；字号缩放 `ReadingAids.zoom_by`/`apply_zoom` 只改字号不动行距缩进 token，`set_preview` 分块收尾与 `desktop_script_edit_session._reset_preview_text` 末尾调 `preview._reading_sync` 回调重放 tag 字体与行号/大纲/查找状态。
