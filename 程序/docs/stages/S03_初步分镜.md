# S03 初步分镜

## 需求

目标：以已确认的结构剧本为唯一来源，按场景并行制作可通过助手校验的分镜 JSON（镜头链），经校验后"采用"，作为分镜预演（S04）及后续阶段的输入。本阶段不整理角色／场景／道具档案，不重写结构剧本。

### 输入与启动

- **REQ-S03-01** ✅ 输入只有"初步分镜"栏中已选的结构剧本（`storyboard_work_plan` → `selected_many(root,'script')`）。读取输入失败，或一份结构剧本都没选，启动失败并提示，不创建任何产出。
- **REQ-S03-02** ✅ 依赖 S02 完成（`DEPENDS['storyboard']=('script_structure',)`）。本阶段不采集、不要求制作锁值（`STAGE_LOCK_REQUIREMENTS` 不含 `storyboard`）。
- **REQ-S03-03** ✅ 启动前先过总控制作锁门禁，手动与自动同样阻断；入口只有 `stage_handler_registry.start()`。
- **REQ-S03-04** ✅ 待办 = 尚未产出分镜的结构剧本；待修订 = 已有分镜 JSON 但尚未采用的文件。两者都为空时不再启动 Agent：自动触发播报"已确认所有已选结构剧本的分镜均已生成并采用"，手动触发无动作。
- **REQ-S03-05** ✅ 并行配置：按场景分单元，同时 2–3 路（上限 3），同一场景内镜头必须串行；失败重试 2 次后阻塞（`stage_parallel.CONFIG['storyboard']`）。
- **REQ-S03-06** ✅ 同一集只输出一份分镜 JSON，已存在则跳过并说明，不生成副本、不换文件名重写；各场景做完后按剧本顺序拼接，并核对跨场景衔接（上一场结束状态＝下一场开始状态）。
- **REQ-S03-07** ✅ 初步分镜页的剧本清单列出每一份可见的结构剧本（每个来源最新的那份，REQ-S02-33），不只列最新的一份：按集各写一份结构剧本时，每一集都能选。模型按集写的结构剧本（REQ-S02-21 的第②种）同样列出；来源原稿已删除的结构稿不列出。（用户 2026-11-22 报：到了初步分镜没有剧本可选。）

### 分镜 JSON 契约

- **REQ-S03-10** ✅ 顶层必有 `episode_id`、`title`、`duration`、`source_script`、`shots`（非空数组），`prompt_language` 为 `"zh"`；所有提示词与对白用简体中文，编号、路径等专有标识保留原文（`storyboard_contract.rules`）。
- **REQ-S03-11** ✅ 每镜必有 `id`（`SH001` 格式、不重复）、`title`、`duration`（2–15 的整数秒）、`characters`、`location`、`props`、`frame`（`frames/镜头编号.png`）、`frame_prompt`、`video_prompt`、`dialogue`。
- **REQ-S03-12** ✅ `video_prompt` 为独立非空字符串，1–1500 字符，整合景别机位、动作起止、运镜、原对白与声音；`frame_prompt` 只写静止的动作起点。
- **REQ-S03-13** ✅ 各镜时长合计等于顶层 `duration`；使用剪辑字段时须满足 `0<=trim_in<trim_out<=duration`、`edit_duration=trim_out-trim_in`。动作或对白超过 15 秒须按动作闭合点拆镜，不得截断、加速台词或放宽校验。
- **REQ-S03-14** ✅ 多集任务镜头编号按集号从小到大连续：集号最小的集从 `SH001` 起，下一集紧接上一集最后编号，不按处理或并行完成顺序分配。
- **REQ-S03-15** ✅ 每镜写清镜头三元组（核心人物／主体、可见动作、景别机位与运镜），人物主导权变化、动作起止、转场或情绪转折按动作闭合点切镜；不把结构剧本的角色／场景／道具档案重复写入分镜。
- **REQ-S03-16** ✅ 背景人物、群演、路人、不露脸或一次性角色不写入 `characters`、不分配 CHAR 编号；普通道具写 `ordinary_props`，不分配 PROP 编号。
- **REQ-S03-17** ✅ 每镜补充 `action_complexity`（simple/medium/complex）及 `complexity_reason`，决定后续是否需要白模。
- **REQ-S03-18** ✅ 提交前须用 `validate_episode(JSON对象, media_root(JSON路径))` 本地校验，仅查本地数据、不调用模型；必须修复全部错误才算完成，未生成参考图只是待制作警告。
- **REQ-S03-19** ✅ 契约与阶段输出契约原把"通过校验并采用后的 JSON"称为"分镜定稿"。用户裁决：03 叫"分镜初稿"，资产尚未同步，"分镜定稿"留给 07。已改 `storyboard_contract.py`、`workflow_settings.py` 文案及 03 页表头（"结构剧本"／"分镜初稿"，`test_ui_edges_pages` 表头断言随标签契约同步）。
- **REQ-S03-20** ✅ 用户裁决：由实现方决定。决定：03 不写 `batch_id`，批次划分归 07（`shot_batches.group` 回填）；`stage_parallel` 的 03 阶段提示已改为"批次划分属于 07，本阶段不写"。

### 采用（分镜初稿 → 后续阶段）

- **REQ-S03-30** ✅ 采用前对整批（已采用＋新增）逐份校验：来源剧本必须是"初步分镜"栏中实际可用的一份（`source_script_error`），且 `validate_episode` 通过；任一份不过则整批拒绝，不改采用记录也不改资产计划，报错带文件名与具体问题。
- **REQ-S03-31** ✅ 采用成功后同步资产计划（`asset_plan._sync_plan`），再把采用清单 `adopted_storyboards` 与当前分镜 `frame_json` 写入项目 `ui_settings.json`；`adopted_storyboards` 缺失时回退读旧单值 `frame_json`。采用清单中的文件必须在项目内且存在。
- **REQ-S03-32** ✅ 无人值守自动采用（`adopt_pending`）：只处理新出现的分镜 JSON；刚写入不足 10 秒的文件记为 waiting 下轮再看；不合法的只跳过它，其余照常采用；整批只同步一次资产计划；重复调用不重复采用。
- **REQ-S03-33** ✅ 取消采用（`remove`）只改采用清单与当前分镜指针，并按剩余清单重同步资产计划，不删分镜文件；当前分镜指针（`focus`）只能指向已采用的分镜。
- **REQ-S03-34** ✅ 来源剧本已失效的 JSON 由 `prune_invalid_adoptions` 取消采用，保留 JSON 文件和历史资产。
- **REQ-S03-35** ✅ 刚创建项目时的种子分镜（`EP001`/`SH001`/"待编写"）不当作已制作的分镜。

### 设计条目

- **DES-S03-01**（REQ-S03-01/04）`storyboard_work_plan(project)` 取 `selected_many(root,'script')` 与 `selected_many(root,'storyboard')`，交给 `build_work_plan(scripts,boards,made,adopted)`：`todo=scripts−made`，`revise=boards−used`。`made` 来自 `stage_execution_service.storyboard_produced_scripts`。`_start_storyboard` 读取失败（OSError/ValueError/KeyError/TypeError）或 `scripts` 为空走 `_fail`；`todo` 与 `revise` 皆空，自动触发（且三虎 `auto.active=='storyboard'`）播报，否则返回空串；否则调 `desktop.open_storyboard_skill(None)`。
- **DES-S03-07**（REQ-S03-07）`storyboard_catalog_service._catalog(kind='script')` 用 `script_contract.structured_script_paths(project)` 的全部结果判断「这是要列出的结构剧本」（原来只认 `structured_script_path` 返回的最新一份）；文件名是结构剧本、但不在这份清单里的（同源旧份、来源已删、正文为空）仍然不列。排序、「原稿已变更」「已制作分镜」标记不变。
- **DES-S03-02**（REQ-S03-02/03）`stage_flow.DEPENDS['storyboard']`；`start()` 先过 `_workflow_lock_error`，因 `STAGE_LOCK_REQUIREMENTS` 无 `storyboard` 返回空串即放行。
- **DES-S03-05**（REQ-S03-05/06）`stage_parallel.CONFIG['storyboard']={unit:SCENE,min:2,max:3,serial:True,limit:3,retry:{attempts:2,backoff:'fixed',on_exhaust:ON_BLOCK}}`；`brief` 对 `storyboard` 追加三条提示（三元组核对、拼接与衔接、同集只出一份）。
- **DES-S03-10**（REQ-S03-10…17）这些约束全部以文本形式由 `storyboard_contract.rules()` 注入 Agent 任务；硬性字段校验由 `episode_contract.validate_episode` 执行，二者是同一契约的"提示"与"裁判"，不得一边改另一边不改。

## 交互

### 页面区域

1. 分镜正文区（主编辑器）：占页面主体的只读／可编辑文本区，显示分镜阅读视图（`format_storyboard_for_editor` 产出 `# EPxxx · 标题 [已采用]` 集头＋逐镜小节）或原始 JSON／剧本文本，带语法高亮与垂直滚动条；由 `S03EditorView._build`（`ui/storyboard_table_ui.py`）建 `TextArea`＋`ttk.Scrollbar`。
2. 镜头定位栏：正文区左侧竖栏，「镜头定位」标题＋计数、`placeholder='搜镜头号/角色/场景…'` 检索框与镜头列表；由 `S03ShotNavigator.__init__` 构建，解析到 ≥2 个镜头锚点（`extract_storyboard_shots`）自动出现，用户手动隐藏后不再自动出现。
3. 查找条：页面顶部、默认收起，含查找输入框（`placeholder='查找镜头、角色、对白或提示词…'`）、命中计数「n/m」或「无匹配」、「上一个」「下一个」「关闭」钮；由 `S03EditorView._build_find_bar` 构建，`show_find_bar` 呼出。
4. 快捷键提示行：页面底部一行说明，随编辑态在 `S03_HINT_READ`／`S03_HINT_EDIT` 间切换；`_build` 建 `ttk.Label`，`set_text` 换字。
5. 过程与回话区：显示用户在本页发的指令、模型的回话、进度、审批、产物；只是记录，不发给模型。⬜ 来源：用户决定 2026-11-21；细节见专题册 08

侧栏、全局状态栏、底部共享输入框与右侧项目文件面板为各页共用部分，不在本文件。本页把 `storyboard` 阶段发送动作经 `set_stage_action` 挂到共享输入框发送键（`_register_storyboard_send_action`→`desktop.send_storyboard('')`）、把右侧文件栏点击接进编辑器（`_register_files_panel_handler`→`show_document`）、把「当前：文件名（类型）｜已采用 N 份分镜，共 M 镜」摘要写进全局状态栏段 `storyboard_note`（`_update_status_segment`）。
