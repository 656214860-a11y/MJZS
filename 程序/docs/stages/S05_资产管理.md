# S05 资产管理

## 需求

目标：把已采用的分镜初稿里出现的角色／场景／道具，整理成带稳定编号、可追溯来源的资产清单，并为角色建立正典板与锚点；资产图片全部导入、角色锚点锁定后，才放行连贯性清单（SG-01）。

### 输入与依赖

- **REQ-S05-01** ✅ 资产清单只由「已采用」的分镜 JSON 导出（`asset_plan` 在非采用流程里按 `storyboard_adoption_contract.adopted` 过滤来源）。项目里没有采用任何分镜时，`active_source` 报“请先…点「手动采用分镜」”，不凭空建清单。
- **REQ-S05-02** ✅ 依赖与入口闸（2026-11-27 由 REQ-S05-53 修订）：数据依赖为 `stage_flow.DEPENDS['assets']=('storyboard',)`；保留入口闸 SG-B（`animatic → assets`，`animatic_ready`，标 `advisory=True`）——手动制作与浏览放行（未锁预演仅状态栏提醒，不拦），全自动 `PRODUCTION` 仍等待预演确认或显式 `skipped`。生成正式资产前由 `require_formal_asset_generation` 强制校验线上 API 模型并返回提醒文案；纯计划与浏览不受限。
- **REQ-S05-03** ✅ 本阶段不采集、不要求制作锁值；`track`、`aspect_ratio`、`resolution` 等锁值由 S01 填写，本阶段只读用（画幅默认 `16:9`、分辨率默认 `1920x1080`，项目锁优先）。
- **REQ-S05-04** ✅ 共享参考图目录 `reference_images` 由分镜预演准备、本阶段复用；资产提示词、正典板、锚点职责仍归本阶段。本地 ComfyUI 草图不进入正式资产登记。
- **REQ-S05-05** ✅ `pipeline-assets` 的 `input` 只声明 `storyboardDraft`／`assetRequirements`。程序（`asset_plan`）从已采用分镜镜头里的 `characters`／`location`／`props` 引用导出清单，不读 `characterManifest`／`sceneManifest`／`propManifest`／`sceneBreakdown`／`emotionCurve`；S02 默认路径也不写这三份 manifest（见 REQ-S02-23）。2026-10-20 裁决 A 将 SKILL 输入收窄到真实依赖。

### 资产清单与契约

- **REQ-S05-10** ✅ 资产编号格式 `CHAR_###`／`LOC_###`／`PROP_###`（至少三位）；分镜里写的是名称时，按名称／别名匹配已有编号，匹配到多个编号报错要求在分镜中指定，匹配不到则新分配下一个空号。
- **REQ-S05-11** ✅ 清单同步不覆盖已有内容：只补缺失的契约字段（`asset_contract.normalize` 只补缺的键），已有值一个不动；`used_in` 记录引用该资产的镜头编号。
- **REQ-S05-12** ✅ 只有被标记“需要独立资产”的道具才进清单（`prop_assets.requires_asset`）；普通道具写进镜头提示词，不分配编号。
- **REQ-S05-13** ✅ 角色字段：`character_anchor`（锚点字符串）、`base_anchor`、`canonical_board`／`canon_board_views`（正典板，7 格：前／右／左／背 4 张全身 + 3/4 左／正面／3/4 右 3 张头部）、`state_variants`（编号 `CST-01` 起，每项含 `override`）、`reference_role`（默认“面部、发型、服装”）、`reference_exclude`（默认“场景、动作、镜头”）、`locked`、字段化 `physical_features`。
- **REQ-S05-14** ✅ 校验规则（`asset_contract.validate`，返回问题列表，空为通过）：角色锁定前锚点不能为空；正典板视角名须是 7 个已知视角；状态编号须形如 `CST-01`、不得重复、必须有 `override`；`physical_features` 不得是整句字符串；缺 `canonical_board` 且无 `canon_board_views` 报缺。场景须有合法 `aspect_ratio`（如 `16:9`）、`resolution`（如 `1920x1080`）和成对的 `spatial_anchors`（`object`+`position`）。道具 `holder` 为空或形如 `CHAR_###`。
- **REQ-S05-15** ✅ 分镜引用的编号在清单里缺 `name` 或生图提示词，由 `missing_ids` 报出（门禁 G-04 使用）。
- **REQ-S05-16** ✅ 清单、名称编号对照、来源、导入进度四份文件作为一个发布包原子写入，写后复核；失败则整体回滚到发布前（`asset_plan._publish_plan_bundle`）。
- **REQ-S05-17** ✅ 只有登记过且文件真实存在于资产库内的图片才算“已导入”；计划里自带的 `image` 路径不被采信（`sync_plan` 先剔除再按登记表回填，状态为“已导入／待导入”）。

### 流程与执行

- **REQ-S05-20** ✅ 一项资产一个 Agent；每项内部固定串行：正典板 → 状态变体 → 锚点 → 参考职责。并发 3–5（上限 5）；失败重试 2 次（固定间隔），耗尽后阻塞（`ON_BLOCK`）。
- **REQ-S05-21** ✅ 默认只出提示词，不因启动本阶段自动出图；实际出图须有明确授权，沿用候选确认、预算与执行器。付费阶段（`PAID_STAGES` 含 `assets`）受预算约束。
- **REQ-S05-22** ✅ 资产图片制作后端：本地与云端模型名由 L0 `production_model_contract` 统一；正式资产请选线上 API 模型。
- **REQ-S05-23** ✅ 新写入目录为 `05资产管理/`；旧 `04资产管理`（R1124 前编号）与 `episode/assets/资产清单` 仅只读兼容，不再写回；旧目录 `02_assets` 为更早的别名。
- **REQ-S05-24** ✅ 资产图片制作结束时不替用户翻页（用户决定 2026-11-22）：批次窗（`ui/asset_batch` 的 `done`）、制图窗（`ui/native_assets` 的 `finished`）结束时，以及 Skill 批次自动导入（`asset_skill_batch.watch`）导入图片后，只有用户正停在「05 资产管理」（含资产详情页、资产清单页）且项目没换，才重画这一页；停在别的页只更新状态栏，不切页。资产管理页不在整页缓存名单里，切回来时按最新数据重建。

### 产出与完成

- **REQ-S05-30** ✅ 阶段完成 = SG-01（`assets_locked`）通过且 `started`：清单每项都导入了真实非空图片；每个 `CHAR` 都 `locked`；每个 `CHAR` 都有 `character_anchor`（或 `base_anchor`）。模型文字、界面提示、manifest 是否存在都不算证据（`stage_completion_service`）。
- **REQ-S05-31** ✅ SG-01 只拦“做过但没做全”：清单不存在、读不出来，或只有刚扫出来的名字（无图、无锁、无锚点）且阶段机没跑过，一律放行并标未开始。
- **REQ-S05-32** ✅ SG-01 的图片以图片登记表 `<资产库>/assets.json` 为准（`asset_batch_service.register_image`／`import_asset_image`／恢复写入处），清单文件里的 `image` 仅作旧数据兜底；`sync_plan` 剔除清单 `image` 的口径不变。修复：此前清单里有锁与锚点、登记表里有真实图片时，SG-01 仍误报“1 项资产还没导入图片”。
- **REQ-S05-33** ✅ 用户可见的资产删除走回收站（`storage_maintenance.recycle_paths`）；删除前由 `deletion_references`／`asset_impact` 列出被哪些镜头引用；恢复可还原相同字节。

### SKILL

- **REQ-S05-40** ✅ 本阶段 SKILL 位于 `skills/05资产管理SKILL/`：`pipeline-assets`（总入口，`dependsOn: pipeline-animatic`，不并行，不付费，输出 `assetManifest`／`canonBoard`／`anchors`）、`asset-auto-fill`、`asset-candidate-wall`（用户确认后才入库）、`asset-copyright-filter`、`asset-dedupe`、`asset-visual-rank`。
- **REQ-S05-41** ✅ 资产缺少来源、身份锚点或版本时不得进入正典；发现冲突只生成待修复项，不覆盖已确认资产。SKILL 只按需读取 `continuity-bible.md` 与 `image-model-adapters.md` 的相应章节，不注入 00 包全文。

- **REQ-S05-50** ✅ 资产图片制作选了模型池里的 API 模型（阶段配置 `engine=="qwen"`）时，由程序在后台线程里直接执行 `image_agent_runner.execute()` 出图（它本来就是确定性本机出图，不需要 LLM），不再启动 Qwen Code Agent；本机 Codex／Claude 引擎路径与批次文件格式不变。直连同样写 `派发状态.json`／`执行状态.json`，既有轮询按原语义导入图片；失败写 `执行状态.json` 的 `failed` 并说明原因；「强制停止制作」可中断（停止后状态为 `failed`，说明已停止，已出图片照常导入）。证据：`tests/test_image_direct.py`。

### 资产详情页与删图确认

- **REQ-S05-51** ✅（来源：用户决定 2026-11-21，DOC-D9-2 与 DOC-D9-1 前半件；设计为需求设计窗口 2026-11-23 所定，其中做法类句子为建议，待确认）资产详情页新增只读块「使用情况」（角色、场景、道具三类都有），摆在「参考职责」和「状态变体」之后、「资产 JSON 原文」之前。内容：①顶部一句汇总，沿用现有顶部影响提示的口径：被几个采用镜头引用；孤立资产写「当前没有采用镜头引用，属可回收的孤立资产」。②每个引用它的采用镜头一行：集、镜头号、首帧状态、视频状态。首帧状态三档——「最新」（首帧在且来源校验通过）、「过期」（首帧在但来源分镜、提示词或参考资产已变，行内写原因）、「缺失」（还没有首帧或文件不在）；视频状态两档——「已生成」「未生成」（视频的「过期」要等专题册 09 §8「视频持久过期标记」做完才显示，本条不做，界面不得假装有）。③角色另有一行「出现过的镜头视频」，列出已生成视频的镜头号。不新增任何要维护的数据：全部由现有账本现算，只读，不写盘，不改资产。资产被引用多时每行可滚动，不撑开页面。
- **REQ-S05-52** ✅（来源：用户决定 2026-11-21；设计为需求设计窗口 2026-11-23 所定，其中做法类句子为建议，待确认）删除资产图片的确认弹窗要把引用情况告诉用户：单项删除弹窗在原文案后面追加引用摘要（被几个采用镜头引用、列前 6 个镜头号；孤立则写可回收）；批量删除弹窗追加一句「其中 N 项被采用镜头引用：<编号列表前 6 个>」。只提醒，不拦截（图片本来就进项目回收站、可恢复）；弹窗按钮和现有「危险操作」确认样式不变。

### 2026-11-27 修订：解耦 SG-B 硬拦截，支持先资产后预演（来源：用户决定 2026-11-27，方案 B）

- **REQ-S05-53** ✅ 保持 `05资产管理` 阶段编号、目录契约（ADR-0003）及「资产清单只从 S03 已采用分镜导出」（REQ-S05-01）不变，解除 `04 分镜预演`（SG-B）对手动进入本阶段的硬拦截，使创作者可在 S03 采纳后自由选择「先预演再资产」或「先资产再预演」：① 数据依赖 `stage_flow.DEPENDS['assets']` 调整为 `('storyboard',)`（与 REQ-S07-03 同一原则：`DEPENDS` 只表真实数据依赖，S05 消费 S03 已采用分镜而不消费 S04 媒体）。② 保留 `SG-B`（`animatic → assets`，`animatic_ready`）在 `stage_parallel.GATES` 链路中的连续位置，但对其统一补齐「未开始不拦」语义（未跑过且无 `animatic_manifest.json` 时 `ok=True, started=False, verdict=UPSTREAM_BLANK`；已开始未确认或源变更时 `ok=False, started=True`；三项确认通过时 `ok=True, started=True`）并标为 `advisory=True`（提醒型）：浏览／手动口径下 `blocked_stages('assets')` 不再阻塞「手动制作资产」确认窗；三虎全自动 `PRODUCTION` 口径仍停在未开始／未确认的预演门禁等待人工确认或显式 `skipped` 豁免。③ `require_formal_asset_generation(project, *, online_model)` 仍强制校验 `online_model`（非线上 API 模型仍抛 `ValueError`，守住 REQ-S04-26／REQ-S05-22），但不再因 `SG-B` 未通过而抛错拦截；未锁定预演时返回非阻塞中文状态栏提醒文案，由 `ui/asset_batch.py` 写入状态栏（零弹窗）。④ `desktop_shared_send.upstream_send_error(project, 'assets', status=...)` 改为校验 S03 已采用分镜就绪（无采用分镜时拦截提示去第 03 步），`SG-B` 未通过仅向状态栏写提醒并放行。
