# S06 连贯性清单

## 需求

目标：把 S03 被采用的分镜与 S05 资产清单交叉核验，冻结必须逐字保住的锚点，列出冲突、批次三元组与跨批次不一致，形成连贯性台账；它是 S07 分镜定稿的前置检查，不生成任何内容。

### 输入与依赖

- **REQ-S06-01** ✅ 输入是当前被采用的分镜 JSON（`storyboard_selection.current_source`）和本集资产清单（S05 的 `assets.json`）。读不到时按空分镜／空资产计算，不报错。
- **REQ-S06-02** ✅ 依赖 S05（`stage_flow.DEPENDS`）。上游门禁 SG-01（资产锁定，`assets_locked`）、下游门禁 SG-02（连贯性台账，`ledger_ready`）；门禁只拦“已开始但不完整”，空项目放行。本阶段全局串行（1 个 Agent），失败重试 2 次后阻塞。
- **REQ-S06-03** ✅ 本阶段不采集、不要求制作锁（`STAGE_LOCK_REQUIREMENTS` 不含 continuity）；SKILL 只读用 S01 填写的锁。

### 清单流程

- **REQ-S06-10** ✅ 台账由 `continuity_ledger.build(shots, assets)` 按规则现场计算，不调用模型。
- **REQ-S06-11** ✅ 台账含 `batches`（批次与冻结锚点）、`conflicts`、`cross_batch`、`triplets`、`drift`、`summary`（批次数、镜头数、是否通过、待办列表），`version=1`。
- **REQ-S06-12** ✅ 冻结锚点逐字取自资产：角色（含服装状态覆盖）、场景（光源＋空间锚点＋尺度）、道具（材质＋尺度）；资产里没有的不补、不改写。
- **REQ-S06-13** ✅ 参考图冲突两类：“职责自相矛盾”（一张图既管身份又管场景／动作／运镜且排除项没写）与“多图抢同一件事”；裁决规则是先出现的参考图负责身份，其余只补风格与光影。
- **REQ-S06-14** ✅ 三元组：每批一行；同一批内 scene_id＋character_ids＋costume_id 出现多种即不通过，提示重切批次，本阶段不改批次划分。
- **REQ-S06-15** ✅ 跨批次：同一锚点（类型＋编号＋状态）在不同批次字符串不一致即不通过；分镜里的 `continuity_flags` 作为“全程必须保住”项记入。
- **REQ-S06-16** ✅ 漂移检测范围＝角色锚点（场景／道具同源恒一致，不比较）。`continuity_ledger.drift` 只遍历 `kind=='character'` 的冻结锚点；只有把已落盘台账与当前资产对比（G-09 `check_drift`）才有意义，重建台账时冻结值与现值来自同一份资产。
- **REQ-S06-17** ✅ 本阶段不生成图片／文字内容、不重新描述锚点、不改分镜、不改资产。

### 产出与完成

- **REQ-S06-20** ✅ 台账、人读版、共享锚点库、三元组字典四个文件一次发布（`publish_bundle`）：`06连贯性清单/output/continuity_ledger.json`、`06连贯性清单/docs/continuity_ledger.md`、`_shared/anchors/anchors.json`、`_shared/triplets/triplets.json`；写后读回校验，任一失败恢复旧字节；重复写入结果一致。
- **REQ-S06-21** ✅ 问题闭环登记 `06连贯性清单/output/continuity_issues.json`：问题编号稳定（`CI-<类型>-<范围>`），状态待处理／已忽略／已解除；忽略必须写理由并记当时证据摘要；证据变化或问题复现则重开；修好自动解除；只有 L3 注入发布器才落盘，否则只读预览。
- **REQ-S06-22** ✅ 严重度：职责自相矛盾、三元组不一致为“高”，锚点漂移、跨批次不一致为“中”。
- **REQ-S06-23** ✅ 阶段完成 = SG-02 `ledger_ready` 通过且 `started`（台账已生成）。台账未生成时门禁放行但不算完成；台账有未处理问题时不通过；被忽略或已解除的问题不再拦；台账说有问题却算不出问题行时不擅自放行。
- **REQ-S06-24** ✅ SG-02 要求台账与当前分镜对应：当前分镜（`frame_json` 指向的已采用分镜，缺省取最后一份）有镜头时，台账各批次 `shot_ids` 必须与这些镜头编号一致，缺镜或多镜都拦，并提示重新生成；没有采用分镜时无可核对，仍按旧口径放行；台账未生成仍放行但不算完成。只核对镜头编号，不比对资产内容（资产变动由漂移检查负责）。另：没有镜头时不再生成台账（手动按钮与自动链均提示先采用分镜），0 批次的空台账不再被判完成。
- **REQ-S06-25** ✅ 页面数据为现场计算、不落盘；只有“手动生成连贯性清单”才写盘并同步问题登记（DES-S06-01／DES-S06-33）。2026-10-20 裁决 A 按既有设计口径确认，不把页面浏览变成隐式发布。
- **REQ-S06-26** ✅ （2026-10-19 裁决）主观门禁 G-08（“多图抢同一件事”的优先级裁决）是可选、建议项，不作为放行条件：不计入台账待办，SG-02 不要求先裁决，只有“职责自相矛盾”阻塞。`confirm_gates` 的 G-08 说明和 `stage_flow` 的 continuity 恢复提示均已改为“可选、建议，不影响 SG-02 放行”的口径；人工仍可随时裁决，能力保留。
- **REQ-S06-27** ✅ 新台账 `stage` 写现行阶段键 `continuity`；`continuity_ledger.ledger_path()` 统一经 `stage_path_service.read_file(project, 'continuity', 'output', …)` 解析实际文件，SG-02 artifacts 复用该路径。`stage_layout` 的 `03_continuity` 别名与旧 `05连贯性清单` 目录继续只读兼容，旧台账可读、可校验，陈旧判断不依赖 `stage` 字段。

### SKILL 与引擎

- **REQ-S06-30** ✅ 本阶段 6 个 SKILL，位于 `skills/06连贯性SKILL/`：`pipeline-continuity`（总入口，预设默认勾选）、`continuity-anchor-freeze`、`continuity-conflict-adjudicate`、`continuity-cross-batch-guard`、`continuity-drift-audit`、`continuity-triplet-check`。
- **REQ-S06-31** ✅ SKILL 的 `continuity.*` 工具在 `skill_tools` 登记；`continuity.buildLedger` 直接调用 `continuity_ledger.build/write` 本地落盘，其余工具对应页面上的裁决／校验表。
- **REQ-S06-32** ✅ 以实现为准：台账由本地规则计算（见 REQ-S06-10）。`pipeline-continuity` SKILL 已改为只声明 `structured-output`、不设模型偏好，增补“执行方式”一节，写明 `repairList` 是冲突修复项的统称、落盘对应物为 `continuity_issues.json`，不存在独立的 `repairList` 文件；工具补登 `continuity.buildLedger`。
- **REQ-S06-33** ✅ 三虎自动链现在会自动生成台账：`desktop.pet_start('continuity')` 仍经 `stage_handler_registry.start()`，其 fallback `_start_unattended_stage` 新增 continuity 分支，与手动按钮共用 `generate_continuity_ledger`（写台账、同步问题登记、播报），不另设第二入口；没有镜头时返回空串，由宠物报告“没有自动执行入口”。完成仍由 SG-02 核验。

### 非目标（明确不做）

- 不生成或重新描述锚点、不改写分镜、不重切批次（批次划分属 S03／S07）。
- 不做首帧、白模、视频一致性的图像级比对。
- 不设独立的“放行”权限：分镜定稿放行以 SG-02 为准，D 锁（`splice_mode`）只读用。

### 设计条目

- **DES-S06-01**（REQ-S06-01）页面 `continuity_ledger_data` 读 `current_frame_json()` 的 `shots` 与 `asset_requirements()`，两者失败各自降为空后调用 `build`。
- **DES-S06-02**（REQ-S06-02）`stage_flow.DEPENDS['continuity']=('assets',)`；`stage_parallel.GATES` 的 SG-01（assets→continuity）、SG-02（continuity→final）；`CONFIG['continuity']` 单 Agent、重试 2 次、`ON_BLOCK`。
- **DES-S06-03**（REQ-S06-03）`script_contract.STAGE_LOCK_REQUIREMENTS` 不登记 continuity，`stage_handler_registry` 不对本阶段做制作锁检查。
- **DES-S06-10**（REQ-S06-10/11）`build` 依次调用 `batches`、`anchors_of`、`conflicts`＋`adjudicate`、`cross_batch`、`triplets`、`drift`，再由 `resolve_problems` 汇总 `summary`。
- **DES-S06-12**（REQ-S06-12）`anchors_of` 对角色用 `merged_anchor`（含服装状态覆盖），场景拼“光源／空间锚点／尺度”，道具拼“材质／尺度”；缺字段不补。
- **DES-S06-13**（REQ-S06-13）`conflicts` 用 `IDENTITY_WORDS`／`SCENE_WORDS`／`MOTION_WORDS` 词表判定；`adjudicate` 取 refs 第一个为身份负责人；`ask` 为多图抢同一件事生成 2 个候选（G-08）。
- **DES-S06-14**（REQ-S06-14/15）`triplets`／`cross_batch` 只比字符串；`continuity_flags` 去重后以 `kind='flag'` 记入。
- **DES-S06-16**（REQ-S06-16）`drift` 仅遍历 `kind=='character'` 的冻结锚点，与 `merged_anchor` 现值比较；`confirm_gates.check_drift` 在有资产时重新比较。
- **DES-S06-20**（REQ-S06-20）`publish_bundle` 先备份四个目标的旧字节，逐个写入，读回比对，失败 `restore_bytes`；`write` 只是兼容入口。边界由 `tests/architecture/test_continuity_publication_boundary` 守。
- **DES-S06-21**（REQ-S06-21/22）`issues` 把台账未通过项转成结构化问题；`merge_issues` 为纯函数，`sync_issues`／`decide_issue` 仅在 L3 注入 `publish` 时落盘；`SEVERITIES`／`ISSUE_KINDS` 为权威表。
- **DES-S06-23**（REQ-S06-23）`ledger_ready` 读台账；无台账返回 `ok=True, started=False`；有未通过项时用 `issue_gate` 判断是否全部为已忽略／已解除，且必须算得出问题行才放行；完成核验取 `ok and started`。
- **DES-S06-30**（REQ-S06-30/31）SKILL 位于 `skills/06连贯性SKILL/`，`skill_registry` 以 `06` 目录归入 continuity；`workflow_settings` 预设默认 `pipeline-continuity`；`skill_tools` 登记 `continuity.buildLedger` 等。
- **DES-S06-24**（REQ-S06-24）`continuity_ledger.stale_reason(ledger, shots)` 比对规范化镜头编号与各批次 `shot_ids`；`stage_parallel._current_shots` 取 `frame_json` 对应的已采用分镜；`ledger_ready` 在“台账存在”之后先查它，再用共享的 `continuity_ledger.open_problems` 查待办。`generate_continuity_ledger` 对 0 镜头抛 `ValueError`。
- **DES-S06-32**（REQ-S06-32）以实现为准，改 SKILL 不改代码；`test_skill_reference_injection` 要求保留的 `repairList` 字样保留并注明对应 `continuity_issues.json`。
- **DES-S06-33**（REQ-S06-33）`desktop_media_pages.MediaPagesMixin.generate_continuity_ledger` 是手动与自动的唯一实现，`pet_continuity_ledger` 为自动链薄包装，由 `desktop._start_unattended_stage` 的 continuity 分支调用，入口仍是 `stage_handler_registry.start()`。
- **DES-S06-26**（REQ-S06-26）G-08（“多图抢同一件事”的优先级裁决）是可选、建议项，不是 SG-02 放行条件：`stage_parallel` 的 SG-02 仍只调 `ledger_ready`，不要求先有 G-08 确认；`confirm_gates` 的 G-08 说明与 `stage_flow.RECOVERY_HINTS['continuity']` 统一改为“可跳过、不影响 SG-02 放行”，人工裁决能力保留。

## 交互

### 页面区域

1. 「选择分镜」下拉条（页顶注入，有已采用分镜才显示）：决定本页台账按哪份分镜与资产范围算（`frame_json` 指向与 `asset_scope`）；`ui.storyboard_source_selector.source_selector`（`desktop_page_nav.show` 注入，`page_navigation_controller.needs_source_selector` 判定）。
2. 「清单」按钮行：「手动生成连贯性清单」与「清单目录」两颗按钮；`desktop_media_pages.continuity_page` 内 `FlowBar`＋`PrimaryButton`／`SecondaryButton`。
3. 页头结论行：台账一句结论（通过显示绿字、有待办显示黄字）＋落盘状态「已落盘：continuity_ledger.json」或「还没生成，按左边的按钮生成」；`continuity_page` 内 `head` 区。
4. 「批次与冻结锚点」表：每批的镜头、秒数、逐字冻结锚点；`table_of`（行数据 `media_page_controller.batch_rows`）。
5. 「跨批次与三元组校验」表：三元组、跨批次、参考图裁决、锚点漂移四类结论行；`table_of`（行数据 `media_page_controller.check_rows`）。
6. 「问题闭环」表（有已登记问题时才出现）：编号、类型、严重度、状态、涉及镜头/资产、证据；`table_of`（行数据 `continuity_issue_rows`＋`media_page_controller.issue_table_rows`）。
7. 「待办与裁决」区：台账待办（最多列 8 条）或「没有待办：批次、锚点与三元组都对得上。」；G-08「参考图优先级（每条选一个，问过就不再问）：」候选与「采用推荐」；待处理问题的「忽略（写明理由）」；`continuity_page` 内 `foot` 区。
8. 过程与回话区：⬜ 未实现的目标（来源：用户决定 2026-11-21）——显示用户在本页发的指令、模型的回话、进度、审批、产物；只是记录，不发给模型；细节见[专题册 08](../specs/08_对话式交互与输出排版.md)。
9. 共用部分不在本文件：侧栏、状态栏、底部共用输入框、右侧项目文件面板。
