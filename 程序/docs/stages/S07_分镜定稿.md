# S07 分镜定稿

## 需求

> 编号说明：第 07 阶段，阶段键 `final`，目录 `07分镜定稿`（`stage_layout.STAGES`）。旧目录名 `06分镜定稿` 仅存在于 `stage_path_service.LEGACY_NUMBERED`，只读兼容；当前 `06` 是 `continuity` 连贯性清单。

目标：把已采用的分镜初稿，对齐资产清单（角色／场景／道具编号与参考图），按镜头三元组切批次并回填 `batch_id`，发布一份可追溯的定稿（`episode.json` + `assets.json`），供首帧阶段使用。定稿后原工作稿经回收站退役，不静默覆盖。

### 输入与依赖

- **REQ-S07-01** ✅ 输入是一份分镜 JSON（顶层对象、`shots` 为数组）加资产清单；`finalize` 在 `storyboard_final.finalize` 校验格式，不合格抛错且不写任何产出。手动入口缺源文件时直接报错（`desktop.py:1758`）。
- **REQ-S07-02** ✅ 进入本阶段受 SG-02（`ledger_ready`）约束：连贯性台账已生成且无未裁决待办；台账读不出或不存在时放行（只拦“已开始但不完整”）。证据：`stage_parallel.py:525,724-751`。
- **REQ-S07-03** ✅ `stage_flow.DEPENDS['final']=('storyboard',)` 只表达数据依赖；连贯性与资产的前置属于业务门禁，只由 SG-02（`ledger_ready`）与 SG-01（`assets_locked`）表达。2026-10-20 裁决 B：不把 `continuity`／`assets` 塞进依赖表，避免改变阶段机启动语义。
- **REQ-S07-04** ✅ 本阶段执行为全局单任务：`stage_parallel.CONFIG['final']` 为 `min=max=1`、失败重试 2 次后阻塞（`stage_parallel.py:66-68`）。
- **REQ-S07-05** ✅ 定稿期间不得有制作任务在跑：手动入口在有 `worker` 或视频会话忙时拒绝（`desktop.py:1760`）；自动入口遇忙等待，不抢跑（`final_service.py`、`desktop_auto_flows.py:352-355`）。

### 定稿流程

- **REQ-S07-10** ✅ 资产对齐：镜头里的角色／场景／道具先解析为资产编号（`CHAR_`／`LOC_`／`PROP_` + 数字，或经“名称编号对照”映射）；解析不到编号即抛“无法匹配资产编号”，不静默跳过（`storyboard_final.finalize`）。
- **REQ-S07-11** ✅ 每镜写入 `asset_bindings`（名称、图片、状态）、`reference_images`（仅已导入资产的图）、`asset_status`（待补齐资产／已匹配资产）；未导入的资产汇入顶层 `missing_assets`，`assets_ready` 随之为假。资产缺图不阻止定稿，只标缺（`storyboard_final.finalize`）。
- **REQ-S07-12** ✅ 台词 `speaker` 按名称映射替换为角色编号（`storyboard_final.finalize`）。
- **REQ-S07-13** ✅ 批次划分：三元组 `(scene_id, character_ids, costume_id)` 任一变化即切新批；同批 ≤4 镜（`BATCH_MAX_SHOTS`）、累计时长 ≤18 秒（长段落参数放宽到 25 秒）；`batch_id` 形如 `B01…`。同时补齐九个必填字段，只增不改，老字段（`id/characters/location/duration`）不动。证据：`shot_batches.py:24-48,115-145`、`storyboard_final.finalize`。
- **REQ-S07-14** ✅ 批次设计区间（每批 3–5 镜、每集 18–25 镜／5–7 批、单镜 2–5 秒）只作 `advise` 提醒，不是错误；硬校验只有“每批 ≤4 镜、≤18 秒、三元组一致”（`shot_batches.py:199-240`）。
- **REQ-S07-15** ✅ 切批失败中止定稿：`finalize` 里 `shot_batches.assign` 抛任何异常时，先经 `app_logging` 记一次日志，再抛带中文原因的 `ValueError`（原异常作 `__cause__`），不再继续发布；失败时不创建新的定稿目录、不写 `episode.json`／`assets.json`、不登记别名、不退役工作稿，源文件字节不变。切批成功的正常路径行为不变。证据：`storyboard_final.finalize`。
- **REQ-S07-16** ✅ 定稿以内容签名复用：已存在签名相同的定稿则不新建，只补血缘并按需退役工作稿（`storyboard_final.finalize`）。
- **REQ-S07-17** ✅ 同一集再次定稿写回同一目录（同 `episode_id` 的别名映射，或源本身就是定稿）；新目录命名 `<EP>_分镜定稿[_日期]`（`storyboard_final.finalize`）。
- **REQ-S07-18** ✅ 发布前后各复核：源文件在同步期间被修改则中止并保留原 JSON（`storyboard_final.finalize`）；两次 `validate_episode`。
- **REQ-S07-19** ✅ 发布走原子发布包：`episode.json` 与 `assets.json` 经 `publish_final_storyboard_bundle` 成对落盘；资产图与帧图复制进定稿目录，同名异内容时加哈希／随机后缀并改写引用（`storyboard_final.finalize`；`stage_execution_service.py:906`）。
- **REQ-S07-20** ✅ 发布完成后才退役工作稿：仅当源是“工作稿”（`storyboard_lifecycle.is_working_source`）时，经 L3 注入的 `retire_storyboard` 进回收站并留别名；L2 `finalize` 本身不持有退役实现，缺注入即抛 `TypeError`（`storyboard_final.finalize`、`storyboard_final_controller.py:20-32`）。
- **REQ-S07-21** ✅ 来源血缘：定稿记录追溯到稳定的结构剧本（源 JSON 的 `source_script`），而不是会被退役的工作 JSON；源本身是定稿时不新记（`storyboard_final._lineage_source`）。

### 入口与交互

- **REQ-S07-30** ✅ 手动入口按钮名“手动同步资产”（`stage_flow.MANUAL_LABELS['final']`），实现为 `make_final_storyboard`，对当前选中的分镜 JSON 异步定稿，完成后三虎播报并重建定稿页。
- **REQ-S07-31** ✅ 无人值守自动定稿：仅当用户在定稿页显式勾选（`should_auto_run('final')`）、当前分镜仍是工作稿、同一份稿只定稿一次（签名去重）、失败退避重试（`desktop_auto_flows.py:333-364`、`final_service.automatic_finalize_decision`）。
- **REQ-S07-32** ✅ 定稿页只读预览、编辑保存与镜头导航：保存前先校验是合法 JSON，再经 L3 `save_edited_stage_storyboard` 原子发布，发布失败保留原预览（`storyboard_final_controller.FinalStoryboardController`）。
- **REQ-S07-33** ✅ 目录识别：定稿目录名以“定稿”开头或含“_分镜定稿_”（`storyboard_paths.is_final_dir`）；新写入走 `stage_path_service.write_dir(project,'final')` 即 `07分镜定稿`，`06分镜定稿` 旧目录只读。

### 产出与完成

- **REQ-S07-40** ✅ 定稿落在 `07分镜定稿/分镜/<EP>_分镜定稿[_日期]/`，含 `episode.json`、`assets.json` 及资产图、`frames/`。
- **REQ-S07-41** ✅ 阶段完成 = `batches_ready` 返回 `ok` 且 `started`（`stage_completion_service.py:437-442`）；模型文字、界面提示不作证据。`started` 为阶段机跑过或任一已采用镜头已带 `batch_id`。
- **REQ-S07-42** ✅ 出口门禁 SG-03（`batches_ready`）：每镜有 `batch_id`、每批 ≤4 镜且 ≤18 秒、批内三元组一致；无已采用分镜时放行，未开始且有问题时放行，开始后有问题才拦（`stage_parallel.py:528,754-782`）。九个新字段不作门禁，另由 `shot_batches.validate` 校验。
- **REQ-S07-43** ✅ `stage_layout.STAGES` 的 07 阶段产出声明为 `episode.json`、`assets.json`，与 `storyboard_final.finalize` 经 `stage_execution_service.publish_stage_text`／`publish_final_storyboard_bundle` 成对发布的实际产物一致；下游 `stage_layout.STAGES` 中 `keyframe`、`previs` 的输入为 `episode.json`、`assets.json`（`previs` 另含既有的 `frames.json`），`audio` 的输入为 `episode.json`，均与各自实际读取一致。`json_md_rows()` 里批次对照的机器侧改为 `episode.json · batch_id`。`stage_layout.STAGES` 不再出现 `storyboard_final.json`；这些声明只用于生成各阶段 README 与契约展示，不参与运行时路径解析。
- **REQ-S07-44** ✅ `finalize` 在定稿写出成功后，按 `stage_layout` 声明的 `docs/` 位置派生 `batch_plan.md`（按批次列出镜头编号、数量、合计时长与三元组切批依据）和 `shot_table.md`（一镜一行：镜头号、批次、场景、角色、时长）两份 Markdown。两份文件只由定稿数据派生、不是第二份权威（权威仍是 `episode.json`），内容不含时间戳等不确定字段；同一内容签名再定稿时输出保持一致，不生成多份。签名复用分支与非新定稿路径不派生；旧项目读取路径不受影响。
- **REQ-S07-45** ✅ SG-02 的 `ledger_ready` 在“台账陈旧”和“还有待办”分支都用 `continuity_ledger.ledger_path()` 返回实际读到的台账文件；当前 `06连贯性清单` 与旧 `05连贯性清单` 布局均指向磁盘真实路径。台账不存在时仍不返回 artifacts。

### SKILL 与引擎

- **REQ-S07-50** ✅ 本阶段有 6 个 SKILL（`skills/07分镜定稿SKILL/`）：`pipeline-storyboard-final`（总入口，默认勾选，`workflow_settings.py:50`）、`storyboard-asset-sync`、`storyboard-consistency-lock`、`storyboard-final-validate`、`storyboard-prompt-render`、`storyboard-version-snapshot`；frontmatter `stage` 均为“分镜定稿”。
- **REQ-S07-51** ✅ 总入口 SKILL 读取项目锁（`track/material_source/aspect_ratio/resolution/fps/delivery_format/video_model_version/splice_mode/style_*`）而不重新询问；必填缺失退回剧本准备；`splice_mode`（D 锁）在本阶段放行，段缝须冻结 `in_state/out_state/cut_type/audio_bridge/owner`；不加载 00 包全文。
- **REQ-S07-52** ✅ `storyboard_final.finalize` 现在读连贯性台账（`continuity_ledger.require_final_ready`），口径与 SG-02 一致：台账未生成或读不出来放行；台账与待定稿镜头不对应则拒绝（`ValueError`，提示重新生成连贯性清单）；台账仍有未裁决待办（已忽略／已解除不算）则拒绝。D 锁段缝字段仍只由总入口 SKILL 提示词约束，程序不核验（本次裁决范围外，保持现状）。
- **REQ-S07-53** ✅ `storyboard-version-snapshot` 已按现状改为版本登记说明：`storyboard.save` 只登记分镜，定稿目录用日期后缀区分版本，旧版由回收站退役；程序不提供独立快照目录、版本比较或回滚。`architecture.md` 中“输出提示词和快照”的旧表述超出本批范围，另记待裁决。
- **REQ-S07-54** ✅ 07 定稿不重做镜头选型：逐镜核对并保持 03 的 `beat_no`／`context_id`／`forbidden_limits` 未丢，缺失或对不上退回 03 修订，不补造 E-ID。资产对齐清单以分镜编号为主键，在分镜编号右侧增加一列「节拍＃／E-ID」追溯（取 `beat_no`／`context_id` 组合），再列资产编号；资产编号与分镜编号的锁定、对齐规则不变。

### 非目标（明确不做）

- 不改写剧情、镜头内容与台词（只补字段、换编号、挂资产）。
- 不生成首帧、不调用图像／视频模型（属后续阶段）。
- 不删除源工作稿：只经回收站退役，可恢复。
- 不设置第二个定稿入口（手动与自动共用 `finalize_stage_storyboard`）。
- 不把设计区间（3–5 镜／批等）当错误拦截。

### 设计条目

- **DES-S07-01**（REQ-S07-01）`finalize` 先 `storyboard_resolve_source` 取源，再要求顶层 dict 且 `shots` 为 list，否则 `ValueError`，此时尚未创建任何目录。
- **DES-S07-02**（REQ-S07-02/03/04）SG-02 在 `stage_parallel.GATES`，检查函数 `ledger_ready` 读台账并用 `continuity_ledger.gate`／`issue_gate`；`CONFIG['final']` 为单任务、重试 2 次后 `ON_BLOCK`。`DEPENDS['final']` 在 `stage_flow`，与门禁各自独立。
- **DES-S07-03**（REQ-S07-05）手动：`make_final_storyboard` 判断 `self.worker`／视频会话忙；自动：`automatic_finalize_decision(signature, previous, production_busy)`，签名相同 skip、忙则 wait、否则 dispatch。
- **DES-S07-10**（REQ-S07-10/11/12）`_sync_plan` 先刷新资产清单与“名称编号对照”；逐镜按 `CHAR/LOC/PROP` 前缀解析编号，未入库抛错；`prop_assets.normalize_shot` 先补道具字段；状态不是“已导入”的资产记入 `missing`。
- **DES-S07-13**（REQ-S07-13/14/15）`shot_batches.assign` = `group`（三元组变化／满 4 镜／超 18 秒切批）+ 回填 `B%02d`；`check_batches` 为硬校验，`advise` 为软提示；`finalize` 调用 `assign` 期间捕获任何异常，先 `app_logging.swallowed()` 记录，再抛 `ValueError('批次划分失败，已中止定稿：…')` 并把原异常挂到 `__cause__`，因此不会走到写目录／写 JSON／退役；切批成功路径不变。
- **DES-S07-16**（REQ-S07-16/17）`storyboard_lifecycle.signature(episode, assets, base)` 为内容指纹（忽略 `used_in/status`，含图片哈希）；在 `final/分镜` 与 `分镜拆分` 两个读目录里按签名找已有定稿；找不到则 `dated_path(.../分镜, <EP>_分镜定稿)`，或经别名文件复用同 `episode_id` 的上一次目录。
- **DES-S07-18**（REQ-S07-18/19）发布前比对源哈希，不一致抛“分镜在同步期间已修改”；`publish_stage_text` 写 `episode.json`，其回调再调 `publish_final_storyboard_bundle` 成对写 `assets.json`；资产图 `copy2`，冲突时加 12 位哈希并记入 `image_rewrites` 回改引用。
- **DES-S07-20**（REQ-S07-20）`retire_working` 参数由 L3 的 `retire_stage_storyboard` 提供，别名发布器 `storyboard_lifecycle_gateway()` 同样由 L3 注入；`retire` 校验目标已落盘、源未被改、更新别名后调用 `storage_maintenance.recycle_paths`（回收站），失败则保留原稿。由 `tests/architecture/test_final_bundle_boundary` 守“桌面只经控制器调用”。
- **DES-S07-21**（REQ-S07-21）`_lineage_source` 取源 JSON 的 `source_script`（项目内且存在），否则回退源；源是定稿目录的 `episode.json` 时返回 None 不记。
- **DES-S07-30**（REQ-S07-30/31）按钮名在 `stage_flow.MANUAL_LABELS`；自动入口在 `poll_auto_final`，用 `file_hash(source)` 做签名，守卫 `pet.should_auto_run('final')`。
- **DES-S07-32**（REQ-S07-32）`FinalStoryboardController.save_edited` 先 `json.loads`，再 `save_edited_stage_storyboard`，失败抛 `ValueError` 且不替换当前预览。
- **DES-S07-33**（REQ-S07-33/40）`stage_path_service.write_dir(project,'final')` → `stage_layout` 的 `07分镜定稿`；`read_dirs` 追加 `LEGACY_NUMBERED['final']`（`06分镜定稿`）；`is_final_dir` 判定目录名。
- **DES-S07-41**（REQ-S07-41/42）`stage_completion_service` 的 `checks['final']='batches_ready'`，要求 `ok and started`；`batches_ready` 以 `_adopted` 的已采用分镜为对象，`started = has_run(final) or 任一镜头带 batch_id`。
- **DES-S07-50**（REQ-S07-50/51）SKILL 位于 `skills/07分镜定稿SKILL/`；默认勾选来自 `workflow_settings` 的 `'final':['pipeline-storyboard-final']`；D 锁段缝字段写在总入口 SKILL 正文，不由程序核验。
- **DES-S07-52**（REQ-S07-52）`finalize` 在 `normalize_shot` 之后调用 `continuity_ledger.require_final_ready(project, shots)`：未生成放行，与待定稿镜头不对应或有未裁决待办则 `ValueError`；`open_problems` 与 SG-02 共用。

## 交互

### 页面区域

1. 「选择分镜」下拉条（页顶注入，有已采用分镜才显示）：决定本页按哪份分镜做视图；`ui.storyboard_source_selector.source_selector`（`desktop_page_nav.show` 注入，`page_navigation_controller.needs_source_selector` 判定）。
2. 顶部操作行：「手动同步资产」「刷新列表」「分镜目录」三颗按钮；`_FinalStoryboardPage.build`＋`row_button`（FlowBar）。
3. 自动定稿提示条：自动定稿状态文字＋「立即重试」＋「去第05步补资产」；`_FinalStoryboardPage._build_status_bar`。
4. 定稿列表（上半卡片）：已采用分镜表格「同步资产分镜／是否同步／创建时间／项目内位置」；`_FinalStoryboardPage._build_final_table`。
5. 预览区（下半卡片）：文件路径行、「镜头目录」按钮条、定稿正文查看／编辑框；`_FinalStoryboardPage._build_final_table`＋`_build_viewer`。
6. 底部提示行：选择与加载状态文字；`_FinalStoryboardPage._build_viewer`（`note` 标签）。
7. 过程与回话区：未实现的目标（来源：用户决定 2026-11-21）——显示用户在本页发的指令、模型的回话、进度、审批、产物；只是记录，不发给模型；细节见[专题册 08](../specs/08_对话式交互与输出排版.md)。

共用部分不在本文件：侧栏、状态栏、底部共用输入框、右侧项目文件面板。
