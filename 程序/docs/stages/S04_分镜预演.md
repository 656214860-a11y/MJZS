# S04 分镜预演

## 需求

目标：以已采用的分镜初稿、共享参考图和临时声音，在本地生成逐镜草图并合成可播放的 Animatic，让用户在进入资产管理之前人工确认节奏、时长和对白同步。预演只是验证用的草稿，不是正式资产、首帧或正式视频。

### 输入与启动

- **REQ-S04-01** ✅ 本阶段是第 4 阶段（`pet_bus.STAGES` 中 `animatic`，目录 `04分镜预演`），依赖 S03 完成（`stage_flow.DEPENDS['animatic']=('storyboard',)`）；S05 资产管理依赖本阶段（`DEPENDS['assets']=('animatic',)`）。
- **REQ-S04-02** ✅ 输入三样：被采用的分镜 JSON（来源必须在已采用清单里，否则报"请选择已采用的本项目分镜初稿"）、共享参考图（至少一张非空图片）、临时声音（导入的音频，或由临时 TTS 文本合成；两者都没有则失败）。
- **REQ-S04-03** ✅ 手动启动（`stage_handler_registry.start('animatic')`）不自动出图：只切换到预演页、不调用任何生成函数；三虎自动触发时另发"阶段失败"事件，附"分镜预演需要选择参考图与临时声音，生成后请您确认节奏、时长和对白同步"，手动触发无文字返回。生成必须由用户在预演页明确点击。
- **REQ-S04-04** ✅ 本阶段不设制作锁必填项（`STAGE_LOCK_REQUIREMENTS` 不含 `animatic`）；预演画幅跟随项目已填的画幅锁，分辨率与帧率固定为低配预览规格（`animatic_preview_spec`），不受正式交付规格影响。
- **REQ-S04-05** ✅ 开始生成前必须通过 SG-A（`animatic_input_ready`）：已采用分镜非空，且每镜都有安全且唯一的镜头 ID、图片提示词和 0–600 秒内的有效时长；否则拒绝并提示"先完成并采用初步分镜"。
- **REQ-S04-06** ✅ 本地依赖就绪才开工：ffmpeg、ffprobe 路径可解析（设置 > 项目配置 > 运行环境），本地 ComfyUI 先等待就绪；缺任何一项直接报错，不产生半成品。
- **REQ-S04-60** ✅ （2026-10-19 裁决）本阶段输入声明保留 `storyboard_draft.json`：它是采用分镜时由 `storyboard_selection.sync_draft_outputs` 写下的落盘索引（来源路径、episode_id、镜头编号），SG-A `animatic_input_ready` 经 `draft_problems` 读它判断预演输入是否就绪，索引与当前已采用分镜不一致时拒绝进入。确认记录以 `animatic_manifest.json` 的 `confirmed` 为准，`stage_layout` 不再为 `04分镜预演` 登记 `animatic_notes.md`。

### 共享参考图

- **REQ-S04-10** ✅ 共享参考图只有两个来源：用户导入（PNG/JPEG/WebP，单张不超过 20 MB，按内容摘要命名去重）、本地 ComfyUI 文字草图（需填描述与本地已安装模型名）。两者都经 L3 原子发布到 `stage_path_service` 提供的共享参考图目录。
- **REQ-S04-11** ✅ 读取参考图时同时覆盖新旧共享参考图目录，按路径去重。

### 草图与合成

- **REQ-S04-20** ✅ 每镜草图用分镜提示词、全部共享参考图和固定种子（默认 1）经本地 ComfyUI 生成，提示词前带"只生成分镜预演草图，不是正式资产或首帧"。
- **REQ-S04-21** ✅ 并行能力：按 `batch_id` 分批，批与批并行（上限 3），批内逐镜串行；分镜没有 `batch_id` 的全部归入同一批（`default`）。03 不写 `batch_id`、批次由 07 划定，默认流程只有 `default` 一批；批间并行是保留能力，不是默认流程承诺。
- **REQ-S04-22** ✅ 只有明确的生成失败（`ComfyGenerationFailed`）才重试，最多 2 次；耗尽后报"镜头 X 生成失败且重试耗尽，请人工核查"并转人工。
- **REQ-S04-23** ✅ 提交结果不确定（ComfyUI 仍在排队或超时）不自动重投：报错请人工核查，已提交的回执保留在持久工作区（`04分镜预演/.work/run-*`），不随临时目录清理。
- **REQ-S04-24** ✅ 临时声音：有导入音频优先；否则按临时 TTS 文本合成，文件名含脚本签名，已存在且非空则复用，不重复合成（即使后面的出图失败，重跑也复用）。
- **REQ-S04-25** ✅ 合成：每镜图片按各自时长生成片段，拼接后叠加声音，输出 H.264/AAC 的 `animatic.mp4`；输出必须同时含视频流与音频流，总时长与各镜时长之和相差不超过 1 秒，并通过完整解码核验，否则本次不发布。
- **REQ-S04-26** ✅ 预演不改资产：不登记正式资产、不改资产提示词、正典板、锚点与 `assets.json`；正式资产仍走线上 API 生成。

### 发布与完成

- **REQ-S04-30** ✅ 成果写入 `04分镜预演/`：`animatic_manifest.json`、`assets/animatic.mp4`、`assets/temporary_audio.*`、`assets/shots/<镜头ID>.*`、发布器生成的 `animatic_index.json`。所有生成发生在暂存区，整包校验后才一次性原子发布，任何一步失败都回滚（含索引），不留半包。
- **REQ-S04-31** ✅ 发布前整包校验：清单 `kind=animatic`；清单 `files` 与暂存文件一一对应且摘要一致；视频、音频、每镜图都在 `files` 内且非空；`confirmed` 三项必须全为 `false`（生成器不得替用户签字）；成果路径不得越出阶段目录，`animatic_index.json` 只允许发布器写。
- **REQ-S04-32** ✅ 清单记录来源分镜相对路径及其 SHA-256；生成过程中来源分镜被改动则本次不发布。
- **REQ-S04-33** ✅ 观看预演（`animatic_video`）只要成果完整（不要求已确认）就返回视频路径，否则报原因。
- **REQ-S04-40** ✅ 人工确认：节奏、时长、对白同步三项必须一次全部勾选才能确认（`confirm_animatic`）；成果不完整时不能确认；确认只改清单的 `confirmed`，经原子发布。重新生成会把三项重置为未确认。
- **REQ-S04-41** ✅ 阶段完成 = `animatic_service.evidence` 通过：清单存在；来源分镜存在且摘要未变；视频、音频、每镜图都在项目内、非空、摘要与清单一致；三项人工确认全为 `true`。模型文字、界面提示、生成成功本身都不算证据；来源分镜变化后需重新预演并确认。
- **REQ-S04-42** ✅ 门禁 SG-B（分镜预演 → 资产管理）调用同一核验：Animatic 可播放，节奏、时长、对白同步已确认；否则提示"先完成分镜预演并确认三项检查"。
- **REQ-S04-43** ✅ 大媒体核验用流式摘要（`file_cache.file_digest`），不整段读入内存。

### SKILL

- **REQ-S04-50** ✅ 本阶段只有 1 个 SKILL：`pipeline-animatic`（`skills/04 分镜预演SKILL/`，免费、依赖 `pipeline-storyboard-draft`，工具 `animatic.generate`、`animatic.validate`，二者都打开预演页）。
- **REQ-S04-51** ✅ SKILL 的约束与本文一致：仅本地草图、不替代正式资产／首帧／正式视频、资产提示词归资产管理；需要剪映时另行交接，应用内合成不声称剪映原生导出。
- **REQ-S04-52** 🟡 SKILL 正文"本阶段读取的项目锁"列出 8 项以上锁（赛道、素材来源、分辨率、帧率、视频模型等），并称"必填项缺失记为配置缺口并返回准备阶段"。代码里本阶段只读画幅锁（预览规格），不要求任何锁，也不检查缺口（见 REQ-S04-04）。该段是跨阶段模板口径；是否要把它收窄为"只读画幅"，待最终验收时确认。

### 待拍板

- **REQ-S04-61** ✅ （2026-10-19 裁决）与 REQ-S03-20 一致：03 不写 `batch_id`，批次由 07 划定；预演按 `batch_id` 分组时，默认只有一批（`default`）。批间并行是保留能力，不是承诺；本阶段不改变批次归属。
- **REQ-S04-62** ✅ （2026-10-19 裁决）预演成果（草图、临时声音、`animatic.mp4`）只供用户在本阶段核对与追溯，下游不读取，也不做下游消费；文件保留在 `04分镜预演/`，不进入资产、首帧或白模输入。

### 非目标（明确不做）

- 不生成正式资产、首帧、正式视频或正式配音（属 S05、S08、S10、S11）。
- 不做节奏／时长／对白的自动评判；三项确认只能由人完成。
- 不自动导出剪映工程。
- 不修改分镜初稿；发现问题回到 S03 修订并重新采用。

| 层 | 模块 | 职责 |
| --- | --- | --- |
| L4 | `desktop_media_pages.animatic_page` | 预演页：选分镜／音频、导入参考图、本地生成参考草图、生成、观看、三项确认；只注入回调 |
| L3 | `stage_handler_registry.start`（`animatic` 分支） | 手动启动只切页并提示，不出图 |
| L3 | `stage_execution_service` | `run_animatic`、`confirm_animatic`、`animatic_video`、`import_animatic_references`、`import_animatic_audio`、`generate_animatic_reference`、`publish_animatic_bundle`、`animatic_preview_spec` |

| L2 | `animatic_service` | 分镜取值、草图、整包构建与校验、完成核验；不直接写正式成果，发布由注入的 L3 发布器执行 |

### 设计条目

- **DES-S04-01**（REQ-S04-01/03）`stage_flow.DEPENDS` 登记前后依赖；`start('animatic')` 先过 `_workflow_lock_error`（本阶段无锁要求，放行），再 `desktop.show(STAGES.index('animatic'))` 并返回 `_fail(...)` 提示文本，不调用任何生成函数。
- **DES-S04-02**（REQ-S04-02/05）`run_animatic` 先 `stage_parallel.evaluate(project,'animatic')`（SG-A），再要求 `Path(source).resolve()` 属于 `storyboard_selection.adopted(project)`；`build_bundle` 再要求来源在项目根内、参考图非空、`shots_of` 通过。`shots_of` 的校验规则：ID 匹配 `[A-Za-z0-9_-]+` 且唯一，提示词取 `image_prompt/prompt/video_prompt/description` 第一个非空，时长取 `estimated_duration/duration` 且 0<x≤600。
- **DES-S04-03**（REQ-S04-04/06）`animatic_preview_spec` = `script_contract.preview_spec(stage_config.workflow_lock(project))`；`run_animatic` 对 `ffmpeg/ffprobe` 依次取 settings、`config.json`、`platform_tools.tool_path`，缺失抛错；随后 `comfy_runtime.wait_comfy`。
- **DES-S04-04**（REQ-S04-10/11）`import_animatic_references` 校验后缀与大小，以内容 SHA-256 命名，经 `publish_stage_bundle` 发布；`animatic_reference_paths` 遍历 `shared_reference_read_dirs`（新旧目录）并去重。`prepare_reference` 复用 `Comfy.submit` 与 `_collect_sketch`，再交 `import_animatic_references`。
- **DES-S04-05**（REQ-S04-20/21/22/23）`local_sketch` 用 `reference_graph` 构图并把图中所有 `seed/noise_seed` 设为固定种子；`build_bundle` 按 `batch` 分组，`run_batches` 由 L3 注入 `stage_parallel.parallel_map('animatic', ...)`（批间并行、批内串行）；只捕获 `ComfyGenerationFailed` 重试，`retry_attempts` 来自 `stage_parallel.retry_attempts('animatic')`；`_collect_sketch` 在超时内轮询 `collect`，超时抛"不自动重复提交"。持久工作区 `04分镜预演/.work/run-*`。03 不写 `batch_id`、批次由 07 划定，默认流程只有 `default` 一批，批间并行仅是保留能力。
- **DES-S04-06**（REQ-S04-24）`tts_api.script_signature(text, settings)` 参与临时音频文件名；文件已存在且非空则复用；持久工作区下用 `request_id='tts-previs:'+signature` 让重复请求幂等。
- **DES-S04-07**（REQ-S04-25）`assemble_image_timeline`：逐镜 `-loop 1 -t 秒` 生成片段 → concat 清单 → 叠加音频（`apad`、`-t` 总时长）→ `ffprobe` 核验含 video/audio 流且时长差 ≤1 秒 → `-xerror` 全量解码；每镜时长必须有限且 0<x≤600。
- **DES-S04-08**（REQ-S04-30/31/32）`build_bundle` 在读取来源时用 `file_cache.read_stable_json_snapshot`，组装 artifacts 与清单（含 `source_sha256`、`files` 摘要、`confirmed` 三项 `False`）；发布前再次比对来源字节。`validate_bundle` 做整包一致性校验；`publish_animatic_bundle` 做路径越界与索引保留名检查，生成 `animatic_index.json`，通过 `publish_stage_bundle` 原子发布并在失败时回滚（含索引）。
- **DES-S04-09**（REQ-S04-40）`confirm_animatic`：三参数必须全为 `True` → `evidence(require_confirmation=False)` 通过 → `deepcopy` 清单写 `confirmed` → `publish_stage_text` 校验后发布。重新生成走 `build_bundle`，清单重新以 `False` 开始。
- **DES-S04-10**（REQ-S04-41/42/43）`evidence(project, require_confirmation=True)`：读清单 → 来源摘要 → `files` 逐项路径在阶段目录内、非空、`file_cache.file_digest` 一致 → 镜头图均登记 → 三项确认。任一环节异常统一返回 `(False, '分镜预演未就绪、源文件已变化，或节奏／时长／对白同步尚未确认')`。SG-B 与 `stage_completion_service` 共用该函数，无第二套判定。
- **DES-S04-11**（REQ-S04-50/51/52）`skills/04 分镜预演SKILL/pipeline-animatic.skill.md`，`tools: [animatic.generate, animatic.validate]` 在 `skill_tools.PAGES` 登记为打开预演页（`status_of=='page'`）。
- **DES-S04-12**（REQ-S04-61）`animatic_service.shots_of` 仍接受 `batch_id` 分组，缺省归 `default`；03 不写 `batch_id`、07 划定批次，因此默认流程只跑一批。`stage_parallel.CONFIG['animatic']` 的批间并行配置保留为能力，不把跨批并行写成默认流程承诺。
- **DES-S04-13**（REQ-S04-62）草图、临时声音、`animatic.mp4` 只保留在 `04分镜预演/` 供本阶段核对与追溯；资产、首帧、白模等下游只消费 SG-B 的通过结论，不读取这些文件，也不把它们登记为下游输入。
- **DES-S04-14**（REQ-S04-60）采用分镜时 `storyboard_selection.sync_draft_outputs` 写 `03初步分镜/output/storyboard_draft.json`（来源路径、episode_id、镜头编号）；SG-A `animatic_input_ready` 经 `draft_problems` 读该落盘索引，与当前已采用分镜不一致即拒绝进入。确认记录只以 `animatic_manifest.json` 的 `confirmed` 为准，`stage_layout.DOCS` 不再为 `04分镜预演` 登记 `animatic_notes.md`。
- **待定**（REQ-S04-52）REQ-S04-52 的 SKILL 锁段落收窄仍待最终验收。
