# S11 配音与字幕

## 需求

目标：对已采用的定稿分镜，导入或合成对白音轨，导出与音轨对齐的 SRT 字幕与对白核对脚本，经人工确认后作为后期剪辑（S12）的音频输入。不改分镜台词，不覆盖已确认配音。

编号说明：本阶段是 `pet_bus.STAGES` 第 11 位（下标 10，目录 `11配音与字幕`），章节号 S11 与之一致；上游为 S07 分镜定稿，下游为 S12 后期剪辑。

证据列：✅ 代码+测试可核；🟡 代码已有但无专项测试或只有部分覆盖；⬜ 未实现；❓ 方向冲突待拍板。

### 配音

- **REQ-S11-10** ✅ 音轨用途分 对白／旁白／BGM／音效／整轨 五类；非对白音轨文件名带用途前缀，无前缀一律按对白。导入 BGM 不能代替对白配音完成核验。证据：`tts_api.AUDIO_KINDS/audio_kind/marked_audio_name`、`prepare_media_completion` 的对白音轨检查。
- **REQ-S11-11** ✅ 导入配音：仅收 wav／mp3／m4a／aac，空文件拒绝；阶段只认 `audio`／`animatic`，用途须在五类内；发布必须由 L3 注入的发布器（经 ffprobe 校验后落盘），L2 不直接写盘。证据：`audio_import_service.import_audio`、`stage_execution_service.import_stage_audio`、`tests/test_audio_import_service.py`、`tests/architecture/test_audio_import_boundary.py`。
- **REQ-S11-12** ✅ 付费合成两种方式：整段（超 4000 字拒绝，请改逐句）与逐句。整段按台词＋设置签名复用已有成品，不重复扣费；逐句每句以 (镜头, 文本, 音色, 语速, 模型, 端点, 非密钥账号标记) 为身份，成功句 sha256 校验后沿用，中断可接续；开批时冻结端点与模型；提交前给出只读成本预览并须用户确认；状态为 sending／uncertain 的句子不自动重发。证据：`tts_api.run_lines/batch_cost_preview/freeze_settings/line_done`、`desktop_media_pages.generate_tts*`、`tests/test_tts.py`、`tests/architecture/test_tts_publication_boundary.py`。
- **REQ-S11-13** ✅ 程序只保证“稳定角色 ID → 显示名 → 默认音色”的绑定与三级回退（`voice_for`）。“一角一音色”和音色与角色年龄／性别相符属于 SKILL 层面的人工判断，程序不核验；2026-10-20 裁决 A 接受为人工约束。
- **REQ-S11-14** ✅ `voice-emotion-check` 的“逐句比对情绪标注、偏差大的列出来”已有程序实现：`domain.voice_emotion_check.check`（纯函数，L2）对结构剧本逐句情绪标注与 TTS 合成清单的语速/音量/情感参数做区间比对，输出偏差清单与「无法核验」清单；缺标注/缺参数/缺规则单列，不自动改音、不重合成、不调用付费 TTS。证据：`tests/test_voice_emotion_check.py`。

### 字幕

- **REQ-S11-20** ✅ 同一镜头内对白时间“部分标注、部分未标注”直接报错，不静默补齐。证据：`subtitle_timing.timed_entries/calibrate_entries`。
- **REQ-S11-21** ✅ 字幕时间轴非有限、负数、结束不大于开始、与上一句重叠、越过总时长一律报错，不静默修正。证据：`subtitle_timing.validate_entries`、`tests/test_subtitles.py`。
- **REQ-S11-22** ✅ 未给音频时按镜头时长与句长权重估算（校准报告标 estimate／uncalibrated，导出前可列出待校准句）；给出真实音频时长或对齐区间则按其校准；总和超出镜头时压缩并记 overflow 待人工确认。证据：`calibrate_entries/_distribute`、`subtitle_export_service.pending_calibration`、`tests/test_subtitle_calibration.py`。
- **REQ-S11-23** ✅ SRT 导出：时间码 `HH:MM:SS,mmm`，多行台词压成单行，空对白拒绝；以 utf-8-sig 由注入发布器原子发布到 `字幕/对白_<6位>.srt`，并同写 `字幕校准.json`；另可导出供配音核对的 `对白脚本_<6位>.txt`。证据：`subtitle_export_service.export_srt/export_dialogue_script/export_calibration`、`tests/test_subtitle_export_service.py`、`tests/architecture/test_subtitle_export_publication_boundary.py`。
- **REQ-S11-24** ✅ ASS 导出已实现（仅标准库）：`subtitle_timing.ass_text` 渲染含默认样式（Microsoft YaHei 60、白字黑描边、底部居中）的 ASS，时间码 `H:MM:SS.cc`，花括号转全角避免被当作样式覆盖码；`subtitle_export_service.export_ass` 与 `export_srt` 同批发布，共用同一校准轴、时间校验与 6 位文件名主干（`字幕/对白_<6位>.srt` 与 `.ass`，均 utf-8-sig，经注入发布器原子发布）。SRT 先发布，ASS 或校准状态写入失败只记警告、不影响已发布的 SRT。证据：`tests/test_audio_manifest_scope.py`、`tests/test_audio_subtitle_scope.py`（用户裁决“修复”，原 ❓ 已解；SKILL 里 `subtitle.exportAss` 为页面步骤，见交付报告）。

### 音频脚本直连 API

- **REQ-S11-50** ✅ 配音页「手动制作配音」选了模型池里的 API 模型（引擎映射为 qwen、调用方式非 Desktop）时，由程序直连该模型生成音频脚本，不再经 Qwen Code；本机 Codex／Claude／桌面程序路径不变，TTS 原生路径（生成配音、逐句配音）不动。程序打包 S11 SKILL、当前分镜对白与本阶段规则，一次请求让模型同时回 `配音脚本.md` 与整集 SRT；程序校验通过才发布：SRT 编号从 1 连续、时间码合法、每条结束大于开始且不与上一条重叠、不越过分镜总时长；分镜里每句对白在 SRT 与配音脚本中都出现；配音脚本须含每个有对白镜头的编号。不合格带问题清单重试一次，仍不合格不落盘并给出原因。合格经 L3 发布器写入 `音频/配音脚本.md` 与 `字幕/配音_<集号>.srt`；已有配音脚本先备份到 `音频/历史版本/` 且只留 2 份。强制停止可中断请求，停止后不落盘。本需求不改 REQ-S11-04：完成仍以人工确认的音轨清单为准，文字稿与字幕不算完成证据。证据：`tests/test_audio_direct_api.py`。

### 设计条目

- **DES-S11-01**（REQ-S11-01/02/03）阶段顺序在 `pet_bus.STAGES`；目录行 `('11配音与字幕','audio',…,('episode.json',),('voice.json','subtitles.json'))` 在 `stage_layout.STAGES`；依赖 `stage_flow.DEPENDS['audio']=('final',)`，付费 `PAID_STAGES`，并行 `stage_parallel.CONFIG['audio']`（单位=角色轨，`serial=True`，重试 2 次，耗尽转手动）。
- **DES-S11-04**（REQ-S11-04）`media_scope` 取当前已采用分镜及其 sha256；`prepare_media_completion` 做路径限制（须在本阶段 `音频/` 目录内、扩展名限四种、非空）、ffprobe 探测并冻结 `pending_review` 清单；至少一条 `audio_kind==dialogue`；`confirm_media_completion` 仅在人工确认入口调用，写 `成果确认/<fingerprint(source)[:24]>.json`。`_validate_media_completion` 在读取时重核 scope、技术校验、文件大小与 sha256。
- **DES-S11-10**（REQ-S11-10）`AUDIO_KIND_PREFIXES`（旁白_／BGM_／音效_／整轨_）；对白保持原名；`audio_kind` 从文件名前缀推断，识别不出按对白。
- **DES-S11-11**（REQ-S11-11）`import_audio` 做阶段／用途／后缀／空文件检查，目标名 `<标记名>_<6位随机>.<后缀>` 放入 `project_stages.audio(project)`（`<阶段目录>/音频`）；校验与落盘由 `stage_execution_service.media_import_publisher` 注入，经 `publish_imported_media` 用 `agent.media.validate_import`。
- **DES-S11-12**（REQ-S11-12）整段：`script_signature` → `reusable_tts_full_track`／`publish_tts_full_track`。逐句：`build_lines` → `resume_folder` 取续跑目录（`配音分句/`）→ `batch_cost_preview` 只读预览 → 用户确认 → `run_lines`：`freeze_settings` 开批冻结；每句 `RequestLedger.metered_units` 计量；`时间轴.json` 逐句落清单（状态 sending／ok／failed／uncertain，并登记同一请求号 `request_id/cost_request_id` 与 L0 执行身份 `execution.stage/run_id/task_id/attempt_id`；任务中心投影时补项目身份 `project_id`）；`批次.json` 存签名与身份；`line_done` 以 sha256 判定沿用；sending／uncertain 的同身份句子不自动重发；`stop` 事件可中断后续跑。句子身份包含非密钥账号隔离标记 `key_account`（保存密钥时生成或沿用随机本机标记，不写入密钥或其散列）；两边都有标记且不同才算换账号，无标记历史句不因升级自动重发，避免把旧项目成功句重复付费。发布走注入的 `publish_json／publish_bytes`。
- **DES-S11-13**（REQ-S11-13）`voice_for(voices, speaker, name)`：ID 优先，显示名其次，空串=默认音色。
- **DES-S11-20**（REQ-S11-20/22）`_dialogue_rows` 解析对白（字符串旧格式与 dict 新格式）；镜内混合标注直接 `ValueError`；`_distribute` 先扣已知真实时长，剩余按 `line_weight`（可见字符数）分配；已知合计占满或超出镜头则压缩并记 overflow；`calibrate_entries` 返回 (entries, report)，report.mode ∈ estimate／length／mixed／explicit／audio。
- **DES-S11-21**（REQ-S11-21）`validate_entries` 在每次导出前强制调用（`_calibrated`），失败即抛错，不静默修正；`_clamp` 仅用于把作者标注的区间夹进镜头内，不用于修复非法值。
- **DES-S11-23**（REQ-S11-23）`export_srt`：校准 → 校验 → `rows_from_entries` → 注入发布器以 `utf-8-sig` 发布到 `project_stages.subtitles(project)`（`<阶段目录>/字幕`）的 `对白_<6位>.srt`，成功后再发布 `字幕校准.json`（失败只记警告，不影响 SRT）；`export_dialogue_script` 发布 `对白脚本_<6位>.txt`；L2 无发布器时抛 `TypeError`，写盘失败返回 `SystemError`，空对白返回 `UserError`。
- **DES-S11-30**（REQ-S11-30/31）SKILL 由 `skill_registry` 递归扫描 `skills/11配音字幕SKILL/`；总入口 `pipeline-audio-subtitle` 在 `workflow_settings` 阶段默认勾选；`voice-multi-character` 描述标注“已合并”，ID 仅供旧配置兼容。

- **DES-S11-50**（REQ-S11-50）`audio_direct_api`（L3）复用 `storyboard_direct_api` 的执行骨架（`direct_model`、`_Batch`、`_ask`、`Job`／`launch`、取消登记），只新写音频专属部分：`_messages` 组装对白与要求、`parse_reply` 按分隔行 `=====配音脚本.md=====`／`=====SRT=====` 拆回复、`validate_bundle` 校验（SRT 解析复用 `subtitle_timing` 的时间口径，对白覆盖按去空白去标点比较）、`publish_stage_bundle` 发布。分流点唯一：`desktop_idea_chat._FlowAgentLaunch.build()` 中 `stage=='audio'` 分支，调用 L4 `desktop_audio_direct.run_audio_direct`；来源分镜取 `host.current_frame_json()`。发布成功后调用 `refresh_audio_manifests`（失败只记警告）。

7. 「手动制作：配音与字幕」确认窗：摘要行＋「修改配置／直接执行／取消」，由 `orchestrator.stage_models.plan_window`→`ui_stage_popups._show_manual_plan` 构建。

9. 「逐句配音（付费）」确认框：成本预览＋「继续提交？」，由 `desktop_media_pages.generate_tts_per_line`→`media_page_services.confirm` 构建。
10. 「确认本集成果」确认框：校验通过清单＋确认文案，由 `desktop.confirm_stage_media`→`confirm` 构建。
11. 过程与回话区：显示用户在本页发的指令、模型的回话、进度、审批、产物；只是记录，不发给模型；细节见[专题册 08](../specs/08_对话式交互与输出排版.md)。（未实现的目标；来源：用户决定 2026-11-21）
