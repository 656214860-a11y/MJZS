# S10 视频生成

## 需求

目标：把 S08 首帧（及 S09 可播放白模预演）送入云端（万相／Seedance）或本地 ComfyUI，逐镜生成可追溯的视频版本，经技术质检与验收后，成为 S12 后期剪辑唯一认可的成片素材。

### 输入与依赖

- **REQ-S10-01** ✅ 输入是已采用的分镜 JSON（`episode.json`）：每镜须有非空 `video_prompt`、`duration`（2–15 秒）和首帧文件；缺首帧时提示回 S08 生成或导入，不提交。本阶段目录为 `10视频生成`，旧 `09视频生成` 只读兼容。
- **REQ-S10-02** ✅ 本阶段采集并要求三项制作锁值：`aspect_ratio`、`video_model_version`、`delivery_format`（与 S08、S09 相同）。
- **REQ-S10-03** ✅ 流程依赖表 `DEPENDS['video']=('keyframe',)` 只表达视频生成的数据依赖；并非所有视频镜头都需要白模预演。需要预演的复杂镜头由 SG-05 门禁拦截（REQ-S10-04），不把 `previs` 并入依赖表。SKILL 的 `dependsOn: [pipeline-previs]` 保持编排现状，2026-10-20 裁决 B 不修改。
- **REQ-S10-04** ✅ SG-05（白模预演 → 视频生成）：需要白模的复杂镜头必须已有可播放预演才放行；还没有已采用分镜、或没有复杂镜头时放行（只拦“已开始但不完整”）。
- **REQ-S10-05** ✅ 视频生成是付费阶段（与资产管理、配音同属），三虎启动该阶段时按“付费”标记向用户请求批准。
- **REQ-S10-06** ✅ 并发与重试：串行，批 2–3 镜、同时最多 3 个；失败重试 2 次后转人工；视频是唯一处理服务商限流的阶段（降速排队）。

### 生成流程

- **REQ-S10-10** ✅ 提交守卫：离线模式拒绝；同一镜头有未完成或结果不确定的任务时只能查询／恢复，不能再提交；已就绪的视频须先标记“需修改”才能重做，旧版本保留；镜头时长超过剩余制作秒数时拒绝，备用额度不自动动用；先落盘预留版本记录再联网，提交连接中断记为“结果不确定”，不自动重发。
- **REQ-S10-11** ✅ 云端服务商：阿里云百炼万相、火山引擎 Seedance，另可填兼容自定义地址；每个“服务商＋模型＋分镜源”一个会话目录 `cloud_video/<服务商_模型_日期>`；API Key 只存模型池 DPAPI，不写入会话文件；设置页保存不触发提交。
- **REQ-S10-12** ✅ 本地后端：只接受本机回环 HTTP 地址的 ComfyUI；不使用云端额度；提交响应中断时按 `client_id` 在队列与历史中找回任务编号，不重发；无人值守自动补视频只支持本地后端，云端按次计费，必须手动提交。
- **REQ-S10-13** ✅ 逐次调用台账：云端提交前经 `RequestLedger.authorize_units` 授权，终态时 `settle_units` 结算（失败保守保留预算占用）；视频成功落盘后记一笔“条数＋秒数（估算）”请求台账，已按云端结算的版本不重复记。
- **REQ-S10-14** ✅ 查询与取回：任务编号写入 `task_receipt.json`，丢失编号可按回执或手动“恢复任务编号”找回；下载中断保留成功状态、再次查询续取，不重新生成；下载后做技术质检（时长／音轨／分辨率、FFmpeg 解码）；服务商取消或过期只给出原因，不自动重投；提交素材（首帧、白模、参考图）的 SHA-256 来自实际请求的脱敏摘要，缺摘要即拒绝。
- **REQ-S10-15** ✅ 验收：用户可对最新版本通过或标记需修改（仅下载且技术合格的版本可通过），可批量验收；开启“自动验收”时，技术质检通过即放行，记为技术放行而非内容审核；用户可锁定某个已验收旧版本进成片，取消锁定则恢复取最新已验收版。
- **REQ-S10-16** ✅ 镜头正在生成或等待结果时（含其他云会话对同一分镜的任务），不可修改提示词、资产或调用 MCP。
- **REQ-S10-17** ✅ 删除视频镜头只在任务均已确定后打标 `video_deleted`，历史文件与任务记录保留；保存失败回滚内存记录。
- **REQ-S10-18** ✅ 本地与云端“自动验收”读同一个开关 `project_settings.auto_review(项目根)`（持久化在项目 `ui_settings.json`），不再读三虎变量。判据抽为 `engine.auto_review_ready(项目根, 质检报告)`，两路共用：技术质检有错误时一律不放行；开关缺失、读不到或值不是 `True` 时按关处理（默认关）。自动放行只写 `review='pass'`、`review_by='auto'`、`review_note=AUTO_REVIEW_NOTE`，是技术放行而非内容审核。重启后三虎变量回到默认 `False`，但项目设置仍持久化，本地与云端结果一致。

### 产出与完成

- **REQ-S10-20** ✅ 每次提交一个版本目录 `data/<镜头>/vNNN/`（云端工作区为 `镜头/<镜头>/<模型>_<会话>/vNNN/`），含 `request.json`、`assets_manifest.json`、`实际提交提示词.txt`、`task_receipt.json`、`qc.json` 与 `<镜头>.mp4`；版本状态汇总在 `data/state.json`。
- **REQ-S10-21** ✅ 视频阶段清单真实产出：`Studio.publish_manifest` 在视频下载发布、验收（`review`）、选择采用版本（`pin_version`）后，把同一份载荷（`stage`、`shot_count`、`adopted_count`、每镜 `id`／`duration`／`deleted`／`versions`／`adopted_version`／`file`／`sha256`）经 `agent.core.save` 原子写成 `10视频生成/output/videos.json` 与 `video_manifest.json`（落点取 `stage_path_service.write_dir` 与 `stage_layout` 的 `output` 子目录）；采用口径沿用 `adopted_edit_version`；写失败只记警告，不回滚已落盘成片。证据：`engine.py` 的 `video_manifest`／`publish_manifest`、`video_task_state.MANIFEST_NAMES`、`tests/test_video_manifest_scope.py`。（用户裁决“修复”，原 ❓ 已解。镜头删除不触发重写，下一次下载／验收／采用时对齐。）
- **REQ-S10-22** ✅ 阶段完成 = 本集每个未删除镜头都有“已下载＋技术合格＋已验收”且文件与摘要一致的版本（`auto_edit_ready` 返回指纹）。模型文字、界面提示不算证据。注入 `video_ready` 回调时以回调为准（界面传 `studio.auto_edit_ready`）；未注入时按当前镜头 JSON 与 `data/state.json` 做同一选版口径的只读核验（`stage_completion_service.edit_ready_for_project`），页面未打开也能判完成；无镜头 JSON、无已采用版本或摘要不符均判未完成。
- **REQ-S10-23** ✅ 进入成片的版本只认一个口径：锁定版优先，否则取最后一个已验收版；文件缺失、被替换或不可读时该镜判为不可用，不进剪辑。
- **REQ-S10-50** ✅ 视频页「调用 Skill 工作流」（提示词渲染）选了模型池里的 API 模型（引擎映射为 qwen、调用方式非 Desktop）时，由程序直连该模型整理单镜头视频提示词，不再经 Qwen Code；本机 Codex／Claude／桌面程序路径、MCP 优化子进程、分镜定稿原生路径不变。该入口的工作流键是 `video_prompt`（原误传 `final`，`FLOWS` 无此键，会抛“未知的工作流入口”）。程序打包 S10 SKILL、该镜头的定稿 JSON、资产关联与规则文本，只整理文本、不调用视频 API；一次请求让模型只回 `{shot_id, source_signature, video_prompt}` 的 JSON。程序校验通过才落盘：JSON 可解析、`shot_id` 与 `source_signature` 与输入一致、`video_prompt` 非空且不超过 1500 字；不合格带问题清单重试一次，仍不合格不落盘并给出原因。合格由 JSON 序列化器写入 `video_prompts/<镜头>.json`（已有结果先备份到 `video_prompts/历史版本/`），再由既有的 `PromptResults` 轮询经 `publish_video_prompt` 导入并保存；强制停止可中断请求，停止后不落盘。完成与否仍以 REQ-S10-22 的视频核验为准，提示词文字不算完成证据。证据：`tests/test_video_prompt_direct_api.py`。

### SKILL

- **REQ-S10-30** ✅ 本阶段有 5 个 SKILL（`skills/10视频生成SKILL/`）：`pipeline-video-generation`（总入口）、`video-batch-submit`、`video-multi-model-route`、`video-quality-check`、`video-retry`。
- **REQ-S10-31** ✅ “视频 100 镜/项目”上限已在代码实现：`video_task_state.VIDEO_MAX_SHOTS = 100` 与 `shot_count_error(shots)` 是唯一判定（已标记 `video_deleted` 的镜头不计数），`Studio.validate` 在打开本集视频工作台时调用，超限抛出“本项目有 N 个视频镜头，超过上限 100 镜/项目；请把剧本拆成多集或多个项目后再制作视频”，云端与本地工作台共用。证据：`tests/test_video_manifest_scope.py`（用户裁决“修复”，原 ❓ 已解）。
- **REQ-S10-32** ✅ 5 个视频 SKILL 的页面位置已统一为 `pet_bus.stage_label('video')` 现算的“10 视频生成”；`video.batchSubmit`／`retry`／`pause`／`resume` 如实登记为页面动作，不是可由模型直接执行的工具。总入口 `parallelizable: false` 与其余四个 `true` 的元数据差异本批保持现状，另记待裁决。
- **REQ-S10-33** ✅ 视频提示词只写动作与运镜，不重复写场景、人物和风格（场景人物靠首帧图承载）。

### 架构定位

- **REQ-S10-40** ✅ 层级：提交、轮询、验收、拼装在 L3 `engine.Studio`；`cloud_video`、`local_video` 是 L4 页面；`cloud_video_service`、`video_lifecycle_service`、`video_task_state`、`video_source_evidence` 是 L2。`architecture.md` 与 `PROJECT_MAP.md` 原把 `cloud_video`／`local_video` 写在 L2、并称 `cloud_video.py` 负责云端提交与轮询，已按代码更正。

### 非目标（明确不做）

- 不自动重投结果不确定、被取消或过期的任务。
- 不在无人值守下提交云端付费视频。
- 不做配音、字幕、剪辑和交付（S11–S13）。
- 不把技术放行当成内容审核。
- 本阶段不接入腾讯混元（设置页仅有说明链接，标“尚未接入”）。

### 设计条目

- **DES-S10-01**（REQ-S10-01）`stage_layout.py` 登记 `10视频生成`；`stage_path_service.py` 的 `LEGACY_NUMBERED['video']='09视频生成'` 仅供读取。`Studio.validate`校验时长 2–15 秒与非空 `video_prompt`；`Studio.frame`缺首帧时提示回首帧阶段。
- **DES-S10-02**（REQ-S10-02）`script_contract.py` 把 `video` 列入 `STAGE_LOCK_REQUIREMENTS`，字段与 `keyframe`、`previs` 相同。
- **DES-S10-03**（REQ-S10-03）`stage_flow.py` 的 `DEPENDS['video']=('keyframe',)` 是数据依赖；白模预演前置只由 SG-05（`previs_ready`）表达，不是所有视频镜头的必经步骤。SKILL `dependsOn: [pipeline-previs]` 保持编排现状，不并入依赖表。
- **DES-S10-04**（REQ-S10-04）`stage_parallel.py` 的 SG-05 行 `{'id':'SG-05','from':'previs','to':'video','check':'previs_ready'}`；`previs_ready`无已采用分镜或无复杂镜头即放行，其余逐镜用 `previs_routing.ready` 核对可播放预演，缺失的镜头列入问题清单。
- **DES-S10-05**（REQ-S10-05）`stage_flow.py` 的 `PAID_STAGES`；`pet_ui_stages.py` 以 `paid=stage in PAID_STAGES` 调 `agent.approve('stage.run', ...)`。
- **DES-S10-06**（REQ-S10-06）`stage_parallel.py` 的 `CONFIG['video']`（串行、2–3 镜、上限 3、重试 2 次、`on_exhaust` 转人工、`rate_limit=True`）；`rate_limited`只对视频返回真。
- **DES-S10-10**（REQ-S10-10）`Studio.submit`：离线拒绝 → `submission_block_reason`→ 时长对剩余秒数→ 先写 `submitting` 版本再联网。服务端 5xx 与连接中断记 `unknown` 且保留预留，不自动重发。
- **DES-S10-11**（REQ-S10-11）服务商表 `cloud_video_service.py`；会话目录 `session_folder`按“服务商＋模型＋分镜源”复用或新建；`saved_provider_key`优先读模型池，旧 `.env` 只读兼容。`cloud_video.py` 经 `model_pool.save_named_key` 保存密钥，会话配置只写 `key_provider='model_pool'`。
- **DES-S10-12**（REQ-S10-12）`LocalAPI.__init__`仅放行 `http` 与 `127.0.0.1`／`localhost`／`::1`；`reattach`按 `client_id` 找回任务；`auto_plan`遇非 `LocalStudio` 抛错，不静默提交云端。
- **DES-S10-13**（REQ-S10-13）云端：`ledger.authorize_units`→ 提交 → `settle_units`。落盘后 `record_video_usage`记 `videos` 条数与估算 `seconds`，已有 `money_request_id` 即跳过。本地版本 `charged=False`，只走 `record_video_usage`。
- **DES-S10-14**（REQ-S10-14）`task_receipt.json`与 `poll` 的回执恢复；下载失败保留 `succeeded` 并写 `download_error`；质检 `agent.media.check` 加 FFmpeg 解码；`provider_failure_reason`；`submitted_sources`要求 `sha256:` 64 位十六进制摘要。
- **DES-S10-15**（REQ-S10-15）`Studio.review`、`review_many`、`pin_version`；自动验收两路同读 `engine.auto_review_ready(项目根, 质检报告)`，即 `project_settings.auto_review`，本地不再读 `pet_ui.should_auto_run`。
- **DES-S10-16**（REQ-S10-16）`assert_prompt_editable`／`prompt_locked`；`generation_active`还扫 `cloud_video/*/config.json` 中指向同一分镜的其他会话。
- **DES-S10-17**（REQ-S10-17）`mark_video_deleted`遇未决状态返回 `UserError`，发布失败时 `shot.clear()`／`update(previous)` 回滚。
- **DES-S10-18**（REQ-S10-18）`engine.auto_review_ready(project, report)` 是自动技术放行的唯一判据：`not report['errors'] and project_settings.auto_review(project)`；`Studio.poll` 与 `LocalStudio.poll` 都调用它，写入 `review`／`review_by='auto'`／`review_note=AUTO_REVIEW_NOTE`。三虎 `auto_review_var` 仍由 `_set_all_auto_actions` 与项目设置同步写入（兼容既有页面），但不再参与本阶段放行判定。
- **DES-S10-20**（REQ-S10-20）`Studio.task_folder`与 `submit` 落盘的 `request.json`／`assets_manifest.json`／`实际提交提示词.txt`、`publish_downloaded_video`写 `qc.json` 并带 `sha256`。
- **DES-S10-21**（REQ-S10-21）`Studio.video_manifest` 组装载荷，`Studio.publish_manifest` 经 `agent.core.save` 写 `write_dir(project_root(root), 'video')/output/` 下 `video_task_state.MANIFEST_NAMES` 两个同载荷文件；`publish_downloaded_video`、`review`、`pin_version` 在各自状态落盘后调用；`LocalStudio` 继承同一发布点；采用版本用 `adopted_edit_version(versions)`（不带 root，不重算成片哈希，沿用版本记录里的 `sha256`）。云端工作集的清单只反映当前会话工作集。
- **DES-S10-31**（REQ-S10-31）`video_task_state.VIDEO_MAX_SHOTS`／`shot_count_error` 为上限唯一权威；`Studio.validate` 首先调用，`LocalStudio` 同走。

## 交互

### 页面区域

1. 返回区：左上角「返回生成方式」，工作台页固定出现；由 `ui.video_navigation.show_back` 构建。
2. 顶部说明与共享操作行：说明文字（`header_note`）加「刷新镜头」「刷新白模」「查看首帧」，本地工作台再加「启动 H3 / ComfyUI」；由 `ui.shared_video_controls.build` 与 `desktop_media_pages.videos` 构建。
3. 镜头内容框：首列勾选框加十一列数据格（「镜头号」「内容」「选择资产」「秒数」「首帧」「当前任务」「本地进度」「线上进度」「验收」「版本数」「白模 · 上传」），首帧列盖缩略图；由 `app.App._build_shot_table` 构建。
4. 「生成声音 / 音轨」勾选行：仅本地 ComfyUI 工作台显示；由 `app.App._build_audio_options` 构建。
5. 提示词动作行：「手动制作提示词」「MCP 优化」「MCP 设置」「保存提示词」「导入提示词」「当前提示词目录」；由 `app.App._build_prompt_actions` 构建。
6. 提示词编辑区：选中镜头的 `video_prompt` 可编辑文本框；由 `app.App._build_prompt_box` 构建。
7. 底部动作区（页脚两行）：第一行「手动制作视频」「播放视频」「查看全部版本」（本地再加「本地设置」），第二行「通过」「打开素材目录」「恢复任务编号」「打开视频目录」「需修改」「批量生成勾选镜头」「删除勾选镜头」「验收备注：」；由 `app.App._build_video_actions` 构建。
8. 进度与日志区：「打开剪辑成片目录」、进度行（左侧选中镜头状态、右侧本侧进度汇总）、「动态日志」框与「清空日志」；由 `app.App._build_progress_and_log` 构建。
9. 生成方式落地页（未选方式时的整页形态）：说明文字、「开工前先确认」信息卡（分镜／首帧／本地模型／线上模型四行）、「本地生成」卡（「进入本地生成」与无人值守说明）、「线上生成」卡（「进入线上生成」）；由 `desktop_media_pages.video_home` 与 `ui.video_navigation.confirm_rows` 构建。
10. 过程与回话区：显示用户在本页发的指令、模型的回话、进度、审批、产物；只是记录，不发给模型；细节见[专题册 08](../specs/08_对话式交互与输出排版.md)。（未实现的目标；来源：用户决定 2026-11-21）
