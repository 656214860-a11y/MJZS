# S08 首帧管理

## 需求

> 编号说明：代码里首帧管理是第 8 阶段（`pet_bus.STAGES` 共 13 项，目录 `08首帧管理`），不是 07；07 是分镜定稿。本稿用 S08。

目标：为每个已采用的镜头建立一张非空、可追溯、与分镜／提示词／参考资产版本一致的首帧图，作为白模预演和视频生成的唯一画面起点。

### 输入与依赖

- **REQ-S08-01** ✅ 唯一输入是 S07 分镜定稿已采用的分镜（含 `batch_id`、提示词）及其引用的资产参考图。未采用的分镜不产生首帧。
- **REQ-S08-02** ✅ 依赖 S07 完成（`stage_flow.DEPENDS['keyframe']=('final',)`）。S07→S08 的门禁是 SG-03「批次划分」：每镜有 `batch_id`、每批 ≤4 镜且 ≤18 秒、批内三元组一致。
- **REQ-S08-03** ✅ 启动本阶段前必须已填三项制作锁：`aspect_ratio`、`video_model_version`、`delivery_format`；缺任何一项，阶段不启动。锁值由 S01 填写，本阶段只读用。
- **REQ-S08-04** ✅ 空项目（还没有已采用分镜）或本阶段从未开始时，门禁放行；门禁只拦“已开始但不完整”。

### 首帧生成与导入

- **REQ-S08-10** ✅ 首帧只认 PNG：非 PNG、空文件、超过 64MB、校验和损坏的图一律拒绝，且拒绝时不替换已有首帧。
- **REQ-S08-11** ✅ 首帧尺寸必须符合项目画幅锁（`aspect_ratio`）和记录的期望尺寸。
- **REQ-S08-12** ✅ 批量生成有三种模式：只补缺失（默认）、重试失败、显式替换。只补缺失只处理没有首帧的镜头；已成功的镜头永不重复提交；本集之外的镜头不进计划。
- **REQ-S08-13** ✅ 已删除的首帧在任何模式下都不被后台复活；用户须先在首帧管理页恢复。空文件、未配置路径、路径越出当前目录的镜头，列为“不可生成”并给出原因，不静默跳过。
- **REQ-S08-14** ✅ 提交结果不确定的任务（可能已扣费）标“结果待核实”，不自动重提；“记录称已完成但文件不可用”同样要报告。
- **REQ-S08-15** ✅ 首帧提示词取镜头的首帧提示词（`frame_prompt`），缺失时退到关键帧提示词；不得用视频提示词代替。
- **REQ-S08-16** ✅ 手动导入首帧时，导入内容必须对应当前镜头：分镜已被修改、镜头号非法、非 PNG 都拒绝；关联失败时保留旧来源与已发布首帧，不留半成品。
- **REQ-S08-17** ✅ 后台生成结果迟到时，若来源分镜已变化，不采用该结果。
- **REQ-S08-18** ✅ 首帧模型以阶段配置（`stage_config` 的 `keyframe.model`）为唯一来源；可选模型始终含两个原生模型。
- **REQ-S08-19** ✅ 有付费的生成动作；首帧生成动作须在用户确认后执行（流程第 3 步 `needs_confirmation`）。受并行配置约束（`stage_parallel.CONFIG`），限速与同一镜头不并发。

### 追溯与生命周期

- **REQ-S08-20** ✅ 每张首帧在镜头里记录来源校验证据：图片事实（尺寸、哈希）+ 来源分镜、提示词、参考资产的版本哈希。
- **REQ-S08-21** ✅ 校验不通过的原因分明：缺证据（旧首帧）、被外部替换（即使 mtime 相同）、来源分镜／提示词／参考资产变化、参考资产缺版本信息，都要求“重新导入复核”，不静默通过。
- **REQ-S08-22** ✅ 一个镜头的参考资产变化只影响引用它的镜头，不让其他镜头的首帧失效。
- **REQ-S08-23** ✅ 删除首帧走回收站（`storage_maintenance.recycle_paths`），可恢复；删除、恢复、替换都是事务：保存分镜状态失败时回滚到原首帧和原状态；替换会把旧版本放回收站。
- **REQ-S08-24** ✅ 首帧图写入 `08首帧管理/` 下阶段目录；旧目录 `07首帧管理` 只读兼容，不回写。

### 完成与门禁

- **REQ-S08-30** ✅ 阶段完成 = `frames_ready` 通过且本阶段已开始：每个已采用镜头有未删除、位于项目媒体目录内、非空、且通过证据校验的首帧。模型文字、界面提示不算证据。
- **REQ-S08-31** ✅ S08→S09 的门禁是 SG-04「首帧校验」：本阶段已开始但任一镜头缺帧或校验不过，白模预演被阻塞，并说明原因。
- **REQ-S08-32** ✅ 视频生成、本地视频渲染遇到缺首帧的镜头：拒绝并指向首帧管理页，跳过时给出“尚无首帧”的原因，不用空图顶替。

### 产出清单

- **REQ-S08-40** ✅ 阶段产出清单统一为 `stage_layout` 契约名 `08首帧管理/output/frames.json`（用户裁决：修复，让代码与文档一致）。阶段核验 `frames_ready` 通过、发出完成事件前，`stage_completion_service.publish_stage_manifest()` 把已采用分镜每镜的 `frame`、`frame_deleted`、`frame_evidence.image.sha256` 写入该文件；它是回执，不是完成证据（完成仍只认 REQ-S08-30 的核验），写入失败则本次完成不成立。流程模板第 4 步改为“写入 frames.json”（action `write_frames_manifest`），`architecture.md` 不再出现 `keyframe_manifest.json`。
- **REQ-S08-41** ✅ `pipeline-keyframe` SKILL 的 `output` 里的 `keyframeManifest` 是逻辑名，落盘文件即 `frames.json`（SKILL 正文已写明对应关系；`不得发布 keyframeManifest` 的门槛措辞保持不变）。

### SKILL

- **REQ-S08-50** ✅ 本阶段 6 个 SKILL：总入口 `pipeline-keyframe`；`firstframe-batch`（批量生成，付费）、`firstframe-auto-fill`（缺帧自动补，付费）、`firstframe-retry`（只重试失败项，付费）、`firstframe-quality`（质检，免费）、`firstframe-thumbnail`（缩略图，免费）。
- **REQ-S08-51** ✅ 总入口 SKILL 依赖 `pipeline-storyboard-final`，约束“每个首帧文件非空、绑定镜头和资产版本、失败不发布半成品”。
- **REQ-S08-52** ✅ 首帧批量出图选了模型池里的 API 模型（`current(root,"assets")["engine"]=="qwen"`）时，程序先静默拉起 ComfyUI，再在后台线程里直接执行 `image_agent_runner.execute()`，不再启动 Qwen Code Agent；Codex／Claude 引擎路径不变。批次与 `执行状态.json` 语义不变，既有轮询按镜头导入；失败写 `failed` 并说明原因，强制停止可中断（停止后未出图镜头保持待导入，可重新提交）。证据：`tests/test_image_direct.py`。

### 非目标（明确不做）

- 不改写分镜、提示词或批次（属 S07）。
- 不做白模预演和视频（属 S09／S10）。
- 不在本阶段采集制作锁（属 S01）。
- 不接受 PNG 以外的首帧格式。

### 设计条目

- **DES-S08-01**（REQ-S08-01/02）`stage_flow.DEPENDS['keyframe']=('final',)`；`stage_layout` 行 `('08首帧管理','keyframe',…, 输入 episode.json、assets.json)`。
- **DES-S08-03**（REQ-S08-03）`script_contract.STAGE_LOCK_REQUIREMENTS['keyframe']=('aspect_ratio','video_model_version','delivery_format')`，`stage_handler_registry.start` 对非剧本阶段按它取必填锁。
- **DES-S08-04**（REQ-S08-02/04）`stage_parallel.GATES` 含 `SG-03(final→keyframe, batches_ready)`、`SG-04(keyframe→previs, frames_ready)`；`frames_ready` 在没有已采用分镜时返回放行。
- **DES-S08-10**（REQ-S08-10/11）`keyframe_evidence.image_facts` 全量解码 PNG 一次（按内容哈希缓存，不信文件名／mtime），拒绝非 PNG、空文件、>64MB、CRC 错；`_check_dimensions` 校验画幅。
- **DES-S08-12**（REQ-S08-12/13/14）`keyframe_batch` 的 `STATE_*` 状态机与 `MODE_MISSING/RETRY/REPLACE` 计划；`ATTEMPT_NOTES` 区分 sending／uncertain／completed／pending／cancelled。
- **DES-S08-15**（REQ-S08-15）首帧提示词取 `frame_prompt`，缺则 `keyframe_prompt`，不读视频提示词。
- **DES-S08-16**（REQ-S08-16/17）`keyframe_import.register` 在来源指纹不符时拒绝；关联失败保持旧来源与已发布首帧。
- **DES-S08-18**（REQ-S08-18）`keyframe_model_service.current_model` 读 `stage_config` 的 `keyframe.model`。
- **DES-S08-19**（REQ-S08-19）`stage_parallel.CONFIG` 对 `keyframe` 限速，`parallel_map(…, resource=镜头号)` 保证同镜头不并发。
- **DES-S08-20**（REQ-S08-20/21/22）`keyframe_evidence.make_evidence` 写 `frame_evidence{version:1, image, expected_size, aspect_ratio, source}`；`source_evidence` 只取该镜头引用的资产，故其他镜头不受影响；`frame_problem` 返回可执行的复核原因，空串表示通过。
- **DES-S08-23**（REQ-S08-23）`keyframe_lifecycle_service.delete/restore/replace_keyframe` 经 `storage_maintenance.recycle_paths`／`restore_latest_recycled_*`，保存分镜失败回滚；L2 要求 L3 注入发布回调。
- **DES-S08-24**（REQ-S08-24）`stage_path_service.write_dir(project,'keyframe')`；`LEGACY_NUMBERED['keyframe']='07首帧管理'` 经 `read_dirs` 只读回退。
- **DES-S08-30**（REQ-S08-30/31）`frames_ready` 读已采用分镜的 `frame`／`frame_deleted`，路径须在 `media_root` 内，非空，且 `frame_problem(…, aspect_ratio=workflow_lock(project)['aspect_ratio'])` 为空；`stage_completion_service` 的 `checks['keyframe']='frames_ready'`，要求 `ok` 且 `started`。
- **DES-S08-32**（REQ-S08-32）`engine.py`、`app.py`、`local_video.py` 缺首帧时抛错／跳过，并经 `pet_bus.stage_step('keyframe')` 指向本阶段。
- **DES-S08-50**（REQ-S08-50/51）SKILL 位于 `skills/08首帧管理SKILL/`；`skills/templates/keyframe_process_template.yaml` 四步，第 3 步 `needs_confirmation`。
- **DES-S08-52**（REQ-S08-52）与 DES-S05-50 共用同一分流点与 `image_direct`／`desktop_image_direct`；`keyframe_import.launch` 对 qwen 引擎经 `open_direct_flow_agent` 提交 `direct={"image": 批次.json}`，保留 `app.launch_comfy(silent=True)`。
- **DES-S08-40**（REQ-S08-40/41）`stage_completion_service.publish_stage_manifest(root, 'keyframe')`：遍历 `stage_parallel._adopted`，每镜取 `frame`／`frame_deleted`／`frame_evidence.image.sha256`，经 `agent.core.save` 写入 `write_dir(root, 'keyframe')/output/frames.json`；`emit_verified_completion` 在核验通过、发完成事件前调用，失败返回未完成。SKILL 的 `keyframeManifest` 是该文件的逻辑名。

## 交互

### 页面区域

1. 镜头内容框区：首帧勾选列表，每行一个镜头，列为「镜头／内容／秒数／首帧状态／图片文件(点击查看)／首帧图片提示词(点击查看)」，勾选列在 `#0`；由 `_FirstFramePage._build_state_and_table` 构建。
2. 选中镜头行（紧贴内容框下方）：左侧「选中镜头」下拉框，右侧依次是刷新、查看与文件维护按钮；由 `_FirstFramePage._build_state_and_table` 构建（`target_row`）。
3. 底部操作行：主按钮「手动制作首帧」；由 `_FirstFramePage.build` 构建（`actions`）。
4. 空项目提示区：没有已采用分镜时整页只放提示文字与「去第03步」按钮；由 `StoryboardPageMixin.storyboard` 构建。
5. 过程与回话区：显示用户在本页发的指令、模型的回话、进度、审批、产物；只是记录，不发给模型；细节见[专题册 08](../specs/08_对话式交互与输出排版.md)。（未实现的目标；来源：用户决定 2026-11-21）
