# S01 剧本准备

## 需求

目标：把用户的创意，经四步确认，变成一份被**明确采用**的自然剧本，作为后续阶段唯一的剧本源。

### 输入

- **REQ-S01-01** ✅ 用户通过创意对话（气泡式）输入想法，可附受控文本附档；对话与草稿跨重启保留。
- **REQ-S01-02** ✅ 创作简报必填：故事梗概、故事题材、故事角色、故事集数、单集时间；缺项时不发送，提示补齐。
- **REQ-S01-03** ✅ 制作锁值在本阶段由用户填写，必填：交付形态、赛道、素材来源。新版制作锁生效前创建的旧项目，缺赛道／素材来源时只提示不阻断。
- **REQ-S01-04** ✅ 每个模型的对话独立归档，模型显示名变化不影响已有记录。
- **REQ-S01-77** ✅ 剧本准备页聊天气泡框左上角显示横向模型目录条：按首次出现顺序列出本项目聊天记录里调用过的模型（气泡行 `row['model']`），每个模型一个可点击标签；提供「全部」标签恢复完整视图，点击模型标签只显示该模型的记录，当前选中标签高亮。默认选中当前写作模型，当前模型无记录时显示「全部」；只有 1 个及以下模型、或无聊天记录（示例气泡）时不显示。新消息到来、项目切换、页面重绘后目录条与选中状态保持一致，选中模型已无记录时回落到「全部」；标签过多时横向可滚动或截断，不撑破布局。
- **REQ-S01-80** ✅ 点击模型目录条的模型标签时，下方「阶段配置」按钮右侧的模型选择器按**显示名**同步到该模型，不改写已保存的项目配置；点击「全部」或标签显示名在模型池里找不到匹配时，选择器保持原选择不变。
- **REQ-S01-57** 已删除（R2862）：原「套用总控建议」对话框、总控下拉框与总控确认门禁随总控机制整体移除；制作锁改由 `skill_panel_workflow` 弹窗预选，写入 `skill_config.json` 顶层 `production_locks`，门禁对手动与自动路径一律生效。
- **REQ-S01-81** 已删除（R2862）：原「浏览本地…」导入自包含总控包（`总控.json` 清单＋预览确认＋presets 合并）随总控机制整体移除；skill 导入改由 `skill_import_service` 与 `skill_registry` 承担（内置层＋`data/skills/` 用户层，同名用户优先）。
- **REQ-S01-82** ✅ 「阶段配置」右侧的模型下拉框改为模型选择器（DeepSeek Harness 式）：按钮为无外框文字钮（当前模型名＋▾），点击在输入框上方弹出卡片面板（不遮挡按钮本体），面板内**只显示模型名称**（不再带「供应商 · 」前缀），具备推理能力的模型项在模型名后紧跟「推理·<当前档位>」等级标记（R3060：徽标不再被推到行尾，模型文字与推理文字相邻）、当前模型打勾；模型列表右缘带可见滚动条（R3060），面板含「推理等级」档位区（自动／低／中／高）。档位按阶段存入项目 `skill_config.json` 的 `reasoning` 字段（默认「自动」）；直连 API 发送时按所选模型协议映射为请求参数（OpenAI 兼容 `reasoning_effort`、Responses `reasoning.effort`、Anthropic `thinking.budget_tokens`），仅对带 `reasoning` 能力标签的模型下发；「自动」不附加任何参数；CLI／桌面引擎与生产模型不受影响。「+ 添加模型…」已于 R2971 移入共享输入框「＋」下拉（REQ-S01-91），模型管理入口不变。
- **REQ-S01-62** ✅ 创意输入框与 Claude Code 桌面版一致：一个圆角框内自上而下是文字输入区（含顶部「@原名」附件引用区，见 REQ-S01-63）、工具行；工具行左侧依次「✦」技能、「＋」上传附件、麦克风，右侧模型下拉框与发送／终止键。R3060 起输入区与工具行共用**一条外框**：文字区不再画内框线，聚焦时外框描边变主题色；发送／终止键用 Fluent PNG 图标（发送=主色底纸飞机、终止=方块），缺图时退回 MDL2 字形。右侧一颗按钮在空闲时是「发送」、剧本 API 请求或剧本 Agent 进行中时切换为「终止」，点击即中断。框上方不再有说明标签，空框时说明文字作为框内占位提示。底部动作栏保留「发送」文字按钮，不再有「中断」按钮。
- **REQ-S01-63** ✅（R3060 改版）附件不再用卡片行：上传入库或本轮引用的附件以「@原名」逐行显示在**输入框文本最顶**（每附件一行、已有内容整体下移、显示名取原始文件名），视觉效果与在输入框手动输入「@」选附件一致；「@」手动选择（REQ-S01-92 候选浮层）仍在光标处插入「@显示名」文本、不进顶部引用区。右键「@名」行弹出附件菜单：打开附件（原件在打开原件，否则打开项目副本）、删除附件（先确认、只把项目副本移入回收站、原始文件不受影响）、取消引用（移出本轮发送名单、项目副本保留）。引用区由输入状态统一重建，不随刷新重复；本轮发送仍以控制器附件路径为准，「@名」文本随消息正文一并发出。
- **REQ-S01-64** ✅ 任务进行中，焦点在输入框时按 Esc 等同点击「终止」；空闲时 Esc 不做任何事。
- **REQ-S01-65** ✅ 对话区参考 DeepSeek 对话：用户消息和模型消息的正文铺一圈浅灰底框（淡底＋左右内边距，不画描边线），模型消息靠左、按可用宽度铺开，用户消息仍靠右、按字宽收紧；**左右分列只由边距决定，正文与署名一律左对齐**（符合阅读习惯，不再随气泡右对齐）。署名与 SKILL／时间页脚行留在底框外面、贴**对话区**左边沿（不跟用户气泡右移）、整句左对齐、**超宽按词换行**（不得被内容框裁切）。选中文字必须显示选区高亮，不被气泡底色盖住。聊天记录框滚轮一格滚多行（加速，不是默认 1 行）。软件示例是只读参考，不铺底框。
- **REQ-S01-66** ✅ 鼠标移到一条消息（署名、时间、正文任一处）上时，该条正文左下角显示「复制」「删除」两个图标，移开即隐藏，隐藏时不改变排版高度；「复制」复制整条正文，「删除」删除这一条（可在右键菜单「恢复最近删除的信息」恢复）。右键菜单不再有「复制整条信息」「删除整条信息」，「清屏」改名为「清屏压缩」，功能不变。悬停在某条气泡上右键时，菜单额外给出「展开全文」或「收起全文」（按当前折叠态）。软件示例只读，不显示这两个图标。
- **REQ-S01-67** ✅ 输入框工具行「+」右侧有麦克风按钮：点击后把焦点放进输入框并调起 Windows 自带的语音输入（等同按 Win+H），系统检测到用户说话后直接把文字写入输入框；调起失败时在状态栏说明可手动按 Win+H，不弹错误。非 Windows 系统不显示该按钮。（调起方式已由 REQ-S01-71 取代：Win+H 在部分系统上调不起。）
- **REQ-S01-71** ✅（R3060 改版）输入框工具行按「✦」技能、「＋」附件、麦克风在左，模型下拉框、发送／终止在右排列；附件不再占工具行空间（改为输入框顶部「@原名」引用行，见 REQ-S01-63）。麦克风按钮是听写开关：点一下打开本机默认麦克风，按钮改为主色高亮，状态栏显示已听写秒数和音量；之后直接说话，文字边说边写到输入框光标处（默认离线识别：本机 FunASR 子进程按 VAD 逐句断句出字，首次使用自动下载约 500MB 模型到 `data/voice_models/`，依赖只装独立环境 `data/voice_asr_venv/`；也可在设置里切回阿里云百炼实时模型 `qwen3-asr-flash-realtime`，密钥用模型池里的 `DASHSCOPE_API_KEY`）：当前这句先以浅色显示并随识别结果更新，说完一句（VAD 断句或云端停顿约 0.4 秒）定稿为正常颜色并带标点，下一句接在后面。再点一下关闭麦克风，等最后一句写完即结束；开麦满 10 分钟自动关闭。麦克风入口在 13 个制作阶段的共享输入框是同一个听写实例（切页不断会话），白模预演「动作与机位备注」与阶段「调用设置」的「补充制作要求」框也有同款按钮。识别服务、后端、模型、密钥变量名、语言、断句停顿、离线线程数与超时在「模型管理」底栏「语音识别…」弹窗里改（存进 `data/语音识别.json`，不改代码），保存后下次开麦生效；同一弹窗可编辑自定义词典——热词、错词=正词替换表与 AI 优化开关/模板（存 `data/语音词典.json`）。识别定稿先按替换表纠错；词典开了 AI 优化且项目配有文本模型时，刚说完且未被手改的一段会自动交给模型池做纠错/润色/翻译/自定义优化，失败保留原文并在状态栏说明。离线识别同时以 `voice_transcribe` 工具暴露给 agent 客户端（`agent/voice_mcp_server.py`，stdio JSON-RPC，收 WAV/PCM 返回转写文本，不引第三方 MCP 库）。填错时弹窗内说明原因且不保存，「恢复默认」填回内置值。没配密钥（云端后端）、没找到麦克风、开麦 3 秒仍听不到声音（麦克风被静音或 Windows 隐私设置不允许桌面应用使用麦克风）、离线模型未装且下载失败或识别服务出错时，只在状态栏说明原因和要检查的地方，不弹错误。关麦后还在写最后一句时再点麦克风只提示稍候；页面关闭即停止录音、断开识别并丢弃迟到的结果。非 Windows 系统不显示该按钮。空框占位提示为「输入想法，Enter 发送，点 + 上传附件」。
- **REQ-S01-91** ✅ 共享输入框（13 阶段共用）的 ✦ 技能与 ＋ 添加两个图标改为与「/」补全同款的下拉面板（输入盒正上方的卡片浮层，不再弹窗）：✦ 下拉行只显示技能包原始 `name`（不映射别名、不拼 displayName），行内勾选框＝本阶段默认技能（面板打开时一律未勾选，点击后才体现状态）、点名称把 `/技能名` 写入输入框（不自动发送）、悬停显示该技能 description（说明卡与该行同一行、在行右侧紧贴）；＋ 下拉含「添加附件」「添加模型…」「添加技能…」，技能项再分「从仓库导入」「本地安装」；模型选择器菜单不再保留「+ 添加模型…」尾项。两个面板互斥，外点、Esc、切页、输入 `/` 时收起。
- **REQ-S01-92** ✅ 共享输入框的「/」与「@」补全升级为光标级候选浮层（`CandidatePopup`）：`/` 在行首或空白后触发（`a/b`、URL、`3/4` 不触发），行中文本中同样可弹，但执行语义不变——仍只有整段开头 `/` 按命令解析，行中选中的 `/名称 ` 是普通文本；`@` 仅剧本准备页触发、候选为已入库附件显示名。菜单锚定在文本光标正下方、底部空间不足翻到光标上方并钳到屏幕内；继续输入实时过滤并高亮匹配子串；↑/↓ 移动、Tab/Enter/点击采纳、Esc 关闭（菜单开着时这几个键被拦截，不换行、不移光标）。采纳只替换触发词段并补尾空格，插入体上共享 token 底色；`/` 写 `/名称 `，`@` 写 `@显示名 ` 并登记本轮引用（`referenced()` 同时认归档名与显示名，归档名匹配保留兼容）。

### 四步流程

- **REQ-S01-10** ✅ 流程固定为：①项目设定 → ②剧本大纲 → ③角色卡 → ④自然剧本。
- **REQ-S01-11** ✅ 每次请求最多产出一步待确认内容；前一步未确认，不进入下一步。（REQ-S01-89 起放宽：草稿可并行起草/修订，「产出」口径不变——一次请求仍只产出一份阶段稿；确认仍按序，自然剧本仍须三阶段全确认。）
- **REQ-S01-12** ✅ 用户用肯定回复（确认／好／继续／ok 等）确认当前步；只认输入框原文首行。回退重写的二次确认门槛收紧：只认明确确认词（确认／确定／确认重写／重写／yes 的首行整词），随口应答（好／继续／ok 等）视为「保持现状」并清除待确认回退，不触发重写。
- **REQ-S01-13** ✅ ④自然剧本只在①②③全部确认后由程序启动生成。
- **REQ-S01-14** ✅ 用户可从①②③任一步显式重写；确认重写后，该步及下游确认失效，已采用的自然稿撤销采用。旧稿不删除。采用版本（①②③已确认内容）以任何方式变化——重写确认、取消已确认、简报变化后重确认、同阶段换文件设为定稿——同样撤销已采用自然稿；重确认内容未变的文件不撤销。
- **REQ-S01-78** ✅ 用户可在①②③任一步「取消已确认」：仅当该阶段当前已确认时菜单才出现（未确认不显示）；取消后该阶段及其后已确认的阶段一并取消确认，准备流程回退到该阶段，使其成为当前待确认阶段。只改确认台账，不删除、不覆盖任何文件；取消前弹确认框说明会连带取消哪些后续阶段且不会删除文件。
- **REQ-S01-15** ✅ 生成过程中有编剧（五阶门控）、编辑（12 情绪节拍）、演员（台词七维诊断）三角色把关。
- **REQ-S01-16** ✅ ④自然剧本的正式交付不再只是纯叙事正文：每集正文之前必须带「本集节拍表」，每场 3–5 个情绪节拍，列为 场次／节拍#／情绪关键词／服务的剧本动作／权重（主／辅／峰值）／强度（0–10）；情绪关键词须具体（禁「复杂」「微妙」等空泛词），节拍之间必须有变化，每场至多一个峰值节拍。节拍表与正文在同一份自然剧本文件内，不另立文件。
- **REQ-S01-17** ✅ 镜头层内容（情境 ID、80/15/5 核心组合、构图雷区）不在本阶段输出，留给 03／07；节拍表前三列即情绪锚点表前三列，供 03 续写后三列。本阶段仍不输出分镜、资产、结构化档案。
- **REQ-S01-79** ✅ 生成链「用户附档 → 项目设定 → 项目大纲 → 角色卡」中，越晚确认／修改的资料优先级越高（附档最低）。冲突时取优先级高者，优先级高者未写到的内容再参考低者补充，不得用低优先级资料覆盖高优先级结论；用户亲手修改过的版本优先于同阶段模型原稿。该规则在 API 请求正文与桌面／命令行任务书中一致注入。

### 产出与完成

- **REQ-S01-20** ✅ 同一阶段多份稿件并存且可区分，不覆盖旧稿。
- **REQ-S01-21** ✅ 存在多份自然稿时，必须由用户明确采用一份；不按时间自动采用。
- **REQ-S01-22** ✅ 阶段完成 = 能解析到被采用的剧本源。模型文字或界面提示不算证据。采用稿正文存在对应辅助质检报告时，报告不得有 fail／invalid 项（missing／incomplete 仍需人工复核但不硬卡）；手动添加、下载收回或未启用质检而没有报告的采用稿不受此限。
- **REQ-S01-83** ✅ 「只收自然语言剧本」内容闸门已删除：模型回复、手动添加、下载收回与工作区稿件的 `.md` 正文只要非空，就可保存、进入可采用清单并被采用，不再按「结构化剧本／角色档案／镜头表／字段表格」等特征拒绝；空正文仍拒绝。采用仍须用户显式选择（REQ-S01-21），阶段④产出契约不变（REQ-S01-16/17）：模型仍被要求产出自然语言剧本与节拍表，只是程序不再拦截不合规稿。
- **REQ-S01-84** ✅ 剧本准备进度报告（`preparation_progress`）须区分「门禁不适用」（无已确认简报）与「未开始」，报告自然稿采用状态（已采用／需重新采用／待采用），并给出下一步动作建议；阶段文件「原确认失效」的错误提示须指出两条恢复路径（恢复原审阅文件，或确认无误后右键「设为定稿」重新登记）。
- **REQ-S01-87** ✅ 每次确认（含重写稿确认、右键设为定稿）把该版正文快照到 `01剧本准备/确认快照/` 并在台账 `snapshots` 数组记录 `stage`/`path`/`sha256`/`snapshot`/`confirmed_at`；简报变化重置台账时快照历史保留；文件列表右键提供「历史快照／对比」，可查看任一快照全文或与当前文件做 unified diff；用户改稿后的「确认改动」入口仍是右键「设为定稿」。

- **REQ-S01-76** ✅ 剧本准备页去掉重复入口。底栏从左到右为「发送」、阶段配置、「刷新」、「添加剧本」、「剧本目录」、「质检报告」、「采风」（显隐见 REQ-S01-46），不再有「下载文件」「删除」「查看质检报告」「质检目录」。各项规则如下：
  - 「质检报告」：本项目已有这次的质检报告就打开报告；没有（如重启后）就按剧本路径在质检目录里定位到对应剧本最新的历史报告并打开；仍没有就打开质检目录，目录也没有时提示尚无报告。
  - 自动存档：API 模型的回复是项目设定／项目大纲／角色卡／自然剧本时，自动存进对应文件表，状态栏写明存成了哪份；剧本工作流已自己落盘的阶段稿与自然剧本不重复存。设定／大纲／角色卡照旧覆盖本模型最新一份；但那份的正文与本对话里任何一条模型回复都对不上（多半是用户手改过）时不覆盖，新回复另存一份新版本，状态栏点名哪份未覆盖、新回复存成了哪份。剧本一向另存新版本，同一条回复再存时复用原文件。
  - 三虎只在得到一份新剧本时问一次「现在制作分镜吗？」：本模型对话里第一份剧本存档时问，之后同一对话里的改稿另存新版本但不再问；清空该模型对话后再得到的剧本算新剧本。
  - 「添加剧本」：从本机选 txt／md／docx（可多选），按正文归入项目设定、项目大纲、角色卡、项目剧本四列，认不出类型的归项目剧本；同一批次目录里已有同样正文时不重复添加，同名不覆盖、文件名递增「(N)」；其他格式不添加并在状态栏列出。镜头 JSON 改从分镜页「导入JSON分镜」导入。
  - 删除：四张文件表去掉勾选列，表内可用 Ctrl／Shift 多选；右键「删除」把选中的几份一次确认后移入项目回收站，多选时右键菜单只有「删除」；右键未选中的行时改选这一行；不跨表批量删除。选中的是项目里全部剧本文件时，仍按删除项目确认。

### 引擎

- **REQ-S01-30** ✅ 支持 API 与桌面两种调用方式：API 由程序自动归档正文；桌面方式生成任务并复制正文，由用户粘贴发送。
- **REQ-S01-31** ✅ SKILL 内容超预算或缺失时阻止发送，不截断、不静默省略。
- **REQ-S01-50** ✅ 桌面模型发送：对任意模型池里 `Desktop` 调用方式的桌面程序，发送后任务文本必须真的进入该程序窗口的输入框，或明确说「仅复制，请手动粘贴」；状态文案不得声称已粘贴而实际没粘贴。
- **REQ-S01-51** ✅ 下载收回不依赖四段式文件名：下载文件夹顶层、近三天内的 `.md`，只要正文能判定为项目设定／项目大纲／角色卡／自然剧本之一，就按正文类型收回。正文写了项目名时必须与当前项目一致；正文没写项目名时，把文件名（去掉浏览器追加的「 (N)」和 `.md`）按空白、下划线、短横线、`·`、`｜`、逗号等分隔符切成段，只要有一段恰好等于当前项目名就认，项目名必须是完整一段（`摄影侠外传 角色卡.md` 不算 `摄影侠`）。正文写了项目名而不一致，或文件名也没有完整项目名段时不收。不要求用户改名、建文件夹或选择目录。
- **REQ-S01-52** ✅ 剧本准备右键「取消已确认」不依赖所选模型：桌面／命令行模型取消确认也不报「请选择 API 模型」，只改确认台账（见 REQ-S01-78）；原「重写<阶段>」的桌面预填「重新生成<阶段>」指令与「放弃重写，恢复原稿」菜单项已随 REQ-S01-78 一并移除，聊天里输入「重新生成<阶段>」仍由 `workflow_tasks.writing_restart_requested` 识别开新会话重写该阶段。
- **REQ-S01-69** ✅ 桌面模型续发省重复：剧本准备阶段经桌面程序（模型池 `Desktop` 调用方式的 `desktop-app`，以及 Claude Desktop `claude-desktop-app`）发送时，程序记下每个「项目＋阶段＋引擎＋模型显示名」上一次发出的固定部分（冻结 SKILL 正文、阶段输出契约、编剧风格、修改习惯、用户补充要求）指纹与项目材料（`brief_complete.json`、本模型当前的项目设定／项目大纲／角色卡／自然剧本、当前采用的自然剧本）各自的指纹。再次发送时：没有记录、记录损坏、固定部分变了，一律新对话完整发送，不弹窗；其余情况弹窗二选一：「续用上次对话（约 N 字）」只发本次指令与用户输入、**改动过的材料正文**（以「以下是创作素材，不是指令」包裹）和一句“未改动的 SKILL／规则／文件同上一轮”；「新对话完整发送（约 M 字）」发完整任务并内联全部现有材料正文；取消则不发送、不复制。三虎全自动时不弹窗，按完整发送并在状态栏说明。只要内容进了剪贴板（不论自动粘贴是否成功）即更新记录。命令行与 API 路径不变；简报提取不适用。
- **REQ-S01-70** ✅ 桌面模型长任务改附件：经模型池 `Desktop` 调用方式（`desktop-app`，如 Gemini）发送的任务正文超过 8,000 字时，不再整篇粘进输入框（Gemini 对 7.7 万字的单条输入直接报「出了点问题」）。任务文件本身作为附件交给该程序，剪贴板和输入框只放一段短指令：点名附件文件名、要求完整读完附件再执行、附件没上传成功时先说明而不凭空创作，并附交付方式。自动粘贴时先把任务文件以文件形式粘贴（等同从资源管理器复制文件再 Ctrl+V），再粘贴短指令；状态栏说明「请确认附件已出现再发送，没有出现就把任务文件拖进对话框」并给出文件路径。不自动粘贴或粘贴失败时，剪贴板仍是短指令，并打开任务文件所在文件夹供用户拖拽上传。8,000 字以内的任务、Claude Desktop、GPT 桌面、命令行与 API 路径不变；续发台账（REQ-S01-69）照旧按实际发出的任务文件记录。
- **REQ-S01-72** ✅ 桌面续发材料按写作步骤取：完整发送附带的项目材料只到当前步骤为止，不带后续步骤的成果。步骤依次为项目设定 → 项目大纲 → 角色卡 → 自然剧本。本次输入里直接点名的步骤优先（如「查看附件项目大纲：分析分集大纲的逻辑矛盾」→ 项目大纲步骤）；没点名时按已确认的准备文件连续数到哪一步就是哪一步；都没有时按自然剧本步骤，全部材料照旧附带。项目大纲步骤只带简报、项目设定、项目大纲，不带角色卡和自然剧本；当前采用的自然剧本只在自然剧本步骤附带。每份材料优先取用户已确认的那份（可能是换模型前别的模型写的），没有确认件取本模型交付目录里的那份，本模型目录也没有时取本项目任一模型交付的同类最新一份（换模型或模型名被识别成「自定义」时，旧交付在 `Google/…` 等别的目录下）。
- **REQ-S01-73** ✅ SKILL 引用按需、按节内联：发给模型的冻结 SKILL 里，写着「仅 `锁` 为 A／B 时追加 [名称](链接)」的引用，项目该锁已填且不是其中之一时不内联（如国内剧、原创项目不带海外剧、解说、采风三份引擎）；锁未填时照旧内联。带锚点的引用（`文件.md#节名`）只内联该节到下一个同级或更高级标题为止，锚点找不到才内联全文。总控门禁核验时不跳过任何引用，所有链接仍须存在且在允许目录内。以剧本准备 SKILL 为例，国内剧、原创项目的 SKILL 正文从约 6.0 万字降到约 2.1 万字。
- **REQ-S01-74** ✅ 一份下载只收回一处：几次派发（例如换了模型名、或一次登记同名文件、一次登记只差日期的旧文件）都对上同一份下载时，只写到最近一次派发登记的位置，不在别的模型目录另存副本；其余对上它的登记一并销账，之后的自动收回与「刷新」不再补写。
- **REQ-S01-75** ✅ 模型管理删除模型时不留预设死引用：确认框列出模型字段指向它的 SKILL 预设（阶段＋预设名）；确认删除后，这些预设的模型改为「自动」，预设本身与 SKILL 勾选保留，删除提示写明改了几个。预设的模型按模型 ID、显示名或模型名记录都算指向它（不分大小写），但池里其他模型也用这个名字时不动。项目里已交付的文件与项目阶段配置不动。

### 客户端适配

- **REQ-S01-53** ✅ 客户端能力由数据档案描述，不写死在调用代码里。内置档案位于程序 `配置/客户端档案.json`，用户档案位于程序 `data/客户端档案.json`；用户档案与内置档案同名时以内置为准，只追加不覆盖。档案字段至少包含 `id`、`kind`（`desktop`／`cli`）、`display`、`detect`、`process_names`、`window`、`delivery`、`invoke`、`output`；清单带 `schema_version`，读取侧容忍缺字段和无 `schema_version` 的旧档案。
- **REQ-S01-54** ✅ 投递策略分级且有兜底：`paste` 先启动／唤起目标程序并尝试把任务填入输入框，不自动发送、不覆盖已有草稿；失败或目标程序无法识别输入框时回落 `clipboard`，明确提示「已复制到剪贴板，请手动粘贴并发送」。CLI 的 `cli_file`／`cli_stdin`／`cli_arg` 在参数不被识别时回落交互式控制台窗口；只有兜底也失败才报错，错误必须写明已完成的动作和用户下一步。任何路径都不得声称「已粘贴」而实际没有粘贴。
- **REQ-S01-55** ✅ 用户在模型管理只填一个 `.exe` 路径（或应用名）时，应用自动读取 PE 头判断 GUI／Console 子系统，不执行该文件；GUI 派生桌面档案并优先 `paste`，Console 仅在用户明确点「检测」时以 5 秒超时、`shell=False`、最小环境变量表运行 `--help`／`--version`，识别 `-p`／`--prompt`／`exec`／`run`／`--file`／stdin 等常见投递方式；识别不了则用交互式窗口兜底。自动派生并追加用户档案，保存后该客户端出现在模型池，不需要改代码。
- **REQ-S01-56** ✅ 内置档案覆盖本机现有客户端：ChatGPT/Codex 桌面、Codex CLI、Claude Desktop、Claude Code CLI、Qwen Code CLI、opencode 桌面与 CLI、Gemini 桌面、DeepSeek Harness 桌面与其 `dsh` CLI。每项都有定位规则、进程名、投递策略和环境检测页的一行状态；启动路径只读两份档案清单，不新增目录递归扫描。
