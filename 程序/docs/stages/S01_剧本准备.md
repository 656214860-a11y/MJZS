### 四步流程

- **REQ-S01-10** ✅ 流程固定为：①项目设定 → ②剧本大纲 → ③角色卡 → ④自然剧本。（LOST-04 注记：用户 11-22 23:12 第 1 条取消先后依赖链，四份文档任意顺序、任意组合生成，见 REQ-S01-111；本条仅保留阶段名册含义。）
- **REQ-S01-11** ✅ 每次请求最多产出一步待确认内容；前一步未确认，不进入下一步。（REQ-S01-89 起放宽：草稿可并行起草/修订，「产出」口径不变——一次请求仍只产出一份阶段稿。LOST-04 注记：「确认仍按序」「自然剧本须三阶段全确认」已取消——各阶段独立确认，已采用自然剧本即可进入④，见 REQ-S01-111。）
- **REQ-S01-12** ✅ 用户用肯定回复（确认／好／继续／ok 等）确认当前步；只认输入框原文首行。回退重写的二次确认门槛收紧：只认明确确认词（确认／确定／确认重写／重写／yes 的首行整词），随口应答（好／继续／ok 等）视为「保持现状」并清除待确认回退，不触发重写。
- **REQ-S01-13** ✅ ④自然剧本只在①②③全部确认后由程序启动生成。（LOST-04 注记：已取消——用户点名自然剧本或模型按语义判定进入④时即可启动，不要求①②③全确认，已确认阶段稿作为参考上下文，见 REQ-S01-111。）
- **REQ-S01-14** ✅ 用户可从①②③任一步显式重写；确认重写后，该步及下游确认失效。旧稿不删除。已采用的自然剧本不随①②③的变化撤销（用户 2026-11-22 裁决：设定、大纲、角色卡、自然剧本四份文档各管各的，原来的顺序链取消）：生成新稿、重写确认、取消已确认、简报变化后重确认、同阶段换文件设为定稿、按段落采用，都只改剧本准备台账，不动自然剧本的采用记录。此前已被撤销的项目（采用记录是空的）程序不替用户补回，需要用户重新采用一次。

- **REQ-S01-30** ✅ 支持 API 与桌面两种调用方式：API 由程序自动归档正文；桌面方式生成任务并复制正文，由用户粘贴发送。

- **REQ-S01-51** ✅ 下载收回不依赖四段式文件名：下载文件夹顶层、近三天内的 `.md`，只要正文能判定为项目设定／项目大纲／角色卡／自然剧本之一，就按正文类型收回。正文写了项目名时必须与当前项目一致；正文没写项目名时，把文件名（去掉浏览器追加的「 (N)」和 `.md`）按空白、下划线、短横线、`·`、`｜`、逗号等分隔符切成段，只要有一段恰好等于当前项目名就认，项目名必须是完整一段（`摄影侠外传 角色卡.md` 不算 `摄影侠`）。正文写了项目名而不一致，或文件名也没有完整项目名段时不收。不要求用户改名、建文件夹或选择目录。

### 页面区域

1. 模型目录条：聊天气泡框上方的横向滚动标签条，每个已调用模型一个标签（右上角 × 清空该模型历史），选中高亮、无记录隐藏；由 `IdeaBubblesMixin.build_idea_model_bar`/`render_idea_model_bar` 构建。
