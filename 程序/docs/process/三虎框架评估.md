# 三虎框架评估：要不要引入 GitHub 桌面宠物框架

> 出处：用户 2026-11-22 22:45 第 4 条（丢失需求清单 LOST-07）——「三虎不够智能，评估 GitHub 成熟的桌面智能宠物框架，目标是更好帮用户完成短剧创作而不是摆件」。
> 评估基线：`6e687b94`；查证日期：2026-11-23。代码行号以本工作树为准。

## 结论（先看这里）

**不引入外壳，只借用「决策层」设计，落到现有模块。**

一句话理由：三虎不是摆件——「听懂 → 审批 → 执行 → 播报」的闭环、真实盘上数据、主动提示和自动链推进都已存在且在跑（见第一部分）；而三个候选全是 Qt 系独立应用，许可证、依赖白名单、Tkinter 基调、分层登记、事件／启动／删除唯一入口七条硬约束无一例外冲突（见第二部分）。「不够智能」的真实缺口在**决策层覆盖面**（单步意图、快照缺数据、主动检测只有五类），不在缺一个外壳；这三处都能在现有 `pet_agent`／`pet_llm`／`pet_ui_voice`／`pet_ui_stages` 内补齐，且不新增顶层模块、不动契约层（见第三部分）。

## 一、三虎今天能做什么

### 1. 一句话能触发哪些动作

链路：云朵输入 → 后台线程 `dispatch` 只出结论 → UI 线程 `run_plan` 落地（`ui/pet_cloud.py:1212-1273`、`ui/pet_ui_stages.py:467-534`）。

- 意图来源三级：SKILL 点名（`pet_agent.py:171-209`）→ 规则表 `RULES`（`ui/pet_agent_rules.py:13-59`，命中不花 Token）→ DeepSeek Flash 兜底，只认一行严格 JSON `{intent, stage, params, reply}`（`pet_agent.py:258-283`、`infra/pet_llm.py:67-75,86-95`）。
- 规则表已覆盖：进度／面板／用量／详情、暂停／继续／重试／跳过、静音／日报／周报、切档位、项目清单、一键执行、增量自检与三项优化检查、导出交付、13 个阶段的 `goto`、首帧／分镜／视频的 `generate`（`ui/pet_agent_rules.py:13-59`）。
- `run_plan` 登记的可执行意图共 20 余种：`goto` 翻页、`generate` 派发、`skill` 走编排器、`export` 带路、`oneclick` 一键收尾、`retry/skip/pause/resume/model/details/level/projects/report/weekly/test/performance*`（`ui/pet_ui_stages.py:481-527`）；**未登记的意图一律不动手**（`:527`）。
- 审批：`approve()` 按只提醒／半自动／全自动三档决定跑、确认还是只提示，付费动作白名单固定（`pet_agent.py:727-754`、`:45`）。

### 2. 能读哪些页面／项目状态

- 给模型的固定快照 `context()`：项目名、当前阶段、百分比、自动化档、失败阶段清单、项目列表、待答提问（`pet_agent.py:985-1005`）。
- `progress()`：阶段机进度、摘要、缓存命中率、Flash 占比、当日 Token、暂停与档位（`pet_agent.py:1007-1018`）。
- 真实盘上计数 `counts()`：剧本／分镜／镜头／首帧／已采用／资产（`ui/pet_ui_voice.py:416-439`）；缺口 `gaps()`：未采用分镜 JSON、缺首帧镜头（`ui/pet_ui_voice.py:441-468`）；忙闲 `busy()` 只认 running／retrying（`ui/pet_ui_voice.py:469-481`）。
- 阶段状态机 `infra/pet_state.Machine`：pending／running／success／failed／retrying／skipped 六态，事件驱动、落盘恢复（`infra/pet_state.py:14,24-115`）；上游门禁 `blocked_reason()` 给人话（`pet_agent.py:838-840`、`ui/pet_ui_stages.py:373-392`）。

### 3. 阶段能不能推进、卡住会不会主动提示

- **能推进**：非只提醒档下 `agent.advance()` 给出下一阶段（`pet_agent.py:1020-1027`），心跳 `tune_advance` 把它叫醒（`ui/pet_ui_stages.py:152-193`）；`start_stage` → `pet_start` → `stage_handler_registry.start()`（`ui/desktop_pet_bridge.py:54-66`、`orchestrator/stage_handler_registry.py:104`）。手动档也能 `goto` 翻页、`generate` 派发——首帧走本机 ComfyUI 免费通道、分镜走 Agent 准备链，付费阶段只带路不代按（`ui/pet_ui_stages.py:430-461`）。自动链由 `script.completed` 武装，逐阶段推进、失败即阻塞（`ui/pet_ui_stages.py:96-118,254-288,340-357`）。
- **会主动提示**：150ms 心跳 `pump()` 依次做事件分发、通知聚合播报、云朵回答回贴、失败播报、进度气泡、日报周报提醒、一键执行征询、自动推进（`ui/pet_ui.py:626-663`）；免打扰 23:00–07:00 只记账、出窗补汇总（`pet_agent.py:959-971`）；预算越线暂停并上报（`pet_agent.py:850-865`）；门禁阻塞补一句人话（`ui/pet_ui_stages.py:400-410`）。

### 4. 对照「只是摆件、不会干活」的具体情形

| 用户感受（对应 LOST-07「不够智能」） | 现状判断 | 缺什么 |
| --- | --- | --- |
| 一句话让三虎「把这集做完」 | 规则表与 `run_plan` 只支持**单步**意图；`TASKS` 里的 `plan.multi_step` 是写作 API 的任务，不是 dispatch 的消费端（`infra/pet_llm.py:93`、`ui/pet_ui_stages.py:481-527`） | **缺能力**：无多步计划产出与执行器 |
| 问「项目进展／还差什么」答得笼统 | `counts()`/`gaps()`/门禁明细都是真实数据，但没进 `context()` 快照（`pet_agent.py:985-1005` vs `ui/pet_ui_voice.py:416-468`） | **缺接线**：数据已存在，没喂给路由与应答 |
| 三虎不会自己发现问题 | 主动检测已有五类：未采用分镜、缺首帧（`pet_ui_voice.py:455-468`）、失败待确认、门禁阻塞、收尾征询；**没有**「阶段停滞」「质量类（节奏／一致性）」检测 | **缺能力**：检测器覆盖面窄 |
| 三虎只是个会说话的猫 | 不成立：已能派发 SKILL、推进 13 阶段、出日报周报、按档审批（本节 1–3） | 本质是**决策覆盖窄＋主动性覆盖窄**，不是没有执行能力 |

## 三、结论：不引入外壳，只借用「决策层」设计

### 为什么不是另外两项

- **整体引入**：三个候选都是「Qt 外壳＋自带 agent 循环」的完整 App，与本产品的 13 阶段流水线、事件契约、审批闸、预算台账零共享；引入即推翻 Tkinter 基调与全部硬约束，换来的「智能」是通用桌面助手能力（聊天、看屏幕、操作电脑），与「帮用户完成短剧」不对口。代价远大于收益。
- **不值得做**：不成立——缺口是真实存在的（第一部分第 4 节），只是解法不在外面。

### 借鉴落点（全部在现有模块内，不新增顶层模块、不动 `contract/`）

参照系：miku-on-desktop 的「纯函数状态机＋受限工具集 agent loop＋主动交互调度」与 Lazily01 的「工具即意图注册表」思路；**只借设计，不搬代码**（两仓许可证均未查明，DyberPet 为 GPL-3.0）。

1. **多步计划意图**：`route()` 目前只产单步 plan（`pet_agent.py:258-283`）。借 agent loop 思路，把 `intent.route` 的输出契约从单步扩为「有序步骤表」，仍走 `approve()` 同一审批闸、`run_plan` 同一执行器逐步落地。落点：`pet_agent.py`（route/dispatch）、`ui/pet_agent_rules.py`（规则表）、`infra/pet_llm.py`（`SYSTEM_PREFIX`/`TASKS` 增计划任务）、`ui/pet_ui_stages.py`（`run_plan` 增计划执行）。
2. **快照接数据**：`context()` 只带阶段级字段（`pet_agent.py:985-1005`）。把 `counts()`/`gaps()`/`blocked_reason()` 的真实缺口接进快照（数据已在 `ui/pet_ui_voice.py:416-481`），`intent.route` 的 `reply` 即可基于事实回答「进展／还差什么」。落点：`pet_agent.py`（context 组装）、`ui/pet_ui_voice.py`（提供只读摘要）、`infra/pet_llm.py`（快照上限 `REQUEST_CONTEXT_MAX_CHARS` 内消化）。
3. **主动性扩容**：现有五类检测器（第一部分第 3 节）可再借「主动交互＝事件＋空闲＋安静时段」调度思路，加两类：**阶段停滞**（`running` 超时无 `detail` 增量，数据在 `infra/pet_state.Machine.detail()`）与**质量提示**（节奏／一致性已有 `pipeline-pacing-check`、`storyboard-consistency-lock` 等 SKILL 可复用作检测源）。落点：`ui/pet_ui_voice.py`（gaps 增检测）、`ui/pet_ui.py`（复用既有 150ms `pump()` 节拍，不加线程不加定时器）。
