# 实机走通清单（发布前人工验收操作表）

登记：2026-11-25（REL-12）。来源：`docs/process/联调测试出口基线.md` §2 手工步骤列、§4 三条 A 级「待实机复验」、`docs/requirements/产品需求规格.md` §10 八项待真实验收项、REL-03／REL-04／REL-14 落地结果与 REL-07 遗留复验。

性质：**操作表**，只登记「人在真机上怎么点、看什么、证据存哪」。本表是投影，权威源是产品代码与测试断言；步骤与界面不一致时以代码为准，并把差异记进执行记录。AUD-REAL 已按用户决定不自动执行真实链路，本表只把「实机走一遍」落成可照做的步骤，不代替执行。

## 0. 使用口径

- **执行人**：开发者本人（产品负责人）。`scripts/dev.py release-gate` 的自动判定不覆盖本表；「实机清单已执行并有证据目录」是发布检查单里的人工确认项，由执行人在发布前逐项走完并留证。
- **分档**：**免费档**（第一层）只走界面与本机文件，不调用付费模型、不联网请求供应商，约 60 分钟可走完；**待真实使用档**（第二层）需要真实模型、真实剪辑软件或用户参与，对应 PRD §10「待实际使用阶段验收」口径——发布前不强制，但步骤与证据位先备好，启动后按表执行。
- **环境**：已安装副本或开发副本均可；界面操作用 `启动漫剧制作助手.pyw` 正常启动。同一次走查只在一台机器上串行做，不与自动测试、别的会话并行抢界面。
- **证据**：每步证据写进 `程序/验收证据/<YYYYMMDD>/` 目录，文件名 `REL12-<编号>_<主题>.md`，截图、录屏、命令输出附同目录。证据文件提交进 Git（PRD §10 验收流程第 2 条）；原始数据不进 PRD 正文。
- **判定**：每步记 通过／不通过／不适用（缺硬件或环境）／未执行（需付费留待真实使用档）。「不适用」「未执行」不算通过；第一层有不通过即按发布检查单 §3 处理，不进入发布。
- **执行记录**：走完一次在文末 §4 填一行（日期、机器、代码版本 `git rev-parse HEAD`、各组结论）。

## 3. 与其他文档的关系

- **release-gate**：`scripts/dev.py release-gate` 负责机器可判定的 8 项（随包工具、CI、全量收据、分发自检、版本一致、升级保留用例、NOTICE、证书告警）；本表负责机器判定不了的人工项，两者合起来才是发布前的完整确认。「实机清单已执行并有证据目录」作为人工确认项登记，不由门禁自动判定。
- **发布检查单**：`docs/process/发布检查单.md` 管「合入后怎么发」（构建、安装、观察、回滚）；本表管「发之前真机走一遍验收什么」。发布顺序：release-gate 绿 → 本表免费档走完并留证 → 发布检查单。
- **联调测试出口基线**：本表 §1.2 对应其 §4 三条 A 级挂账、§2.1 对应其 §2 手工步骤列；某条实机复验通过后，按基线 §7 维护检查单回写其状态列。
- **PRD §10**：本表 §2.2 是 §10 的操作化；验收完成后按 §10 流程回写其状态列与证据索引。
