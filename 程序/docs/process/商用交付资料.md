# 商用交付资料核验

先在质检交付页完成媒体技术校验和人工确认，再点击“生成商用待填资料”。填写生成的 pending.json 后，通过“核验商用交付资料”导入。原待填文件不会覆盖；更换成片或分镜必须重新审核。

该入口核验记录完整性及文件是否改变，不判断法律效力、不运行自动内容识别，不替代权利人的授权或审核人的判断。技术成果确认不会自动获得商用通过。生成待填资料时会从已确认交付版本出发，沿 edit_bundle.json、镜头 assets_manifest.json 与「产物来源关系.json」中已登记的来源边递归盘点实际采用文件；没有登记边的外部精修、定制工作流内预置媒体和其他未知项仍不能自动证明完整，必须由 inventory_reviewer 实名补齐并将 inventory_complete 设为 true。

categories 必须包括 script（剧本）、reference（参考）、image（图像）、video（视频）、music（音乐）、font（字体）、voice（声音）。每项素材登记在 items 中；未用类别填写 unused_reason，剧本和视频不能空缺。生成素材也要登记平台／模型与适用授权凭据，声音需记录声音来源和必要的授权。

每条 items 记录字段：path（项目内相对文件路径）、sha256（文件SHA256）、source（来源及版本）、rights_holder（权利人）、license（适用许可或授权范围）、commercial_allowed、derivative_allowed、obligations_fulfilled（后三项须有依据才能填 true）、authorization（包含授权凭据本地相对 path 和 sha256）。所有凭据须非空且在本项目内，原件或授权说明应留存；不可随意填 true。

content_review 中 infringement、nsfw、sensitive 分别登记侵权、成人内容及敏感内容审查。每项必须填写 reviewer、evidence（具体审核记录与处置说明），全部未决问题处理完才将 status 置为 cleared。无自动检测能力时由人工逐镜检查画面、音轨、字幕及参考素材；空记录或 pending 不能通过。

scope、outputs 是系统生成的版本绑定字段，不要手工改成另一版。核验通过会保存独立 commercial.json；再次核验时会重新检查媒体及全部引用文件摘要。通过只表示提交的证据满足程序规则，并非保证商用合法。

video 清单必须覆盖每个实际交付文件的路径与摘要，不能用其他有授权的视频代替。成片旁存在 edit_bundle.json 时，还会检查其成片摘要，并要求全部已登记镜头来源摘要出现在授权素材清单中；遗漏或过期来源清单不能通过。未登记的外部制作来源仍需审核人补齐。

script 清单必须覆盖采用分镜 source_script 按项目规则解析出的实际剧本路径与摘要；无独立来源链接时，须覆盖采用分镜文件本身。来源缺失、越出项目或格式无效时不能通过。其他作品的授权资料不能代替；此检查只覆盖已知关联，外部未登记来源仍由审核人补齐。

font 清单须覆盖 edit_bundle.json 登记的实际叠字字体路径与摘要。旧成片目录存在 font.ttc 时同样要求授权，不能填写未使用或放入其他类别代替。字体变化须重新核验；未登记的外部字体仍需人工补齐。

新成片的 manifest.source 相对成片目录记录实际镜头路径（跨盘保留绝对路径）；核验要求来源位于项目内且视频类别授权覆盖该路径与摘要。旧清单没有路径时只能核对视频类别摘要，无法证明原路径，需要审核人补齐来源。

生成待填资料会预填已知剧本、成片、镜头、参考、音乐、字体及 edit_bundle 逐镜 audio 边登记的声音文件摘要，同类别同路径去重，授权字段仍为空或 false。inventory_warnings 与 inventory_trace 提示无法自动盘点的来源、缺失或越出项目的文件、版本变化和未登记来源边；它们不是审查结论。核验覆盖不全时会把多个缺项合并成一条错误，分别列出类别与文件、摘要或来源边，避免首个缺项吞掉其余待办。交付页会按当前文件重新比对已填资料，分开显示遗漏、来源变更、人工补录与未登记来源边。须逐项补全来源和授权凭据，处理提示，并人工补齐未关联来源，最后确认清单完整。

新剪辑成片会从各镜头旁 assets_manifest.json 的 assets 保留生成时参考资产路径与摘要到 references，待填资料预填 reference 类别；即使旧 edit_bundle 未展开 references，商用盘点也会沿镜头来源递归读取仍可用的 assets_manifest.json。核验要求参考或图像类别覆盖该路径与生成时摘要，不能以替换后的参考图或其他类别代替。旧任务无资产清单及外部编辑未登记来源仍需人工补齐；此功能不证明未知来源不存在。

R1556起，云视频新请求将实际嵌入请求的首帧和白模摘要写入资产清单：首帧在成片 references 中标记 category=image，白模使用 reference。摘要来自实际请求而非后来重读文件；未提交的白模不登记。旧记录不会自动补造历史证据；已登记进 edit_bundle 的音乐与逐镜声音会进入自动盘点，未登记音乐、声音及其他外部来源仍须人工补齐。

R1557起，本地Comfy视频会在提交生成前保存首帧和已上传参考图的实际字节摘要，随后与云视频共用成片来源及商用核验链。只覆盖应用实际上传的文件；自定义工作流内预置媒体及外部音轨仍需人工登记，旧任务不会补造上传证据。

R1558起，音频与外部成片导入旁保存 .source.json 来源记录，记录原始位置和已导入副本摘要，许可状态始终 unknown。商用资料可预填已登记成片的外部来源，并在 source_receipt 中冻结来源记录文件摘要；核验已提交音频/视频授权条目时同时检查现有导入记录，来源记录缺失、内容被改或与素材摘要不一致都不能通过。没有 source_receipt 快照的旧资料，只要条目仍使用模板写出的“外部导入：…”来源，也会比对该来源文字，不能只改 .source.json 的来源字段静默通过。音频阶段全部文件不等于成片采用音轨，仍须审核人明确实际采用项；来源记录不能代替授权。
