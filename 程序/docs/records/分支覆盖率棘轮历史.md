# L0/L1 分支覆盖率棘轮报告（T8.4）

- 工具：`scripts/branch_coverage_report.py`（开发期工具，不进发布包；零第三方依赖，`sys.settrace`）。
- 范围：`tests/architecture/_layers.py` 登记层 0/1 的 80 个顶层生产模块。
- 口径：**决策点双结果覆盖**——`if`／`while`／`for`（含 async）／`try`（含 `except*`）／`match`
  每个决策点要求两个方向都被真实执行过才算覆盖，单侧命中不算。
  - `if`：体入口被访问 ∧ 存在「测试行→体外」弧（else 入口、join、循环头回边、函数出口均可）。
  - `while`/`for`：体入口被访问 ∧ 迭代器/条件正常走完（`break`、`return` 离开不算走完）；
    `while True` 恒真循环改用「体→走出整个 while 范围」作为第二结果。
  - `try`（仅带 handler 的）：任一 handler 行被访问 ∧ 存在「try/else 行→handler 之外」的干净弧。
  - `match`：任一 case 体入口被访问；末位非 `case _` 时还要求「selector 行→走出 match」落空弧。
- 动态证据按 `(文件, co_qualname)` 归属代码对象作用域，嵌套函数／类／推导式返回不会
  污染外层分支判定（有专门用例 `test_nested_function_scope_isolated` 锁定）。

## 不计入分母的边界（诚实声明）

- 单行复合语句（`if x: y`、`while x: break`、`case 1: a=1`）：测试与体同一行，行粒度不可分辨。
- 表达式内短路：`and`／`or`、三元 `IfExp`、推导式 `if` 子句——与 coverage.py 行弧口径同级。
- `try/finally`（无 handler）：没有可见分支。
- 异常路径只记真实发生的；被吞掉的异常不产生证据。

  `script_contract` 29.9%、`platform_tools` 36.5%；13 个模块 0 决策点记 100%。

  （实测百分比向下取整，只许人工上调，工具重测不改写）。

  下限不回退／工具可用性四件事，不重跑测量）；工具单元测试 `tests/test_branch_coverage_report.py` 22 条。

## 口径提醒

这是**定向测量**：只覆盖登记的 64 组用例碰到的路径，不是全量套件分支覆盖率；
0% 模块只说明这组用例没走到，不等于整仓无覆盖。刷新基线须显式重跑工具
（命令见工具 docstring），目标用例失败时工具拒绝写基线。
