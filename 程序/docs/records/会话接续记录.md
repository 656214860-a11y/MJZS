# 会话接续记录

用途：每个结束或中断的会话在这里留一节，写清楚做到了哪里，供下一个接手的模型读。接手时先读最后一节，再用仓库现状核对：提交、分支、合并队列以仓库为准。

和其他文档的分工：

| 要找什么 | 看哪里 |
|---|---|
| 会话做到哪了、下一步做什么 | 本文件 |
| 用户提过的要求落在哪条规格 | [对话需求追溯](对话需求追溯.md) |
| 和用户怎样配合 | [用户沟通与要求标准](../process/用户沟通与要求标准.md) |
| 主干当前状态、全量欠账 | [project_status.md](../../project_status.md) |
| 某一轮改了什么 | `tasks_round/tasks_round_<轮次>_result.md` |

## 维护办法

1. 一个会话一节，标题写「日期 · 会话 ID 前缀」，新的一节加在文件末尾。
2. 每节写六段：目标；已定的决定；已完成（带轮次号和提交号）；进行中；等用户确认的问题；下一步。
3. 只写去标识的摘要。不抄聊天原文，不写姓名、账号、密钥、本机路径和用户项目内容。
4. 会话收尾时写。会话很长时，每做完一个阶段就改本会话那一节，直接改，不另起一节。
5. 每节注明「截至」时间。之后仓库有变化的，以仓库为准。
6. 2026-11-20 之前的会话没有回补；要回补时另出任务卡。
