# 项目文件整理与文档简化 — 诊断报告

> 只读诊断轮（AGENTS.md §3.5）。本报告不修改任何 `.py`、不搬目录、不删文件、不领轮次号、不提交。
> 产出日期：2026-11-13。审阅后按 §「执行顺序」分轮执行。

## 一、结论摘要

项目规模：3386 个被 git 跟踪文件；`程序/` 下 1037 个顶层 py 模块、634 个测试、254 个 SKILL 文件。

本次诊断识别出三类可整理内容，按风险从低到高：

1. **未跟踪历史现场**（低风险，可直接归档）：`工作流任务/` 705 个文件（33MB）、重复图标、空目录。
2. **已跟踪但已停更的历史文档**（中风险，需 git 提交）：`.agent-handoff/`（29 文件）、`程序/HANDOFF*.md`（9 个）、`crud_audit_20260926.md`。
3. **文档冗余/膨胀**（需分轮简化）：`README.md` 2169 行中约 85% 是逐期界面变更日志；`使用说明.md` 阶段数过时（12 vs 13）。

**不可动的核心结论**：`skills/` 目录（254 个 git 跟踪文件）是运行时依赖，其 13 个阶段 `.skill.md`、`templates/`、`00全流程SKILL/总控.json` 与 `AIGC创作全流程` 包被 `skill_registry.py` / `workflow_settings.py` / `master_skill.py` 硬编码加载，**不能随意删除或合并**；`docs/stages/` 是唯一需求-设计真源，被测试门禁锚定。

**但 skills 并非完全无整理空间**：探查发现 4 个「断链预设」和少量死文件（见 §八），这些是真实缺陷，属于「修复」而非「删除」范畴。

## 三、文档简化方案（分轮执行，每轮 ≤3 模块）

### 1. README.md 瘦身（优先级最高，收益最大）

**现状**：2169 行。真实构成：

- 第 1~5 章（1~331 行，15%）：SKILL/模型路由说明正文——配置、扩展 SKILL、新增模型、预设。
- 第 6~33 章（332~2169 行，85%）：「六、第 45 期」到「三十三、第 70 期」逐期界面变更日志，中间夹第 61~71 期的一次性交付物（目录树、JSON Schema、SKILL 去重清单等）。

**方案**：
1. 保留 1~331 行正文 + 精简的「当前状态摘要」。
2. 将 332~2169 行整体迁入 `程序/维护记录/归档/2026-11/README_界面变更日志.md`。
3. README 正文末尾留一行链接指向归档。

**必须遵守的锚点**（否则测试红）：
- `tests/test_app_metadata.py:93` 校验 README 首行标题含 `app_metadata.APP_NAME`（=「漫剧助手」），不得改标题。
- `tests/test_line_endings.py:38` 钉住 README 行尾为 CRLF，迁移时用 `line_endings.write_text` 保持 CRLF。
- README 是 `distribution_manifest.md:20` 的「面向用户随附说明」，瘦身后仍须覆盖完整功能说明（不能只剩导航）。

## 八、skills 目录的断链与死文件（新增发现，属「修复」而非「删除」）

探查 `程序/workflow_settings.py` 的 `SKILL_PRESETS` 时发现 **4 个断链预设**，其 folder 键指向的实际路径已因目录移动而失效，导致这些预设**在 UI「常用 Skill」下拉框里根本不出现**：

| 预设 | folder 键 | `_bundled_skill` 拼出的路径 | 实际位置 | 状态 |
|---|---|---|---|---|
| 万能剧本工作流 | `coconah-ai-short-drama-agent-skill` | `skills/screenplay/SKILL.md`（经 alias） | `screenplay` 目录已不存在 | **完全死链** |
| 鲸剧工作流 | `jingju-skills` | `skills/jingju-skills/SKILL.md` | `00全流程SKILL/jingju-skills/` | 断链（位置变了） |
| 导演分镜 | `cinematic-director` | `skills/cinematic-director/SKILL.md` | `00全流程SKILL/cinematic-director/` | 断链 |
| Blender 白模 | `create-blender-story-video` | `skills/create-blender-story-video/SKILL.md` | `09白模预演SKILL/create-blender-story-video/` | 断链 |

根因：`workflow_settings.py:138-143` 的 `SKILL_ALIASES` / `_bundled_skill(folder)` 直接拼 `skills/<folder>/SKILL.md`，但第三方 skill 曾被移入 `00全流程SKILL/`、`09白模预演SKILL/` 子目录，预设表未同步更新。

影响：`skill_panel_support.py` 的 `flow_skill_choices()` 和 `workflow_settings_dialog.py` 用 `preset_skill(folder).is_file()` 过滤，所以这 4 个预设不显示；`defaults()` 里 `writing`（默认 `coconah-ai-short-drama-agent-skill`）和 `previs`（默认 `create-blender-story-video`）的默认 SKILL 实际为空。

**修复方案（二选一，执行时定）**：
- 方案 A（推荐，与整理方向一致）：在 `SKILL_ALIASES` 补映射，把 3 个仍存在的 folder 指向子目录；`screenplay`（万能剧本工作流）因源目录已消失，评估是补回目录还是从预设表移除。
- 方案 B：把第三方包移回 `skills/` 顶层（恢复历史位置，与整理方向相反，不推荐）。

**死文件/重复包装**：
- `skills-lock.json`：全仓无代码读取（仅自引用和 R811 诊断），是待接线的死文件。
- `skills/storyboard-image-prompts/.agents/`：与顶层 `SKILL.md`/`agents/`/`references/` 完全重复，可归档 `.agents/`。

**孤儿 gitlink**（无 `.gitmodules` 的 160000 子模块指针）：`00全流程SKILL/AIGC创作全流程`（总控依赖，不能动）、`01 剧本准备SKILL/剧本锻造`、`01 剧本准备SKILL/编剧技能集`（第三方剧本包，可评估）。
