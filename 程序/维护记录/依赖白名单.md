**生效轮次**：R3199 起

---

## 一、白名单策略

项目从 R3199 起放开"零第三方依赖"约束，采用**谨慎白名单**策略：

- 只白名单经过评估的、久经考验的库
- 新库逐个评估，满足条件才加入白名单
- 白名单库预装在 `运行环境\Python\Lib\site-packages\`，用户无需自行安装

## 三、新库评估标准

新库加入白名单需满足以下条件：

1. **兼容性**：
   - 纯 Python 实现，或有 Windows x64 预编译 wheel
   - 支持 Python 3.14+
   - 无需用户编译或额外配置

2. **稳定性**：
   - 5 年以上维护历史
   - API 稳定，无频繁破坏性变更
   - 有清晰的版本策略（如 semver）

3. **职责单一**：
   - 单一职责，不引入重度框架
   - 传递依赖 ≤ 5 层
   - 总体积增量 < 10 MB

4. **社区支持**：
   - PyPI 下载量 > 1000 万/月
   - GitHub stars > 5000（如果开源）
   - 活跃维护，安全漏洞快速修复

5. **项目需要**：
   - 替换自实现模块，或提供标准库没有的关键功能
   - 预期省开发/维护时间 > 5 天

---

## 四、禁止清单

以下类型的库**不允许**加入白名单：

- UI 框架（除 Tkinter 标准库外）
- Web 框架（Django、FastAPI、Flask 等）
- 数据库 ORM（SQLAlchemy 等）
- 深度学习框架（TensorFlow、PyTorch 等）
- 重度依赖的库（传递依赖 > 10 个）

---

## 五、门禁检查

架构门禁测试 `tests/architecture/test_dependency_whitelist.py` 守卫（只统计
`sysconfig` purelib 即随包环境，不扫描用户级 site-packages）：

1. 随包环境内的所有第三方分发包都在白名单内
2. 白名单库的版本与记录一致
3. 白名单中的库都已安装（随包环境完整）
