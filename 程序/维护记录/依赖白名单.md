# 第三方依赖白名单

**更新日期**：2026-12-08  
**生效轮次**：R3199 起；R3224 拆分生产锁与开发可选允许项；R3671 准入 psutil 与 nvidia-ml-py

## 一、策略与权威源

项目采用白名单准入：按实际用途逐项评估依赖，生产运行环境只交付已批准的生产包。

已登记能力优先复用成熟实现，不自造通用轮子。新增任何依赖前，先证明标准库与现有已批准包确实不足；再造轮子必须在当轮结果文件写明理由、替代方案与实测依据。准入不降低——「允许引入」指的是允许在证明必要后引入，不是默认放行。

- `程序/requirements.txt` 是生产依赖名称及精确版本的唯一权威，包含直接依赖和传递依赖，不另建依赖管理器。
- 当前生产锁包含八个 distribution：requests、urllib3、certifi、charset-normalizer、idna、Pillow、psutil、nvidia-ml-py。本页不复制版本表；升级时修改生产锁并验证实际安装结果。
- 开发工具只供维护、静态检查和探针使用，不进入产品 runtime；现有维护环境可保留批准的可选工具，生产包不必安装这些工具。
- 测试只读取当前解释器 `sysconfig` 的 purelib 内实际 distribution，不扫描、清理或修改用户 site-packages。

## 二、生产依赖及用途

| 包 | 角色 | 用途与边界 |
| --- | --- | --- |
| requests | 直接依赖 | 已批准的 HTTP 客户端；本轮只锁定依赖，不改 HTTP 实现 |
| urllib3 | requests 传递依赖 | HTTP 连接与连接池 |
| certifi | requests 传递依赖 | CA 证书集合 |
| charset-normalizer | requests 传递依赖 | 字符编码识别 |
| idna | requests 传递依赖 | 国际化域名处理 |
| Pillow | 直接依赖 | 产品图像处理与缩略图能力；从旧开发工具表移入生产必装 |
| psutil | 直接依赖（R3671 准入） | L1 资源感知：内存、磁盘读写、网络计数、进程树；惰性导入，不在启动关键路径 |
| nvidia-ml-py（导入名 pynvml） | 直接依赖（R3671 准入） | 可选显存采集；惰性导入，无 NVIDIA 驱动即降级 |

requests 的修复依据见官方 [HISTORY.md](https://github.com/psf/requests/blob/main/HISTORY.md)。生产验收只接受当前锁定版本，不因旧维护环境仍装有旧版本而同时放行；不把早期版本批准记录视为持续安全背书。

### 复现方式

在独立的 Windows 打包准备环境中，使用与产品一致的 Python 与目标架构，通过已有 pip 工具安装 `程序/requirements.txt`，例如在 `程序` 目录执行：

```powershell
& '<独立准备环境>\python.exe' -m pip install --no-deps -r requirements.txt
```

八包已经包含传递依赖并精确锁版；`--no-deps` 避免解析器在锁表之外追加或升级包。安装工具属于准备环境，不要求进入产品 runtime。之后必须使用目标生产解释器执行本页门禁，核验交付 purelib 的实际结果。该锁固定包版本，不声称固定 wheel 哈希、下载源或整个 Python/系统环境；Python、Tkinter、FFmpeg/FFprobe 的交付另循既有流程。

本轮隔离运行环境已由父任务准备；本轮没有安装包、升级包或修改共享运行环境。

## 四、精选评估标准

新依赖先说明具体需求及标准库、现有实现是否足够，再记录以下依据：

| 维度 | 应核对和记录的内容 |
| --- | --- |
| 用途 | 产品还是开发维护用途；现有调用入口、替代方案、直接和传递依赖范围 |
| 维护 | 官方维护状态、发布与兼容策略、已知问题、安全公告和修复记录 |
| 许可证 | 直接及传递依赖的许可证、再分发及声明义务是否适合交付 |
| Windows 支持 | 目标 Python/架构支持、可用 wheel、原生库和外部程序要求，以及实际验证结果 |
| 体积 | 对目标交付物实测安装前后增量，注明环境、口径、原生组件及额外下载；未测写未测 |

不再用固定星数、月下载量、维护年限、依赖层数、体积或“节省几天”的未实测硬阈值代替判断。社区热度可以作为线索，不能代替用途、维护、安全与许可证核验。体积、耗时和收益没有测量依据时不填估算值作为验收结论。

产品仍以 Tkinter 为 UI 基础，不因某库热门就引入 UI/Web 框架、ORM 或深度学习框架。重型组件和大量传递依赖应先证明产品需求、部署边界及维护成本；独立工具环境不自动获得进入产品 runtime 的资格。

## 五、门禁与验证边界

`tests/architecture/test_dependency_whitelist.py` 使用 `importlib.metadata.distributions(path=[purelib])` 只枚举目标解释器目录，不使用用户 site 或导入模块来推断安装版本：

1. 生产锁的八包必须齐全，版本必须与 `requirements.txt` 精确一致。
2. 开发允许包缺失不报错；安装了有版本约束的开发工具则检查该约束。
3. 生产锁、开发允许项以外的实际 distribution 报未知包。
4. 缺包、错版本、未知包、仅生产八包和含开发工具的正常组合均由可注入映射的纯验证函数覆盖；发现路径用替身校验，不接触用户目录。
5. 锁表只接受 `包名==精确版本` 和注释；重复名称、范围及安装指令报错。名称统一大小写及 `-`、`_`、`.` 差异。

在 `程序` 目录使用目标解释器运行：

```powershell
& '..\运行环境\Python\python.exe' -B -m unittest tests.architecture.test_dependency_whitelist -v
```

本门禁检查实际安装的元数据及锁表契约，不等同于自动漏洞扫描、许可证审计或产品功能全量回归。旧主树版本不匹配应报告失败，不能放宽锁表或修改共享 runtime 来制造通过。

### R3224 定向实测（2026-11-17）

| 环境与阶段 | 实际结果 |
| --- | --- |
| 隔离环境，修改前 | 3 项中 2 项失败：旧版本断言及七个开发工具被当作必装 |
| 隔离环境，修改后 | 上述 unittest 命令 15/15 通过；purelib 实有六个生产 distribution，无开发工具 |
| 旧主树解释器，加载本树测试 | 15 项中 1 项失败，唯一版本差异为 requests 实装 2.32.3、锁定 2.34.2；其余 14 项通过 |

以上只验证本轮依赖门禁；默认冒烟、其他架构门禁及全量回归未在本子任务运行，不能把 15/15 解释为全产品绿色。未安装或修改任何共享运行环境。

### R3671 依赖准入实测（I15／L1-H6）

| 包 | 锁定版本 | 许可证 | Windows wheel | 冷导入实测 | 体积增量 | 维护状态 |
| --- | --- | --- | --- | --- | --- | --- |
| psutil | 7.2.2 | BSD-3-Clause | cp314 win_amd64 wheel 可用 | ≈21–22 ms（≤50 ms 阈值） | 隔离安装 ≈895 KB（≤5 MB 阈值） | 活跃维护，GitHub psutil/psutil |
| nvidia-ml-py | 13.615.71 | BSD | 纯 Python（pynvml.py），无原生扩展 | ≈30.8 ms | 隔离安装 ≈703 KB | NVIDIA 官方维护仓库 |

准入结论：两包均满足 L1-H6 四项阈值（冷导入 ≤50 ms、非启动关键路径惰性导入、体积增量 ≤5 MB、许可证／Windows 支持／维护状态已记录）。psutil 在 `infra/resources.py` 内惰性导入，模块导入零成本由 `tests/test_resources.py::LazyImportTests` 断言；nvidia-ml-py 无 NVIDIA 驱动时 `snapshot()` 的 `vram` 字段降级为 'unavailable' 不抛异常（I15-2）。
