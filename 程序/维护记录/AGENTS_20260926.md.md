## 双角色工作模式

### Executor（默认）

1. 读 `project_status.md`，确认当前状态。
2. 扫描项目，定位涉及文件，输出清单,无需用户确认。
3. 只做本轮任务，不改其他文件。
4. 输出：修改的文件路径 + 改动摘要 + 验证结果。
5. 不输出完整前后对比，只输出摘要。



### Reviewer（每次 Executor 完成后自动切换）

1. 本轮任务是否满足验收标准？
2. 是否改了范围外的文件？
3. 是否通过了 `python smoke_test.py`？
4. 是否引入了新的代码问题？

输出审查报告：通过 / 不通过 + 理由。
只有 Reviewer 通过，本轮才算完成。

## 自检规则

| 时机         | 命令                                      | 说明                                           |
|:---------- |:--------------------------------------- |:-------------------------------------------- |
| 每轮         | `python smoke_test.py`                  | 只跑本轮快速检查；不通过不得继续                             |
| 改动活跃逻辑     | `python smoke_test.py --affected <模块名>` | 只跑受影响测试模块，例如 `--affected idea_chat workflow` |
| 需要增量回归     | `python smoke_test.py --gate`           | 按台账串行执行改动过的测试文件                              |
| 发布前／用户明确要求 | `python smoke_test.py --all`            | 完整串行回归；不通过先修复                                |

不再按轮次自动触发完整自检：Tk UI 全量回归耗时长、会创建大量界面，不适合作为日常开发门禁。

## 每轮结束时

1. 更新 `project_status.md`：

   - 把本轮完成的任务从待办移到已完成

   - 更新当前轮次

   - 更新自检计数器

   - 更新检查点

   - 控制在 5K token 以内，只保留当前有效状态

2. 在项目根目录的tasks_round文件夹内新建 `tasks_round_N_result.md` 记录本轮结果。

2. 你的目标是一次性地完成当前分配的任务。
3. 完成任务后，请运行项目自检测试命令。
4. 如果所有测试通过，你的最终回复必须是：`[TASK_COMPLETE]`, 然后自动开始完成阻塞或待办或队列中的任务。
