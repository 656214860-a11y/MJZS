## 八、本会话新增的三件事（第 64 期任务的收尾）

### 8.1 旧目录归位（第 3 条）：只做联接，绝不搬运

用户报「文件还在旧文件夹中，没有导入新的文件夹架构」。真搬会把这些路径上的读者一起改掉
（`writing/`、`episode/`、`storyboard/`、`cloud_video/`、`workflows/` 到处都在读），所以只做**目录联接**：
老目录照旧是权威位置，阶段目录下多一个同名入口。用真项目副本实测：

```
ensure: 94 个目录
归位: 7 条；跳过: []
    \00_script\writing              -> 链接
    \01_storyboard_draft\分镜拆分    -> 链接
    \02_assets\资产清单             -> 链接
    \03_continuity\资产清单         -> 链接
    \04_storyboard_final\分镜拆分    -> 链接
    \05_first_frame\frames          -> 链接
    \07_video_gen\cloud_video       -> 链接
老目录还在吗: True
抽查：00_script/writing 里的东西 = ['创意_2026…', '剧本_2026…', '历史备稿']
关软件时的清理也不碰联接（单独验 `storage_maintenance._remove()`）：`_remove(链接, root) -> False`，
连名字叫「历史版本」的链接也一样不动，真身一个字节没变。
```

规矩：落脚点上已经有东西＝跳过并记一笔；建链接失败＝也记一笔，**绝不拦下「打开项目」**；
老目录本身已经是链接＝不再接一条（免得链到链）。

### 8.2 资产页提速（第 7 条）：先把钱花在哪量清楚

真项目副本上量的（1400×900 可见窗口，79 张图）：

| 量什么 | 数字 |
|---|---|
| 第一次打开资产管理页 | 3.4～4.2 s（其中 6 张图要整张解码） |
| 之后再翻回来 | 0.79～0.92 s |
| 缩略图新解码 | 首开 6 张，之后 **0 张**（缓存命中） |
| `sync_plan`（两种 scope） | 0.029 s ／ 0.053 s |
| `prune_raw_outputs` | 0.004 s |

结论：**已经不是第 55 期那个「整库解图」的卡顿了**（那时每项资产都解一遍），现在的大头是
Tk 自己的版面重排（`update_idletasks`）与并发在跑的后台批次。据此只做了一处有依据的改动：

`asset_thumbs` 的淘汰规则从「先进先出」改成「最久没看的先走」（LRU），容量 240 → 1200。
先进先出挤掉的恰恰是**最早造**的那几张（天天在看的资产图），图一多每次翻回来都要重解码；
LRU 只挤掉最久没看的。
