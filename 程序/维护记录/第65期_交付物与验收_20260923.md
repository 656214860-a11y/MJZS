## 三、四个根因（深挖）

### 3.1 ComfyUI「打开后不开始」：任务排上了，接口却回 500

真机复现：`/drama/assets/start` 交一批 → `/drama/assets/dispatch` 回 HTTP 500，而 ComfyUI 日志里
已经写着 `got prompt`、`/queue` 里躺着那一条。助手把 500 当整批失败，于是弹窗里只有英文
`HTTP Error 500`。修法：节点 `/drama/assets/health` 里声明了 `direct_submit: true`，助手就自己
POST `/prompt` ＋ `POST /drama/assets/ack`，老节点才退回 `/dispatch`，失败不再中断整批。

### 3.2 弹窗最小化后不可见：还原那一拍当场重设 transient

Tk 不肯对 transient 窗调 `iconify`（`can't iconify … it is a transient`），所以最小化前要先把 owner
摘掉。原来在 `<Map>` 里当场 `win.transient(owner)` 挂回去——实测（`work/probe_min3.py`）：

```
shrunk   iconic 0 alpha 1.0
restored withdrawn 0 alpha 1.0      ← 窗口成了 withdrawn：看不见、任务栏也点不回来
shrunk2  iconic 0
Timeout (0:00:25)!                  ← 第二次还原卡死在 wm_transient（界面线程死锁）
```

修法：窗口真的回到 `normal` 之后，隔 150 毫秒再挂 owner；那一拍窗口又被最小化／已经关掉就不挂；
`<Destroy>` 把没到点的定时器撤掉；owner 摘不掉就不最小化。改后实测连做三轮
最小化／还原都是 `iconic → normal`，窗口一直在。

### 3.3 「模型没有会话:空回复」

`finish_reason == 'length'`：模型把这一次的输出额度全花在思维链上，正文一个字没剩。
`idea_chat.reply_text()`／`pet_agent.extract_content()` 兜 `reasoning_content`／`reasoning`，
并把这种情况翻成一句人话（`why_empty()`）。

### 3.4 并行自检里剪贴板被抢（顺手修）

`--all` 8 路并行，剪贴板是全机器共用的一块。上一轮全量就红了一条：期望 `窗边的猫`，读回
`一只猫在窗边 …`——那是**另一个测试进程**写进去的。修法是 `clipboard_lock.py` 把这四个断言
串起来排队。

## 四、修改前后对比（关键两处）

```
# 最小化：改前（窗口会丢）

# 最小化：改后
known_owner(); win.transient(''); win.iconify()               # 失败就把 owner 挂回去、不最小化
win.bind('<Map>', lambda e: put_owner_back())                 # 隔 150ms、且窗口是 normal 才挂
```

tests_active(): 显式开关 / unittest·pytest 在 sys.modules / test_·probe·run_selftests 主模块名
plan(): if PLANNER is None and tests_active(): return 'run'

## 六、已知限制

- 最小化之后再还原，owner 是「隔 150 毫秒挂回去」的：那 150 毫秒里又被最小化／关掉就不挂了，
  窗口保持独立的顶层窗（任务栏里有它自己的按钮）。
- `tests_active()` 把「`unittest`／`pytest` 已经在 `sys.modules` 里」也算测试阶段——这是有意的
  （用户要的就是「代码测试阶段无需弹窗」）；程序自身不 import 它们，真跑应用不会误判。
- 剪贴板锁等不到（30 秒超时）就照旧往下走：那种情况下仍可能与别的进程抢。
- 首帧那一路仍走节点自己的 `/prompt`（不使用 drama 组件），输出节点固定 `'14'`、尺寸必须与
  `batch_frames_tool/config.json`（768×432）一致，不符就报失败。
