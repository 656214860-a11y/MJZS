## 二、逐条「改前 → 改后」

### 1. 通用原则 1：统一前缀布局

- `程序\pet_llm.py`：`build_payload()` 里手搓的三段消息

  ```
  改前：messages = [system(前缀)] ／ 追加 system(快照) ／ 追加 user(压缩后的指令)
  改后：fixed = [前缀]（＋快照）；messages = token_saver.layout_messages(fixed=fixed, current=指令)
  ```

  产物一字不差——`test_pet_llm.CacheFirstTests` 那几条断言（前缀在第 0 条、快照键序稳定、
  快照为空就不出现、用户输入被压缩）全部照旧通过。

- `程序\model_router.py`：`ModelAdapter.payload()` 原来只会拼 `{'model','max_tokens','temperature'}`，
  没有 system 位；`chat()` 也没有这一档。

  ```
  改前：payload(model, messages, options=None)
  改后：payload(model, messages, options=None, system='')  ← system 永远排在第 0 条
        chat(messages, options=None, model='', system='')
  ```

### 2. 通用原则 4：子 Agent 拿不到环境变量（本期最实的一刀）

- `程序\codex_tasks.py`：

  ```
  改前：subprocess.Popen([exe,'app-server','--stdio'], …, encoding='utf-8', creationflags=…)
  改后：新增 RPC.__init__(program)／RPC.subagent_env()／RPC.environment()
        Popen(…, env=self.environment(), creationflags=…)
  ```

  `environment()` ＝ `dict(os.environ)` ＋ `{'CODEX_CODE_SUBAGENT_MODEL': 'fast', 'MAX_THINKING_TOKENS': '10000'}`；
  设置里改过就按改过的来，配置读坏了也照样给出出厂那一对。

### 3. 通用原则 5：压缩阈值只能调低

```
改前：没有这把键
改后：token_saver.normalize({'model_context_window': 128000, 'model_auto_compact_token_limit': 200000})
      → model_auto_compact_token_limit = 115200（窗口的 90%；写大了静默压回）
```

### 4. 阶段二 Claude：新协议档

- `程序\model_pool.py`：`WIRE_APIS` 加 `('messages', 'messages（Anthropic 原生）')`；
  `PROVIDER_WIRES['anthropic']` 由 `'chat'` 改成 `'messages'`；`probe()` 加这一档
  （地址 `/v1/messages`、头 `x-api-key` ＋ `anthropic-version`、仍是 16 个 token）。
- `程序\model_router.py`：`endpoint()`／`headers()`／`payload()`／`chat()` 都认这一档；
  新增 `AnthropicAdapter`（`claude-opus-5`／`claude-sonnet-4.5`）。
- `程序\pet_llm.py`：`usage_of()` 的命中那一格现在两家都认
  （`prompt_cache_hit_tokens` 或 `cache_read_input_tokens`），返回的三个键一个不多、一个不少。
### 5. 设置新增一格「Token 节省」

- `程序\pet_settings_ui.py`：

  ```
  改前：TABS = (basic, model, level, budget, dev)
  改后：TABS = (basic, model, level, token, budget, dev)
  ```

  新增 `TOKEN_TITLE`／`NOTE_TOKEN`／`TOKEN_ROWS`／`TOKEN_ENTRIES`／`token_seed()`／`token_project()`／
  `token_page()`；`open_hub()` 的 `seams` 里多一格 `'token'`。三个选择项用 `ttk.OptionMenu`
  （**不是** `ttk.Combobox`）：`test_pet_settings` 里那条用例数的是整扇窗里的下拉框
  （「默认／对话／升级／降级四个」），多三个就会红。
- `程序\pet_ui.py`：`_settings_entries()` 的兜底表同步；新增 `Pet.token_settings()`／
  `Pet.set_token_settings()`（读写全局配置里那把 `token` 键）。
- `程序\pet_agent.py`：`SETTING_KEYS` 加 `'token'`；`load_settings()` 把这一把原样带回。

  页面四颗键：`保存`（写全局配置）、`恢复默认`（填回出厂）、`写入项目`、`写入全局`；另有一块只读
  预览，显示 AGENTS.md／.codexignore／.codex/config.toml／clawmux.json 四份文件写下去长什么样。

### 6. 写盘三件套

```
token_saver.deliver_project(root)   → <项目>/AGENTS.md、<项目>/.codexignore、<项目>/.codex/config.toml
token_saver.deliver_global(home=…)  → <CODEX_HOME 或 ~/.codex>/config.toml
token_saver.scan(project=…, home=…) → 只读报告：写了哪几把键、三份文件齐不齐、环境变量有没有
```

三份文件的写入全是「合」（缺哪条补哪条、顶层认得的键就地改），再写一次字节不变（幂等用例钉着）。

## 四、没做／没动的地方（如实记）

- **阶段三 ClawMux、阶段四 CC Switch 是外部工具**（附件原文是 `npm install -g clawmux` 与
  「打开 CC Switch 界面」）。程序里给的是可写盘的配置、健康检查地址、四步起法、四家 Provider 地址
  清单与本地路由环境变量——没有假造一个本地代理冒充它们。
- **`stage_parallel` 那张按阶段算的并行表没动**：附件注意事项 5 说的「并行子 Agent ≤ 2」是
  Codex 子 Agent 的用量建议，与本程序「分镜／资产按单元并行」不是同一件事，硬改成 2 会把
  「资产 3-5 路」「首帧 4-6 路」那一整套打乱。这一条落成 `SUBAGENT_LIMIT = 2` 与
  `parallel_advice()`，在设置页与用例里都查得到。
- **`token_saver` 不自己发请求**：真发请求仍走 `pet_llm` 与 `model_router`，这里只做
  「算得准、写得出、验得到」。
- `test_pet_llm.CredentialTests` 单跑仍红（DPAPI 在沙箱里被拒），`--all` 绿——第 65 期就记过，
  与本期改动无关。
