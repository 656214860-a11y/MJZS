## F. 证据与复核方法（供复核者重放）

- `scan.py`：节点= `production_runtime_files()`（与架构门禁同口径）；边= AST Import/ImportFrom（含 `from pkg import submodule` 解析、相对导入、`import_module`/`__import__`/`.module(` 常量实参）；BFS 种子= `.pyw` 全部导入＋`UI_PLUGINS` 解析目标；产出 `scan1.json`（tier/prod_in/ext_consumers/coverage/layer/facade）。
- `verify_refs.py`：非 LIVE 节点四类针全仓匹配 → `refs.json`。
- `classify_refs.py`：命中行分类（IMPORT 仅认 `import <lit>`/`from <lit>` 真平铺引用，`import pkg.<lit> as <lit>` 别名不计；每文件每针取最强类别）→ `classified.json`。
- 覆盖率基线 `维护记录/覆盖率基线.json` 仅作辅助：cov=0 与死候选吻合，但懒加载插件/子进程天然低覆盖，不单独作判据。
- 已知盲区：跨行 `import_module(变量)`、`getattr` 链、`.json`/`.skill.md` 内模块名引用（已做反向 grep 兜底但未逐条裁决）、`from pkg import name` 形式的包内子模块引用在命中分类中不计 IMPORT（实体侧以 import 图 prod_in 为准，不受影响）。
