## 结论

- 本仓的模型主链将凭据用于 HTTP `Authorization` 请求头，未发现其进入本仓 `logs/`、`启动错误.log`、任务 JSON、prompt 正文、`broadcaster` 或 `skill_panel` 的可达写入链。
- 假值探针经 `model_secrets → pet_llm.credential → pet_llm.headers` 成功；默认冒烟后，对允许范围内产物扫描未命中。
- 存在一项外部持久化风险：Comfy 云资产链把密钥作为 `extra_data.api_key_comfy_org` 发送给本地 Comfy 服务。本仓台账写入发生在发送前，未保存该字段；但 Comfy 的队列／历史是否保存请求体不在本仓可证范围，故列为存疑并升级为 `[SECURITY]` 待排期项。

## [SECURITY] 单开任务书要素：Comfy 请求体携带密钥

**影响面**：云资产批量提交与原生资产直接提交；`asset_batch_execution.py:124`、`native_assets.py:152-166`。风险是本地 Comfy 队列、历史、诊断或插件可能把请求 `extra_data`／`api_key` 持久化或展示。

**最小整改**：先以隔离的假值在实际 Comfy 运行实例确认 `/prompt`、队列历史、节点日志与任务 JSON 是否持久化字段；若确认，移除提交 payload 中的原始 key，改为服务端本地配置或不可逆、短期引用标识。不得以仅掩码显示替代移除原值。

**验收判据**：

1. 假值不出现在 Comfy 队列、历史、日志、项目任务 JSON 或本仓日志；
2. 认证后的云资产提交仍可完成，且失败消息不含请求体或 header；
3. 静态门禁拒绝 `api_key`／`api_key_comfy_org` 进入持久化任务结构；
4. 用假值复跑 source→sink 探针与默认冒烟。
