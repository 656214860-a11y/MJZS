# 总控包 scripts 机检桥接入边界

## 范围与权威

`aigc_lint.py`（L1 基础设施）是总控包（`skills/00全流程SKILL/AIGC创作全流程/.../scripts/`）机检脚本到本应用 `skill_tools` 的**受控桥**，不改写、不复制上游脚本判据——脚本本身仍是上游子模块（`lixiaoxiao9888-create/manju-laoli-skill`）的唯一权威。本文件只记录「桥已就绪」之后，各脚本在应用里的**适用时机、输入形态、是否已接线**，供后续功能轮按此接入，避免再次拿错输入形态。

## 输入形态错位（为什么未直接接门禁）

三类脚本的输入与本应用现有产物**不是同一形态**，直接接线会误报、误阻断：

1. **`feed.validate` / `feed.gateCheck` 吃「七段式投喂稿」**，而应用视频阶段产物是**单镜 `video_prompt` 文本**（`video_prompts/<镜头>.json`，≤1500 字，含资产编号/动作/运镜/台词/环境声）。拿单镜文本喂七段式校验器，`validate_prompt.py` 会直接报 **exit 3（非投喂稿）**，等于白白阻断视频阶段。应用当前**没有**「七段式投喂稿」这个受管产物形态（见 `video_prompt_direct_api.py`：`MAX_CHARS=1500`，`video_prompt_rules()` 明确单镜文本）。

2. **`style.lockRecommend` / `style.lockLadder` 吃「题材描述文本」**（需含打斗/特效等信号词），而应用的题材输入是**2~4 字标签**（`故事题材` 字段，如「冒险悬疑」，见 `idea_chat._brief_fields` 的 `genre`）。标签没有「打斗/特效/画风基底」信号，喂推荐引擎只能命中默认族，失去推荐意义。

3. **画风锁在应用里是「用户手动锁定的值」**，不是「需 AI 推荐」：`style_base`（画风基底，4 选一）+ `style_directors`（导演风格卡，≤4 张），在阶段配置里由用户填，属于可选制作锁（`skill_panel_workflow._optional_lock_keys`）。推荐引擎的语义（给题材 → 出候选卡）与「用户已选好画风」的现状不同构。

## 正确的接入时机（供后续功能轮）

| 脚本 | 正确时机 | 前置条件 |
|---|---|---|
| `feed.validate` / `feed.gateCheck` | 视频生成阶段**提交前**，作为投喂稿的确定性门禁 | 应用先产出「七段式投喂稿」受管产物（或提交前把单镜 `video_prompt` 拼成七段式临时稿）。这是**产物形态改动**，需单独立功能轮并改 `docs/stages/` 的需求/设计文档 |
| `feed.auditContract` | 质检交付阶段收尾 | 同上，需要全流程交付稿（P0~P5）作为输入 |
| `style.lockRecommend` / `style.lockLadder` | **剧本准备阶段**（用户填完 `故事题材`、尚未锁 `style_directors` 时） | 需要① 把「题材标签」扩展为可喂推荐引擎的「题材描述文本」（含打斗/特效/画风信号），或② 提供独立的题材描述输入框；③ 推荐结果以「候选卡」UI 弹出让用户勾选。改动面跨 `idea_*` 与剧本准备页 UI |
