# 每分钟成本核算

项目用量总览读取项目根目录 `cost_profile.json`。配置缺失时只展示已落盘用量，不猜费率。此入口输出已录入成本估算；“录入项齐全”不是实际账单或交付验收通过。

## 录入步骤

1. 保留既有配置中的 `budget_amount`、`price_table.model_rates` 和费率版本；不要用下面示例覆盖项目预算。
2. `duration_seconds` 填本次成功交付成片的实际秒数，不填所有生成片段、失败任务或重试时长之和。手工片长只校验有限正数，界面明确标注尚未绑定证据。已有交付确认时，优先使用下述 delivery_outputs 文件列表。
3. `overheads` 填本次交付额外发生的 GPU、存储、带宽和人工金额，均与价格表同币种。未知填 `null`；确认没有发生才填 `0`。已经包含在云服务费用中的 GPU 等资源不要重复加算。
4. 在“设置→预算→费用核对”核对请求金额。旧视频/Comfy 费用先显式导入，再按真实账单核对。保留非空本地凭据及核对人，程序记录凭据摘要和修订历史。此操作不代表远端未知任务已完成，也不会重发任务。
5. 打开项目用量总览，检查缺费率、未知请求、预留和外部费用缺项，再读取每分钟结果。不得把已知部分当全部实际成本。

结构示意（费率和版本须替换为项目真实口径；示例不是供应商报价）：

```json
{
  "duration_seconds": 60,
  "human_minutes": null,
  "price_table": {
    "currency": "CNY",
    "version": "替换为适用费率版本",
    "rates": {"seconds": 0.1},
    "model_rates": {
      "替换为实际图片模型ID": {"images": "0.1"}
    }
  },
  "overheads": {"gpu": null, "storage": null, "bandwidth": null, "human": null}
}
```

`rates` 用于通用请求单位；已接入逐模型金额台账的请求采用冻结费率或人工核对金额，不与通用费率重复相加。模型条目支持输入/输出 Token、图片张数、视频秒数和 TTS 字符的对应单位，实际支持范围及预算配置见 [模型金额预算](模型金额预算.md)。不自动换汇，也不猜不同规格的适用价格。

## 结果口径

- 制作成本：模型费用 + 额外 GPU + 存储 + 带宽，再除以成片分钟数。人工不计入此项。
- 人工编辑耗时：项目配置顶层 `human_minutes` 填本次成本范围的实际人工编辑分钟数（多人工作分别累计，不用任务挂起或机器运行时间代替）。未知填 `null`；确认未发生才填0。总览同时显示总人工分钟和每成片分钟对应人工分钟，不由金额倒推耗时。
- 含人工全成本：制作费用完整且人工金额已录入时，显示两者之和除以成片分钟；任一金额缺项则显示未知。人工耗时缺失不阻止已知金额相加，但仍单列耗时未知。该结果仍受估算/账单及共享成本覆盖边界约束。
- 人工编辑费用：单列金额和每分钟费用；未录入显示未知，不补零，也不阻断已录入制作成本的完整性。
- 已知部分：允许有缺项时展示已知金额；未知请求、预留、缺少费率或制作费用缺项时不输出完整总成本。
- 估算与账单：用量总览分别显示冻结费率估算支出和人工已核对金额。每分钟汇总可能混合两者及人工录入的外部费用，仍不能冒称全部供应商账单已对账。

核算例：成片30秒，模型费用2元、存储1元、GPU与带宽确认为0、人工2元，制作费用为6元/分钟，人工为4元/分钟。删除人工录入后，制作结果仍为6元/分钟，人工显示未知。删除存储录入后，只能显示模型已知部分4元/分钟，总制作成本未知。

## 尚需实际验收

已接入主要文本、Seedream、TTS、云视频和内置Comfy云图片的逐次费用与预算，并提供人工账单核对及旧账导入。仍不能宣称全入口费用覆盖100%：本地GPU自动采集、自定义云节点、共享资产分摊、自动账单对账、跨币种换算尚未完成。真实一分钟成本验收仍需完整账单、资源费用及对应交付成片；本地测试不能替代这些证据。


## 使用已确认交付文件的片长

在同一 cost_profile.json 增加 `"delivery_outputs": ["13质检交付/成片.mp4"]`，路径应替换为本项目实际交付文件，也可列出不同集的文件。先在交付阶段通过现有“校验并确认本阶段成果”入口完成技术探测和人工确认；成本核算不会替您完成确认。

配置该字段后，程序从成果确认清单取探测片长，重新核对文件大小、SHA256、已采用分镜及其摘要，不再采用 duration_seconds。同一采用分镜的多个导出格式不能重复计时；多集各选一个交付文件后汇总秒数。缺少确认、文件替换、分镜改稿、空列表或重复文件均显示核算错误，不静默回退手工片长。核算只读取，不修改预算、文件或交付状态。

分子仍是整个项目归属的已记录费用。因此应选齐本次成本范围内所有交付集；选少会使每分钟成本偏高。共享资产跨项目/集分摊尚未自动处理。交付确认含人工内容确认，并不代表商用审核、两人质量评审或供应商账单核对已经完成。
## Comfy 费用覆盖核对（R1571）

用量总览会核对 `workflows/comfy_*.json` 与请求台账。没有关联记录、关联已丢失或任务文件损坏时，逐项显示费用覆盖缺项，总成本保持未知；排队、失败及提交结果不确定也不推定免费。已关联的任务沿用原台账计价，不重复加价。

这项检查覆盖已有任务文件，不采集 GPU 时长，也不推断自定义节点价格；填入 GPU 总额不能自动证明每份任务已核对。

R1572起可在设置→预算→费用核对→“导入视频/Comfy 旧账”显式导入本地与自定义工作流。每份工作流按费用组登记，不假设是一张图片；进行中任务须查询终态后重新导入，再填写金额、币种、核对人及非空凭据。已核对且来源摘要仍匹配时解除该项覆盖缺口；来源变化后重新导入会保留审计并将金额恢复为未知。只存在费用组的项目也能显示核对金额并核算成本。

同一GPU支出若已按任务核对计入台账，不要再计入overheads.gpu；该字段只填写额外未计入的GPU费用。导入前本地发送策略保持原样；主动纳入总账后，未知费用或来源变更会影响已启用的金额上限。自动GPU用量采集仍待完成。
