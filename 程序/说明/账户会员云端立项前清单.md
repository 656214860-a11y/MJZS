## 3 决策清单（D1–D16，按依赖排序；每项须先有结论才可开工）

### 3.1 身份与账号 D1–D5

- **D1 身份基线**：账号制（用户表述倾向）还是设备授权？账号与设备的绑定关系、单账号设备数上限、设备解绑与转移规则。
- **D2 账号来源**：自建账号（须口令哈希、找回、撞库防护、可能的多因素）／第三方登录（责任外移，但引入外部生态依赖与可用性耦合）／混合。既有订阅决策第 1 项「身份（设备／账号）」按**账号**口径重估。
- **D3 最小信息集**：邮箱／手机号／仅用户名？手机号等于实名与短信成本面，须说明是否必需（PIPL 最小化原则）。
- **D4 未成年人**：短剧内容场景是否设年龄门槛或实名——**须法务确认，不是工程能自定**。
- **D5 注销与数据导出**：PIPL 删除权与可携带权；账号注销后本地项目数据、云端凭据、账单留存各自如何处理、保留多久。

### 3.2 订阅与计费 D6–D11b

- **D6 授权模型**：软件授权制入口闸门（既有决策）还是功能分级；**闸门只能落在统一的 L3 入口，禁止内联散写**（既有约束）。
- **D7 定价与试用**：3 天试用／月 39／季 99／年 399（既有登记）是否维持、是否随云端成本调整。
- **D8 服务器权威**：本地「是否已付费」被改不算数；桌面只缓存**带签名、带过期时间**的续验结论（既有决策）。
- **D9 试用计时**：以**服务器时间**为准，防本地钟回拨或前调（既有决策）。
- **D10 凭据存储**：**禁走 DPAPI 机器绑定**（既有决策）；订阅令牌不入日志／任务 JSON（覆盖率审计 27）。
- **D11 付款资质与合规**：商户＋对公、ICP 备案、托管收银台**不碰卡号**、PIPL、退款与账单对账口径。
- **D11b 离线与宽限（新增）**：断网或验权失败的宽限窗口多长；超窗后的降级行为（只读？禁止生成？禁止导出？）。

### 3.3 云端后端与数据 D12–D16

- **D12 云端职责边界（关键分叉，应最先定）**：只做**鉴权与订阅**（用户仍自带 API Key、不碰模型调用链，等于既有决策），还是**代理模型调用**（随之带来密钥托付、成本垫付、限流与滥用、内容责任、合规升级）。
- **D13 项目数据是否上云**：本地项目是否需要同步／备份／跨设备。这决定隐私面、存储成本与离线可用性的上限。**默认建议：不上云，只做鉴权**——上云等于把「用户素材不离开本机」这条产品前提作废。
- **D14 数据库与迁移**：选型（托管 PostgreSQL／MySQL 等）；**迁移与回滚策略必须在设计期定**（前向迁移＋回滚脚本＋备份＋演练），不得上线后补。
- **D15 服务端部署与发布**：云端 CI/CD、客户端与云端 API 版本协商、最低客户端版本强制升级、服务端回滚。阶段5 的 U1（触发载体）／U6（观察判据）／U12（指标聚合）正是这里要用的接缝。
- **D16 可观测与限流**：服务端日志与脱敏、失败率与延迟 SLO、配额、撞库与滥用防护、审计留存期。

## 4 与既有硬约束的冲突清单（开工前逐条裁决）

| 现有约束 | 与账户／云端的冲突 | 处置方向 |
| --- | --- | --- |
| 密钥 DPAPI 机器绑定 | 既有决策又要求订阅凭据**禁** DPAPI | 两套策略并存，不得复用同一存储路径；先定义边界再写代码 |
| 无网络监听（入站零暴露） | 云端服务天然有入站面 | 云端入站只暴露鉴权 API；**本机不得反向暴露端口**给云端或他人 |
| 零第三方依赖＋裁剪解释器（无 `sqlite3`） | 服务端必然有框架与数据库依赖 | 桌面端与 **服务端依赖策略分离**；不得把服务端依赖带进 `运行环境/` |
| 单进程 Tkinter | 账号态、验权、心跳都是网络调用 | 验权不得阻塞 UI 线程，须走既有后台任务生命周期（`BackgroundTaskLifecycle`） |
| 删除权威／路径权威 | 账号化后出现「谁能删谁的数据」 | 本机用户可见删除仍走回收服务；云端不做本机文件权威 |
| 覆盖率审计 27（令牌不入日志/JSON） | 新增服务端日志与埋点 | 同一约束延伸到服务端日志与错误上报 |
| AGENTS §2.1 不写密钥、保护用户数据 | 云端成为新的数据汇集点 | 服务端不得成为绕过授权的旁路；不采集项目素材 |

## 5 需随本立项重估的既有 N/A 与接受裁决

- **阶段4 T6／T7** 的性能口径是本地桌面口径（冷启动、页面、编码队列），**不覆盖服务端** → 服务端须另立延迟与可用性 SLO。

## 6 验收候选（立项后才定稿，此处只记方向）

- **授权对抗**：改本地钟、改本地状态、重放旧续验结论、离线伪造，均不能通过。
- **计费不变量**：延伸到服务端——分项求和＝总额、不出现负额、币种隔离、退款与扣费对称。
- **迁移**：前向迁移、回滚脚本、失败恢复、旧数据兼容（对齐 §3.8 可靠性/数据迁移轮口径）。
- **灰度**：小流量观察授权失败率／错误率／成本，含回滚触发条件与**回滚演练凭据**。
- **安全**：跨账号越权读写、支付绕过、注入、凭据不外泄、订阅令牌不入日志。
- **合规**：隐私政策、数据导出与注销、付款资质与备案——**须法务确认，工程不能自证**。
