# 发布检查单（U5／U6／U7／U13 登记）

只登记流程和口径，不新增机制。标「未实现」的步骤现在靠人工，对应队列项见 `维护记录/优化待办队列.md` 阶段5。

## 1. 发布前（构建→自检→更新记录）
1. 工作树干净，`project_status.md` 当前轮次与最新结果文件一致。
2. 自检：`本地CI.cmd exit` 出口绿（口径见 runbook §3、§4）。
3. 构建分发副本：`scripts\distribution_build.py --plan` → `--build --destination <新目录>` → `--verify --destination <新目录>`；只往新目录写，不动开发目录。
4. 构建自检：发布前跑 `本地CI.cmd release`（= `exit` 全部步骤 + `scripts\distribution_selfcheck.py`），非 0 不得发布（U2，R2229）。`exit` 本身不含分发自检，日常提交仍只跑 `exit`。
5. 在 `说明/更新记录.md` 写本次版本条目（见 §4 版本↔提交映射）。

## 2. 安装与回滚点
6. 升级前先留回滚点：**现状靠 Git 与上一版分发副本，没有专门的升级前快照目录（U4 未实现）。** 覆盖安装前，确认上一版分发副本仍保留。
7. 安装只覆盖程序文件，保留 `config.json`、`projects.json`、`desktop_settings.json`、`private`、`data`、项目与素材。**现状：仓库里没有 `install_release.py` 与 `reorganize_install.py`（旧文档提到的脚本已不存在），安装靠手工解压覆盖，并按 `安装信息.json` 与 `distribution_manifest.md` 对照落位。**
8. 安装后：关闭旧窗口重新打开，跑默认冒烟 `smoke_test.py`（8 项全过）。

## 3. 发布后观察与回滚触发（U6）
- **观察期 24 小时**（用户 2026-11-01 裁定）。自安装完成、首次启动起算。
- **判定样本：至少 5 次阶段运行**（用户 2026-11-01 裁定）。样本不足 5 次时只做记录和提示，不据此判定回滚。
- **立即回滚（不等样本）**：应用无法启动；项目数据读不出或被写坏；密钥出现在日志或任务 JSON 里。
- **样本够 5 次后回滚**：阶段运行失败占比明显高于上一版同口径（暂定「超过上一版一倍」，**该比例用户尚未裁定，待 U12 指标聚合落地后复核**）。
- 观察期内只读指标：`logs\` 里的启动与异常记录、阶段完成核验结果（`stage_completion_service`）、任务失败记录。自动聚合与告警（U12）未实现。
- 回滚动作：停应用 → 用上一版分发副本覆盖程序文件（同 §2 的保留项）→ 重新打开 → 默认冒烟 → 在 `更新记录.md` 写回滚条目和原因。回滚演练与凭据（U8）未实现。

## 4. 版本↔提交映射（U7）
- 每次正式发布在 `更新记录.md` 的版本条目里写：版本号、对应提交哈希（取发布时的 master HEAD 前 8 位）、最新轮次号。`VERSION` 横跨多轮，不能单靠它定位提交。
- 约定打本地标签 `release/<版本>-R<轮次>`，指向上述提交；标签只留本地，不 push（AGENTS 禁止未授权 push）。**现状：尚未打过标签，标签仍是约定。** U3（R2229）已让 `分发清单.json` 带 `commit`（HEAD 完整哈希）与 `round`（HEAD 提交标题 `R<N>:` 的轮次），在非 Git 目录或读不到时留空，不阻断构建。
