# 版本控制处置说明

Git 是源码与文档的回滚依据。`升级备份/` 与 `.bak_*` 保留现状，作为 Git 引入前的历史证据；后续修改不再新增 `.bak_*`，需要恢复时优先使用 Git 提交历史。

## .git 损坏

1. 停止写入仓库，不删除工作目录或用户项目目录。
2. 复制当前工作目录到安全位置，并保留 `.git/` 作为诊断证据。
3. 由维护者确认远端/可信备份后，重新克隆或重建 Git 元数据；再用只读比较恢复未提交源码。
4. 恢复后运行默认冒烟、架构门禁与需要的安全全量，再建立新的轮次提交。

## 误提交密钥或用户数据

1. 立即停止推送与共享；撤销或轮换对应密钥，假定已泄露。
2. 记录涉及的提交、文件路径与密钥类型，但不把密钥值写入工单、日志或结果文件。
3. 由具备仓库管理员权限的维护者按托管平台流程重写历史或撤销访问；不要在普通工作轮自动执行历史清理。
4. 补齐 `.gitignore`、暂存前凭据扫描与受影响密钥轮换证明后，重新验证并提交。
