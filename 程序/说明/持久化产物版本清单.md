# 持久化产物版本清单

用途：给「正式 JSON 产物的格式漂移」一个可核查的入口。版本权威是
`程序/contract/artifact_schema.py`；本文件是它的阅读投影，只登记**已在源码核实**的事实，
未核实的一律标「待核查」，不得据本文件推断某产物已有版本。

## 约定

- 新产物写入 `schema_version`，用 `artifact_schema.stamp(kind, payload)`；`version` 高于登记版本会被拒绝。
- 读取侧用 `artifact_schema.classify(kind, payload)` 判定五态（`current`／`legacy`／`missing`／`future`／`invalid`），只读、不抛异常、不自动改写用户数据；`future` 可读但不迁移不回写。
- 历史产物沿用旧键 `version` 的，由 `artifact_schema.migrate(kind, payload)` 按 `STEPS` 版本阶梯显式抬升，只加键；缺迁移步返回问题清单而非抛错。需要落盘时由属主写路径调 `artifact_schema.migrate_file()`（`.bak` 备份＋失败回滚＋读回版本断言）。
- 新增产物类型必须先在 `artifact_schema.REGISTRY` 登记版本、必备字段与写入模块；跨版本的数据抬升同步在 `artifact_schema.STEPS` 按级登记。

## 已核实：无版本键（U11 收口，R2330）

按「读源码写入口」逐项核实，下列产物现行格式**没有版本键**，读取侧按字段容错，本轮不改磁盘格式：

| 产物 | 现行格式 | 依据 |
| --- | --- | --- |
| `natural_script_selection.json` | 固定两键 `{path, sha256}`，读取时校验路径与哈希，不匹配即视为未选定 | `script_workspace_service` 写、`script_contract.resolve_script_source` 读 |
| `skill_config.json`（项目阶段配置） | 按阶段 id 存模型与技能，无版本键；程序级预设 `stage_config` 才带 `version: 2` | `stage_config.path` |
| `assets.json`（资产管理） | 模型／技能产出，应用只读取和校验，不由应用写版本 | `asset_contract`、`asset_batch_state_service` |
| 批次／三元组定稿台账、其余 manifest | 随各自写入模块登记；新增产物写 `schema_version`，历史文件继续用旧键 | 见上表与「边界」 |

要给这些产物加版本，须另立功能轮并写迁移与回滚；单纯加键会让旧版本程序读到未知字段，不在收口范围。

## 边界

- 本轮为登记与只读校验，未改动任何既有产物的磁盘格式，无用户数据迁移。
- 新产物写 `schema_version` 是"新增写入"约定；历史文件继续用旧键，读取侧兼容。
