# 目录协作协议

本目录只服务开发与CI，不在桌面程序启动时运行，也不进入产品分发。目录协议的机器权威是 `structure.json`；规则理由只在 `decisions/0001-directory-layout.md`，不另建同主题 ADR。581 条旧跨模块测试归属以精确路径冻结，不能通过放宽通配把新测试悄悄放行。

## 开工检查

1. 确认独立工作树、任务范围和真实轮次，不修改其他车道索引。
2. 确认新增路径所属角色与 owner；不存在合适角色时先修改协议并评审。
3. 执行：`python -B governance/check_structure.py --check --root <仓库根> --summary`。新增未跟踪文件追加 `--candidate 程序/相对路径`，每个候选必须是文件。
4. 运行结构测试与受影响回归，再按项目协议提交。完整架构门禁包含结构检查。

路径一律相对仓库根，用正斜杠。程序目录承担 src 角色；不为目录形式迁移现有技术层包。新独立组件按运行时/业务职责划分，不按文件格式分组。

## 规则与分级

| 规则 | 含义 | 处置 |
|---|---|---|
| STR002 | 自有路径无角色/owner、目录决策缺失 | 硬错误 |
| STR003 | 命名违规 | 存量指纹冻结，新增即红 |
| STR004 | 源文件父目录相对程序根深度超过4 | 存量指纹冻结，新增即红 |
| STR005 | 自有顶层纳管目录为空 | 硬错误，不检查用户/运行/第三方目录 |
| STR006 | 测试缺模块或跨模块契约归属 | 存量指纹冻结，新增即红 |
| STR008 | legacy内容无来源/版本/owner/退役理由 | 硬错误 |
| STR009/010 | 产品静态导入/可确定动态路径指向legacy | 硬错误 |
| STR011 | 开发/退役内容未被分发清单明确排除 | 硬错误；另用真实构建plan验证 |
| STR012 | 跟踪运行/私有/构建数据，文件缺失，忽略规则缺失 | 硬错误 |

配置错误、路径逃逸、符号链接/junction、大小写碰撞、Git冲突均退出2，不允许纳入历史基线。检查新增违规退出1，无新增退出0。

命名：自有代码/测试为英文小写下划线；新目录英文小写；文档允许中文，禁止日期/版本副本。标准入口、历史任务、阶段/ADR编号、第三方原名分类处理。根模块深度0是接受的现状，不为达到2层而造目录。

## 协议字段

- `source_root`：源码角色根（程序）；`roles`：职责、owner与说明。owner是当前真实责任角色“项目维护者”，不虚构多人团队。
- `excludes`：精确边界及原因，不允许用通配排除整个自有源码。gitlink作为原子条目，不进入子仓库、不下载初始化。
- `naming_exceptions`：精确文件豁免，包含理由、owner、复核条件。
- `test_ownership`：含真实测试用例的同名模块测试可推导；跨模块新测试须列精确目标/作用域和契约，不能仅凭无关 import 认领，不强制一对一镜像源码。
- `frozen_contract_tests`：只冻结当前索引中 581 个确实无法从同名目标推导的存量测试路径（含后续主干测试；合并时逐项复核），共用真实 owner、理由与复核条件；删掉的旧路径报错，新文件绝不继承豁免。
- `packaging`：构建/签名配置未来落点、分发排除、共享忽略。没有真实配置不创建空packaging目录。签名私钥永久在仓库外。
- `retirement`：实际legacy对象的来源、适用版本与退役证据。没有对象就不创建legacy目录。
- `decisions`：结构决策唯一位置。

## 基线与归档

`structure-baseline.json` 保存实际旧违规身份 `(rule_id,path,subject)`，不是总数。删一个旧违规再加一个新违规仍失败。检查不会更新基线。

仅显式运行 `--write-baseline` 可更新；更新前审查added/removed和理由，不允许接受硬错误。基线含来源提交、索引清单摘要、协议摘要。索引摘要用于追溯，不要求每次源码提交重建；协议摘要必须匹配，规则改变须显式复核且不能接受新硬错误。旧违规减少会报告清债。

主数据、密钥、运行目录、缓存、工作树和第三方包内部不扫描正文。空目录只查已声明自有源码根的直接目录，不用“删光所有空目录”干扰运行状态。分发隔离不等于Git忽略，二者分别验证。

## 已接受的能力边界

legacy检测覆盖静态import、字面量动态导入及脚本/资源路径；运行时用户输入与任意反射无法静态证明安全，须在迁入legacy前人工核对注册表、消费者和分发计划。扫描器不执行legacy。第三方包许可证、gitlink状态不能靠命名检查替代。

当前源码技术层布局、中文资源目录和历史任务命名不是本轮全仓重构目标。维护记录与历史轮次保留原样，现行文档统一由 docs/README.md 导航。
