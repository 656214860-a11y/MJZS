## C 优化清单 T1–T12（待确认，不自动执行）

### 集成 / E2E

- **T1（E2E 自动化缺位）** 现状：`recovery_to_delivery_baseline.py` 已覆盖只提交一次、断网/429/轮询超时/进程重启/强杀/取消/运行中改稿/下载中断、真实编码与 `assemble`，但**只能手工跑**，不在 `run_selftests.py` 任一层。建议：把其核心断言收编为一条无 GUI 的 gated E2E，单列层或挂全量安全层，先记耗时再定频率。代价：编码+进程重启预计 +30~60 秒；缺 ffmpeg/无 node 时须按 skip 卫生登记。
- **T2（门禁覆盖不均）** 现状：`stage_parallel.py` 定义 7 个交接门禁（SG-A/SG-B/01..05），端到端探针只执行 SG-01..05；SG-A/SG-B 仅静态/单元覆盖。缺口：管道首段（剧本→结构→分镜→预演→资产）与末段（视频→配音字幕→剪辑→质检交付）无“真实证据级”端到端断言。建议：探针扩到 SG-A/SG-B，末段加“产物齐备→可导出”证据级断言；无门禁阶段显式登记为“无门禁”，不得默认通过。
- **T3（无运行期串行用例）** 现状：`tests/architecture/test_pipeline_stage_io_contract.py` 是**声明式**依赖图契约，不跑一遍。建议：加运行期串行用例（按依赖图释放阶段、断言输入来自上游产物、不许跳级），用假适配器/最小夹具控成本。

### AI 质量

- **T4（无自动指标）** 现状：金标准表为空、按设计延到付费阶段；除记分规则外无任何自动质量/结构回归。建议：加“结构不变量”层（离线、假传输、零依赖）：固定提示词→断言字段齐备、镜号唯一、时长合计、提示词长度上限、JSON 可解析、无控制字符、无路径穿越，作为提示词/模板改动闸。风险：结构指标不得冒充“AI 可用率”。
- **T5（换模型无对照）** 现状：`tests/test_adapter_failure_conformance.py`（Q5）固定**失败**分类；成功路径只有各适配器自身单测。建议：加“同一逻辑请求→各适配器请求体字段映射”对照表用例（假传输），防换模型时字段静默丢失。

### 性能 / 稳定性

- **T6（口径窄）** 现状：5 条绝对指标（冷启动<1500ms、300 项页<800ms、滚动帧<45ms 且重排格数<200、缩略图<25ms、内存增量<30MB）+ 启动 5 项上限。缺口：无批量生成/并发提交吞吐、无编码队列吞吐与积压、无弱网/高延迟（现有故障是离散错误不是延迟分布）、无队列压力下 UI 响应口径。建议：先补本地可测两条（批量首帧每镜耗时、后台队列 N 并发排队时延）；供应商延迟只登记外因、不进门槛。
- **T7（长跑与抖动）** 现状：30 分钟内存长跑是手工；全量时长在凭据里波动大（近期 419–717 秒）；`test_desktop_startup_perf` 的“首日选择框 1 秒内可见”在并发负载下会抖（d8d0fc5 全量红、单跑 14/14 绿）。建议：轻量 soak（3–5 分钟固定循环）纳入全量安全层；全量时长只记观测 P95 不设硬阈值；对已知抖动用例定重试/串行隔离策略，否则凭据可信度受损。

### 功能

- **T8（通过率无分母口径）** 现状：`说明/产品需求与验收矩阵.md` US01–US07 最后一列是**验收责任角色**，不是用例/证据编号；“≥95% 通过率”没有按需求或模块的分母。建议：给 US01–US07 各挂“自动化用例 / 手工步骤 / 未决项”三态映射，未决项直接指向 8 项待验收。另：skip 台账 227 个**登记位**（PLATFORM_TKINTER 203），本机 tkinter 可用，实际跳过约 3 个（node 1 + bundled skill 2）——须登记“当前环境实际跳过清单”，避免把登记位读成已跳过。
- **T9（缺陷无闭环索引）** 现状：`维护记录/缺陷台账_20261001.md` 有 3 条“A 级·待实机复验”挂账（desktop.py 启动饿死链、项目改名认领、右键删除失效登记），无“守护用例”反向索引，台账本身是 2026-10-01 普查。建议：每条 A 级挂账补“守护用例/复验步骤/状态”，并把“待实机复验”列为阶段4出口的显式未决项，不计入通过。

### 安全

- **T10（注入面）** 现状：无 `shell=True`/`pickle.load`/裸 except，路径/删除/JSON 有边界门禁。缺口：LLM/SKILL 文本会落到项目文件并注入下游提示词，未见“模型输出不得越出阶段目录/不得写任意路径/不得顶替上游引用”的对抗用例。建议：以假模型输出构造样本（`../` 穿越、绝对路径、超长、非法 JSON、控制字符/换行、伪 front-matter），断言写入受 `stage_layout` 约束、引用不被顶替、失败有可见原因。
- **T11（出站外泄）** 现状：密钥有 DPAPI+sink 审计（覆盖有限函数内传播）。缺口：**上传给供应商的文件**无白名单断言。建议：给每个上传路径加“出站文件必须来自阶段目录内已登记素材，不得含密钥/其他项目/用户私有目录”的断言（假传输，断言实际读到的路径集合）。
- **T12（口径澄清）** 本地单用户桌面应用、无网络监听、无账户、无支付通道（花费是 API 与本地资源，走 `usage_overview`/`RequestLedger`，已有金额不变量）。**“越权”“支付漏洞”不适用，应显式记 N/A**，不得用不存在的攻击面凑数；适用的安全面是注入（T10）、出站外泄（T11）、供应链（3.15.0a2 alpha 解释器 + `skills/**` 第三方库）。
