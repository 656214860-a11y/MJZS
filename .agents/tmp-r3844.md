## 精确API与真实fixture

固定官方源码：https://raw.githubusercontent.com/theupdateframework/python-tuf/v7.0.1/tuf/ngclient/updater.py 、同标签`tuf/api/metadata.py`、`tuf/ngclient/fetcher.py`、`examples/manual_repo/basic_repo.py`及`tests/repository_simulator.py`。

运行时inspect与源码一致：`Updater(metadata_dir, metadata_base_url, target_dir=None, target_base_url=None, fetcher=None, config=None, *, bootstrap)`。bootstrap是必需关键字，正式初始根应随可信安装包交付；`bootstrap=None`只用于明确选择已有可信缓存。序列`refresh → get_targetinfo → download_target`；未知目标返回None，`find_cached_target`复用已验证文件。FetcherInterface只实现`_fetch`；使用内存map、域名fixture.invalid，socket与DNS直接设为拒绝，绝无真实API/仓库请求。

签名fixture使用官方Metadata/Root/Targets/Snapshot/Timestamp/MetaFile/TargetFile和CryptoSigner.generate_ed25519，四角色key仅在build进程内存；输出只含公开root/签名元数据/合成目标字节。根轮换由旧根和新根双签，不自行实现签名或TUF版本比较。

| 场景 | 实测结果 |
|---|---|
| 正常refresh/目标下载/缓存/未知目标 | 哈希验证一致、缓存路径复用、unknown返回None |
| 相同长度目标首字节篡改 | LengthOrHashMismatchError，target目录无半成品 |
| timestamp无签名 | UnsignedMetadataError，target目录空 |
| 过期元数据 | ExpiredMetadataError，target目录空 |
| 先v2后v1，同一持久metadata目录 | BadVersionNumberError；没有清缓存伪造防回放 |
| 旧/新根双签轮换 | 可信root版本升至2 |
| 非可信key签署bootstrap root | UnsignedMetadataError |

结果：**7 passed / 0 failed**。第一次client脚本误将DownloadHTTPError从不存在的tuf.ngclient.exceptions导入而失败；对照固定官方fetcher源码纠正为tuf.api.exceptions后完整7/7，两进程隔离再次复跑仍7/7。没有把脚本调试失败删成“首次就通过”。
